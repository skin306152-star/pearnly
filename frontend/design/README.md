## 为什么要搬这份，而不是自己定颜色

用户 2026-09-18 明确："涉及到颜色皮肤 css 的地方，用 pearnly-app 的颜色"。
而旧产品里已经有一份自称 **"Pearnly unified design system"** 的文件，被**五个入口共用**
（旧构建脚本 `check_cachebust.py` 里那份共用清单就是它），语义层注释写着
`Purple v2 = home's exact values` —— 也就是说它的色值就是当前产品线上真正的样子。

自己再定一套颜色，结果就是新界面和旧界面不是同一个产品。

## 品牌色（抽出来的实值）

| 令牌 | 亮色 | 暗色 | 用途 |
|---|---|---|---|
| `--accent` / `--brand` | **`#7c4dff`** | `#a974ff` | 主色（紫） |
| `--accent-deep` / `--brand-hover` | `#6b3ff2` | `#c7a8ff` | 悬停 / 按下 |
| `--accent-weak` | `#eee5ff` | `#2c2347` | 浅底（选中、徽标底） |
| `--accent-ink` | `#fff` | `#1d1438` | 主色上的文字 |

中性色与状态色同样在这份文件里：`--bg` / `--card` / `--ink`(`#231942`) / `--ink2` /
`--ink3` / `--line` / `--good` / `--warn` / `--bad`，外加 Open Props 的
violet 与 gray 两条色阶、间距、圆角、字号、阴影。

> 别把三种紫搞混：产品用的紫色是 **`#7c4dff`**；
> `#a974ff` 是它的**暗色模式**版本；
> 而登录页那套是第三个值 `#7655f6`（那一屏本来就和产品界面不是同一套，且已按原设计整份复用）。

## 文件里有什么（五层）

| 层 | 内容 |
|---|---|
| 1 | Open Props 原语（violet / gray 色阶、间距、字号、圆角、阴影），MIT |
| 2 | 语义令牌·亮色 —— **产品真实的色值就在这一层** |
| 3 | 语义令牌·暗色（靠 `.dark` 类或 `[data-theme=dark]` 切换，刻意不用系统媒体查询） |
| 4 | 兼容别名（`--brand` → `--accent` 等，让旧选择器继续有效） |
| 5 | 组件类：`.pu-btn` / `.pu-toast` / `.pu-modal` / `.pu-empty` / `.pu-error` / `.pu-skeleton` |

## 搬迁规则

1. **逐字节复制，不手改。** 要改先改旧仓源头，再整份重搬 —— 免得两边越走越远。
2. **本文档记来源 SHA-256**：搬新版本时同步更新它，这样"这份是从哪来的"永远查得到。
3. 文件自包含（没有 `url()` 外部引用），可以直接被构建工具引。

## 还没定的

ADR-005 定的是"新业务页面用 Vue 3 + Frappe UI 组件库"。而这份文件自带一套 `.pu-*`
组件类（纯 CSS）。两者怎么合，是本轮要定的事：**文字与色值来自这份文件（已定），
组件是用 Frappe UI 再套这层皮、还是直接用 `.pu-*`** —— 见 ADR-007。
