# 租户登录后直接进工作台（不要"桌面"那一屏）

日期：2026-09-18。状态：**已实现并实测**（两个真开通的租户 + 控制面，19 项断言全过）。

## 用户要求

> "用户登录现在是到桌面吗？然后选择模版进入工作，对吗？我不要这个桌面，
> 直接进入工作台，左侧导航。"

先回答"现在是什么样"——当时实测的确实是两屏：

```
登录 → /desk（标题 Desktop，页面上只有 1 个图标，没有左侧导航）
     → 点那个图标 → 工作台（这才有左侧导航）
```

不是"选模版"，是"先落一屏图标网格、再点进去"。用户不要这一屏。

## 根因（三处叠加，缺一条都还是先看到桌面）

| # | 位置 | 问题 |
|---|---|---|
| 1 | `User.default_workspace` 没设 | Frappe 的首页规则靠它算落点。它为空 → 规则返回 `desk` → 落到桌面 |
| 2 | 登录回调 `identity.py` | 落点**写死** `saved.get("redirect_to") or "/app"`，而访客入口那步传的就是 `/desk`（`login_redirect.py` 里也写死），等于**绕开首页规则** |
| 3 | 工作区 `content` 是空 `[]` | 工作台是按 `content` 里的"方块"画的，光有 `links` 不够 → 页面只剩一句"欢迎来到 XXX" |

第 3 条是**改完前两条才暴露出来的**：以前没人把工作台当落点，所以空着也没人看见。

## 改法

### 1. 让每个业务账号都有默认工作区

新增 `pearnly_core/workspace.py`：

- `apply_to_site_users()`：开通收尾时给站内**所有还没有**默认工作区的业务账号设上；
- `apply_to_new_user()`：挂在 `User.after_insert` 上，管**之后新增**的员工账号
  （否则新员工又会先落到桌面）；
- **已有值不动** —— 那可能是用户自己在界面上选的，重跑开通不能顶掉。

工作区名从产品 App 自己的 `modules.txt` 推模块名再查，不在代码里再抄一份模块名。

为什么选 `User.default_workspace` 而不是别的：

| 方案 | 否掉的理由 |
|---|---|
| `Role.home_page` | 一个设置覆盖全站，但工作区名**每租户一个**（"开通验证租户 65956"），框架的 `role_home_page` 是静态映射，对不上 |
| `Website Settings.home_page` | **会连带改掉访客的首页行为**，副作用超出这件事 |
| `User.default_workspace` | Frappe 专为该场景准备的字段；用户在界面上看得到也能改；清掉不影响别处 |

### 2. 登录落点交给首页规则

`identity.py` 的落点改成 `workspace.resolve_after_login()`：

- 访客本来要去的**具体页面**照旧尊重；
- 但如果那只是"站点的门"（`/`、`/login`、`/app`、`/desk`），就换成他自己的首页。

`login_redirect.py` 同步改成把**访客本来要去的那个入口**带过去，不再写死 `/desk`。

### 3. 已登录用户打开裸域名也回工作台

新增 `login_redirect.send_root_to_home()`。

为什么需要：Frappe 把 `/desk/<工作区>` 用「**URL 不变**」的方式渲染成 SPA，
所以根路径拿到的其实是同一套页面、地址栏停在 `/`，SPA 看到路径是 `/` 就显示桌面。
表现就是"登录时对了，但从书签或重开浏览器进来又看见桌面"。

**只处理根路径，不碰 `/desk` 与 `/app`**：那两个是明确的"去桌面"入口，
拦掉会让工具栏的应用切换图标看起来"点了没反应"，反而更难用。也只在目标确实不同时才跳，避免自跳成环。

### 4. 工作台要画出卡片

`ensure_product_workspace` 现在同时写 `content`：每个 Card Break 对应一张卡片方块
（`{"type": "card", "data": {"card_name": …, "col": 4}}`，一行三张），
形状照抄框架自带工作区。

## 实测

`scripts/sample-verify-tenant-landing.mjs`，**19 项全过**：

| 项 | 验到了什么 |
|---|---|
| 入口 | 访客打开站点根 → 统一登录页 |
| **落点** | 登录后落在 `/desk/开通验证租户-65956`（不是 `/desk`） |
| **左侧导航** | 侧边栏在，且里面有工作区条目；左下角有账号菜单 |
| **工作台内容** | 出现"录入工作台"（cowork）/ "身份证录入"（dms）卡片 |
| 空态 | 不再是"欢迎来到…"那种空工作台 |
| **根路径** | 已登录打开裸域名 → 仍回工作台 |
| 不误伤 | 显式打开 `/desk` 仍可用 |
| 不越界 | 控制面访客没有被送去统一身份（ADR-004） |
| 干净 | 无 JS 报错、无意外 4xx |

截图：`docs/p4/evidence/tenant-landing-{cowork,dms}.png`。

## 踩到的两个坑

1. **hooks 缓存是上一轮的**。改完 `hooks.py` 重建镜像、重建容器之后，
   `frappe.get_hooks("before_request")` 里**只有旧的钩子**，新加的那个没出现；
   而同一份文件里的 `doc_events` 却是新的。原因是 app hooks 缓存在 Redis 里、
   容器重建不会清。**改完 hooks 必须 `bench --site <站点> clear-cache`。**
2. **工作台空态不容易发现**：`links` 有数据、工作区也在侧边栏看得到，
   只有 `content` 是空的那一句"欢迎来到…"。不打开看是发现不了的。

## 边界（没做 / 不确定）

- 只在本机 Colima 验证过，**没部署**，没有真机验收。
- **控制台一直刷 `socket.io` 连接失败的 404**：本地样例没把 socketio 端口映射到
  宿主机，属于既有环境问题，与租户落点无关，这次没处理。验证脚本里把这一条
  **明确按 URL 排除**，不是笼统地"忽略所有报错"。
- 工作台的卡片是 **DocType 列表入口**，还是框架自带的样子。产品自己的界面属于
  ADR-005 的前端工程，还没开始；等前端做出来，这一屏会被产品界面替换。
- "首页（订阅与计费）"这个功能没有对应 DocType，所以**工作台上没有它的入口**
  （不装样子的原则，见 `docs/p4/09-authorization.md`）。要它出现得等前端。
