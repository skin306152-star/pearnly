# 建单执行体：把预览卡的确认真正变成一张单

日期：2026-09-19。承接 [43-booking-attempt-contract.md](43-booking-attempt-contract.md)。
线上基准 `501589f0`。

这一批落的是**最后一块拼图**：预览卡的确认 / 取消 / 重试怎么变成一次真实提交。
它是 43 号那层"提交登记"的**唯一调用方** —— 到这一步，LINE 那条链从
"拍卡 → 建档 → 订车逐问 → 预览卡"接上了"→ 确认 → 建单 → 推送"。

## 一、搬了什么

| 新平台 | 线上 | 说明 |
|---|---|---|
| `dms_booking_flow.py`（新增） | `booking_flow.py` | 建单执行体（14 个名字与线上对齐） |
| `dms_out.enqueue/start_loading/download_content`（补） | `_out.make_spawn` / `start_loading` / `download_content` | LINE 出口 + 后台调度那一层 |
| `line.start_loading`（补） | `line_platform.client.start_loading` | "正在输入"动画 |
| `line_session.replace_claimed_booking_payload`（补） | `session_store.replace_claimed_booking_payload` | 受守卫的草稿改写/丢弃 |
| `dms_booking.book_in_session`（补 `on_attempt` 透传） | `_book_in_session` | 建单入口必须把登记回调传下去 |

## 二、顺序不能变（这一层全部的价值都在这儿）

    确认按钮 → 消费 nonce → 后台执行体
      ① 先查"这张草稿登记过没有" —— 登记过就**不再提交**，回"结果未知"
      ② 解端点 → 下附件 → 建单（**提交前登记**，登记失败就不写）
      ③ 成功 → 台账 + 回执 + 清理草稿；失败 → 按"能不能重试"分流

几条钉死的规矩：

· **确认是一次性的**：nonce 被原子消费，同一张卡的第二次点击必然 mismatch。
· **取消在登记过之后不许说"已取消"**：那时请求可能已经发出去了，改说"结果未知、
  请管理员按这个号核"。这是"不许撒谎"那条规矩在取消路径上的落点。
· **重试只对"明确发生在建单之前"的阻塞开放**（并发挤下线 / 主档暂时读不到 / 客户查不到 /
  公司银行主档没就绪）。主档**已变更**不重试（重试只会拿到同一份主档，那是"改内容"）；
  任何已经写下去过的结果（`submitted`、有 `booking_id`）**一律不重放** —— 重放未知写入
  就是双单。
  **有意变化（2026-10-13，业主拍板）**：连不上 / 网络异常 / 排队超时改用与建档同一份口径
  （`config/pacing.RETRYABLE`），原来订车自己一份名单、漏了网络异常（只回一句没有按钮的
  "请稍后重试"，十几分钟后才冒出重试卡）。还给按钮时"连不上"说现有的「连接 DMS 超时或
  网络异常 · 请稍后重试」，不说「…请联系管理员」。登录页都没打开（账号密码还没提交）时，
  同一个任务先自动用下一档再试一次（`run_logged_in(line_write=True)`）；业务一旦开始绝不
  自动再试。后台任务 600 秒时限到点报可重试的网络异常，不再说"服务器内部错误"；已登记
  提交的照旧改判"结果未知"、不给重试卡。
· **钱没填够**走另一条路：回预览卡让人补齐（轮换 nonce，新卡能再确认），不是重试卡。
· **建单成功但附件没挂全**：绝不谎报附件成功，但回执也**不等附件**。
  **有意变化（2026-10-13，业主拍板）**：原来是"回执里如实补一句"，实际代码是先补附件、
  补不上就不发回执 —— 单已建成、草稿已清，操作员 LINE 上什么都收不到，点"查看结果"
  还可能看到"已过期"而重录出第二张单。现在：回执照常当场发（与附件齐全时逐字相同、
  同一刻走免费回覆）；发出回执的那一轮不补附件；之后每轮（`delivery.schedule_due`）
  只把缺的附件补进同一张单，补齐不发任何消息；补到第 6 次仍不行（任何失败都算，
  与回执重试分开计数）就停，先定好"单号 + 现有的 `dms.card.qa.TXT_ATTACH_FAIL`"
  和它自己的 retry key 再发一次，LINE 接受了才转 Review；改绑一律直接转 Review、不发消息。

## 三、三处**不是漏搬**

线上的 `_spawn` / `_book_in_session` / `_card_payload` 在新平台没有对应物：

· `_spawn` → 后台调度统一走 `dms_out.enqueue`（`dms_flow` 也改成用它，一套实现）；
· `_book_in_session` → 早就是新平台的 `dms_booking.book_in_session`（本批只补了
  `on_attempt` 透传）；
· `_card_payload` → 在新平台是**死代码**：建单层自己用 `card_from_customer` 从客户档
  造卡，线上那个辅助函数只喂给旧的 `_book_in_session`，而那个函数我们已经不走了。

## 四、验证：`sample-verify-dms-booking-flow.py`（31 项）

出口全换成记录器、建单换成假的，**会话用真的**（跑真 `consume_nonce` /
`replace_claimed_booking_payload` `record_booking_attempt`）。钉住：

· nonce 对不上 → 过期话术且**不建单**；吻合 → 丢后台且 nonce 被一次消费掉；
· 取消：没登记过才真清；登记过 → 改说结果未知（带单号）；
· 执行体：已登记过 → 只回结果未知、**不再提交一次**；
· 成功路径回执含单号/车型/交车日/顾问，写台账，附件齐全时**不**提附件；
· 附件没挂全 → 回执照常当场发、与附件齐全时逐字相同，这一轮不补附件；
  结果未知 → 只说结果未知且**不给重试卡**；
· 可重试的阻塞 → 出重试卡且草稿被重挂成待确认（新 nonce、认领标记已摘）；
· 钱没填够 → 回预览卡；重试判据逐条（六种情形；网络异常 2026-10-13 起给重试）；
· 附件下载：PNG/jpeg 头识别、取不到按附件失败记且不阻断建单；
· 主档变更后的两条回头路：改名重发摘要、被删退回该步骤 / 顾问被删直接丢草稿。

写用例时踩到两次同一个坑，值得记：**payload 在真实路径里是 `consume_nonce` 给出的**
（草稿此时已被认领）。我漏了这一步，于是"重挂草稿"被正确地拒绝了 —— 用例错、代码对。

## 五、还差什么

**入口**：菜单层（`menu_cards` / `menu_flow`）与"建档之后接着订车"的接线。
菜单卡上还有两行是网页链接（进入 DMS / 改密码），要等前端页面那批；
Rich Menu 的发布还缺公网图片与门户页。`booking_edit.py`（逐问期编辑）也还没搬。

另外顺手修了守卫的一个假阳性：防漏键正则 `cards\.` 会把 `qa_cards.XXX` 也算进来，
于是拿一条住在 `dms.card.qa.*` 的键去 `dms.card.*` 里找（真被绊到一次）。
已加 `(?<!qa_)` 并把 `qa_cards.` 那条路单独扫 —— 现在两个命名空间都管得住。

全套验证：**509 项**全绿（16 个脚本）。
