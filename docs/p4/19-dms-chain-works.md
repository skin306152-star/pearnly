| 我们这边 | 老产品 | 干什么 |

| `dms_errors.py` | 老产品里的 `_DMS_FRIENDLY` | 20 个错误码 × 5 语言的用户话术 |

另外给端点表补了 `booking_defaults`（JSON）字段并迁移了四个站 ——
老产品把这套建单默认值放在 `endpoint.config` 里，我们落到 DocType 上。

### 两处实现差异（逻辑没变）

1. **主档缓存**：老产品存 Postgres 表，我们存 Frappe 的 Redis 缓存。它本来就是缓存，
   过期/被逐出只是"下次重新抓"，不影响正确性。
2. **凭据来源**：老产品从 config 里取 Fernet 密文自己解；我们读端点文档
   （密码在 `__Auth`，框架负责加密）。

**失败语义照抄，一条没改**：普通读取时登录失败 → 回退陈旧缓存（状态诚实优先于报错）；
`force_refresh` 失败 → **直接空 dict（fail closed）**，绝不把旧主档冒充成刷新过的。

## 二、验证结果

### A 部分：纯逻辑 —— `scripts/sample-verify-dms-intake.sh dms`

**24 项全过**。覆盖：身份证 mod-11（改一位就不过、泰文数字要认、非 ASCII 数字不放行）、
字段 diff（**电话按纯数字比所以假差异不报**、空值=没信息绝不覆盖、`people_id` 永不进）、
相似候选打分（**证号完全一致直接满分**，因为泰国重名太常见）、顾问匹配
（启发层同层多命中→弃权、**精确层认出但不在顾问下拉→拦截且不回落**）、
公司银行转账（账户从主档消失→报错，不许拿旧值提交）、错误码文案兜底。

### B 部分：对真系统只读 —— `scripts/sample-verify-dms-intake-real.sh dms qd65956.localhost`

**全过**。这是"识别 → 查重"那一半，用真客户 `ลูกค้า ทดสอบ ราย 1`（59 号）跑：

| 验的东西 | 真结果 |
|---|---|
| 场景判定 | `exact`（证号命中） |
| 回带客户全字段 | 姓名 + **三套地址块**（户籍/联系/寄送） |
| **字段差异清单** | `phone 1→0812345678`、`house_no 1→99/1`、`moo →3`、`province_id 65→1` |
| OCR 文本 → 主档 id | 府 1 / 县 4 / 区 29 / 邮编 147 |
| 地区四级级联 | 77 个府 → 50 个县 → 5 个区 → 1 个邮编 |
| 相似候选 | 按姓名搜到 `ทดสอบ ซ้ำ 380530`（分 48） |

**差异清单这一条是这次最有价值的输出**：它就是面版上"要不要覆盖"那块标红的内容，
证明 diff 引擎在真实数据上算得对（电话那个假差异没被报出来，说明纯数字归一有效）。

### C 部分：建档（**真写**）—— `scripts/sample-verify-dms-push-real.sh dms qd65956.localhost`

**全过**。这是整条链路里唯一会往 DMS 写数据的验证，约束：只对测试账号、客户名带
`PEARNLY TEST` 前缀、证号用**真正合法**的 mod-11 号（`9990000000014`）。

| 验的东西 | 真结果 |
|---|---|
| 建档前查重 | 不存在 |
| 建客户 | **客户号 126**，`mode=create` |
| **回读核对** | 姓名 / 证号 / 门牌 / 府 id 全部对得上（**没信 PHP 200**） |
| **幂等** | 同证号再推一次 → 如实回 `update`，且**还是 126 号**（没重复建档） |
| 建完再查重 | 命中，且是同一个客户号，场景 `exact` |

⚠️ **本次在测试 DMS 里留下了一个客户：`PEARNLY TEST 20260918`（126 号）。**
没有自动删 —— 删除本身也是一次写操作，我们还没搬也没验过删除路径；
而老产品的笔记里明确写过"某个账号调 `alldel.php` 返回 Delete Success 但客户不删，
测试 orphan 会累积"。所以留着并**如实报出来**，而不是悄悄调一个没验过的删除接口。
要清就在 DMS 客户列表里搜 `PEARNLY TEST` 删掉。
