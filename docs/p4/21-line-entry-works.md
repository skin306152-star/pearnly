## 四、验证：合成事件驱动整条链（真 OCR + 真写 DMS）

`scripts/sample-verify-line-flow-real.sh dms qd65956.localhost` —— **全部通过**。

做法：拦掉 LINE 传输层（`reply`/`push` 记下来、下载图片给真样本图），后台任务改成同步执行，
然后按真实事件顺序喂进去。**不冒充真机验收**（真手机 + 真 LINE 通道是另一层）。

```
发绑定码 → 绑定成功
未绑定发图 → 明确提示要绑定（不静默丢）
发身份证 → 真 OCR（Vertex）→ 提示输手机号
  会话进 collecting，身份证存进会话
输手机号 → 真查重 → 出确认卡（差异卡，主按钮[อัปเดตข้อมูล]）
  卡上复述的是真 OCR 出来的姓名 สมชาย ใจดี
  手机号原样透传进 draft（没在我们这边改写格式）
点确认 → 真写 DMS（客户 127）→ 回执说「อัปเดตข้อมูลลูกค้า」
  会话被清（不留一张能重放的旧卡）
重放同一确认 → 说过期，**不重复写**
乱点旧卡 → 说过期
เริ่มใหม่ → 清会话
```

## 五、这一轮踩到的两个真 bug（都是搬的过程中发现的）

1. **推送台账 `trigger` 值不合法**：老产品写 `"id_card"`，我们台账的选项是
   `manual/line/auto` —— 照抄会直接校验失败。业务结果不受影响（台账失败已兜住），
   但**记录会静默丢**。已改成 `line`。
2. **LIKE 查询的 `%` 没转义**：`'%"people_id_tail"...' % tail` 里的字面 `%`
   被当成格式符，报 `unsupported format character '"'`，台账兜底整段失效。
   已改成 `%%`。

另外这次还补了一个**依赖**：`pymupdf`。老产品注释里写明"相册/相机图片在到达接口前会经
`imagesToPdf` 变成 `photo_*.pdf`"，而识别器只吃图片 —— 不装 PDF 栅格化，网页上传那条路
会直接报"读不出"。**版本与老产品不同**（它锁 1.24.10 跑 Python 3.11；我们基础镜像是
Python 3.14，那个版本没有 cp314 轮子，pip 会退回源码编译并失败），改用 1.28.2
（提供 `cp310-abi3` 轮子）。这是版本跟随，不是换库。
