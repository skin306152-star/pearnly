## 二、两条设计要点（都在验证里钉住）

### 1. 权限是**二次校验**的

动作入口查一次 —— 没权限连菜单都进不去（回"还没有查询权限"）；**后台任务发结果之前再查一次**
—— 读 DMS 要几秒到十几秒，这几秒里权限可能被收回。

少了第二次，刚被收权的人还会收到一份数据。这条**在界面上完全看不出来**，所以验证里专门造了
那个场景：读之前有权限、读之后没有 → 必须**只发拒答、不发数据**。

### 2. 两步都丢后台，条件进会话

`_begin_records` / `_begin_top` 只做两件事：条件写进会话（`query_results`）→ 丢后台任务。
翻页、重读都走同一套：**条件从会话里取、任务从参数读**，不依赖内存里的状态。

几个容易抄错的细节，验证里都钉了：

· 记录的页大小上限是 **10**，看板是 **30**（不一样）；
· 分页时要**核对卡片上的类别与会话里的是否一致**，对不上就说"这单过期了"—— 否则会拿上一批的
  条件去翻下一页；
· 自定义期间 `01/08/2569-31/08/2569 15`：格式不对或条数超 30 都**重问**，不在服务端偷偷夹
  （夹了用户就以为查的是 30 条）；
· 期间用**佛历**（本月 1 号 → 今天），而卡片上的"读到几点"是公历 —— 两套口径，别统一。

## 三、接线（三处）

· `dms_menu_flow`：`QUERY_FLOW_LANDED` 翻成 `True` —— 第 5 项与单字 `5` 都开；真判据仍是花名册
  那一栏（`dms_query_access.can_query`），这个开关只管"这一版有没有这功能"；
· `dms_text_router`：查询那两条"等打字"的态**排在订车之前**（照线上顺序：查询 → 逐问 → 待确认）；
· `dms_flow.handle_postback`：查询动作（含 `menu_query`）归查询层 —— 它自己的权限门在里面。

顺手改了一处：路由里那句 `from ... import dms_query_flow` 原来写在函数体内（每条消息都会多一次
import，而且测试补丁打不中），提到模块级。

## 四、验证：`sample-verify-dms-query-flow.py`（46 项）

出口全换记录器、读数据换假的、**会话用真的**。除了上面那些设计要点，还钉了：

· 四路维度（最新一览 / 要打字 / 要选状态 / 畅销榜）各自落什么态、出什么卡；
· 分组/指标认不出时**落到默认值**且保住已选的另一项；
· 后台任务：开工时没权限 → **静默不发**（连拒答都不发，避免骚扰）；读失败按 `ERR_NO_CREDS` /
  有友好话术 / 无话术兜底三种说话方式；
· 打字：空输入重问、别的态不接管、翻页在首页点"上一页"停在第一页；
· 接线：第 5 项按权限画不画、`menu` 态打 `5` 交给查询层、路由顺序、postback 分发；
· 流程层里**一个泰文字符都不留**（分页过期那句也进了包）。

## 五、这一批撞出的两个"守卫自己"的问题

1. **`cards` 守卫被第三个命名空间串台**：本仓库现在有三套（`dms.card.*` / `.qa.*` / `.query.*`），
   对应模块叫 `cards` / `qa_cards` / `query_cards`。守卫的 `cards\.` 把 `query_cards.` 也算进来 →
   报了一批假"缺键"。已改成 `(?<![\w.])cards\.`（只认裸的 `cards.`）。
   这是同类问题**第二次**（上次是 `qa_cards`），所以注释里把三套命名空间都写明了。
2. **`menu-wiring` 里两条断言写的是"查询还没搬"的旧行为**（"不画第 5 项""不认 5"）——
   功能落地后它们必然失败。已改成断言新意图（按权限画不画、单字 `5` 交给查询层）。
   这也是个提醒：**断言"某功能还没做"会随功能落地而过期**，写的时候要能一眼看出这是临时断言。
