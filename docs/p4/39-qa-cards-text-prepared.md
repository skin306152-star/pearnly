# `qa_cards` 的文本侧先落包（代码那步对着现成的包搬）

日期：2026-09-19。承接 [38-booking-ledger.md](38-booking-ledger.md)。
线上基准 `501589f0`。这是 [37](37-booking-qa-batch-shape.md) 路线里的第一步，
但**只做文本侧**：数据、可逐字核对，不给代码留半截。

## 一、为什么先做这一步

`qa_cards.py` 是 489 行、**64 个常量 + 36 个函数**。常量里绝大多数是泰文卡片文案，
按本项目规矩要全部进语言包。手抄 60 条泰文的风险很高（一个字母错，泰国销售就看不明白），
所以我用 AST 从线上源码里**逐字抽**，再逐条核对。

## 二、抽了什么（用脚本，不手抄）

`th.csv` 新增 **60 条** `dms.card.qa.*`：

| 类别 | 条数 | 例子 |
|---|---|---|
| 逐问问法 `TXT_ASK_*` | 20+ | 问车型、问颜色、问日期、问付款渠道、问金额… |
| 按钮 `BTN_*` | 12 | 确认 / 编辑 / 丢弃 / 分页上一页下一页… |
| 预览卡标签 `LBL_*` | 10 | 销售顾问 / 车型颜色 / 交车日 / 订金合计… |
| 渠道名 `pay.*` | 6 | 现金 / 转账 / 支票 / 现金支票 / 卡 / 其它 |
| 分隔符提示与手工问法 | 3 | `TXT_SEP_HINT`、支票/刷卡的手工银行问法 |
| 其余（状态与回执用） | 9 | 主档变更、要凭证、附件没挂全、`_TH_RETRY`… |

## 三、**没有**进包的三类（也都是有意的）

1. **`PAGE_TOKEN = '__page:'`** —— 这是分页的**协议载荷**，不是给人看的字。
   进包等于把协议翻译了（同 `ACT_*` 动作码的道理）。
2. **`TXT_MASTER_UNAVAILABLE` / `_EMPTY` / `_CHANGED` / `_UNMATCHED` /
   `_TH_ADVISOR_UNMATCHED`** —— 它们直接取自老产品的错误话术表
   （`_DMS_FRIENDLY[码]["th"]`）。那 24 条**早就在我们的包里**（`dms.err.*`），
   再抄一份就是两处维护。代码那步直接 `t("dms.err.<码>")`。
3. **数字常量**（`_MAX_BTN` / `QR_LIMIT` / `QR_PAGE_SIZE` 等）—— 不是文案。

## 四、拼接出来的四条：包存"前缀 + 占位符"

线上是运行时拼的，我按同样的语义拆：

| 常量 | 包里的形态 | 运行时怎么拼 |
|---|---|---|
| `TXT_ASK_CHEQUE_REF` | 只存字面量前缀 | 前缀 + `TXT_SEP_HINT` |
| `TXT_ADVISOR_BLOCK` / `_NO_USER` | 只存字面量前缀 | 前缀 + `dms.err.ERR_DMS_ADVISOR_UNMATCHED` + `_TH_RETRY` |
| `TXT_BAD_PAYMENT_DETAIL` | `…ทั้ง 2 ช่อง **{hint}**` | `_t(..., hint=t(TXT_SEP_HINT))` |

## 五、验证：两头都核过

**主机侧（逐字比对源码）**：重新用 AST 抽一遍期望值，与写进 CSV 的逐条比 ——

```
期望 60 条；实际包里有 60 条 dms.card.qa.*
逐字不一致: 无      缺失: 无      空值: 无
含逗号的条目（验引号处理）: ['dms.card.qa.TXT_BAD_AMOUNT', 'dms.card.qa.TXT_SEP_HINT']
RESULT: ALL PASS
```

那两条含**逗号**的（`เช่น 5000 หรือ 5,000.50`、分隔符提示）是故意挑出来验 CSV 引号处理的 ——
写包最容易在这里把一条切成两条。

**容器侧（验框架读取器）**：`i18n.pack("th")` 读得出全部 60 条、无空值、
`{hint}` 占位符能套进去。

全套 **345** 项仍全绿（加键不影响既有的"防漏键"与"没有空文案"两条断言）。
