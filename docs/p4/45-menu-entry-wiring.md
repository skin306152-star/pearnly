# 入口接上了：เมนู 弹菜单 → 建档 → 接着订车 → 确认建单

日期：2026-09-19。承接 [44-booking-flow.md](44-booking-flow.md)。线上基准 `501589f0`。

最后一块：**用户在 LINE 里怎么走到那条链**。到这一步，DMS 的对话链从入口到建单
整条接通：`เมนู` / 问候语 → 菜单卡 → 选 1 建档 / 选 2 订车 → 拍卡 → 客户档 →
（订车）逐问 → 预览卡 → 确认 → 建单 → 推送。

## 一、搬了什么

| 新平台 | 线上 | 说明 |
|---|---|---|
| `dms_menu_cards.py`（新增） | `menu_cards.py` | 入口行卡（标题区 + 整行可点的行卡） |
| `dms_menu_flow.py`（新增） | `menu_flow.py` | 弹菜单 / 选菜单项 / 续订车 / 重拍 / 落档分叉 |
| `dms_query_access.py`（新增） | `query_access.py` | "能不能查 DMS"的服务端判据 |
| `public/images/menu/*.png`（新增） | `static/dms/line-icons/menu-*.png` | 菜单卡图标 |

接线（改动都在既有文件里）：

· `dms_text_router.route`：**分支顺序照线上重排** —— 全局命令 → 逐问态 → 待确认态 →
  菜单态单字 → 含数字（手机号）→ 无会话弹菜单卡 / 有会话给缺料提示；
· `dms_flow.handle_postback`：`qa:` 前缀 → 建单执行体（确认/取消/重试）→ reset →
  **菜单层** → 保留旧档（`ACT_KEEP`）→ 写档守卫；
· `dms_flow.execute`：写档成功后不再直接说"已保存"，改交 `menu_flow.after_customer_saved`
  按下 `mode` 分叉；
· `line_handlers`：图片事件先看会话在不在逐问态 —— 是则归逐问（收凭证图），否则才当
  身份证去识别。

## 二、两处**有意**与线上不同

### 1. 图标地址改成"本站点自己"的

老产品写死 `https://pearnly.com/static/dms/line-icons` —— 那在"一个域名一个产品"的时代
没问题；新平台**一家租户一个域名**，写死等于所有租户的菜单卡都去别人的站点取图。
现在取 `frappe.utils.get_url()` + `/assets/pearnly_dms/images/menu`，图片随 app 走。

### 2. 卡片上暂不画"进入 DMS / 改密码"两行

第 3/4 项是网页链接（门户页 + 凭证页），那两页在新平台**还没做**（前端那批）。
按本项目既定规矩 —— **点不动的按钮比没有更糟** —— 宁可不显示；页面到位后照老产品
补回（那两行还有 `altUri.desktop` 的分支）。

顺带同一道理：第 5 项"搜索资料"**先不显示、也不认单字 `5`**。判据本身是真的
（`dms_query_access.can_query` 查花名册），但查询那一族（`query_flow` / `query_cards`）
还没搬 —— 门在 `dms_menu_flow.can_query` / `QUERY_FLOW_LANDED`，那一批落地时翻一行即可。

## 三、验证：`sample-verify-dms-menu-wiring.py`（32 项）

菜单层自己是薄的，**风险都在接线**：顺序错了（比如"含数字→手机号"抢在逐问前面）
或分叉没接上，症状都是"用户卡在某一步、没有任何反应"。

· 菜单卡：默认只有 1/2；查资料 **即使花名册给了权限也不画**（查询族没搬）；图标地址是本站。
· 弹菜单：落 `menu` 态且**保留已收料**（含 `mode`/`endpoint`）；问候语先寒暄再出卡。
· 选菜单项：选 1 → `mode=customer` + 提示发身份证；选 2 → `mode=booking`；
  已在菜单里收齐料的用户选 1 → **直接查重**（不让他重拍一次）；手机号不会被吃成菜单键；
  查询那一项没搬 → 不认 `5`（也不假装接管）。
· 续订车：客户号对不上 → 过期话术不开局；对得上 → 开局时把**身份证附件源**与草稿带过去。
· 重拍：nonce 不对 → 会话不动；对 → 清身份证、留 `phone/mode/endpoint` 回 collecting。
· 落档分叉：`booking` → 接着开逐问（且**不**清会话）；`customer` → 收尾不提订车、会话结束；
  零写入路径话术不谎称"已保存"，且姓名回退草稿。
· 路由顺序：`เมนู` / 问候语 → 弹菜单；无会话 → 菜单卡引路；**逐问态的文本先归状态机**；
  待确认态只提醒点确认/丢弃、**会话不被覆写**；登记过的待确认态说"结果未知"。
· postback 分发：`qa:` → 逐问；确认/取消/重试 → 建单执行体；菜单项 → 菜单层；reset 归本文件。

写用例时又踩了自己的坑三次（断言错了层、列表按字符串取、漏了"先消费 nonce"）——
三次都是**用例错、代码对**，改完照旧全绿。
