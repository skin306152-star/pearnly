# 统一登录页改成"复用旧设计"（不再重画）

日期：2026-09-18。状态：**已实现，并用真实浏览器跑了 31 项验证，全部通过**。

## 用户纠偏（这篇文档的起点）

> "你这个自己重新画是不对的，这个登录呀当初画了好多时间才调整好，因为它是一张背景图，
> 所以我们不应该再画那么多时间去重新做，想想简单快捷的办法。"

前一版是在身份服务（Keycloak）里**用手写 HTML/CSS 重画**那套登录页 —— 方向错了。
按旧代码的注释与原文件核对，这套登录页的真实形态是：

```
auth-shell  1402×1122    背景 = 一整张图 auth-bg-desktop.png（4096×3291）
  ├─ brand-panel         猫、气泡、清单卡、引言的"底"都画在图里；
  │                      真实文字按坐标叠上去（.welcome-copy top/left 等都是当年调出来的）
  └─ auth-card  616×914  一张**不透明的磨砂卡**，盖住图里画的登录面板
                         （旧代码注释原话："Option B · 真磨砂卡片整体盖住背景图里
                           画的登录面板(消除控件重影)"）
```

所以正确做法是整份复用，不是重画。

## 这次怎么做的

| 部分 | 做法 |
|---|---|
| 样式 | 旧登录页那 8 个样式文件按原顺序拼成一份，**一条规则都没重写**（`build-login-css.sh`） |
| 结构 | 模板按旧 DOM 输出同样的 class（`.brand-panel` / `.auth-card` / `.field` / `.primaryline`…） |
| 背景图 | 同一张图转 WebP：**5.6 MB → 258 KB**，像素尺寸不变（4096×3291） |
| 缩放 | 照搬旧页的 `landing-scale.js`（窄屏等比缩放），原样拷贝 |
| 语言 | 旧页是 JS 按钮；这里必须改成**服务端链接**（文案在服务端渲染），走身份服务的 locale |
| 文案 | 逐条取自旧页 `landing-i18n.js` 的四语副本，没新编 |
| 去掉的 | 注册、第三方登录（Google/LINE）、条款那一行 —— 只有这三块 |

保留的部分都是旧设计里本来就有的：左上角玻璃徽标 + 字标、问候语、气泡、待办清单、
今日 Quote 卡、帮助卡（Email / @pearnly / 电话）、页脚三条安全说明、手机端底部
"登录"按钮 + 联系方式。短信登录按之前结论**不做**。

## 踩到的三个坑（都记在代码注释里了）

1. **旧 `landing-auth.css` 文件头有个 BOM**（U+FEFF）。单独一个文件没事，拼到别的
   文件后面就落到文件中间，浏览器把 `.auth-card{position:absolute}` 当成非法选择器
   **整条丢掉** → 登录卡直接贴到页面左上角。
2. **macOS 的 `sed` 不认 `\xef` 转义**。我第一次写的清 BOM 命令 (`sed 's/^\xef\xbb\xbf//'`)
   安安静静什么都没做，等于没修。改用 `perl -pe 's/\xef\xbb\xbf//g'`。
3. **Keycloak 会把主题资源的 gzip 副本缓存在容器里**
   （`/opt/keycloak/data/tmp/kc-gzip-cache/<版本>/`），**重启容器不会清**。
   浏览器发 `Accept-Encoding: gzip` 拿旧文件，`curl` 不带压缩拿新文件 ——
   两边看到的不是同一份内容，极难排查。用 `reload-login-theme.sh`（清缓存 + 重启）解决。

## 语言（详见 ADR-006）

登录页的语言设置原来是我直接敲 API 设的，仓库里没有记录，现在补成了可重复执行的
`scripts/sample-configure-login-theme.sh`：

| realm | 默认语言 |
|---|---|
| `pearnly-business`（租户登录口） | **泰语**（用户 2026-09-18 定："新租户默认泰语"） |
| `pearnly-platform`（控制面登录口） | 中文（只有老板自己用，ADR-004） |

实测的取值行为：泰语/中文/日语/英语浏览器各看各的，**匹配不上的浏览器（如法语）
才回落到默认的泰语**；登录页上仍可自己切，切换结果记在账号上。

顺手修掉一个静默 bug：语言切换的"当前选中"高亮**从来没生效过** ——
原写法拿字符串比 Keycloak 的 Locale 对象，恒为 false，四个标签永远是空 class。
正确写法是 `locale.currentLanguageTag`（`l.active` 在这个版本不存在，会 500）。
现在验证脚本里有专门一组盯着它。

日语文案里有两处是我抄写时改写的、与旧页原文不一致，已改回原文；另有 3 条标准键
本就有准确译文（新密码 / 确认密码 / 退出其它设备），已改为复用标准键。

## 边界（哪些没做 / 不确定）

- 登录页**只在本机 Colima 里的身份服务上验证过**，没有部署到服务器，也没有真机验收。
- 登录后的控制台里能看到租户站点自己的 `socket.io 404` —— 那是本地编排没把 socketio
  端口映射到宿主，**不属于登录主题**，单独记着，没在这次改。
- 身份服务里其它更少见的页面（OTP、WebAuthn、IdP 链接、注册等）没有逐个改造；
  它们会继承 base 的原生模板，套不进这套外观。当前流程用不到，需要时再补。
- 帮助卡里的联系方式（Email / @pearnly / 086-889-2228）是旧设计里原有的，
  这次照搬；如果不想在登录页公开电话，说一声我去掉。

## 怎么改、怎么生效

```bash
cd infrastructure/keycloak/themes/pearnly
./build-login-css.sh      # 只有改了旧页样式才需要（重新拼样式包）
./reload-login-theme.sh   # 改完一定要跑这个：清 gzip 缓存 + 重启
cd /Users/skin/pearnly && node scripts/sample-verify-login-theme.mjs
```
