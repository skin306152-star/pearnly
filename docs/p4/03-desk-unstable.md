# 控制面原生后台（/desk）不稳定 —— 根因已找到并修复

日期：2026-09-17。状态：**根因已定位并修复，服务器侧已验证；浏览器侧最终确认未完成**（工具故障，见文末）。

## 根因（一句话）

**我们缺了前置 nginx。** 官方的 Frappe 容器要把 `/socket.io` 转给实时服务，没有 nginx 时
这些请求打到 gunicorn 上会**一直挂住**（浏览器 Network 里显示 *Pending*），Desk 于是
反复重试，表现为"界面壳出来了、主区域空白、一直闪"。

决定性证据来自用户自己截的 Network 面板：

- `socket.io/?EIO=4&transport=…` → **Pending**（一直不返回）
- `frappe.core.doctype.session.session` → 200（正常）
- `frappe.desk.page.setup_wizard…`、`desk` → **Pending**

请求挂住 → 页面重来 → 资源全部走内存缓存（0 ms）→ 再挂住，如此循环。

## 修复

给控制面加 `control-frontend`（nginx 容器）：

- 把 8104 端口从 web 容器移到 nginx
- `BACKEND=control-web:8000`、`SOCKETIO=control-socketio:9000`
- 静态资源也由它提供（顺带取代之前"让 gunicorn 兜静态"的临时做法）

## 服务器侧验证（实测）

| 检查 | 修复前 | 修复后 |
|---|---|---|
| `GET /socket.io/?EIO=4&transport=polling` | **一直挂住（Pending）** | **HTTP 200，耗时 7 ms**，返回合法握手 `{"sid":"…","upgrades":["websocket"]}` |
| 带会话访问 `/desk` | 200（但页面不工作） | **200** |
| `setup_complete` | 曾为 0 | **true** |
| 静态资源 | 之前 404，靠 gunicorn 兜 | **200** |
| nginx 日志 502 | — | **0 条** |

## 其他产品组有同样缺口（未改）

`cowork` / `erp` / `dms` 三组的编排里**同样没有 nginx 前置层**，它们各自的
`-socketio` 容器也没有被任何东西转发。它们的 Desk 会有同样的问题。
本轮只改了控制面，其余三组**未动**（避免在无法验证的情况下扩大改动面）。

## 我自己的复现

用自动化浏览器打开该页面，**连续 6 次读取页面状态全部失败**，报的是
"页面在捕获过程中一直在变"。作为对照，同一工具读 `/pearnly-issue` **一次成功**。

结论：**不是工具问题，是这个页面确实从不静止。**

## 控制台显示 No Issues 的含义（重要线索）

报错列表每次整页加载都会清空。控制台干净 + 页面一直变 → 更像是**整页反复重载**，
而不是脚本抛错。所以排查方向应当是"什么在触发整页跳转/重载"。

## 已排除

| 检查 | 结果 |
|---|---|
| Desk 的 JS 资源 | 全部 200，不缺文件 |
| 已登录访问 `/desk` | 200 正常，**不是 HTTP 跳转循环** |
| 未登录访问 `/desk` | 301 → `/login`（会引发另一种缓存型循环，见下） |
| 控制面组缺实时服务容器 | **确实是缺口**，已补 `control-socketio`；**但不是本次原因** |
| 站点未标记"安装完成" | **确实是配置错误**（`setup_complete=0`），已修成 1；**但不是本次原因** |

以上两项都是真实缺陷、都已修，但**都没能让 `/desk` 稳定下来**。

## 另一个独立问题（已确认成因，未修）

未登录访问 `/desk`、`/app` 时，服务器返回 **301（永久重定向）**。
浏览器会**永久缓存**这条跳转，登录之后就会形成
`/desk → /login → /desk → …` 的循环，表现为另一种闪屏（用户第一次遇到的就是这个）。

临时规避：用无痕窗口，或清掉该站点的缓存。

**待修**：让这类依赖登录状态的跳转返回 **302（临时）**，不要用 301。
