# ADR-019：Pearnly 智能体底座（Claude Managed Agents + assistant-ui，三产品共用）

- 状态：已采纳（2026-10-10，第一版骨架在分支 `pearnly/agent-foundation`，未合并、未部署）
- 决策依据（用户 2026-10-10，本会话）：
  - 「做一套属于 pearnly 的智能体，模型用 Claude Managed Agents」；「网页端用户 PWA 这样用，然后桌面端也要有」，前期不做应用商店 App；LINE 是锦上添花。
  - 前端框架在 dsh / LobeHub / LibreChat / Ant Design X / Lobe UI 等对比后，「那就 assistant」。
  - 「这个产品不是专门给 Cowork 用的，ERP 和 DMS 也要用；登录全部采用后台开户的账号密码登录，沿用我们的租户隔离、用户权限、套账隔离、数据隔离等大框架」。
  - 「API 密钥在租户管理后台填入，和开户时填，可修改更换，不用用户填」。
  - 「小助手到时候也要融进框架的 App 里面」：桌面端由现有 Windows 小助手升级承载（后续批次）。
- 关联工作包：[2026-10-10 智能体底座](../work/2026-10-10-assistant-foundation.md)
- 与 [ADR-005](0005-frontend-architecture.md) / [ADR-007](0007-frontend-skin.md) 的关系：本 ADR 为「智能体对话页」开一个**限定范围的例外**；其余产品 Web 仍是原生 Desk。

## 问题与约束

- 要一个像 claude.ai 的对话入口：手机（PWA，不上架）、电脑浏览器、桌面端打开的是同一段对话，并能调用 Pearnly 的业务（识别、推送、对账、查询等）。
- 三个产品都用；登录、租户、用户权限、套账与数据范围必须沿用现有体系，不另造账号或权限。
- 原生 Desk 没有流式对话、工具卡片、批准按钮、断线续接这类对话控件，在 Desk 里自建等于重做通用 UI（ADR-007 明确不允许）。
- 不新增常驻 Node 服务，不新增固定月费；空闲零花费。

## 选项

1. **LobeHub / LibreChat / Open WebUI 整套产品**：自带智能体运行方式，与 Managed Agents 二选一；自有账号体系与数据库；LobeHub 的衍生作品需商业授权。排除。
2. **dsh（DeepSeek Harness）的壳**：单用户本机设计（无服务器级认证、数据在本机目录、桌面端本地运行），官方声明为未经安全审计的预览版。多租户、PWA、同步都要大改。排除。
3. **Desk 内自建对话页**：违反 ADR-007 的通用 UI 规则，手机体验差。排除。
4. **assistant-ui（MIT）+ Anthropic 官方 Managed Agents 示例（MIT）+ Frappe 后端**（采用）：对话控件现成；会话本身存在 Managed Agents，天然多端同步；后端留在 Frappe，权限与隔离不变。

## 决定

1. **落位：共用层 `pearnly_core.assistant`**（与身份、OCR 同类的跨产品底座）。产品只**声明**自己的工具：`hooks.py` 里 `pearnly_assistant_tools = ["<app>.<module>.TOOLS"]`，每条声明含 `name / description / input_schema / handler`（ADR-009 的「产品自己声明」）。
2. **入口**：每个产品的租户站点提供 `/assistant`（`pearnly_core/www/assistant`），登录就是本站会话（后台开户账号经 Keycloak 登录）；没有 `pearnly_product` 的站点（本机管理后台）拒绝。
3. **隔离**
   - 租户：站点即租户。会话归属记在本站表 `Pearnly Assistant Session`，接口先按「本站 + 当前用户 + 当前引擎」核对归属再碰厂商服务；会话列表只读本站表。引擎侧会话带 `pearnly_site / pearnly_product / pearnly_user` 元数据，仅作追溯。
   - 用户权限、套账、数据范围：工具在服务端以当前登录用户身份执行，只调用产品已有服务（沿用其校验），业务拒绝作为 `is_error` 结果交回模型。工具名和参数由服务端从会话里读回，不信浏览器。
   - 幂等与审计：每次工具调用按唯一 `tool_use_id` 记一条 `Pearnly Assistant Tool Run`，同一调用只执行一遍。
4. **引擎、模型与密钥**：站点配置 `pearnly_assistant_engine / pearnly_assistant_model / pearnly_assistant_api_key` 由**租户管理后台**在开户单或租户表单填写、之后可改可换，经开通步骤 `set_assistant` 推到该租户每个产品站点（与 LINE 凭据同一条链路，只写配置不重启）；用户不接触。模型留空用所选引擎的默认模型。远端资源**不需要人工配置**：站点按「引擎 + 密钥指纹 + 模型 + 智能体说明」缓存，由适配器在该账号中查找、缺则建、变了则更新（`engine.prepared`），换引擎 / 换密钥 / 换账号 / 换模型无需手工步骤。
5. **前端**：`frontend/assistant/`（Vite + React 19 + assistant-ui，Tailwind 4），构建为静态文件放 `pearnly_core/public/assistant/`，由站点提供；**不新增 Node 服务**。PWA 清单随产物发布。会话逻辑与工具卡片改自 Anthropic 官方示例（`NOTICE.md`）。
6. **例外范围**：React 只允许在 `frontend/assistant/`，只服务 `/assistant` 这一个入口；不得扩展成第二套普通产品 Web。
7. **引擎可换，不写死厂商**（2026-10-10 用户：「任何可扩展可维护的框架不要写死」）：
   - 引擎目录 `pearnly_core.assistant.engines.ENGINES` 是唯一登记处：代码、显示名、适配器、密钥格式、默认模型、运行镜像依赖。管理后台下拉与保存校验、开通步骤写配置前的校验、站点取用都读它。
   - 适配器接口 `engines/base.py`：备资源、开会话、状态、改名、归档、删除、读事件、发事件、附件、文件列表、读文件。站点的会话、文件、工具派发只经这层；对话页只认统一对话事件（沿用 Managed Agents 事件格式），别家适配器负责翻译。
   - 智能体说明（名字、系统提示词、Pearnly 工具表）与厂商无关（`definition.brief`），适配器补自家的模型参数与自带工具。
   - 新接一家 = 加一个适配器模块 + 目录一行 + 镜像锁定其 SDK；离线测试逐家检查接口完整、依赖已锁定，并拦截共用层、控制面与开通步骤里出现厂商名。
   - 首家：Claude Managed Agents（默认 `claude-opus-5-5`；所有模型思考强度 `low`；内置沙箱工具开启、自动批准，网页搜索 / 抓取关闭，业务只经 Pearnly 工具）。
   - 后台换了引擎，旧引擎的会话不再列出（会话表记 `engine_code`）；同一引擎换账号时旧会话在新账号里读不到，属于已知限制。

8. **实时推送**（2026-10-10 改，原为轮询）：实测引擎「列出事件」偶尔单次 30 多秒（测试机与本机相同），事件流连接稳定约 0.4 秒。用户一侧每次发出前，站点在本进程起一个后台线程接该会话的事件流（`relay`，Redis 锁保证一路、只活一轮），逐条经 Frappe 实时通道推到会话主人的房间，含回复的逐字预览；对话页低频补拉兜底（推送断开时退回高频）。不占网页请求线程与后台队列进程。
9. **计价分档与上下文接续**（2026-10-10）：Managed Agents 的自动压缩要接近 1M 才触发且不可配置，而 Haiku 5.5 单次输入超过 10 万 token 整次按 5 倍计费。引擎目录登记各模型的分档线（`tiers`），对话输入到分档线的 60% 时，下一轮在新的一段远端会话里开始，并用系统消息带上前文文字（不带旧附件）；浏览器仍认同一个对话编号，历史与文件按各段合并。
10. **对话提醒、当地日期与推送**（2026-10-12）：产品经 `pearnly_core.assistant.notices.post` 给某个用户发提醒，记在表 `Pearnly Assistant Notice`（平台记录，去重键唯一）。提醒不写进引擎会话：挂在用户自己的对话上时在对话里出卡片（补拉与整段重放时按时间并入），没挂对话的只走手机推送和电脑通知。用户下次发话时，还没带过的提醒（本对话的加上没挂对话的，最新 10 条）和当地日期时间（站点时区、佛历年）合成批末唯一一条 `system.message` 带给智能体，不改智能体说明；前提是所选模型接受对话中途的系统消息，上线前逐个模型实测。手机网页推送自己实现 RFC 8291/8292，只用 cryptography，不加推送库依赖；推送地址按白名单限定（防 SSRF）、不跟随跳转；只在 404/410 时删订阅（403 可能是我方签名问题，不删）；VAPID sub 用 https://pearnly.com、exp 1 小时；后台脚本收到推送一律弹通知；不处理 `pushsubscriptionchange`，每次打开对话页重新认领订阅（公钥变了退订，退出登录只删服务端订阅）。

## 后果与验证

- 实时进度走推送（见 8）；轮询只作兜底。
- 浏览器只负责提醒服务端「有待执行的工具」；页面关闭时工具不会被执行。改为引擎回调（Managed Agents 为 `session.status_idled` webhook，接入时作为适配器的可选能力）触发服务端执行，是做「下班用手机派活、做完通知」的前置项。
- 依赖：镜像按引擎目录锁定各家 SDK（首家 `anthropic==1.8.0`）；前端依赖逐个锁定版本（`frontend/assistant/package-lock.json`）。改了共用层，合并前按「共用层候选检查」在生产镜像跑完整离线检查。
- 成本：模型 token 按量 + 会话运行时间 0.08 美元/小时，空闲不计费；无固定月费。
- 待办（后续批次，各自记录）：对话页文案与组件内英文提示的三语化（新文案先经用户批准）；桌面端由小助手内嵌；LINE 桥接；各产品第一批业务工具。
- 回退：本功能只有新入口与新表，不改现有业务；撤掉入口与 hooks 即停用，不影响其他页面。
