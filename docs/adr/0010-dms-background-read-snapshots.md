# ADR-010：DMS 后台完整读快照

> 后续决定：[ADR-011](0011-dms-manual-read-snapshots.md) 已取代下文的周期采集、自动预取和硬过期策略。下文保留为历史背景，不指导当前触发行为。

- 状态：用户已采纳，2026-09-24；本批仅本机实现和验证，不部署。
- 背景：45/90 秒请求驱动缓存与实际 240 秒 scheduler tick 不匹配；前台查重、编辑及颜色读取仍登录 DMS，并排在长任务后。

## 决策

1. 业务目录（完整客户字段、车型/全部颜色、五类银行、员工/顾问等）及各员工的原生销售记录每 5 分钟调度同步。全国地址按用户补充批准，首次后台完整建立、之后每日全量更新。
2. 地址逐级读取较慢，采用有界分批和原生 DocType 私有 checkpoint；完整树才原子发布。读者不读 staging。每块释放外部账号锁，失败保留已发布代际；6 小时仍未建完则重建该半成品。时间标记使用首块开始时间，不以最后一块冒充全树同时读取。
3. DMS Read Snapshot 属 DMS 的 snapshots 域，使用原生迁移及 MariaDB 事务；无客户角色的通用 CRUD/导出/分享权限。凭据不落 payload/日志，读取范围按 Site、上游登录凭据分隔。员工销售另外按 Endpoint、owner 和 Operator 权限版本隔离。
4. LINE 菜单 1/2/5 的预览、去重、翻页、选项和编辑 load/geo/paints/save 只读本地；缺失不触发登录、不等待长队列、不当成空表。菜单 3 门户登录、4 修改凭据、OCR 和最终业务写入是有意例外。
5. 客户新建/更新、订车最终提交继续实时身份/地址/主档/付款/顾问复核、写者锁、幂等与独立回读。已验证的完整客户回读立即写穿，本地写过的客户 ID 持续纳入后台直读以绕过上游搜索隐身期；不把旧 overlay 当新鲜源数据。成功订单触发本员工异步原生查询刷新，不伪造销售行。
6. 前台及卡片显示真实业务/地址数据时间。业务快照默认最多接受 30 分钟，地址最多 3 天，超过目标刷新周期即标记滞后。明确认证/授权拒绝不允许陈旧回退；临时错误不覆盖完整好包。
7. 原生排行不能穷举任意日期。默认本月条件后台预取，自定义条件登记后后台读取、首查明确待同步。最多 32 个活跃条件，7 天无访问退出预取；不把管理员可见范围交给普通员工，不自行重算统计。
8. DMS 产品在 hooks 声明采集器；snapshots.schedule 只负责范围去重和原生 RQ 派发，adapter / query 实现外部读。专用 dms_sync worker，不与 OCR/long 混队；仅 DMS bench 的原生 scheduler tick 配成 60 秒。原生 Scheduled Job Type 的窄 mixin 仅将本 dispatcher 投到 dms_sync，避免它还在 default 等普通 long worker；其他任务保持原生队列、去重和执行账本，不修改 Frappe。生产文件仅准备，不在本批应用。

## 一致性与限制

第三方没有可用的事务快照 revision。客户/销售依原生 count 严格分页、核预期行数及末尾数量/ID，异常和漂移拒绝发布；这仍是有界完整扫描，不等于第三方数据库原子快照。地址记录逐块来源时间，读写分离不改变最终实时复核。

MariaDB 长只读事务在外部采集完成后先结束，再检查当前 scope 并发布。已确认客户写穿使用独立原生 DB 连接、当前凭据/权限锁和短缓存事务；只提交缓存，绝不提交或回滚调用方尚未落账的业务证据。原生 RR 旧视图与锁读并发变更会导致整事务回滚，不能只捕获异常掩盖；此边界用真实双连接验证。一般完整快照发布函数仍不隐式 commit。

后台定时触发不保证第三方在任意故障/规模下每 5 分钟完成。队列去重、时间/页数/请求/字节预算限制重叠和锁持有，失败可观测，不发布局部成功。

## 依赖与兼容

- snapshots 只依赖纯 contracts 和框架/Core 本地能力，不反向导入流程或采集器。消费者及采集器单向依赖本地域。
- contracts.geo_matching 是 live 和 cached 地址选择的同一纯规则；html/unicodedata 仅字符串正规化，无 IO，因此纳入纯标准库准入，不扩大违规基线。
- 通用实际登录执行体移到 adapter.operations；内部 booking/recovery/delivery 和管理端 masters_cache 直接引用新入口，masters → intake 的旧方向换为 masters → adapter（仍只用于管理端显式读取，不是 LINE 按需刷新）。intake.service 暂保留显式兼容导出供旧诊断脚本，旧已排队 adapter.warm 指向新调度/采集入口，master_shared 只读完整新快照，旧 45/90 秒按需登录路径退休。
- 不修改 ERP/Cowork 的菜单、业务页面或队列；新增 worker 纳入生命周期与容量检查，不能绕过发布容量闸。
