# ADR-020：CC 按公司主档组织对话（全所主档、知识库、按电脑授权文件夹、按月处理）

- 状态：已采纳（2026-10-15 凌晨，用户在主会话授权今晚自主施工）；实现分三包：A 服务端（本 ADR 的服务端部分，分支
  `pearnly/cc-company-core2`）、B 前端、C CC 桌面版（`be797d1c`）。合入 `main`、部署与发 CC 桌面版 1.6.0 都等用户在测试机试过。
- 决策依据（用户 2026-10-15，原话见任务记录）：左侧栏按公司分类，新建公司（基础信息）为主档，公司里新增对话 + 本次处理任务的
  文件夹和资料；给公司填一点知识库；Express 的主档公司或供应商可能有分店；会计第二天要知道哪些单要处理。
- 规格：`~/pearnly-devtools/night-2026-10-15/company-master-spec.md` 与补充 `company-master-amend.md`（冲突处以补充为准）。
- 关联工作包：[2026-10-15 CC 公司主档](../work/2026-10-15-cc-company-master.md)

## 问题与约束

- 会计按客户公司干活：同一家客户每个月一批单据、一个文件夹、一份（或几份分店的）账套。原侧栏按时间排，对话散在一起；
  CC 每段对话都要重新问是哪家、哪个月、哪个文件夹。
- Cowork 不做公司数据隔离（2026-09-26）：主档是全所共用的视图，不是权限边界；账套、选择、任务、草稿已经各有自己的键，
  不能为了主档迁数据或加外键。
- ERP、DMS 也用同一个对话底座（ADR-019），它们没有「客户公司」，界面和接口必须完全不变。
- 文件夹授权的边界不变：只能在 CC 桌面版里经 Windows 原生选择框选（网页从不传路径）。

## 决定

1. **共用层只记「对话挂在哪家、处理哪个月、哪个范围」**：会话表加 `project`（不透明编号，空 = 「最近」）、`period`
   （`YYYY-MM`，空 = 不指定）、`project_scope`（产品自定的范围，Cowork 存 5 位分店号）与 `project_noted`（带给 CC 的说明的
   哈希）。哪些编号有效、谁能用、说明写什么，由产品在 hooks 声明的 provider 决定（`pearnly_assistant_projects`，ADR-009）。
   没有声明的产品 `kind = None`，侧栏与接口与以前逐字段一致。
2. **公司主档在 Cowork 新域 `companies`，全所一家一份**，只能从账套目录建，服务端自己读目录、自己算身份：
   有 13 位有效税号 → `tax:{税号}`（**按法人算一家，不带分店**，同税号各分店的账套都归这一份）；Express 没有税号 →
   `name:express:{连接}:{名称键}`；MR.ERP → `mrerp:{连接}:{公司代码}`。主档只存名称、法定名、身份、合并申报标记、知识库
   与按电脑的文件夹绑定；分店、账套、任务、草稿、记住的选择都按各自现有的键现算。
3. **知识库**：`Cowork Company Note` 一条一句（≤500 字、每家 ≤50 条），团队共写；CC 只能经「允许」卡片写或删；随批末系统
   消息带给 CC 时转义、包在 `<company>` / `<team_notes>` 里并写明是数据不是指令，有字数上限，哈希没变不重带。
4. **文件夹按「公司 × 电脑」各一行**（`Cowork Company Folder`，放在 `folder_intake`，`binding_key` 含预留的
   `reader_device`），状态读时现算；月份子文件夹只按电脑已上报的文件夹名认（纯函数），认不出交给 CC。一台电脑最多 200 个
   根目录、文件夹名合计 2 万个，多的只丢多余的（与 CC 桌面版同名常量由契约测试比对）。
5. **分店**：分店清单从账套现算；对话可指定分店（`project_scope`）；没指定且有几个分店时，CC 按票面买方（销项看卖方）
   分店挑账套，票面没有的问一次。合并申报（ยื่นรวม）这一批只显示与写进说明，不改草稿算法。
6. **待处理**：从推送状态现算（不存），按公司计数；早上 08:30（曼谷）接在定时任务提醒的同一入口给负责人推一条对话提醒
   （网页推送 + 电脑通知，不发 LINE），数量为 0 或没有新增不推。
7. **实时事件**沿用 `pearnly_assistant_event` 信封，类型 `pearnly.project`（`move / upsert / delete`），逐人推到各自的房间，
   不广播。

## 有意变化（登记）

- 文件夹授权入口从设置页移到公司主档页（仍只在 CC 桌面版里）；一台电脑的根目录上限 20 → 200。
- 不复用 `Cowork Client` / `Cowork Workspace`：前者是旧买方客户表，后者是站点内部归属。
- 没挂对话的提醒可以指定点开去的页面（`Pearnly Assistant Notice.view`，现在只有 `tasks` / `pending`）。

## 后果

- 新服务端 + 旧页面：`listing` 不带 `grouped` 时语义不变，多出的 `project / period / scope` 键旧页面忽略；`pearnly.project`
  旧页面忽略。新服务端 + 旧 CC 桌面版：主档、知识库、对话都能用，文件夹一栏提示更新。
- 回退：服务端回到上一个镜像即可（新表新字段旧代码不读，没有数据补丁）；唯一例外是 CC 桌面版 1.6.0 已在某台电脑加到
  21 个以上根目录后，服务端只能回退到已含 200 上限的版本。
- 下一批：同税号 Express 与 MR.ERP 各有账套时合成一家、合并申报的汇总算法、公司级参考文件、批量添加、按公司分权限。
