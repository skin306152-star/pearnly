# ADR-021：事务所多台电脑各用 CC 桌面版（连接是池、电脑是成员）

- 状态：已采纳（2026-10-15，用户「D1–D9 全部按建议」）；按方案第 9 节分批施工，批 1–4、6 攒成一次服务端发布，批 5
  （CC 桌面版 1.6.0）在服务端上线后发正式版；真机验证与用户试用通过前不合入 `main`。
- 方案与审查意见：[多电脑方案](../work/2026-10-13-cc-multi-desktop-plan.md)；施工与证据：
  [多电脑施工记录](../work/2026-10-15-multi-desktop-build.md)。
- 本文写到第 1 批（服务端身份层）为止；后面几批落地时在此补「决定」与「有意变化」。

## 问题

今天处处按「一条连接 = 一把密钥 = 一台电脑」写：`active_key = sha256(站点, 连接)` 唯一，登记只取最早一条连接，
第二台电脑只能 `in_use` 或把第一台顶掉；只有管理员能登记电脑。多人事务所各用自己的电脑写同一份（或各自的）Express
账套时，这条单槽假设让电脑互相顶替。

## 决定（第 1 批）

1. **连接是池、电脑是成员**。新 DocType `Cowork CC Desktop Device`（companion 域，名字不带旧称）：归属、登记人
   （`device_owner`，只管权限；`owner` 是 Frappe 保留字段）、最近登录 CC 的人（`signed_in_user`，只管写账路由）、电脑名、
   设备密钥摘要（`secret_digest` = sha256(站点, 设备密钥)，唯一，补丁建的旧电脑留空等认领）、常驻、版本、载荷版本、
   `host_names`（原样存）、主档索引待重建、退役时间与人。只能经 companion 域写，原生读写与分享一律拒绝。
2. **密钥按电脑**。密钥加 `device`。`active_identity(站点, 连接, device=None)`：迁移来的、旧版发的密钥**永远**是原公式
   （旧槽位，服务端回退也认）；register v2 新发的是 `fingerprint([站点, 连接, 电脑])`。唯一约束不变，于是每个（连接，电脑）
   最多一把；代数仍按连接递增。认证按 `token_digest` 找到行，再核：行的连接 = 密钥中段、`active_key` 按本行公式重算、
   电脑没退役、签发人此刻仍有权；加锁顺序 Connection → Credential（→ Device）不变，失效按电脑各自发生。
3. **register v2**（`device_key` / `device_name` / `rekey`，回复加 `device`）：新电脑 `created`；这台已有密钥 `exists`
   （只记登录人，不改登记人、不吊销）；`rekey`（登记人或管理员）同一事务里轮换；没装 Express 的挂 MR.ERP 主连接，没有
   就挂 Express 池当只读文件夹成员，都不吊销任何人；不带设备密钥的旧版在池里没有认领过的电脑时逐字照旧（`in_use` /
   `replace`），有了就回 `update_needed`。
4. **认电脑的机器方法**（第四张表 `DEVICE_METHODS`，与另外三张不重叠，MR.ERP 的只读文件夹密钥也放行）：
   `device_hello` 把已认证的密钥挂到电脑上，**不改 `active_key`**；密钥已被另一台认领（同一配对码抄到两台）回
   `claimed_elsewhere`；新挂上的，下一次心跳回复不带 `account_sets_unchanged_ok`，逼电脑整份重报。`device_leave` 吊销这把
   密钥本身。
5. **下线 `companion.api.issue / revoke / status`**：没有界面调用，多台电脑后「当前那把」说不清。内部 `credentials.issue`
   只给 `register` 的旧路径用；内部 `revoke` / `status` 仍只限管理员，只留给实验室与运维脚本。
6. **补丁 `v0_0_19_companion_devices`**（第 1 批只做方案 4.1 第 1 步）：每把有效密钥建一台「旧电脑」，登记人 = 签发人，
   名字取心跳报的电脑名 → 文件夹同步报的 → 连接名，摘要留空；密钥补 `device`，`active_key` 不动。幂等。

## 有意变化（迁移保护「身份、授权」与「外部写者锁」里的登记）

- **D1 登记电脑的权限**：录入角色（或管理）、且在这条连接的使用名单里，就能给**自己的**电脑发密钥，签发人 = 本人。
  机器每次认证改为要求签发人「录入或管理 + 使用名单」，不再要求管理权限（不改的话录入角色签发的密钥第一次心跳就失效）；
  失权即失效不变。建池（`connections.service.configure`）仍只限管理员，非管理员遇到本站没有池回 `no_connection`。
  旧槽位的 `replace`（顶掉另一台）对录入角色只允许顶自己签发的那把。管理员签发的旧密钥在管理员只剩录入权限时仍有效
  （与录入角色签发的同一判据）。
- **D6 写者锁粒度**（第 3 批落地时在此补全）：Express 不再取整条连接的 endpoint 锁，收窄到物理账套（account + company）。
- 不变：密钥只存摘要与末四位、回执与派发分开（被吊销的密钥只能回执自己那一件）、fence、请求回执幂等、
  `binding_generation` 只能为 0、`exp_` 密钥不能登录或调用普通 RPC。

## 兼容

- 旧 CC 桌面版（≤1.5.0）+ 新服务端：密钥照常有效（旧槽位）；不带设备密钥的登记在全是旧槽位的池里逐字照旧，
  池里一有认领过的电脑就回 `update_needed`，旧版不能再顶掉新版。
- 新 CC 桌面版 + 旧服务端：`DEVICE_METHODS` 在旧服务端按机器请求在信封处拒绝（401），桌面端把 401 / 403 / 404 都当旧服务端
  （第 5 批）；对话页随服务端发布，不会把新参数发给旧服务端。
- 回退：第 1 批本身可回退（新表新字段旧代码不读，`active_key` 没动，旧代码按连接取旧槽位仍认得迁移来的密钥；register v2
  发的按电脑密钥旧代码不认，那几台要重新登录）。**整次发布（含第 3 批锁口径 v2）不能直接回退**，见方案 2.6；
  回退前提在第 3 批补进本节。
