# ADR-009 各产品自己声明菜单、功能目录与术语表

- 状态：已采纳（2026-09-21，用户决定）
- 决策依据：用户要求"除了 OCR、登录页、订阅、UI 之外，各产品维护自己的源码"；此前三个共享点（控制面功能目录、共用菜单、共用术语表）让两个工作窗口反复在同一张表里冲突
- 关联工作包：[shared-files-split](../work/2026-09-21-shared-files-split.md)
- 关联：[ADR-003](../adr/README.md)（本仓是唯一权威位置）、[ADR-005](0005-frontend-architecture.md)（原生 Desk）

## 问题与约束

同一个仓库、同一个 bench，但产品是三个，工作流也是几路并行。事实与边界：

- **产品本来就已经各在自己的 App 里**：`pearnly_dms`、`pearnly_cowork`、`pearnly_erp_portal` 各有自己的目录、清单与翻译包；DMS 的 DOCType 与业务包也在自己家里。
- **共用层是运行方式决定的，不是偏好**：一个 bench、一个站点、一套数据库、一套登录；订阅计费、Keycloak、LINE 通道、原生外壳属于共用层，用户也明确要它们共用。
- **真正跨产品的只有三处**：控制面的功能目录（谁来卖、每个功能对应哪个岗位与哪些表）、共用层的菜单（哪几个产品各显示什么入口）、术语表（所有文案的唯一来源）。
- 产品站点只装 `frappe + pearnly_core + 自己的产品 App`；**控制面站点不装任何产品 App**，所以它 `import` 不到产品代码。

## 选项

1. **维持一个中心文件**（原状）：一处改动最容易撞车，产品加一个功能要同时改控制面与产品清单两份镜像。
2. **共用层直接 import 产品的清单**：控制面站点没有装产品 App，运行时必然失败；用 `sys.path` 或路径补丁假装能 import，是把结构问题藏起来。
3. **各产品在自己的目录里放**声明文件/钩子，控制面与共用层只汇总。

## 决定

选 3，并把每个共享点按"谁能读"分别落位：

| 共享点 | 正本位置 | 汇总方怎么读 |
| --- | --- | --- |
| 可售卖功能目录（功能码、标签、默认开关、岗位、可挡的 DocType、只读表、图标、模块） | `apps/<app>/<app>/features.json`（纯数据） | `pearnly_control/features.py` 按 bench 路径**读文件**；缺文件直接报错，不静默降级成空目录 |
| 侧边栏菜单（每一项：标题键、页面路由、图标、所需功能码；以及"已做出来的页面"与每页准入判据） | 各产品 `hooks.py` 里的 `pearnly_navigation` | `pearnly_core/desk/navigation.py` 用 `frappe.get_hooks` 取**已装产品**的声明；站点只装一个产品，就只声明得到那一个 |
| 术语表（唯一来源） | `apps/<app>/<app>/i18n/messages.tsv`（一条文案一行） | `scripts/i18n_glossary.py` 汇总给 `i18n-build.py` / `i18n-apply.py`，翻译包仍是生成物、仍要提交 |

配套规矩：

- **语言归属不变**：译文落在哪个 App 仍由"谁渲染"决定（租户站点不装 `pearnly_control`，所以控制面文案仍要落到 `pearnly_core`）。拆表之后，"放哪个 App"就是"把那一行写进谁的术语表"。
- **共用层不再保存产品内容的镜像**；新增功能、改菜单、改文案都在自己产品里做完，控制面与共用层不需要跟着改。
- **共用层仍可持有跨产品策略**：首页功能（订阅与计费）、基础角色、产品顺序属于控制面自己的策略，不下放给产品。
- 不是"共享层里只允许 OCR/登录/订阅/UI"的机械规则：**文件头明确写着"三产品共用、谁用谁 import"的模块（OCR 引擎、浏览器层、外部连接层）继续留在共用层**；判定依据是声明与其实际用途，不是目录名。

## 后果与验证

- 产品改自己的功能/菜单/文案，不再动共用文件；两类工作流不会因为同一张表冲突。
- 代价：控制面多了一层"读文件"，必须处理缺文件与形状错误——**选择报错而不是空目录**，否则开户会静默少发角色。产品 App 必须与控制面在同一个 bench（生产镜像与开发挂载都是这样，已核对）。
- 菜单从"共用层持有全部产品"变成"产品自己声明 + 按已装产品取"，所以未装产品的页面在任何站点都不可能出现（新增了一条自动验证）。
- 验证：控制面目录在拆表前后**逐字段相同**（含 `roles_payload` 的岗位与只读覆盖）；菜单契约（三个产品的项数 4/11/14、功能归属、"只列已做出来的页面"）由 `tests/test_native_desk_contract.py` 针对产品声明断言；术语表拆表前后内容相同（1561 条去重文案，仅一处有意改文案），生成的翻译包逐字节未变；真实 Site 上 `migrate` 会按声明重建侧边栏。

## 2026-09-22 增量对齐

ERP 原生侧栏分组由自身 `pearnly_navigation[0]["groups"]` 声明，Core 仅通用渲染。成本字段的 `field_permissions` 也放在 ERP `features.json`，Control 只按已授予角色及产品管理员过滤，Core 按原有校验落地。具体基线与开发顺序见 [对齐记录](../work/2026-09-22-shared-foundation-alignment.md)。
