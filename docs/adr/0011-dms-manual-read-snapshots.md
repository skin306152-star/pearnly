# ADR-011：手动建缓存，交互读本地，提交查实时

- 状态：用户采纳，2026-09-24；替代 ADR-010 的周期触发、自动预取和硬过期策略。
- 本轮只在本机实现与隔离容器验证，不部署、不接真实 LINE/DMS。

## 决策

1. 管理员在原生连接页明确选择并启动基础资料、客户、地址读取。三组独立成功、独立时间、独立失败；私有半成品不对读者公开，失败不清除旧完整资料。按用户最新要求，连接页不展示读取后的资料或状态字段；执行期间使用原生全屏浅色遮罩，结束只提示结果。仅活动任务查询本地状态，不触发第三方读取，空闲不轮询。
2. 一次点击注册有范围、身份、时间和唯一 ID 的显式请求。原生 dms_sync 队列处理有界批次及同一请求的有限续读，不是周期任务。重复点击共享正在执行的请求，过期/失败可手动重试。独立登记已提交才派发，不依赖外层 RPC 提交；派发失败明确标失败。
3. 取消五分钟业务采集、每日地址采集、全员工查询预取、订单成功后的销售全量采集。旧持久入口无 token 时无副作用返回；原生 migrate 移除读档 Scheduled Job，保留订车恢复、交付恢复和菜单维护。DMS worker 保留专用 420 秒超时，不再改 bench scheduler tick。
4. LINE 菜单 1/2 的查重、卡片、编辑保存、车型/颜色/地址交互只读本地。缺少完整资料提示手动读取，不伪装空表、不隐式登录。菜单 3/4 的真实登录及凭据修改、OCR、最终提交保持真实操作。
5. 菜单 5 只在明确刷新时读取当前员工当前原生查询条件，分页读该条件完整本地结果。首次条件/新日期待读取，不当零结果；权限能力首次也需要明确读取。绑定、用户、凭据、查询权限版本隔离；不自行重算第三方统计。
6. 客户及订车提交实时复核。新建撞到实时已有客户返回差异确认，不自动覆盖。编辑按原始基线、用户意图、当前实时值作三方合并；未改字段保留最新值，同字段冲突重新确认，旧 nonce/审批不能沿用。外部结果未知不允许当失败盲重试。
7. 只有独立完整回读确认的客户才单条写穿，不能更新全库来源时间。缓存与业务台账事务隔离，缓存失败不能逆转或重试已成功外部写入。读取中客户 ID/页数漂移时丢弃半成品，下次人工重试重新建包。
8. 小块只读采集遇到我方前台操作意图或占锁就退让，状态为等待，需要再次点击；不自动重试。每块释放账号互斥，下一块重检身份与请求。已在执行的请求不能强行中断，也无法约束第三方网页人工登录。
9. 保留实际开始/完成时间作为后台元数据，连接页不再展示。消费侧已有的资料年龄提示仍使用真实时间：主档/客户超过 30 分钟、地址超过一天、查询超过五分钟显示滞后，但这些仅是年龄提示，不触发自动读取，也不强制使全部业务停摆。已知认证/授权拒绝阻断相同 reader 范围；凭据/绑定/权限变化隔离旧包。重新验证成功的读取才能清除认证拒绝。

## 一致性与边界

没有 API、变更日志、数据库权限或 webhook 时，无法保证第三方修改即时通知我方。人工更新之间可能陈旧；按钮不会把全量读取变成瞬时操作。分页校验不等于上游原子快照，分批开始时间也不冒充所有字段同一时刻。

最终复核与写入间仍有第三方竞态。我方写者锁/幂等不等于第三方事务或条件写入；不能承诺 OCR、最终真实提交与第三方故障时也立即完成。

## 实现与验证

保留 ADR-010 读写分离结构。connections → snapshots.manual → 产品 hooks；不反向导入业务。客户冲突纯规则进 contracts，外部执行和独立读回留 intake/client/booking。
