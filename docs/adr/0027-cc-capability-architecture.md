# ADR-027：CC 能力架构与标准

- 状态：**提议**（2026-11-08，CC 线负责窗口 stoic-hugle 起草，等主会话审、用户点头后改「已采纳」）。
- 关联：[ERP / Cowork 版 CC 差异盘点](../work/2026-11-08-erp-cowork-cc-parity-盘点.md)（§0–§11，含场景清单与 ERP 网页动作对照表）；
  ADR-009（产品自己声明）、ADR-019（智能体底座）、ADR-020（CC 按公司）、ADR-021（多台电脑）、ADR-025（共用机器通道）、ADR-026（代录目标）。

## 给用户看的一段话

CC 能替你做的事 = **这个产品网页上能做的事 + 代录**。Cowork 的 CC 能做 Cowork 网页上的事，ERP 的 CC 能做 ERP 网页上的事；代录是 CC 独有的，
两个产品一模一样。CC 和网页走的是**同一套后台功能**：网页上你有权限做的，CC 才能做；网页上算钱、检查的规则，CC 一条不少；网页上做不了的，
CC 也不会自己想办法绕过去（比如自己看图读票据、自己算金额）。以后网页加了新功能，没给 CC 配上的话，检查会直接拦下来，不会再出现「Cowork 有、ERP 没有」
这种漏。

## 问题

11-08 盘点：Cowork 版 CC 76 个工具、ERP 版 19 个；ERP 网页能做的识别、盘点、库存查询、改单、收付款、任务看板，CC 大多没接；同一类工具两个产品各写一份，
说法、参数、行为有出入；没有工具时模型会自己读票据、自己算。原因不是有意不做，是**没有标准**：每次只补当时要的那几个工具，没有「网页有的 CC 都要有」的检查。

## 决定

### 1. 三层

| 层 | 是什么 | 一份还是多份 |
|---|---|---|
| **业务功能层** | 网页和 CC 调的同一组服务端函数（如 `purchasing.entry.post`、`inventory.count.close_count`）。权限、校验、金额规则（Decimal）、幂等、审计都在这一层 | 每个业务一份，归产品所有 |
| **工具层** | 共用层按**类别**出标准模板（见第 2 条）：统一工具名（`<产品>_<类别>_<动作>`）、参数、返回形状、出错形状（`status: not_saved / not_found / failed` + `reason`）、给模型的说明文字、步骤名与译文。产品只声明「这个动作调我哪个函数、要哪些字段」，**不另写工具逻辑** | 共用层一份模板；产品只有声明 |
| **执行方式层** | 直写（CC 对话里直接办）与代录（CC 桌面版打开账本一张张录）用**同一套工具**；代录特有的 intake / uploads / regroup / target / resolve 只在共用层一份（`pearnly_core.express_operator`），产品只声明接法 | 共用层一份 |

工具执行时的上下文由共用层统一套（`pearnly_assistant_tool_context`，11-08 起）：例如 ERP 的「当前公司」= 对话挂的那家，所有按当前公司取数的业务函数自动跟着走，
工具不再逐个传公司。

### 2. 工具模板（共用层 `pearnly_core.assistant.templates`，施工时建）

| 类别 | 动作 | 说明 |
|---|---|---|
| 单据 | 列 / 看 / 看原件 / 改（带依据）/ 提交 / 作废 / 收付款 / 导出 / 打印 | 产品声明单据种类（采购、销售、出入库、调拨、调整、收银日汇总……）对应的列表、详情、入账、作废、收付款函数 |
| 识别 | 识别附件 / 识别结果 / 补页重读 | 共用骨架：取对话附件原件、代录里不重复识别、挂着等结果、进度、「报识别值不报自己读的」；产品声明识别入口与落成什么（Cowork 识别记录、ERP 待提交记录） |
| 推送 | 写账前确认卡（已有 `pearnly_precheck`）/ 推送 / 推送结果 / 结果不明核对 | 已在共用层（`direct_push`、`write_precheck`），产品声明写账函数 |
| 盘点 | 列 / 看差异 / 新建 / 记数（含重盘）/ 结束 / 生成调整单 / 导出 / 删 | 两个产品各自的盘点服务，工具形状一份 |
| 库存 | 在库一览 / 单品收发存 / 仓库仓位 | ERP 有；Cowork 无库存业务（不适用） |
| 主档 | 物料 / 供应商 / 客户：列 / 看 / 建 / 改 / 停用 | 产品声明主档服务 |
| 任务看板 | 看板 / 卡片：看 / 建 / 改 / 移 / 评论 / 搜 | 看板代码先下沉共用层（盘点 P2-3），工具一份 |
| 公司与记忆 | 公司列表 / 资料 / 团队备注 / 记住的选择 看与删 | 已半共用（`masters.cc_tools` 与 `company_tools` 规则共用），并成一份 |
| 电脑与连接 | 电脑在不在线 / 重读账套 / 移除电脑 | 共用机器通道（ADR-025）与 Cowork 通道各声明 |
| 产品专属 | Cowork：文件夹定时录入、月结回读、对账、报税草稿、POS 导入；ERP：收银台查询、班次 | 仍按模板的参数 / 返回 / 出错形状写，只是只有一个产品声明 |

### 3. 四条标准与机器检查

| 标准 | 内容 | 怎么检查 |
|---|---|---|
| **覆盖** | 产品地图里每个网页动作行（`desk` 页的按钮、列表、提交）对上一个 CC 工具，或登记「不适用 + 原因」（如收银台现场收款） | `scripts/check-product-map.py` 加一项：网页动作行必须有 `cc = "<工具>"` 或 `cc_na = "<原因>"`；新加网页功能没配就拦。存量逐页补，补完前用基线文件（只许减少） |
| **一致** | 同类工具两产品去掉前缀后：名字、参数（名字、类型、必填）、返回形状、出错形状、步骤名译文逐项一致；只有模板声明的「产品差异」可以不同 | 新检查 `scripts/check-cc-tools.py`（CI 跑）：按模板比对两产品声明，列出差异 |
| **行为** | 只经工具办事；不自己算业务数据、不自读票据；权限同网页（同一组服务端函数）；跟用户这句话的语言回答；禁止类规矩与对应能力**同批上线**（不先上「不许做」再上「能做」） | 共用系统提示的离线断言（`test_assistant`）；工具源码守卫（工具模块不直接读写库、不 `ignore_permissions`）；场景清单真模型复测 |
| **验收** | 同一份场景清单（盘点 §10，约 20 条），ERP、Cowork 两个产品、电脑 + 手机，真模型跑一遍 | 每段上线前跑；结果记进任务记录，截图留证；测试费按台账记 |

### 4. 迁移（Cowork 76 个、ERP 19 个工具改成模板声明）

- 先给 Cowork 现有工具生成黄金样本（声明、说明文字、调用结果逐字节，同 11-02 `direct_push` 下沉的做法），改成模板声明后逐字节比对，**Cowork 现有行为不变**；
  确需统一的说法（两产品不一致时）单列清单给主会话 / 用户看，同意后再改黄金样本。
- 分批：① 单据 + 推送 + 公司（两产品都有，先统一）→ ② 识别（与第 5 条第 2 段同批）→ ③ 盘点 + 库存 → ④ 任务看板（随看板下沉）→ ⑤ 电脑与连接 → ⑥ Cowork 专属（只换形状）。
- 每批：gate、候选离线、受影响流程、CI 绿，合入前发主会话。

### 5. 五段计划（估时 = 写码 + 机器跑，小时）

| 段 | 内容 | 写码 | 机器 | 用户能感到的 |
|---|---|---|---|---|
| 1 摸底 | 本 ADR、盘点 §9–§11（场景清单、ERP 网页动作对照表）、覆盖与一致两个检查的骨架 | 4 | 1 | 无（文档与检查） |
| 2 识别 | 共用识别骨架；ERP 对话识别（每张票落成待提交记录，用户说「录入 / 入账」或卡片选了入账才提交）；P0-1「不自读票据」同批；代录放文件交识别（intake / uploads / regroup 下沉共用层，ERP 补齐）；Cowork 识别改模板声明 | 14–18 | 5 | ERP 里传票据 CC 能识别、给内容、能录入；两个产品代录都能放文件 |
| 3 补齐 ERP | 按盘点 §11 对照表把「缺」的做完：单据（作废、收付款、导出、打印、采购改单）、主档、库存、盘点补全、公司资料、电脑与连接；Cowork 同类改模板声明 | 26–34 | 8 | ERP 网页能做的，CC 都能做 |
| 4 统一代录 | resolve 两边一套（见第 6 条待定）；代录界面逐项核对两产品一致；target 接口两边都有，MR.ERP 执行层一起等岳父账号 | 6–10 | 4 | 两个产品的代录一模一样 |
| 5 验收上线 | 场景清单两产品 × 电脑 + 手机真模型；按批次部署 | 2 | 6（另测试费约 3 美元） | 全部上线 |

合计写码约 52–68 小时、机器约 24 小时（不含等人与排号）。任务看板下沉（盘点 P2-3，约 10–12 + 3 小时）排在段 3 里，随看板工具一起。

### 6. 待定（施工到时发主会话）

- **代录 resolve 统一**：11-02 定 ERP「结果不明交原电脑核对」的理由（`2026-11-02-erp-cc-chat-push.md` §5）：ERP 单据的写账状态还驱动库存对齐与主档挂码，
  「人报单号记成已写入」会绕过电脑读回、Express 单号对不上库存流水。段 4 开工前把这条理由的影响面查清给主会话；没有硬理由就统一成「人核对后报单号 + 电脑读回核实」一套。
- **收银台的退款 / 作废小票**：网页能做，但通常在柜台当面办（要退现金）。对照表先标「待定」。

## 不做

- 不给 CC 开网页没有的路（例如销售发票作废重开、绕过电脑读回直接记已写入）。
- 不加确认卡来代替代码里的底线（金额、状态、权限、幂等在业务功能层守，主会话 11-08 第 4 条）。
- 不先上「禁止」再上「能力」（11-08 P0-1 教训：只上「不许自读票据」而 ERP 还没识别工具，会比现在退步）。
