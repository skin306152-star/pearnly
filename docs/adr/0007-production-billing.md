# ADR-007 — 云端计费、本地控制面

状态：用户于 2026-09-19 确认；实施中，未宣布生产可用。

## 决定

- 新平台部署到 Contabo 新加坡 194.233.74.40；旧 pearnly-app 的 Cloud Run 与主域名不切流。
- 管理后台、开户单和人工充值审核 UI 留在 Mac。
- 余额、套餐、充值申请与扣费流水由云端独立 `billing.internal` Site 唯一记账。电脑关闭不影响已有租户的余额查询、识别扣费或使用。
- 复用 `pearnly_control.billing` 的规则与四张计费 DocType，不另写定价实现。云端安装该 App 是为了复用 schema 和规则，不提供管理后台。计费 HTTP 服务只在 Docker 内网与服务器 loopback 监听，且只放行精确的计费 API 白名单；无 Desk、开户、用户管理、任意 RPC 或 REST 文档入口。
- 本地审核通过受 SSH 隧道保护的管理 API；管理员会话在本地校验，云端另验管理凭据与审核人白名单。租户凭据不能审核充值。
- 租户凭据按租户和产品派生；不能拿 A 的凭据查询 B，也不能用 DMS 凭据替 ERP 扣费。主密钥只存在控制面和云计费服务。
- 本地充值单是只读显示缓存；审核结果和钱均以云端为准。断线明确失败，不落本地余额，不假装到账。
- 账户搬迁使用精确租户 ID 和计费记录 ID；不把已存在余额当作新的充值再次入账。迁移前后核对余额、流水数、金额、套餐周期，切换期间停计费写入，不允许双写。

## 发布约束

精确 SHA → CI 构建 amd64 → 前端、框架版本、Chromium验证 → 私有 GHCR digest → 受限镜像接收器 → 显式启用服务。镜像接收器只能拉指定仓库 digest，不能运行 shell 或启动服务。

生产使用独立 secrets 与持久卷，不使用样板密码、源码挂载或浮动 latest。数据库、Redis、计费、Keycloak 管理面不开放公网。产品页面、登录及 LINE 回调使用有有效证书的 HTTPS 子域名。

## 验收

零余额新租户、充值申请、仅管理员审核、重复/并发审核不重复到账、相同 OCR reference 重试不重复扣费、跨租户/跨产品拒绝、套餐周期与现价不变、Mac 断开后已有租户计费可用、恢复后待审核单可见。真实 LINE 与第三方 DMS 业务回查另记，不能用接口 200 代替。
