# 文案与语言：标准做法

用户 2026-09-19 定：**不许写死任何文案和语言**，包括管理后台与租户站点。
这份文档写清楚"标准做法是什么、怎么自查、新代码该往哪加"。

## 一条原则

**代码里不留中文，也不留"只有一门语言"的写法。** 界面文字一律是**英文 msgid**，
各语言的显示名由翻译包给。

为什么 msgid 必须英文：`_()` / `__()` 在译文表里找不到时**原样返回 msgid**。
msgid 写成中文，等于这门语言永远是中文；写成英文，至少有一个说得通的兜底。

## 三层各有各的落点

| 层 | 怎么写 | 译文放哪 |
|---|---|---|
| Frappe 原生：DocType 标签、Desk JS、服务端消息、www 页面 | `_("English")` / `__("English")` | `apps/<app>/<app>/translations/{zh,th,ja}.csv` |
| 工作区卡片、角色名、功能目录（**存进库**的值） | 也存英文 msgid | 同上，但见下面"放哪个 app" |
| LINE 卡片文案 | `i18n.t("dms.card.*", lang="th")`（语义键，另一套） | `apps/pearnly_dms/pearnly_dms/translations/*.csv` |

## 译文放哪个 App：看**谁渲染**，不是看谁定义

Frappe 只加载**这个站点装了的 App** 的译文。所以：

· 功能目录写在 `pearnly_control/features.py`，但工作台卡片渲染在**租户站点**上，
  而租户站点不装 `pearnly_control` —— 这条译文必须落在 `pearnly_core`（每个站点都装）。
· 租户站点装的是 `frappe + pearnly_core + 对应产品 App`；控制面装的是
  `frappe + pearnly_core + pearnly_control`。

拿不准就放 `pearnly_core`。

## 术语表是唯一来源

同一条文案在三处用（服务端 `_()`、Desk `__()`、DocType 的 label），各写一份必然对不上。
所以：

1. 在 `scripts/i18n/messages.tsv` 加一行：`app` / `en` / `zh` / `th` / `ja`；
2. 跑 `python3 scripts/i18n-build.py` 生成各 App 的翻译包（生成物**要提交**）；
3. 名字、叫法上也以这张表为准（"账套""提交""过账"这类术语不要各翻各的）。

## 存进库的值：注意哪些地方框架**不会**自动翻

`__()` 不是到处都有，实测过的边界：

· **会翻**：Link 字段的显示值、Select、Autocomplete、工作区卡片标题
  （`base_widget.js` 的 `set_title`）、表单字段标签、角色名（`roles_editor.js`）。
· **不会翻**：`Data` 字段在**列表里**的值（`formatters.js` 只翻 Link/Select/Autocomplete）。
  遇到这种，用 `frappe.listview_settings[doctype].formatters` 补一次
  （样板：`pearnly_feature_list.js`）。
· **不要拼后缀**：`f"{label} 列表"` 这种拼法是**存进库的数据**，渲染时只做精确查表，
  拼出来的串永远查不到 —— 表现是"卡片标题已经是泰文，下面那条还是英文+中文"。

## 自己怎么查

```bash
python3 scripts/check-i18n.py            # 报告：哪里还有写死的中文
python3 scripts/check-i18n.py --list     # 逐条明细
python3 scripts/check-i18n.py --strict   # 有发现就退出码 1（给闸门用）
python3 scripts/check-i18n.py --missing-all   # 英文 msgid 缺哪几门语言的译文
node scripts/sample-verify-i18n-ui.mjs   # 界面上是不是真的翻了（控制面）
```

`check-i18n.py` 把"日志/断言里的中文"单独归为 `py-internal-cjk`：那些不进界面，
不因为它们拦人。**框架自带的词条**（Save / Submit / Search…）由 frappe 自己的
`locale/*.po` 提供，不在我们这几个 App 的 CSV 里 —— 报缺时要先判断是不是这一类。

## 改动注意

· 改**角色名**要三处同步：`features.py` 的 `ENFORCEMENT`/`PRODUCT_ADMIN_ROLE`、
  `pearnly_core/billing_www.py` 的 `ADMIN_ROLES`（按名字判权限）、
  以及 `pearnly_core/patches/` 里负责给老站点改名的补丁。
· **Select 的 options 是存进库的值**，改它会破坏已有数据，要另外做数据迁移。
  DocType 的 `label` / `description` 只是显示文案，改它们安全。
· 改完记得让站点重读：`scripts/dev-reload.sh <组>`（译文缓存在 Redis 里，
  `--no-cache` 会跳过清缓存，改译文时不能用）。
