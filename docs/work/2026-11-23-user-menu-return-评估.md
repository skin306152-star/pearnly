# 左下角头像：进账号区落第一项、再点回到进去前那一页（评估）

11-23，主会话 local_0d36f9f2 派（拼车窗口等 K1 期间做）。分支 `pearnly/user-menu-return`，基于 main e8b2246f4。

## 0. 需求原文与理解

用户 11-13：「图一界面是，库存，当我点左下角时，跳转到图二（这个我当时要求是默认，这个取消），然后我又点左下角，跳转到图三，
这个交互界面有点不太对，应该跳转到上次界面」。已答：进设置区后先落在「公司」。

理解（三产品共用外壳 `apps/pearnly_core/pearnly_core/public/desk/product.js` 的 `p.user_menu`）：
1. 点左下角进账号区：右侧落在该产品账号区的**第一项**（按声明顺序：ERP = 公司；Cowork = 个人信息（团队管理在它下面）；DMS 只有个人信息）。
   当前用户没有「公司」权限时服务端已把它从 boot 里筛掉，第一项自然是个人信息。不再一律先进个人信息。
2. 再点左下角出账号区：回到**进去之前那一页**（路径 + 地址栏查询参数，即列表筛选），侧栏画回业务菜单。
3. 进去前本来就在账号区（直接打开账号区链接 / 刷新）→ 再点出来回首页（`/desk`，产品首页）。
4. 在账号区里点了别的账号项（公司 ↔ 个人信息 ↔ 团队管理）：「进去前那一页」不变；点了业务入口 / 浏览器后退离开账号区：照常走那条路由，记住的那一页作废。

## 1. 现有同类与复用

- 现状（2026-09-23 口径实现）：点开 → 不在账号区就 `route_to_user()` 进个人信息（ERP 也一样，没按「公司」）；再点 → `make_sidebar()` 只画回业务菜单，
  **页面停在账号页**，这就是用户说的「图三」。
- 复用：仍是同一个 `p.user_menu`、同一个 `state`（挂在侧栏实例上）、同一个路由监听；只加「进入前路由」一个字段，不新建模块。

## 2. Frappe 原生能力

- 锁定 Frappe 16.33：左下角原生按钮只有 `route_to_user()`，没有账号区侧栏，也没有「再点返回」（主会话已核）。账号区是 9-23 按用户口径自建。
- 返回用框架路由：`frappe.set_route("/desk/…")`（`router.get_route_from_arguments` 认整段路径，去掉 `desk` 前缀）。查询参数照框架处理站内链接的原生写法
  （`router.js` 点链接：`frappe.route_options = URLSearchParams(search)` 再 `set_route(pathname)`），页面按原生 `route_options` 读回筛选。
  不用 `history.back()`（账号区内点过几项后退会退到上一个账号项），不自造历史栈。

## 3. 按类通用

三产品同一段外壳代码，按各产品 `pearnly_navigation.user_menu` 声明自动适配；不按产品写分支。

## 4. 上下游数据

纯前端路由交互，不碰服务端、不改 boot 内容、不写库。

## 5. 隔离与权限

不变：账号区里有哪几项仍由服务端按「页面已实现 + 当前用户能进」筛（`desk/navigation.py user_menu`）。第一项随之按人变化（员工没有公司 → 个人信息）。
返回的是本人刚才所在页，不越权。

## 6. 入口：网页、手机、LINE、拍照

- 电脑宽度：侧栏常驻，按上述。
- 手机宽度：侧栏是抽屉，左下角按钮在抽屉里；同一段代码。验收时核：进账号区后抽屉状态、再点返回后落到原页（抽屉收起与否按原生，不另加处理）。
- LINE / LIFF / CC 桌面版 / 智能体页：不经这颗按钮，不受影响。

## 7. 共用件与连带回归

`check-impact.py --files product.js` 命中 desk-shell（49 个入口）与 upload-box（16 个入口）。这次只改 `p.user_menu` 一段，upload-box 入口代码不动；
desk-shell 的页面入口按清单跑自动冒烟（`[auto]` 项），手工项里与侧栏有关的 `shared.sidebar-order`、`erp.company-menu` 实点一次。
产品地图：左下角账号区目前没有自己的地图行，同一提交补一行（`shared.user-menu`：进入落第一项 / 返回原页 / 直接打开账号页再点回首页），挂到 desk-shell 共用件。
