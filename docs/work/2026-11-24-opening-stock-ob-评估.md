# 需求影响评估：补期初卡写 STCRD「OB…」期初行（K2 同类风险）

证据：本机 NLTTEST 副本（11-20 基线，先进先出 + 分仓计价）与测试机1 C 盘 70EXP 100 本 T 账套只读统计，脚本 `~/pearnly-devtools/stock-k-1124/ob_stats.py`。

> 库存 K 后续窗口 11-24。只评估，审定后再施工。

## 一屏结论（大白话）

- **原生 Express 的期初根本不写库存卡（STCRD）**：期初只记在物料主档的「期初数量 / 期初货值」（STMAS.OPNBAL / OPNVAL）和各仓的期初（STLOC.BEGBAL），
  批次链的第一批叫 `B/F`，之后的出库直接指向 `B/F`。本机 NLTTEST 副本：272 件有期初、339 行出库指向 `B/F`、库存卡里**一行期初都没有**、
  单号前缀不在单据簿（ISRUN）的行 **0 行**。测试机1 C 盘 100 本测试账套（清空过单据的副本）：库存卡里 `OB` 行 0、
  不在 ISRUN 的前缀只有 1 行（测试时写的 `PREP-…`）；76 本主档批号是 `B/F`（期初批）。
- **CC 的补期初却两头都写**：主档 OPNBAL 设成期初数，**又**在库存卡加一行进货（POSOPR 0、单号 `OB{yymmdd}-{nnn}`、没有单头）。
  风险有两层：① 和 K2 一样，`OB` 多半不是这套账的单据簿前缀，Express 重算那天会弹 Message 43、挡住财务原生录单；
  ② 更大的一层：Express 重算时从「期初 + 库存卡逐行」起算，期初被算两遍，数量和成本翻倍（未实测，需 A/B 证实）。
- **这条路现在没有入口**：本仓里没有任何代码往单据记录写 `opening_stock`（旧仓的「补期初卡」端点没有迁过来），
  只剩 preflight 透传、CC 照写。也就是说新数据走不到这里，只有旧数据里残留的才会触发。
- **建议**：不修写法，**整条删掉**（preflight 透传、CC `set_opening_stock` 与 `opening_stock` 参数、对应单测）。
  卖出时没库存的情况，现在已由负库存规则统一处理（允许就写成负、不允许就转人工，K1 出超按 0），不需要 CC 自己造期初。
  删前一次生产只读：数一下单据记录里还带 `opening_stock` 的有几条（预计 0），以及 CC 写过的账里有没有 `OB` 开头的库存卡行（有就列出来给财务看，不自动改）。
