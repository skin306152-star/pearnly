# 扣费读本月按量页数计数（2026-10-01）

分支 `codex/billing-usage-counter`，基线 `origin/main` 4091731d。归属：控制面 `pearnly_control.billing`（计费服务）。
来源：压测窗口第三轮慢查询（生产 7bfe2165，同一租户 128 / 256 / 500 份发票）第 1 项。**用户 2026-10-01 在本窗口同意**这项计费改法。

## 问题

每扣一笔按量费，都在租户锁里锁住并加一遍本月全部按量用量行（阶梯价按本月已用页数定）。生产慢查询：`select … from tabPearnly Tenant
… for update` 1443 次、823 秒、平均 0.57 秒；同一租户的扣费排成一队，持锁时间随当月用量增长。这是那一轮端到端时间最大的单项。

## 改法（价格口径不变）

- 钱包加两个只读字段：`usage_month`（计数属于哪个曼谷年月）、`usage_checked`（计数最后一次与台账核对的曼谷日期）。原有的
  `pages_used_this_month` 就是计数。
- 扣费（已持租户锁）：计数是本月、今天核对过 → 直接用；否则（每个租户每月第一笔、每天第一笔、上线后第一笔）从台账算一次——计数与台账
  对不上就记错误日志 `billing usage counter drift`、以台账为准。扣完在同一事务里计数加上这笔页数，台账行的 `billing_month` 与计数用同一个
  月份（跨月那一刻也不错开）。按量用量行只有 `charge` 一处会写，计数恒等于台账里本月 payg 行的页数之和。
- 问余额（只读、不加锁）：读计数，计数不是本月就照原来从台账算（不改钱包）。
- 订阅额度、Excel 扣费、余额与台账写法都不变；`estimate_cost_thb` 的输入仍是本月已用页数。
- 每天核对不另开定时任务（计费服务没有调度进程）：放在每个租户每天第一笔扣费里，在锁内从台账算一次。

## 验证

- 离线：`tests/test_control_billing_usage_counter.py` 6 条（计数对得上不扫台账；换月 / 上线后第一笔从台账算一次且不算漂移；每天核对发现漂移
  记日志并修正；问余额不加锁不改钱包；扣费按计数定价、计数与台账行同月同步移动）；`test_control_billing_gate.py` 4 条仍过。
- 测试机（生产同一镜像的测试栈，计费服务 2×4、512MiB；同一租户每轮同时 50 次问余额 + 200 笔扣费，3 轮 = 600 笔；新代码只临时放进
  测试栈计费容器并迁移出新字段，测完已重建容器还原）：

  | 计费代码 | 扣费 中位 / 95% / 最慢 | 扣费出错（HTTP 500，死锁） |
  | --- | --- | --- |
  | 旧镜像 51e73a9f | 2.45 / 4.60 / 5.25 秒 | 2 / 600 |
  | main（余额闸已修） | 2.58 / 4.85 / 5.51 秒 | 7 / 600 |
  | 本分支 第 1 轮 | 1.63 / 2.99 / 3.61 秒 | 1 / 600 |

  1200 笔并发扣费之后：钱包计数 3165 = 台账本月 payg 页数之和 3165，漂移日志 0。测试机比生产快约 5 倍，看的是同条件下的相对变化。
- 测试账本还原：这几轮扣费（参考号 `loadtest:*`，2987 笔）按用户之前选的做法删除，余额回到 660.5、本月页数回到 178，`usage_checked` 清空，
  下一笔扣费重新核对。
