## 二、试点怎么做

### 2.1 四层里只测「执行层」

讨论记录里的四层（入口 → 理解 → 执行 → 核对）：

- **理解层视为全对**：草稿单直接由语料里 Express 的**标准答案**（会计手录的账）生成，再换到试点账套的主档上。
- 测的是「**照草稿单录进 Express**」这一步，加上录完的**核对**。识别准确率不在这次范围（代录也不会让识别变准）。

### 2.2 单据从哪来

- 语料：测试机 `C:\PearnlyStress\语料\06-录入推送\有答案\<公司>\答案\<Express 账套>\`（约 6,205 份，按公司分，带 Express 正确答案）。
- 取四种常见单：赊购 RR、现购 HP、赊销 IV、现销 HS。
- 筛掉暂不适合照录的：带折扣、行金额 ≠ 数量 × 单价、合计或税额对不上、无税 / 特殊税率、超过 15 行。被筛掉的按原因计数，写进结果。
- 换主档：对方和商品按原码固定映射到试点账套已有的供应商 / 客户 / 库存品；日期挪进试点账套的会计期间（保留日）。
  数量、单价、行数、对方单号照原单；标准答案的税前 / 税 / 含税合计用来核对。
- 先每种跑几张，跑通后按历史数据放量（用户已同意「必要时用历史数据仿照全量单据跑一次」）。

### 2.3 四种方式

| 方式 | 做法 |
|---|---|
| ① Haiku 5.5 + 固定流程 + Opus 5.5 兜底（主推） | 固定流程按键录入；表头、每一行、保存前后由 Haiku 看截图核对；出意外先 Haiku 接手（≤ 8 轮），不行交 Opus（≤ 14 轮），再不行停下要人 |
| ② Opus 5.5 + 固定流程 | 同上，核对和接手都用 Opus |

| ④ 直接写入（基准） | 同一批草稿单用现有 CC 直接写入代码写进试点账套的**本机副本**，同一把尺子核对，不花钱 |

### 2.4 执行器（`scripts/express-operator/pilot/`）

- **测试机上**：一个执行代理在 skin3 的桌面会话里隐藏运行（pythonw，只听本机端口）。
  - 截屏（缩到 1280×720 给模型）、发键、点按、剪贴板 + Shift+Insert 贴泰文。
  - **每次按键前核前台必须是 ExpressI，点击还要核落点也在 Express 上**，否则拒绝。
  - 读账套只许读 69EXP\test（先拷到临时目录再读），启动程序只许服务器版 Express。
- **本机上**：执行器经 ssh 端口转发连代理，一批动作一个来回（局域网毫秒级）。
  - 每一步后拿到 Express 的窗口清单：弹窗如果是独立窗口、读得到字，就按规则处理（单位框、4079、4107、605 回车；
    4224 / 4091 负库存被拦停这张；-70 网络读写错误整批停，按手册「先别点」）。认不出的弹窗交 AI。
  - 关键点截图让模型核对：表头、每行、保存前、保存后（单号变正式号）。不符就交 AI 接手，接手后再核一次。
  - 录完读账套新增的行，和草稿单逐字段对：对方码、日期、对方单号、税前 / 税 / 含税、每行品码 / 仓 / 数量 / 单价 / 金额、税务记录。
- **每张单单独一段对话**，提示控制在 9.5 万 token 以内（Haiku 超 10 万单价翻 5 倍）；旧截图由服务端上下文编辑清掉，对话前缀走缓存。
- **花费**：每次调用的 usage 记账换算美元。累计到 90 美元自动停；每满 10 美元停下向主会话报实际花费；要超过 100 美元先问主会话。
- 每张单记：成本（按模型分）、用时（模型 / 操作分开）、读回是否全对、一次做对没有、AI 接手几次在哪、要不要人、卡在哪、Express 崩没崩、截图留证。
- 中途停下（要人、崩溃、到预算点）后原样再跑，从没做的那张接着录。

API 写法按 claude-api 技能 10-26 核对：Opus 5.5 / Haiku 5.5 的电脑操作只认 `computer_toolset_20260801`；
Opus 5.5 思考关不掉，只用 effort 调；Haiku 5.5 核对时关思考。
没开服务端「拒答转其他模型」：试点要测的就是这两个模型本身，遇到拒答按「要人处理」记。

## 六、「每次开跑前登录一次服务器版 Express」设计进 CC（用户 10-26 要求）

### 6.1 用户看到的

1. CC 设置里有一页「Express 登录」：
   - 用户勾选「允许 CC 在这台电脑上替我打开并登录 Express」；
   - **本人**输一次 Express 的用户名和密码，点保存。
2. 之后每次开始代录，CC 自己：
   - 打开服务器版 Express（只认白名单里的那个程序）；
   - 等登录窗口出来、核对是 Express 的登录窗口；
   - 填用户名、密码、回车；
   - 选公司（按账套路径 / 公司代码选，截图 + 状态栏文字核对是这一家），确认工作日期；
   - 开始一张张录。
3. 用户可以随时「忘记这台电脑上的 Express 登录」。

### 6.2 存在哪、谁能拿到

- 存进 **Windows 凭据管理器**（普通凭据，只存在这台电脑、只给这个 Windows 用户，系统用 DPAPI 加密）。
  - 不写文件、不上传服务器、不进 CC 日志和截图（填密码那一刻不截图）。
- **Claude / 模型永远拿不到密码**：自动登录由 CC 程序在本机做，回给执行器的只有「成功 / 失败及原因」。
- 改了密码：登录失败 → CC 提示用户重输一次。

### 6.3 雏形（`scripts/express-operator/pilot/cc_login.py`）

- `save`：弹一个小窗，用户本人输入、保存进凭据管理器。
- `fill`：执行代理的 `login` 动作调用。核对前台是 ExpressI 且标题像登录窗 → 取凭据 → 切英文输入法打用户名、Tab、密码、回车 →
  3 秒后看登录窗还在不在，回成败。
- `forget` / `status`：删除；只显示「已存 / 未存」。
- 登录窗的标题和要不要先点用户名格，第一次由人对着画面写进 `login.json`。
- **还没在测试机上演示**：要用户本人在测试机上存一次。

### 6.4 剩下的风险（拿不准的先报主会话）

- 凭据管理器只防别的 Windows 用户，**同一个 Windows 用户下的其他程序也能读**。
  建议代录用**专用的 Windows 账户**（只装 CC 和 Express），也顺带解决「代录时别人不能用这台电脑」。
- 密码含泰文等非英文字符时，雏形不支持（直接报失败），产品里要另外处理。
- 试点真跑时**仍由用户本人登录**（任务书要求）；雏形只做演示，不用在批量真跑里。

## 七、做成产品还缺什么（第 1 步看到的，真跑后补充）

1. **执行代理放进 CC 桌面版**：CC 本来就在用户的 Windows 会话里，不需要 ssh 和计划任务；但要守住「CC 要轻量」：不录单时零占用。
2. **每种单一份标准流程**（菜单键、各格位置或按键顺序、弹窗规则），按 Express 版本维护。
   - 坐标依赖分辨率和窗口最大化，要有标定和版本检测；Express 升级后要回归。
   - 目前只有赊销的表头 / 明细坐标是实录核实的，其余要第一次真跑前标定。
3. **弹窗认不认得出**：如果 Express 的弹窗读不到字，就只能靠截图核对，成本和稳定性都会差一截（真跑第一件要确认的事）。
4. **主档缺失**：新供应商 / 新客户 / 新商品要先在 Express 里建，是另一套流程（试点用已有主档绕开了）。
5. **崩溃与断点**：Express 崩溃或 -70 后，自动重开、登录、进公司，读账套判断那张单存没存（按对方单号），再决定重录，避免重复。
6. **被拦留下的空单头**：负库存被拦时 Express 会留一张金额 0 的空单头、占一个号，要作废掉。
7. **独占电脑和授权**：代录时那台电脑不能锁屏、不能有人用；要在有正式授权的 Express 上做。按「谁的活谁的电脑做」排队，可排在夜里。
8. **实时观看与留证**：画面推到 CC 给人看；截图含公司数据，要定存多久、存哪里。
9. **成本闸**：每张单 token 上限、每家公司每月预算、超了自动停或降级。
10. **安全守卫**：只操作 Express，不关程序、不进设置、不切公司；密码不出这台电脑。
