## 主结论（给岳父看的，待真跑后定稿）

**口径**：客户的单据交给 CC → CC 用产品现有的识别读一次 → 打开事务所服务器上的 Express，照读到的内容一张张录 → 录完读账套核对。

## 附录 A：试点怎么做

### A.1 测什么

只测「拿到单据 → 录进 Express」这一整段，分两步：

1. **识别**：用产品现有的识别（和生产同一条路），单据只看一次，得到「草稿单」。
2. **代录**：照草稿单打开 Express 一张张录，录完读账套核对。

会计在 Express 里手录的账是**标准答案**，**只用来核对**，不当草稿单输入（否则准确率是假的）。

### A.2 单据

- 「录入推送语料」（事务所真实单据，按公司分，带 Express 答案）里抽的 250 份，产品正式识别已经跑过（10-17，甲骨文上的识别闸门，
  走 Cowork 正式代码 + claude-ocr 服务，每份带实际花费）。试点直接用这批结果，**不再花识别费**。
- 251 份识别结果里，能照四种买卖单录的有 87 张：赊购 44、现购 23、赊销 16、现销 4；其中 44 张能和标准答案对上（用来算准确率）。
- 没生成草稿单的（按原因）：不是发票 87、识别缺日期或金额 28、转账单 10、报关单 8、扣税凭证 8、税报 / 清单 6、零税或无税 9、
  贷项通知 3、其他 3。这些在产品里另有录法或要人看，不在这次四种单的范围。
- 识别结果只有表头（单号、日期、双方税号、未税额、税额、合计），没有商品明细，所以草稿单是「一行」：
  试点账套里的一个非库存品，数量 1，单价 = 未税额。另用多行单测「行数多了操作要多久」（只算时间和费用，不算准确率）。
- 对方按税号固定对到试点账套已有的供应商 / 客户；日期挪进试点账套的会计期间（同月同日）。

### A.3 试点电脑与账套

- 账套只用 `\\accserver\d$\account\69EXP\test`（บริษัท Pearnly จำกัด）；程序里写死白名单，别的路径一律拒读。

### A.4 代录怎么做：四层，能不截图就不截图（主会话 10-26 定）

| 层 | 做什么 | 怎么做 |
|---|---|---|
| 1 键盘 | 按操作手册的顺序录 | 菜单编号（Alt+1→4 等）、回车跳格、剪贴板 + Shift+Insert 贴泰文；不靠定位格子。工具栏「新建 / 保存」找不到快捷键前点坐标，单独记次数 |
| 2 Windows 系统接口读状态（不截图） | 每格打完核对内容；每步认弹窗 | 读焦点格文字（Win32 WM_GETTEXT、UI Automation），读 Express 窗口清单和弹窗文字（4079、4224、-70 …）。Express 是 VFP 程序，格子可能读不到——**实测并列出能读 / 读不到的** |
| 3 读 DBF | 保存后确认存上；录完逐字段核对 | 单头表行数加一 = 存上；读新增的单头 / 明细 / 税务记录，和草稿单、标准答案比 |
| 4 截图给 AI | 前三层都判断不了才用 | 认不出的弹窗、格子内容不符、本张有格子读不到时保存前看一眼；出意外先 Haiku 5.5 接手（≤ 8 轮），不行 Opus 5.5（≤ 14 轮），再不行停下要人 |

- 每层判断了多少次、坐标点了几次、给 AI 看了几张截图，每张单都记。
- 不改、不注入、不反编译 Express 程序本身。
- 每张单单独一段 AI 对话，提示控制在 9.5 万 token 以内；旧截图由服务端清掉，对话前缀走缓存。
- 花费：每次调用按 usage 记账换算美元；累计到 90 美元自动停；每满 10 美元停下向主会话报；要超过 100 美元先问主会话。

## 附录 E：「每次开跑前登录一次服务器版 Express」设计进 CC（用户 10-26 要求）

### E.1 用户看到的

1. CC 设置里一页「Express 登录」：勾选「允许 CC 在这台电脑上替我打开并登录 Express」；**本人**输一次 Express 用户名和密码，保存。
2. 之后每次开始代录，CC 自己打开服务器版 Express（只认白名单里的程序）→ 核对是 Express 的登录窗口 → 填用户名、密码、回车 →
   选公司（按账套路径 / 公司代码选，读窗口文字核对，读不到再截图）→ 确认工作日期 → 开始录。
3. 用户可以随时「忘记这台电脑上的 Express 登录」。

### E.2 存在哪、谁能拿到

- 存进 **Windows 凭据管理器**（只在这台电脑、只给这个 Windows 用户，系统用 DPAPI 加密）。不写文件、不上传、不进日志和截图（填密码时不截图）。
- **Claude / 模型永远拿不到密码**：登录由 CC 程序在本机做，回给执行器的只有「成功 / 失败及原因」。
- 改了密码：登录失败 → 提示用户重输一次。

### E.3 雏形（`cc_login.py`）

- `save`：小窗，用户本人输入、保存；`fill`：执行代理的 `login` 动作调用（核对前台、取凭据、切英文输入法、打用户名、Tab、密码、回车，
  3 秒后看登录窗还在不在）；`forget` / `status`（只显示「已存 / 未存」）。登录窗标题等第一次由人写进 `login.json`。
- **没演示**：要用户本人在笔记本上存一次。试点批量真跑时仍由用户本人登录（任务书要求）。

### E.4 剩下的风险

- 凭据管理器只防别的 Windows 用户，同一 Windows 用户下的其他程序也能读。建议代录用**专用 Windows 账户**（只装 CC 和 Express）。
- 密码含泰文等非英文字符时雏形不支持（直接报失败）。

## 附录 F：做成产品还缺什么（真跑后补充）

1. 执行代理放进 CC 桌面版（CC 本来就在用户的 Windows 会话里）；守住「CC 要轻量」：不录单时零占用。
2. 每种单一份标准流程（菜单键、跳格顺序、弹窗规则），按 Express 版本维护；版本升级后回归。
3. 第 2 层能读多少决定成本和稳定性：如果 Express 的格子和弹窗都读不到字，就要靠截图，成本高一截（真跑第一件事是探测）。
4. 识别目前只读表头，没有商品明细：库存类单据要商品明细才能照录，识别要补。
5. 主档缺失：新供应商 / 新客户 / 新商品要先在 Express 里建。
6. 崩溃与断点：Express 崩溃或 -70 后自动重开、登录、进公司，按对方单号查账套判断存没存，再决定重录，避免重复。
7. 被负库存拦下时 Express 留下的金额 0 空单头要作废。
8. 独占电脑和授权：代录时那台电脑不能锁屏、不能有人用；要在有正式授权的 Express 上做。按「谁的活谁的电脑做」排队，可排在夜里。
9. 实时观看与留证：截图含公司数据，要定存多久、存哪。
10. 成本闸：每张单 token 上限、每家公司每月预算。
11. 安全守卫：只操作 Express，不关程序、不进设置、不切公司；密码不出这台电脑。
