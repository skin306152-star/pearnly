## 为什么

LINE 快捷回复一次最多 12 个选项，放不下几十上百份账套（一家事务所 965 份）。改为：LINE 只选目标 ERP、进项 / 销项、
入账方式（MR.ERP 现金 / 赊账，Express 服务 / 存货），账套识别后按票自动挑，挑不出 / 挑错在编辑页改。

## 调查结论（只读，未改）

### 分店（旧项目 2026-08-06 Korn 反映：连锁客户分店票记到总店名下）
- Express 小助手已改为税号 → 分店号（ORGNUM）→ 名字逐级匹配，定不出转人工；新建档写分店号。仍有风险：
  识别几乎读不到分店号（schema 有 `seller_branch/buyer_branch`，但提示词没有规则，L2/L3 没有该键）；只有总店档时按同名复用会挂回总店；
  「สำนักงานใหญ่」被当成没给分店号（不是 00000）；关联客户已配 Express 代码时不看分店；**凭证与进 / 销项税记录（ISVAT）的分店号恒写 0**，真实账套里这一列是对方分店。
- MR.ERP 完全不看分店：客户 / 供应商码就是税号，分店一栏恒 00000。
- 本任务只用了本公司分店号（ORGNUM）区分同税号的总公司 / 分店账套。对方分店号的读取与写入另开任务。

### MR.ERP 现金 / 赊账
- 付款方式与过账类型都不依赖账套；LINE 保留：销项问现金 / 赊账，进项只有赊账（自动选上）。
- 现金销售收款科目默认 TEST2019 的 1111-01 / 1112-01，覆盖映射全站一份不分账套；目标账套没有该科目时 MR.ERP 拒收转人工（推送时的问题）。

### Express 库存 / 服务
- 选择不依赖账套；库存能不能落要看目标账套的存货主档、存货科目组、科目表、单位表、会计期间，都在推送准备 / 小助手写入时用。
- **已有问题、自动挑账套后会更常碰到**：选的不是小助手默认账套时，推送准备拿不到按账套上报的缓存（`connections/preparation.py` 只给默认账套），
  零存货主档检查、存货科目组自动选择失效，失败推迟到小助手写入；连接上的 `stock_acccod` 换账套不清。新平台还没有「选存货科目组」的补救界面。进项库存至今没有真票推过。
