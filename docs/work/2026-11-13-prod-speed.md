# 线上访问速度（2026-11-13 晚起）

用户 11-13 晚报「线上所有站点打开要近 2 分钟」，要求治根、不只针对办公室。本记录分三步：
① 把慢拆开量清楚（本页，只读）；② 不花钱不改架构的改法（清单待主会话定）；③ 线路本身的方案（只出数据，用户定）。

测量脚本与原始数据：`~/pearnly-devtools/prod-speed/`（`README.md` 有用法；明早白天用同一套重测对照）。

## 第 1 步结论（19:30–19:45，晚高峰）

**一句话：慢主要在服务器商机房这一侧的线路（晚上拥塞、绕路），不是只有 True；页面每次都要重下约 300KB，把线路问题放大成 5–7 秒；今晚还叠加了 CC 安装包（154MB）正在往办公室下载。**

每打开一次 testerp 首页（浏览器已有缓存，日常情况）共 7.2 秒：

| 环节 | 耗时 | 占比 |
|---|---|---|
| 服务器出 HTML 首字节 | 0.35 s | 5% |
| 下载 HTML 本身（296KB 压缩后，`no-store` 每次重下，其中 86% 是整套界面翻译词条 `__messages` 11404 条） | 6.6 s | 92% |
| 之后 8 个小接口 | 约 0.6 s（与上重叠部分不计） | — |
| 静态资源（JS / CSS / 字体 / 图标 / 提示音） | 0（全部命中一年缓存） | 0 |

首次打开或发布后缓存失效：testerp 97 秒、testcowork 29 秒，下载 2.5–2.8MB（JS 1.48MB 54%、字体 570KB 21%、HTML 296KB 11%、图标 165KB、CSS 134KB、提示音 103KB），全部在 1 条 HTTP/2 连接上，速度只有 30–90KB/s。

对照：nginx 日志里办公室打开页面文档的平均耗时 **上午 10 点 0.71 秒，今晚 19 点后 16.4 秒（最长 105 秒）**，同一份文档、同一台服务器——变的是线路。

## 测量表

### 页面（本机 = 办公室 True 线路，无头浏览器登录后录，19:32 / 19:35）

| 页面 | 冷缓存 | 热缓存 | 请求数 | 冷 / 热 传输 | 首屏出内容（冷 / 热） |

| testerp `/desk/pearnly-home` | 97.3 s | 7.2 s | 107 | 2.76MB / 0.30MB | 84.6 s / 7.2 s |
| testcowork `/desk` | 28.8 s | 5.8 s | 66–68 | 2.50MB / 0.33MB | 27.1 s / 5.7 s |

- 静态资源都有指纹 + `max-age=31536000`，热缓存时 96/107 个直接取本地；只有 HTML 和接口走网络。
- 阻塞首屏的：HTML（内嵌 839KB 的 `frappe.boot`）→ 9 个 CSS + `libs/desk/controls` 等同步 JS（共约 1.2MB）→ 字体；冷缓存时首屏要等这些全部下完。
- 提示音 8 个、字体 3 个（可变字体 + Medium + SemiBold）都是 Frappe 原生加载，有缓存，只影响首次。
- 实时推送 socket.io 开页时先走轮询（`transport=polling`）3–4 个往返再升级，不阻塞首屏。

### 线路（19:37–19:41）

| 起点 → 终点 | 往返（最低 / 平均 / 最高） | 丢包 | 路径 |
|---|---|---|---|
| 生产 → 自己机房第一跳网关 66.206.27.29 | **6.5 / 33 / 179 ms** | 0 | 正常应 < 1ms：机房内部 / 出口拥塞 |
| 生产 → 办公室 True 124.120.109.61 | 32 / 40 / 132 | 终点 11.7%，中间跳 17–57% | 新加坡交换中心 → 中国移动国际 → True |

| **甲骨文新加坡 → 办公室 True** | **32 / 33 / 49** | **0** | 同样走新加坡交换中心，几乎不抖 |
| 甲骨文新加坡 → KU、CAT | 24 / 25–29 / 32–126 | 0 | 干净 |

| 甲骨文新加坡下载生产静态资源 | 建连 0.15–0.24s，速度 240–320KB/s | | 对照 Cloudflare 新加坡：建连 2–8ms、2–2.5MB/s |

判断：
- 泰国方向本身是好的（甲骨文同城出发到泰国各家都 25–33ms、几乎不抖）；生产到同样目标抖动大、有丢包，连到自己第一跳网关都抖到 179ms → **问题在服务器商（Hivelocity / SSD Nodes 新加坡）这一侧**，对所有用户都一样，不只办公室、不只 True。
- 另有入站绕路：从部分网络（例：甲骨文所走的 NTT）进生产要绕出亚洲，往返 145ms。泰国手机网络走哪条进来今晚没量到（第 3 步实测）。
- 今晚叠加：CC 安装包 154MB 在挤办公室下行；上一晚（11-12 22 点）的慢没有安装包下载，是纯线路问题。

### CC 安装包
- 154MB，从生产 `pearnly.com/downloads/companion/` 直发；今晚测试机2 约 57KB/s、要 45 分钟，办公室同时下载会挤占网页。
- 同一时刻办公室从 R2（media.pearnly.com，曼谷节点）下载 1–9MB/s → 154MB 约 0.5–2.5 分钟。
- 兼容：客户端 `updater.download_installer` 支持绝对地址并跟随跳转（`follow_redirects=True`，仓库最早的 1.1.77 起就是这样），所以已发布版本不用改；
  服务端 `cc_desktop/release.py` 只认 `/downloads/companion/` 开头的相对地址 → 最省事的切法：安装包传 R2，源站对 `/downloads/companion/*.exe` 返回 302 指过去，`latest.json` 留源站不动。
- 费用：R2 存储 10GB 内免费、出流量免费，无月费。
