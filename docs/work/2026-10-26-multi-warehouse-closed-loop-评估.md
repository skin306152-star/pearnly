## 0. 需求原文与理解

- 原话（用户经主会话转述，10-26）：「3说的就是需要一公司多仓库系统，当初好像只设计了一公司单仓库系统，现在新建物料无法选择这个公司的其它仓库，也就是说物料，盘点，出入库销售采购，还没形成一个闭环，没有形成一个一公司多仓库使用的正式系统，然后扫到系统里没有的东西时，可以就地新建，体现到差异里，还有体现到系统里，并标注来由，目前说到的缺陷虽然只有几处，但是是整套系统的闭环逻辑，你要处理好」。起因是岳父演示：建了仓「123」（生产 testerp CO-00001 的 WH-140446，10-26 14:48 建，空仓），之后感觉「用不了」。
- 主会话审定口径（10-26，本评估照此写）：
  1. **不恢复公司级默认仓**（09-24 用户：「不要做默认仓，依赖的全部删掉」继续有效）。「统一默认值」= 各入口的**预填规则一致且可改**：从这张单自己的上下文带仓（收银台挂的仓、来源单据的仓、本人在这类单上次选的仓）→ 公司只有一个启用仓时直接用 → 多仓且无上下文必须选，不替人猜。
  2. 新建商品时可直接填「期初数量 + 仓 + 库位」，落成期初流水，**不是**让商品归属某仓。
  3. 「盘哪些货」（按仓 + 分类 / 选定商品 / 库位的部分盘点）纳入本方案。
  4. 盘点扫到未知码：**盘点员当场建正式商品**（有盘点写权限即可，不另设建档审批），扫到的码作条码，现场填名称，单位等最少必填；照样记数、进差异、过账照常进账（成本未知按现有「成本未知」口径）；来由 =「盘点新建 + 盘点单号 + 谁 + 何时」，商品主档与差异报表都显示；多人同时扫同一新码合并为一个商品；同码同仓同库位合并、多人各记一条；不跨公司提示；Cowork 有盘点页就按类一起加。
  5. Express 存货码：先查现有推送是否已会建 STMAS，会就复用。
- 我的理解：一家公司有多个仓时，从**建商品 → 期初 → 采购入 → 调拨 → 销售 / 收银出 → 盘点（含新发现）→ 过账 → 按仓报表 → 写 Express 读回**，每一步都能明确选仓、真落到所选的仓、按仓查得到、写进 Express 对应的仓，且预填规则处处一致。
- 不在本需求范围的（防止顺手扩展）：批号进库存（单据行有 `batch_no`，库存不按批号记，见 G21，另议）；收银台一台跨仓卖货（一台收银台属于一个门店，按设计一台一仓）；生产领料 / 完工；销售单退货 / 采购退货 / 采购单独收货步骤（是闭环外缘，沿用 10-24 Express 库存计划第二期，见 12 节问 5）。

## 1. 现有同类与复用（现状审计）

### 1.1 结论

**代码层是按仓记账的**：结存键 = 商品 + 仓 + 库位（`inventory/stock.py:60-66,94-176`），凡是选了仓的入口货都真落到所选的仓，作废 / 退货按原流水回原仓原库位，服务端核仓属于本公司（`inventory/warehouses.py:57-61`）。生产 testerp 也已有多仓在用（41 家接 Express 公司共 447 个仓；CO-00106 / 00118 / 00120 两仓有结存）。

**但从用户视角确实没闭环**，原因不在「记账不按仓」，而在：没有调拨、采购 / 销售选仓藏在行的收起区且会被改掉、预填规则各入口不一、建商品不能顺手放期初、盘点只能整仓且认不了新货、报表看不到跨仓合计、Express 端新仓与新商品会卡住或写错仓。

### 1.4 盘点新建商品可复用的能力

- `create_product`（`products/service.py:216`）只有品名必填（`:222-225`），编码不填自动发；码命名空间查重在 `products/codes.py:34-72`（编码 / 内部编码 / 条码 / 二维码内容 / 单位条码互不撞）。
- 但：要 `products.manage`（只发给商品岗位，`access/rules.py:45`），盘点岗位是 `count.write`（`rules.py:46,105`）；函数里自带 `frappe.db.commit()`（`service.py:257`，本评估抽查），放进盘点会把盘点事务提前提交；`erp_product` 没有来源 / 渠道 / 单号字段，只有框架自带 `owner`、`creation`。
- 认码只认启用商品（`codes.py:105`），查重却不排除停用商品 → 扫到停用商品的码：认码说「没有」，新建说「码已占用」。
- 盘点并发：每次写入先锁住这份盘点（`count_state.py:10-18`），`request_id` 唯一防重（`erp_stock_count_entry.json:95`、`count.py:930-937`），合计 = 未撤销记录相加（`count.py:704-713`），实时推送（`count_live.py`）。
- 成本：`valuation()` 先取该位置现成本，再取商品参考成本（设过才算），都没有留空 → 「成本未知」，体检列出（`count.py:444-458`；`contracts.py:170-175`；`audit.py:212-216`）。
- **Cowork 盘点**是独立一套（4 个自有 DocType，`apps/pearnly_cowork/pearnly_cowork/stocktake/`），只从上传表建任务，仓是自由文本，扫码只在本任务行里找，找不到报 `stocktake.not_found`，不查主档、不写库存（`stocktake/service.py:1-5,112-133`；`counting.py:28-33`）。前端从 ERP 抄过来，后端不共用。

**结论**：扩展现有，不新建平行体系。仓、库位、流水、盘点、商品建档、Express 推送都在，缺的是「调拨单」「盘点范围」「来由」三块数据和一组入口行为修正。

## 2. Frappe 原生能力

- 选择框：仓 / 库位 / 商品分类 / 商品一律 `ControlLink` + `get_query`（服务端分页搜索），不一次取全。
- 成员按仓：Frappe 原生 **User Permission（allow=ERP Warehouse）** 直接可用，与现有「allow=ERP Company」同一机制；`has_permission` / `permission_query_conditions` 钩子已挂在各表（`hooks.py:506-529`），只要 `masters/access.warehouse_allowed / warehouse_query` 多认一层。
- 调拨：ERPNext 用 Stock Entry「Material Transfer」（同单 s_warehouse → t_warehouse，成本随货走）。本仓没有 ERPNext，按同样语义扩展自有 `ERP Stock Entry`（方向加 `transfer`、行加调入仓 / 调入库位），不另造一套。
- 来由：Frappe 原生 `Dynamic Link`（`origin_doctype` + `origin_name`）记来源单据；谁 / 何时用原生 `owner` / `creation`，不重复存。
- 部分盘点范围：子表（Table MultiSelect）记分类 / 商品 / 库位范围，原生控件。
- 报表：差异报表继续用 Script Report，加「来源」列与按仓筛选；Select 选项改成 `{value, label}`（原生支持），修「只看」失效。
- 必须自定义的：无新外壳；表单都用 Dialog / FieldGroup / Grid。

## 3. 按类通用

- 「所有带仓的库存单据」：采购、销售、出入库、调拨、期初、盘点、收银——统一一个**服务端预填函数**和一个**前端单据头仓控件**，不在各页各写一套。
- 「所有会自动建商品的渠道」：采购识别自动建（`purchasing/entry.py:200` `auto_create_product`）、LINE 收单认不到自动建本地档、商品 Excel 导入、Express 同步、盘点新建——**一起**记来由（渠道 + 来源单据），不只盘点。
- 「所有盘点入口」：Desk 录入、LINE 手机页、Excel 导入、Cowork 盘点——就地新建 / 新发现行同一套口径。
- 「所有写 Express 的库存单」：TK / OU / JU / 调拨 RL / 收银退货 SR，新商品建 STMAS 与仓无码交人，同一口径；收银日汇总补上回填编码。
- 「所有停用」：仓停用与库位停用同样要先清库存；收银台不能绑停用仓。
- 不覆盖：报价单（不动库存）；Cowork 推送 Express 的采购单（不经 ERP 仓）。

## 4. 上下游数据

- **ERP 内单据流**：
  - 新建商品带期初 → 生成 OPN 期初流水（与期初页同一函数），商品本身不记仓。
  - 采购 / 销售 / 出入库 / 调拨 / 收银 → `ERP Stock Movement` + `ERP Stock Balance`（商品 + 仓 + 库位）；调拨一张单两条流水（调出、调入），**成本随货走**（调出按 A 仓该位置均价，调入按同一单价），两仓合计金额不漂。
  - 盘点：范围快照 → 录入（含新建商品、新发现行）→ 过账生成 AD 出入库单 → 差异报表；新建商品的盘盈按盘到数入库，成本按 `valuation()`（现场填了参考成本就用，没填 = 成本未知）。
  - 作废：调拨作废两条流水一起冲回；盘点新建的商品**不随盘点作废删除**（已是正式主档，可能已被别的单用）。
  - 受影响：库存一览、收发存、库存卡、体检（成本未知）、Express 对齐差异清单（`express_stock_diffs`）。
- **Express 映射**：
  - 仓：ERP 仓必须有 Express 仓库码才能写；接 Express 的公司**新建仓时选 Express 仓**（下拉来自已同步的 ISTAB 21 清单）；Express 里还没有这个仓 → 会计先在 Express 建，同步回来按名认领（CC 不建 ISTAB）。推送遇到无码仓**交人**，不再静默写主仓。
  - 新商品：**复用采购 / 销售已有的建 STMAS 通道**（`ensure_stock_item` + 写账规则的同名直接用 / 不同名问一次），扩到 TK / OU / JU / RL / SR；写完回填编码（`link_products` 扩到库存单与收银日汇总）。接 Express 的公司以 Express 为准：同名存货直接认，不重复建。
  - 调拨：写 Express 原生 RL（POSOPR 4 / 3、STTRN.PEOPLE = 调入仓、不带价、不过账）；**先录一张原生 RL 样本**再写（录制清单第 6 条）。
  - 期初：接 Express 的公司仍禁录期初（期初来自 Express 读回，`opening_batch.py:74-75`），新建商品的「期初数量」区同样不出现。
- **CC 桌面版载荷**：要变。新载荷版本 11：RL 单据类型；库存单 / SR 行带「可建档」标记与建档信息（名称、单位、条码）；旧版 CC 按 `payload_contract.py` 诚实拒收。与测试包 e 之后的 CC 版本一起发。
- **Cowork**：盘点页按类加「新发现行」（Cowork 没有商品主档，就地记码 + 名称 + 数量 + 来由，导出与差异里单列）；Cowork 推送 Express 不经 ERP 仓，不受影响。DMS 不涉及。

## 5. 隔离与权限

- 公司隔离不变：仓、库位、调拨两端仓、盘点范围、新建商品认码都限当前公司（调拨的调入仓必须与调出仓同公司，服务端拦）。
- 盘点新建商品：**有 `count.write` 即可**（主会话定），服务端走专用入口 `count.create_product_here`，只许填建档最少字段（品名、单位、条码 = 扫到的码、可选参考成本 / 分类），不能借此改别的商品；`products.manage` 的其余能力不放开。
- 成员按仓（可选，见 12 节问 4）：User Permission allow=ERP Warehouse；没设 = 公司内全部仓（现状）；设了则列表、报表、单据选仓、盘点、收银台都只出允许的仓，服务端 `warehouse_allowed / warehouse_query` 拦。调拨要求两端都有权限。
- 不跨公司提示码（主会话定）：认码与新建查重都只在当前公司可见范围内。

### 13.2 结构性修法（一次到位）

1. **一个预填函数 + 一个单头仓控件**（G2–G4）：服务端 `inventory/warehouses.prefill(company, doctype, context)` 按主会话口径返回「建议仓 + 理由」（收银台 / 来源单据 / 本人上次 / 唯一仓 / 必须选；问 1 定卖货仓是否作为一档）；服务端写库存时**不再兜底**——没传仓且不止一个启用仓就拒（`receiving()` 收敛到 `required()`）。前端共用一个单头「仓库 + 库位」控件（采购、销售、出入库、调拨、期初、盘点同用），行继承、可展开逐行改；选商品**不再动行仓**，库位只在商品建议库位属于该仓清单时预填（服务端 `positions.py` 已有这条，前端去掉硬塞）。删掉 `frappe.boot.pearnly_warehouse` 的用法。本人上次选的仓存在 `User` 级的 DefaultValue（Frappe 原生 `frappe.defaults.set_user_default`，按 公司 + 单据类型 作键），只当预填，不是公司默认仓。
2. **建商品带期初**（G1、G5）：商品新建对话框 / 整页 / Excel 导入加可选「期初库存」网格；提交时与商品同一事务调期初服务生成 OPN（复用 `opening_batch` 的写入，不另写一套）；接 Express 公司不出现。期初模板加仓列（可空 = 表头仓），预览核库位清单。
3. **调拨 = 出入库单第三个方向**（G6、G17 后两项）：`ERP Stock Entry.direction` 加 `transfer`，行加 `to_warehouse` / `to_location`，一次过账写调出 / 调入两条流水，调入单价 = 调出单价（成本随货走）；按台车辆随行换仓（出库核库位一起补）；编号新定义（同 AD 那样独立一段）；作废两条一起冲回。前端出入库页加「调拨」入口（单头调出仓、调入仓）。
4. **CC 写 RL**（G7）：先录原生 RL 样本；载荷 11 加 RL：STTRN（POSOPR 4，LOCCOD 调出、PEOPLE 调入）+ STCRD 成对 4 / 3、不带价、不过账、两边 STLOC；读回核对；作废走现有库存单作废通道。
5. **盘点范围**（G8）：`ERP Stock Count` 加范围子表（库位 / 分类 / 商品，可空 = 整仓）；快照只取范围；范围外扫到的货照现有 `ensure_item` 补行，来源标「范围外」；一份一仓（问 3）。
6. **盘点就地新建 + 来由**（G9–G12、G20）：
   - `ERP Product` 加 `origin`（Select：手建 / 导入 / Express 同步 / 采购自动建 / LINE 收单自动建 / 盘点新建）+ `origin_doctype` / `origin_name`（Dynamic Link）；谁 / 何时用 `owner` / `creation`。所有自动建商品的渠道一起写（按类）。商品详情显示「来由」。
   - `ERP Stock Count Item` 加 `row_origin`（账上 / 范围外 / 新发现）。
   - 新入口 `count.create_product_here(count, code, product_name, unit, [default_cost, category])`：`count.write` 即可；在盘点锁内执行；`create_product` 拆出不 commit 的内核供它调用（商品页照旧 commit）；码作条码、编码自动发，查重照命名空间规则；**同码并发**：在盘点锁内先按码再认一次，已被别人刚建就直接返回那件商品并照常记数（两人填的品名不同以先建者为准，后者的品名记在那条记录的备注）。随后照常 `add_entry`（同码同仓同库位合并成一行，多人各记一条）。
   - 停用商品的码（问 8）：认码返回「停用」标记，允许记数，不新建。
   - Desk 录入、LINE 手机页（加库位选择）、Excel 导入（有品名的未知码行 → 新建；没品名的仍列问题行）三个入口同用这一个服务端函数。
   - 差异报表：加「来源」列与「账上 / 新发现」分节、按仓筛选，修「只看」（Select 用 `{value,label}`）。
   - Cowork 盘点：任务里加「新发现行」（码 + 名称 + 数量 + 谁 / 何时），导出与差异单列；不建主档（Cowork 无主档）。
7. **Express 端新商品与新仓**（G14、G15）：
   - 新商品：写账规则的「同名直接用 / 不同名问一次（选现有 / 新建）」扩到 TK / OU / JU / RL / SR；CC `ensure_stock_item` 在 `dbf_stock` / `dbf_refund` 里复用（载荷 11 的「可建档」标记，旧单照旧拒）；`link_products` 扩到库存单与收银日汇总，回填编码。**推荐复用、不另做「会计先建」**：通道已在采购 / 销售真用，口径一致，少一个人工步骤；会计已在 Express 建好的同名存货会被直接认到，不会重复建。
   - 新仓：接 Express 公司建 / 改仓时必选一个 Express 仓（来自同步清单），清单里没有 → 提示先在 Express 建、同步后再选；推送时仓无码 → 停在人工（新问题码），不写主仓。
8. **卫生项**（G13、G15 交人、G16、G17 前两项）：「只看」修值；仓停用前查库存（同库位）；收银台不能绑停用仓；按台期初 Excel 找仓限公司；打开按台按公司汇总；推送遇无码仓交人。
9. **报表**（G18）：库存一览加「按商品合计」切换（服务端分组分页）；低库存按商品在公司内合计比；收发存开库位筛选。
10. **成员按仓**（G19，待问 4）：User Permission allow=ERP Warehouse，`masters/access` 多认一层，所有库存 / 单据 / 报表查询与收银台跟随。

### 13.4 需实测（留给开发自测与验收脚本）
