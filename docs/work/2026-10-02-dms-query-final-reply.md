# DMS 菜单 5 查询：每次都有终局回复、等结果时打字不串流程、日期只收单日（2026-10-02，batch-1003）

分支 `codex/dms-query-final-reply`，基线 main 7e9d85e2（热修 `2026-10-02-hotfix-dms-query-push.md` 之后）。来源：ris 真实客户两次查询
「只说正在读，之后什么都没有」；热修只止住了「读成功但推结果报错」那一个出口。代码核查（同日）列出的其余静默出口在这里补齐。

## 改动

- **读到最后失败要告诉发起人**：`snapshots/manual.execute` 在三个终态失败处（结果判 failed、继续排队失败、执行抛错）调收集器登记的
  `on_failed`；只有查询收集器（`dataset_prefix: query.`）登记了 `query.snapshot_sync.notify_failed`，连接时读客户 / 公司资料等其他读取不受影响。
  `notify_failed`：同一请求只说一次（按请求号在不淘汰的状态存储里 `SET NX`，24 小时）；绑定已变、或操作员已换查询条件（会话不再是这一组）就不说；
  文案：没账号 `TXT_NO_ENDPOINT`、没权限 `TXT_DENIED`，其余一律 `MANUAL_FAILED`「这次读取失败，请稍后再试」（「读取中断」那句提到的
  「重新读取」按钮已经没有了，不用）。
- **卡住没人管的兜底**：`query.snapshot_sync.sweep_stale` 挂在已有的 `*/5` 定时上：本站快照表里查询读取停在 queued / running 超过租约（15 分钟：
  进程被杀、部署重启、队列积压）的，补说一次（同样只说一次）。只读本站表，不登 DMS，不新增常驻开销。
- **等结果时打的字不串到别的流程**：`query_flow.handle_text` 接管 `query_results` 态——这次读取还在 queued / running 时回「正在读」那张提示
  （`manual_status_message`），不再落进 `text_router.nudge`（以前回的是建档要身份证那句）；已经读完就照旧交上层。
- **日期只收单日**：订车 / 交车日期维度输入不是 `日/月/佛历年` 单个日期（例如 `01/11/2569-30/11/2569`）时回 `TXT_DATE_SINGLE`
  「只能输入一个日期，例如 15/09/2569（佛历），不能按区间查」，留在这一步等重输，不发起读取。依据：DMS 销售列表只按文字片段搜（`sd`），没有日期区间参数。
