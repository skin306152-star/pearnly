# 推到非默认 Express 账套也先做库存检查（2026-09-27）

分支 `codex/express-account-prep`，基线 main 37c874b2。用户 2026-09-27 同意，选 **A：资料没到不拦推送，检查留给小助手写入时做**。

## 问题

- 推送准备的科目表 / 商品 / 客户 / 存货科目组 / 记账指纹只取小助手**默认账套**的缓存；推到别的账套时全空，
  零存货主档检查、存货科目组自动选择都跳过，失败推迟到小助手写入。
- 潜在串账套：按单个账套刷新带回的主档直接盖在公共缓存上，归属还按小助手默认账套记 —— 推到默认账套会用别的账套的存货资料检查。
  现有界面没有触发按单个账套刷新，所以尚未发生；修库存检查必须先修它。
- 连接上选定的存货科目组（`stock_acccod`）换账套不清，会带到别的账套。

## 改动

| 位置 | 内容 |
|---|---|
| 收心跳 `connections/collector.py` | 这次心跳是按单个账套刷新、且不是小助手默认账套：主档另存 `report_json._account_caches[账套]`（带凭据 / 代次、只留最近 10 份），不进公共缓存、不记成默认账套的。`ReportPlan.refreshed_account` 标出属于哪份。 |
| 推送准备 `connections/preparation.py` | 非默认账套：用这份账套的缓存（须出自当前凭据 / 代次），小助手版本类字段取公共的；没有就空着（照旧推）。目录刷新进行中 / 失败不再拦推送（A）。 |
| 触发 | 网页新建录入点「继续」、LINE 选定（或唯一自动选上）Express 账套时，申请小助手读这份账套的主档；识别期间读完，推送时就有。失败不打扰用户。 |
| 换账套 | `targets/choice.py` 换账套时同时清掉 `stock_acccod`。 |
