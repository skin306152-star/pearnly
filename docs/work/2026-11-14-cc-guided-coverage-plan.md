## 3. 后续各期（顺序按用户：ERP 收款 → ERP 采购 / 销售 → Cowork 常规功能 → 其余）

每期都按同一套：业务菜单入口 + CC 发一句 → 引导卡问齐（服务端出题、推荐预选、问一次记住）→ 自动定的不问 → 复核卡（就地改）→ 「写入」/「开始」才办 → 结果卡。
凡是在引导卡上让用户交文件：提交那一个请求里调唯一入口 `pearnly_core.assistant.files.commit(row, file_ids, via="guide")`，卡上移除调
`assistant.api.drop_upload(session_id, file_id)`；不自建上传口、不自己触发识别（接缝约定：分支 cc-upload-read-on-send 的 `docs/work/2026-11-14-cc-upload-read-on-send.md`「接缝」）。

| 期 | 内容 | 引导的步骤（问什么 · 选项从哪来 · 自动定） | 三种账本的差异 |
|---|---|---|---|
| 合入后即做 | 第 1 期欠项：代录开始卡并进引导卡；引导卡失效置灰（等 `cc-card-expiry` 进 main）；A8 / A10（等 CC 桌面版四张小表） | — | — |
| P1 | ERP 收款（直写） | 客户（服务端搜索，ERP 客户主档）→ 未收清发票（快照，多选、每张收多少，默认收清）→ 方式（账套收款类型，按银行与常用排）→ 转账的凭证（卡上交，走 `files.commit`）→ 折扣 / 部门 / 销售员（按账套默认自动定，展开可改）→ 复核卡 → 写入 | 本：RE + 银行明细已有；云：⇢云；MR：⇢MR 收款写法 |
| P2 | ERP 采购 / 销售（直写对话收单 + 复核表 + 结果表）+ ERP 代录同卡 | 票据 → 识别 → 引导卡（付款、对方、物料按行入库 / 仓位、科目、做不做）→ 复核表（识别值就地改）→ 写入 → 结果表 | 本：Express 必填登记表已有；MR：MR.ERP 必填登记要补（付款方式、对方档、分店、币种）；云：⇢云 |
| P3 | Cowork 常规功能（直写）：银行对账、收入对账、POS 日汇总、盘点、预扣税、增值税、读回 | 对账：类型 → 月份 → 文件（流水卡上交；总账「从 Express 读回」一键）→ 预设（按公司记住）→ 开始 → 待答题卡 → 结果；POS：文件 → 版式（认不出时问一次记住）→ 复核汇总 → 写入；盘点：Excel → 仓 → 开始 / 记数 → 结束 → 调整单；预扣税：月份 → 已识别的票与 50 ทวิ（缺的卡上交）→ 草稿；增值税：账套 → 月份 → 读回 → 检查项 → 草稿；读回：账套 → 月份 → 出四本表 | 对账、增值税依赖读回：MR 无读回（用户自己上传总账 / 报表）；云：⇢云 |
| P4 | 其余：文件夹定时任务、待处理 / 结果核对、公司资料与知识库、任务看板、MR.ERP 设置、科目组 | 各自一张设置卡（选项来自产品已有接口），删除类加允许卡 | — |
