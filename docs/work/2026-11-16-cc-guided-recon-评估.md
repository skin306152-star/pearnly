# 需求影响评估：CC 引导式 · 银行对账、收入对账、销项税核查（P3 第 2 类）

> 总表 `docs/work/2026-11-16-cc-guided-master-table.md` 的 CW-D-BR / IR / VC 九格（本 / 云 / MR 各三）。基线 `origin/pearnly/cc-guided-collection`（e590f7fb4）。

## 0. 需求原文与理解

- 原话：用户 11-14「每个功能都要有引导式」，11-16「覆盖所有」；主会话 11-16「LINE / 网页已有成熟流程的格优先、复用」。
- 理解：Cowork 版 CC 对话里点「对账」，一张卡问齐：对哪一种（银行 / 收入 / 销项税核查）→ 两侧文件（卡上交，或「从 Express 读回」一侧）→ 确定 → 后台对账（「等」）→ 结果卡：汇总 + 结果里要人定一次的问题（答了按预设重算）+ 结果工作簿进对话。不靠打字。
- 不在范围：对账算法、结果页、预设规则一律不动；删对账、改 / 删预设（`cowork_recon_delete`、`cowork_recon_presets`）随「删除类走允许卡」（N5）一起做，本类不做。

## 1. 现有同类与复用

- **网页对账中心有完整流程**（`recon_center/api.py`）：「新建」两个上传口 → `jobs.start` 排后台任务 → `jobs.status` 看阶段 → 结果页 `sheets.load`（汇总、没对上的行、问题）→ 答问题 `presets.answer`（记成按账户 / 公司的预设，重算或用原文件重跑）→ 导出（各对账域 `export`）。
- CC 工具 `cowork_recon_start / status / result / answer / export` 调的是同一组函数（`assistant/tools.py:2749` 起）。
- 读回一侧复用刚做的读回引导函数（`assistant/guided/readback.py` 的账套题）与 `readback.service.request / status / file`。
- 结论：**全部复用**。新建一个模块 `assistant/guided/recon.py`（声明 + 薄转调），不另查库、不另写规则。

## 2. Frappe 原生能力

- 不涉及 Desk；引导运行用已有 `Pearnly Assistant Guide Run`；对账任务、预设表不变。

## 3. 按类通用

- 一份声明管三种：菜单一项「对账」，第一题选种类（三种的两侧文件、哪一侧能读回不同，由声明的 `when` 分开）。三格算三格（总表不变），菜单只多一项。
- 「一侧可从 Express 读回」的做法与增值税共用（增值税那类直接引用这里的读回题函数）。

## 4. 上下游数据

- 读回：总账（银行对账右侧、收入对账左侧）、销项税报表（收入对账右侧、销项税核查左侧）可选「从 Express 读回」：选了月份后，这本账套这个月最近一次读完的回读就用它；没有就在出卡时请电脑读一次（同收款「出卡时即时读回」的做法），题目下一行「正在回读」、页面过一会儿再取；电脑没连照实说。
- MR.ERP：不能读回，读回选项不出现，两侧都交文件（MR 格不依赖 MR.ERP 线）。云端 Express：读回通路随云端线放开。
- 计费：Excel / CSV 与文字型 PDF 免费；扫描件、照片按页付费识别（同网页）。**网页现状**：对账中心「新建」页（`public/desk/recon.js` `show_new`）两个上传口下面没有付费的说明，只有银行对账的银行账单一侧有提示「网银导出的 Excel/CSV 或电子版 PDF」（`cowork.recon.bank.leftHint`）。**处理（主会话 11-16）**：不加付费那一行；银行账单那一题沿用同一条提示作事实行，其余不加。
- 不写账本、不写 Express、不发 LINE。

## 5. 隔离与权限

- 菜单：有任一种对账功能的人才见（`jobs.KINDS[kind].require`，同网页）；种类那一题只列这个人有权限的那几种。
- 对账任务、预设不按公司隔开（用户 11-16：Cowork 工作空间对象不分公司）；文件只认本对话、本人的附件（`assistant.files.attachment`）。
- 答结果问题：范围由服务端从任务算（`presets._task_scope`），重跑类只收建任务时的候选（现状），引导不放宽。

## 6. 入口

- CC 对话：业务菜单「对账」+ 说一句（模型只打开引导、说的话不当文件或答案）。手机同一张卡。
- 网页对账中心、LINE：不动（LINE 没有对账入口）。

## 7. 共用件与连带回归

- 只加 `assistant/guided/recon.py`、Cowork hooks `pearnly_guides` 追加一项、术语表追加；不改 `recon_center/*`、`reconciliation/*`。贴 `check-impact.py` 输出于施工提交。
- 依赖引擎能力：**N1b**（结果出来后的问题：`result` 带 `questions`、`follow` 作答）、**N2**（结果卡带文件）、**N10**（结果函数拿到确定时的回包＝对账任务号）。服务端照约定写好、离线测试用约定的形状；`run.py` 那几行等分支 3 进 main 后由本窗口补。

## 8. 存储与成本

- 不新增存储；付费识别同网页（只在用户交了扫描件 / 照片时发生，卡上先有事实行）。不新增固定月费。

## 9. 删除、作废、追溯

- 对账任务删除走 N5 另做；引导运行随删对话删。

## 10. 文案与官方 UI

- 新增词条（四语，过 `check-copy.py`）：菜单「对账」`guide.business.recon`、开场一句 `guide.open.recon`、步骤标题 `guide.step.recon.*`（两侧文件的标题沿用网页 `cowork.recon.bank.left` 等同一组译文：银行账单 / 总账 / 销项税报告 / 销售发票）、来源两项「从 Express 读回 / 交文件」。种类名、问题标题与选项全部沿用对账中心已有词条。
- 不改已有文案。

## 11. 测试与验收

- 离线（照读回引导的替身写法）：种类只列有权限的；三种各自的两侧题与 `when`；读回一侧：有现成回读直接用、没有时出卡请读一次（搜索 / 翻页 / 核答案不请读）、在读给 `wait` 与事实、MR.ERP 不出读回项；文件只认本对话附件、单侧多份只在允许多份的那一侧；确定只开一套（双击不开第二套）；结果：在跑 `wait`、完成给汇总 + 问题 + 工作簿、失败给原因；作答：普通问题重算、重跑类回新任务号继续「等」、不在候选里的不收。
- 流程（接线后）：实验栈假智能体，交两份 Excel 对账 → 结果卡 → 答一题 → 重算。
- 真模型：说「帮我对一下 10 月的银行账」→ 只打开引导。

## 12. 主会话 11-16 已定
