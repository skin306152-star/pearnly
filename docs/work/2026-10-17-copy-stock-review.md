## 15. 闸门误判与收窄建议（开发窗口另做，单独提交）

| 误判 | 涉及位置 | 建议怎么收窄 |
|---|---|---|
| 前端 tr() 的 Frappe 自带 msgid 被判 R-HARD | CC 网页 `scheduled-tasks.tsx:499`「Delete {0} item permanently?」 | 前端 tr() / __() 的 msgid 在 `upstream-msgids.txt` 里时不判 R-HARD（运行时由 Frappe 官方译文翻译） |
| 只用来触发重试的内部异常 | `ocr/remote/callback.py:104`（`frappe.QueryDeadlockError`） | R-HARD 只判会到界面的 `frappe.throw / msgprint` 与 ValidationError、PermissionError、DoesNotExistError 等；QueryDeadlockError 这类重试信号不判 |

| Frappe 自带 msgid 的英文 | 共用层 `Invalid Filters…`（英文 R-DEV、R-LEN）、`Guests are not allowed…`（英文 R-DEV） | 在 `upstream-msgids.txt` 里的 msgid，英文不判（英文不归本仓）；中 / 泰 / 日译文照常判 —— 所以 `Filters must be…` 与 `Invalid Filters…` 的中 / 泰 / 日仍按第 9 节改写，收窄后也不会放过中文 R-LEN |

不建议收窄的：

- 交给模型、同时显示在 CC 网页步骤里的工具结果（`toolrun.py:97`、`tools.py:154 / 160`）：用户看得到，维持扫描，按第 3 节拆成「步骤显示文案走术语表 + 给模型的指令不经 `_()`」。另外 `NOT_SCANNED` 是按路径片段整文件排除（`sources.py:92`），表达不了「tool_result 的参数」，整文件排除又会漏掉同文件里给用户看的 label / ask（`tools.py:80 / 94 / 136`）。
- System Manager 专用 DocType 的 R-HARD（第 14 节）：不进术语表 Desk 就显示英文，维持拦截，补词条。业务角色或 All 可读的 Cowork DocType（第 11 节）同样维持。
- R-TALK「这个 / 这些 / 这条」：Frappe 官方中文用「此 / 所选 / 该」，维持拦截，按第 5 节改文案。
- LINE 快捷按钮 R-LINE20：`BTN_REMOVE_SLIP` 真超长且在用，维持；`BTN_RETRY_BOOKING` 已无引用，删行。
