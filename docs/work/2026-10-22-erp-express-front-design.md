# ERP 当前台、Express 当账本：接入 CC 的架构研究（2026-10-22）

分支 `pearnly/erp-express-front`，基线 `9e4772fd`（= origin/main）。本记录只做研究与方案，**没有改任何代码**。
来由：岳父 10-16 提出的新需求（当时定「ERP 的 CC 先不大做」）；多电脑规则见 [ADR-021](../adr/0021-cc-desktop-multiple-computers.md) 与 10-16 拍板。

## 1. 需求（岳父原话整理，10-20 / 10-22）

- 外地人员用手机上的 Pearnly ERP 开**销售、采购、领料用于生产**；单据写进办公室那台电脑上的 Express 的对应菜单。
- ERP 是轻前台，Express 是唯一账本。Express 的主档回读到 ERP，让两边一致。
- 已回答的问题：
  - **库存不够也照开**，不拦。
  - **单号用 Express 的**。流程照 DMS 预订：先给用户看确认页 → 写进 Express → 回传 Express 单号和实际写入的内容。
- 还没回答的问题：领料单的具体内容；外地开的单要不要当场打印或发给客户。
- 用户口径（10-22）：不针对某一家公司，按事务所 S 盘真账的惯例来设计。

### 2.2 领料（OU）的惯例

- OU 是 Express 里**独立的一类库存单据**，表头存 `STTRN`，明细存 `STCRD`（POSOPR = `6`），**不进** ARTRN / APTRN。
- 10,989 张领料单在总账表 GLJNL 里都找不到同号分录：总账靠 STTRN.POSTGL 由 Express 另外过账。具体机制写入前要再核，见 6.4。
- **单据簿决定科目。** 每份账套有多本 OU 单据簿，借方科目写在单据簿 ISRUN.ACCNUM01 上。标准簿有：
  - 内部领用（OU）
  - **领原料去生产**（PD，借在制品 11-04-03-00）
  - 领样品（XS）
  - 报废（ZZ）

  很多公司还会自建按物料分的簿，比如汽油、氨水、润滑油各一本。所以领料时**选的是单据簿**，不是科目。
- 每张单的行数差别很大：从 1 行到平均 145 行都有。不少公司是月底汇总领一张（单号形如 `DD671231-001`），也有逐笔领的。
- 领的都是库存品（STKTYP = 0）。明细行上的部门：领原料去生产几乎不填，内部领用填了 34%。

## 3. 现状：哪些能复用，哪些缺

代码勘察结论（两路只读勘察，文件与行号以勘察时的 `9e4772fd` 为准）：

- **Cowork 的推送已经是完整的一条链**：
  - 服务端先建 prepared，确认后转 pending（`pearnly_cowork/push/application/service.py:83`、`push/native/service.py:528`）；
  - 电脑按租约领任务、发心跳、回执（`companion/queue_api.py`、`transport.py`）；
  - 按电脑派发（`route_contracts.py`）、按账套加写者锁、最多重试 3 次、回执写单号与核对结果（`native/service.py:839/890`）；
  - CC 写 RR / HP / IV / HS，含库存行、单号分配、失败整单回滚、本机幂等（`companion/src/companion/worker.py:200`、`dbf_writer.py:133`）；
  - 主档上报商品、客户、供应商、部门、科目（`catalog_probe.py:278`），存在 `Cowork Express Account Facts`。
- **写死在 Cowork 里的部分**：
  - 推送记录绑定识别记录：`ReservationContext.history`、`document_identity`、`push_state.mirror` 写回 `Cowork OCR History`；
  - 载荷以识别结果为输入（`push/express/mapper.py`、`sales_mapper.py`）；
  - 机器接口地址都在 `pearnly_cowork.companion.*`。
- **完全没有的部分**：
  - 领料（OU）写入；
  - 仓库：写入写死 `STCRD_DEFAULT_LOCCOD = "01"`，主档里也没有仓库；
  - 库存余量回读；
  - 明细行的部门；
  - 写入前给用户看逐项内容的通用确认页（只有 DMS 预订有一套，没有抽出来）。
- **ERP**（`apps/pearnly_erp_portal`，自建 DocType，不装 ERPNext 业务）：
  - 销售 `ERP Sales Document` 只有 receipt / quotation；
  - 采购 `Purchase Document`；
  - 出入库 `ERP Stock Entry` 的用途有 `return|internal_use|damage|other`，没有「领料去生产」；
  - ERP 自己记库存账：`ERP Stock Movement / Balance`，由 `inventory/stock.py:93/188` 写入；
  - 客户、商品是全租户共用，没有 company 字段；没有部门主档；
  - 与 CC / Express 没有任何连接，`erp_push` 是空占位（`features.json:160`）；
  - `integrations/__init__.py:6` 早就写明「端点与推送账本在 Cowork，ERP 只做投影」。

## 4. 架构方案

### 4.1 选型：Cowork 当「账本网关」（推荐）

```
手机 ERP ──(1) 单据草稿──▶ ERP 站点 ──(2) 服务端调用──▶ Cowork 站点（事务所工作空间）
                                                   │ 推送账本 / 队列 / 派发 / 写者锁 / 回读
                                                   ▼
                                       办公室电脑 CC 桌面版 ──写入──▶ Express 账套
                                                   │
           ◀──(4) 单号与写入内容、主档、库存快照────────┘(3) 回执与主档上报
```

- ERP 不自己做设备接口和队列，把单据交给对应事务所工作空间的 Cowork 推送账本。Cowork 原样复用派发、租约、重试、写者锁和回读。
- ERP 只保存三样东西：自己的单据、推送状态的投影、主档与库存的镜像。这与 `integrations/__init__.py` 早就定下的「ERP 只做投影」一致，也和用户「沿用推送、改造更小」的想法一致。
- 场景上也对得上：Express、CC 桌面版和所有账套本来就在事务所，外地开单的人是客户公司的员工，自己没有 CC。

**不选的两个方案：**

- **把整条推送链下沉到 `pearnly_core`**，Cowork 和 ERP 各接一个来源。这在结构上最干净，但要搬推送账本、DocType，还有 CC 写死的机器接口地址，而这些地址有契约测试守着。改动大，还会碰到 Cowork 正在线上跑的写账链路。以后出现「没有事务所、自己有 Express 的独立公司」这类需求时再考虑。
- **ERP 站点也装 Cowork**：违反「各产品只装自己的 App」的口径。

### 4.2 需要新增的连接：ERP 公司 ↔ 工作空间 ↔ 账套

- 在 `ERP Company` 上绑定：Cowork 工作空间、公司身份（按税号 `tax:{税号}`，加分店号）。
- 账套不在 ERP 里写死。沿用 Cowork 的「按单据日期选当前账套」（`current_book.pick`），同期有两份账套时也沿用「问一次、记住复用」。
- 两个站点之间用服务账号调用，带单据级幂等号（ERP 单据名 + 版本）。Cowork 侧新增一种推送来源 `erp_document`，**不经过识别记录**。为此 `document_identity` 和状态回写要从「识别记录」放宽为「来源 + 来源单据」。这是 Cowork 侧唯一的结构性改动。
- 新增 Cowork 内部域依赖时，先登记到 `architecture-policy.json`。

### 4.3 派发：哪台电脑写

- 外地人员没有电脑，按 10-16 记下的口径：**由服务这份账套的办公室电脑写**，与定时任务「由读那个文件夹的电脑做」同一套判定。
- 电脑都没开就排队，开机后自动接着写。ERP 显示「CC 桌面版未连接」（现有文案），单号暂时为空。

### 4.4 单据流程（照 DMS 预订）

1. 手机填单，从镜像主档里选客户、商品、仓库、部门、单据簿。
2. **确认页**：列出要写进 Express 的逐项内容，包括 Express 编码、单位、仓库、部门、单据类型和单据簿、金额。
3. 确认后交给 Cowork，状态为「排队 / 写入中」。
4. CC 写入，回执带回 Express 单号；按单号回读，逐项比对。
5. ERP 单据显示 Express 单号和回读到的写入内容。比对不一致就显示差异，不标完成。状态口径遵守 `docs/p1/05-control-api-and-events.md` 第五节：HTTP 200 不算写入。

### 4.5 主档与库存：Express → ERP 单向镜像

| 数据 | 来源 | ERP 落点 |
|---|---|---|
| 客户 ARMAS / 供应商 APMAS | 现有上报 | `ERP Customer / Supplier`，加 来源账套 + Express 编码，镜像字段只读 |
| 商品 STMAS（单位、换算、售价 SELLPR1–5、是否库存品） | 现有上报，需补单位与价格 | `ERP Product` 同上 |
| 仓库 | **新增**：仓库代码表，加 STLOC 出现过的仓库 | `ERP Warehouse` |
| 部门 ISTAB(50) | 现有上报 | ERP 新增部门主档或选择项 |
| OU 单据簿 ISRUN | **新增** | 领料单上的「领料类别」 |
| 库存余量 STLOC.LOCBAL | **新增**，按仓库读 | 只读快照 |

- ERP 现在的客户、商品是全租户共用，而 Express 是每份账套一套主档。镜像行要按「来源账套」分开，不能并成一条。
- 手机上显示的库存 = 最近一次回读的 Express 结存 − 已确认但还没写进去的单。
- **绑定了 Express 的公司，ERP 不再自己记库存账**：不调 `stock.apply_lines`；ERP 本地的出入库和盘点对这些公司关掉，或者只出草稿。这是由「这家公司有没有绑定账本」这条数据决定的，不是按租户的功能开关。
- 外地遇到新客户、新商品：**建议只在 Express 建**，同步过来再用。从手机建会带来重名、重复建档，还会和 Express 的建档规则冲突。待用户定，见第 7 节。

| ERP 单据 | Express | CC 现状 |
|---|---|---|
| 销售（要新增「现销 / 赊销」选择） | HS / IV | 已能写；需补仓库、明细行部门、多单位 |

## 5. CC 桌面版要扩的部分

1. **仓库**：去掉写死的 `"01"`；按单据或行写 LOCCOD，同步更新 STLOC 的结存。
2. **明细行部门**：写 STCRD.DEPCOD。
3. **多单位**：写 TQUCOD 和换算系数 TFACTOR，结存按基本单位算。
4. **领料写入器**：
   - 从 ISRUN 的 OU 簿取前缀和借方科目，分配单号；
   - 写 STTRN 表头，POSTGL 照 Express 自己的习惯填；
   - 写 STCRD 明细，扣 STLOC、STMAS 结存；
   - 写完回读核对，失败整单回滚，与现有写入器同一套结构。
5. **新增上报**：仓库、OU 单据簿、按仓库的结存（走现有的增量上报或按需请求 `express_read`）。
6. **负库存**：照账套自己的设置。账套允许（多数）就照写；账套不允许、库存又不够时的处理方式待用户定，见第 7 节。

## 6. 风险与写入前必须先核的事

1. **领料单的金样本。** 先在测试机 C 盘的 T 账套里用 Express 本体手录一张领料单（领原料去生产），对照 STTRN / STCRD / STLOC / STMAS / GLJNL 的变化，照着写，不凭推测。C 盘可以自由写，见用户 10-15 的授权。
2. **STTRN 表头的真实填法。** 语料副本里没有 STTRN，C 盘测试账套的凭证已经清空。要从 S 盘真账**只读**统计表头（部门、备注、POSTGL）。用户 10-22 说过「学习 S 盘怎么录」，照只读规矩做。
3. **总账怎么过。** OU 单据在 GLJNL 里没有同号分录，要弄清 Express 是在月结时过账，还是靠 POSTGL 批量过，避免 CC 写进去之后总账漏掉或重复。
4. **成本法。** 128 份账套 `COSMTD = F`，30 份是 `A`。CC 现在的库存出库（`stock_sale.py`）按**移动均价**结转成本，负结存时按标准成本。`F` 是否代表先进先出、Express 会不会自己重算成本，都要用金样本核实。这同样影响 Cowork 线上已有的库存销售写入，应该单独核。
5. **ERP 的库存账切换。** 绑定账本的公司要关掉 ERP 自己的库存过账，POS、销售确认、采购入库都会受影响。按「改脚本加载方式要逐产品点页」的教训，要逐页回归。

## 7. 要用户定的事

1. 架构是否按 4.1：Cowork 当账本网关，ERP 只做前台和投影。
2. 账套设为**不允许负库存**、库存又不够时：照账套规则不写入并提示（推荐，与 Express 自己的行为一致），还是一律照写？
3. 领料之外，要不要一起做**生产完工入库**（JU / PI）？
4. 外地遇到新客户、新商品：只在 Express 建（推荐），还是允许手机上建？
5. 岳父还没回答的两条：领料单的具体内容；外地开的单要不要当场打印或发给客户。

## 8. 施工顺序（按依赖，不排日期）

1. Cowork：推送来源放宽成「来源 + 来源单据」，新增 `erp_document` 来源与站点间服务调用；派发沿用「服务该账套的电脑」。
2. CC 与服务端：上报仓库、OU 单据簿、按仓库结存；ERP 侧建主档与库存镜像，以及公司与工作空间的绑定。
3. CC：仓库、明细行部门、多单位扩展，并跑 62 套离线回归。
4. ERP：销售（HS / IV）、采购（HP / RR）、确认页、推送状态投影，然后在测试环境走真实写入。
5. 领料：先做金样本和 STTRN 只读统计，再写写入器和 ERP 领料单；完工入库视第 7 节第 3 条决定。
6. ERP 绑定账本的公司切换库存权威，逐页回归。
7. 验证：测试机 C 盘 T 账套写入，回读比对；testerp / testcowork 实时源码试用；用户试用通过后，再按主线集成和部署规矩上线。
