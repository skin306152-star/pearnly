## 0. 需求原文与理解

- **原话**：岳父 10-28 21:16 在 LINE 按菜单重排清单，定「ทำเมนูตรวจนับสินค้าให้สมบูรณ์ก่อน」（先把盘点菜单做完整）。主会话 10-29 转述三条：
  ① 显示扫到的商品编码；② 盘点中可新建商品编码（店里有、系统没有的货当场新建，标注来由，即多仓闭环定的「就地新建」）；
  ③ 盘点进行中就能打印盘点报表核对，可选全部 / 未盘 / 有差异 / 按仓库 / 按库位，加 10-26 定的按筛选导出 Excel / PDF。
  一并评估：库位加「名称说明」栏；仓库改成「仓库编号 + 仓库名称」两栏（岳父选乙）；收货、发货页显示商品内部编码。
- **已定方向（主会话 10-29，写进本评估）**：
  1. 一套通用界面，按公司设定显示。公司档案加「公司类型」（普通 / 汽车 / 手机电器…）和「接不接 Express」：不勾就是普通 ERP；
     勾了未连上只显示连接引导；连上才出推送 / 同步；已连上的要先断开才能取消。用户按所选公司走规则。
  2. 按台管理不拆，只对相应类型的公司显示；普通公司下按台标志一律不理会，不改客户数据。
  3. 批次 / 有效期删掉。
  4. 已连 Express 的公司自动设为「接 Express」，类型默认普通。
- **我的理解**：店里员工在 ERP Desk（电脑 / 手机窄屏）或 LINE 手机盘点页按仓库盘点：扫码后看见商品编码；扫到系统没有的货当场建商品继续数；
  盘点没结束就能按筛选打出核对表、导出 Excel / PDF。公司设定决定盘点里出不出按台、出不出 Express。
- **不在本需求范围**：调拨（多仓 P2）、盘点范围（按库位 / 分类部分盘，P3 的 G8）、成员按仓权限、Cowork 盘点（独立一套，见 4 节）、
  库存一览跨仓合计（P4）。收货单 / 采购入库以外的单据改版不做。

## 2. Frappe 原生能力

- **报表**：差异报表本来就是原生 Script Report（query-report），加筛选用原生 `filters`（Link 到 ERP Warehouse、库位用 Autocomplete / Data），
  导出 Excel 用原生报表导出或 `p.export_file`（10-26 定），PDF 用打印第二批的盘点结果 Print Format，按同一份筛选取数。
- **字段**：公司类型用 Select，接 Express 用 Check；库位说明、仓库编号用 Data；商品来由用 Select + Dynamic Link（同多仓评估）。
- **序列号 / 批号**：Frappe 本身不带 ERPNext 的批号 / 序列号（本仓不装 ERPNext）；按台是本仓自有（`ERP Serial No`），不换成原生。
- **结论**：全部用原生 Page / Dialog / FieldGroup / Script Report / Print Format / 字段类型；不新增自定义样式。

## 3. 按类通用

- **「按公司设定显示」是全站一类**：凡是会出按台、出 Express 的入口都要走两个统一开关，不在单个页面里各判各的：
  - 按台：盘点（Desk / LINE / Excel 导入 / 差异报表 / 打印）、采购 / 销售 / 出入库提交时登记或选台（`p.serials.collect`）、收银台选台、
    开账按台期初、商品页「按台管理」开关与「按台记录」、出入库调整接口。
  - Express：单据列表 Express 列、详情「Express」按钮与提交前预检、公司页同步、仓库页「新建」限制、开账限制、收银日汇总、盘点 TK。
- **「显示内部编码」一类**：入库、出库（收发货）页和它们的打印；同类的采购 / 销售明细、收银小票本次**不改**（需求只点了收发货，
  要不要一起放见 12 节问题）。
- **「库位 / 仓库显示」一类**：所有出现仓库、库位选择的地方（单头控件 `p.place`、明细、盘点、开账、库存一览、库存卡、打印）
  统一显示「编号 · 名称」和「库位 · 说明」，用同一个格式函数，不逐页拼。

## 4. 上下游数据

- **ERP 单据流**：
  - 就地新建的商品是正式主档，之后采购 / 销售 / 收银照常用；盘点过账生成 AD 调整单（现有），新商品的盘盈按「成本未知」或现场填的参考成本入账（已定口径）。
  - 仓库编号、库位说明只是主档属性，不进库存流水的键（键仍是商品 + 仓 + 库位名），改说明 / 编号不影响收发存与历史单据。
  - 公司类型从汽车改成普通：按台记录保留不动，只是不再出现、不再要求选台；改回汽车恢复。普通公司下按台商品按普通商品走数量。
- **Express 映射**：
  - 仓库编号：接 Express 的公司 = Express 仓库码（ISTAB TABTYP 21，主档同步写，只读）；未接 Express 的公司由人填。
  - 库位：Express 没有库位概念（LOCCOD 是仓库），不写 Express。
  - 就地新建商品在接 Express 的公司：盘点过账写 TK 时遇到新商品，现状 CC 整单停 `STOCK_ITEM_NOT_FOUND`；要按多仓评估 13.2-7（G14，P3x）让 CC 在 TK 里建 STMAS 并回填编码，
    或在过账前停下交人。**这一项要 CC 新版本**，建议与本批分开：本批先做到「接 Express 公司里新建的商品，过账写 TK 前停在人工」，CC 版本再放开。
  - 「接 Express」开关：不勾 = `push.linked()` 一律假，不推送、不同步、不预检；已连上（有账套、已同步过）的公司服务端拒绝取消，要先「断开」（断开的定义见 12 节）。
- **CC 桌面版**：本批不改载荷（不写 RL、不在 TK 建档）；接 Express 公司的新商品先停人工。若 12 节定要在本批放开 TK 建档，则升载荷版本、CC 发新版。
- **Cowork / DMS**：Cowork 盘点是独立一套（4 个自有 DocType，从上传表建任务，不查主档），本需求是 ERP 盘点；Cowork 不跟（岳父用的是 ERP）。
  公司设定只在 ERP。DMS 不涉及。

## 5. 隔离与权限

- **服务端拦**：
  - 就地新建：`count.write` 即可（多仓评估已定），只能建在当前盘点所属公司（`count_company`），码查重只在本公司可见范围（不跨公司提示码）。
  - 公司类型、接 Express：`company.manage`；取消「接 Express」在服务端核「已连上」就拒。
  - 报表 / 打印 / 导出：沿用盘点读权限 `count.read` 与「盘点所属公司」核；进行中打印账面数是否给只有 `count.write`（盘点员）的人看，见 12 节。
  - 仓库编号：接 Express 的公司只读（服务端拒改）；同一公司内不重复。
- **不串**：差异报表现有一处要顺手修——不带盘点号时取「最新一份盘点」没按公司过滤（多仓评估 13.4 记过），加筛选时一起按当前公司限定。

## 11. 测试与验收

### 单元 / 离线
- 按公司开关：普通公司 `serials.tracked` 一律空、盘点 `lookup_count` 不回按台、出入库 / 采购 / 销售不要求选台；汽车公司照旧。
- 接 Express：不勾 → `push.linked` 假；勾了未连上 → 假且公司页给引导；已连上取消 → 服务端拒；补丁把已连 Express（有 `express_book`）的公司设为勾选、类型普通。
- 就地新建：权限（`count.write` 可、无权拒）、撞号、停用码认出、同码并发合并、与盘点同一事务、不跨公司提示码（照多仓评估 11 节）。
- 报表 / 打印 / 导出：进行中可开；仓库 / 库位筛选真的生效；打印与 Excel 行数与报表一致。
- 批次 / 有效期：页面不出现；接口传了也不写。

### 实验栈两套固定数据（生产镜像底座 + 被测分支）
**新开户**（照 polymer）：一家公司 7 个仓、零库存；商品有 Express 同步来的（只有内部编码 / 二维码内容）、本地建的、一件勾了按台的；公司类型普通。
1. 二号仓建库位清单 A1「前排货架」、A2；仓库编号填 W01–W07 → 单头仓库控件、库位选择显示「编号 · 名称」「库位 · 说明」。
2. 建盘点（二号仓）→ Desk 扫本地商品条码：弹窗显示编码；扫 Express 商品内部编码：认出、显示内部编码。
3. 扫一个不存在的码 → 当场建商品「Y」（码 = 扫到的码）记 3；LINE 手机页同时扫同一码 → 认到同一个 Y、各记一条合并；商品 Y 来由「盘点新建 · 盘点号 · 谁 · 何时」。
4. 盘点进行中：打印选「有差异」+ 二号仓 + A1 → 只印这些行；导出 Excel 行数相同；PDF 同。
5. 普通公司扫勾了按台的商品 → 不要求选台、按数量记；差异报表无「没盘到的台」列。
6. 过账：盘盈入二号仓 A1；Y 成本未知列入体检；库存数断言。
7. 入库 / 出库页：明细与打印显示内部编码。
8. 把公司类型改成汽车 → 同一按台商品要求选台；改回普通 → 不要求，按台记录不变。
9. 「接 Express」不勾 → 采购单列表无 Express 列、提交无预检；勾上未连 → 只出连接引导。

**老数据**（照 mrerp / testerp）：多公司、有存量、有进行中的盘点（照 polymer 4 份进行中）、商品勾了批次 / 有效期、一家已连 Express（有 `express_book`）。

3. 勾了批次 / 有效期的商品：商品页不出这两个开关，采购单不出批号 / 失效日期；旧数据不丢。
4. 已连 Express 的公司取消「接 Express」→ 拒（要先断开）；仓库编号为 Express 仓库码、只读。

6. 半开户与刚开户站点各跑一次完整迁移（迁移钩子修复合入后）。

- **验收复核**：验收窗口按上面两套数据逐项点 + 连带入口；用户 / 岳父亲自看：就地新建（Desk 与 LINE）、进行中打印核对、公司类型切换。

## 旁见（不在本需求范围）

- 生产 gize：ERP 公司 1 家、**仓库 0 个**（10-29 只读统计）。原因（只读查代码）：开户时 `pearnly_tenant_ready` 走 `masters/company.ensure_default()`（096d2ba8 加），它只建一条空的默认公司，**不建仓**；只有「新建公司」表单（`create_company` → `_create_warehouses`）和 Express 主档同步（`express/companies.py`）才保证「这家公司至少有一个仓」。所以所有走开户自动建公司、还没手工建仓的新租户都是 0 个仓。修法（另排，不在本需求）：`ensure_default` 新建公司时同样调 `warehouses.ensure_for_company(name)`，并补一个补丁给已有的 0 仓公司建 `Main`。
