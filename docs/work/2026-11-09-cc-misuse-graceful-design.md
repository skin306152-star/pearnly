## 给用户看的要点

- **识别完先复核**：直写、代录都一样，识别完出一张复核卡，一批票一张，能看到每张的对方、单号、日期、金额、明细，有问题的格子直接标出来；
  可以就地改，要人定的客户 / 付款 / 仓库 / 物料也在这张卡里一起答；点「开始」（或在对话里说「录吧」）才录入，没确定的不写。
- **同一张票只认一个**：PDF、截图、直写、代录都认作同一张，已经入账的默认不再写，卡里标出 Express 单号。
- **一件事只问一次**：同类问题合成一题、带推荐，按税号 + 分店记住，下次不再问；全部用客户的语言。
- **状态说清楚**：录完一批接一张汇总；放久了的旧任务、旧卡片自动作废；会计每天能看到「已写 / 跳过 / 可疑」清单。
- **我们自己看得见**：页面出错自动报给我们，乱用的样子都进上线前的测试。

## 总原则（每条设计都要满足）

1. **账不靠用户用对来保证**：底线在业务功能层（服务端）守，界面和模型说法只是让人看得懂。
2. **不拦、只标、默认跳过重复**：Express / MR.ERP 不拦的我们不拦（记忆 `express-no-block-no-block`）；用户主动推 Express 里已有同号的（会计手录）照写不变
   （记忆 `push-never-block-duplicates`）。唯一的「默认不写」是：**我们自己已经写成功过的同一张票**（用户 11-08 定），人可以勾回再写。
3. **两个模式分开、各自干完**：直写、代录两个界面不融合；每个模式只拿自己的工具；CC 不提另一种模式、不叫用户换模式（11-08 用户纠正）。
4. **识别后必须复核，除此不加确认步骤、不加说明文案**：CC 入口识别完一律先出复核卡、人确定才写（用户 11-09，见第 0 层，覆盖 10-02 在 CC 入口的口径）；复核卡就是唯一的一步，问题也放在里面，不再另加「你确定吗」；其余用状态、图标、灰掉、计数表达；新增文案四语、官方简短。
5. **按类修**：一处出过的形状，全部入口（网页 / 手机 / CC 桌面版、Cowork / ERP、直写 / 代录、LINE / 文件夹）同一套规则，加机器检查防再犯。

## 第 0 层　识别后复核（用户 11-09 硬要求）

用户原话：「不管是 cowork/erp 的直写还是代录，识别完必须要有一个步骤，识别后的复核，就识别完后把识别结果展示出来，用户确定或者有什么动作后即可录入
或者用户可以在线修改确定后录入……修改后确定才录入」。这条在 **CC 入口**上覆盖 10-02「录入口不加确认步骤 / 不加识别后提示」的口径
（记忆 `intake-no-post-ocr-hints`、`cowork-frontend-ui-rules`）；Cowork 网页录入工作台原有的复核页不在本次改动里。

### 0.1 一批一张复核卡，和要人定的问题放在同一处

- **情形**：11-08 代录里，资料步、开始卡、24 张提问卡、结尾汇总四处都在讲同一批票，人看不到识别出来的内容就被要求点「开始」；直写里每张截图识别完直接推送，岳父没机会看一眼，
  IV/69/06751 就这样写进了真账。
- **反应**：识别完，对话里出**一张复核卡**，这一批所有票都在里面（不是一张票一张卡），从上到下：
  1. **要人定的问题**：客户 / 供应商、付款、仓库、物料，同一类合成一题，标明管几张，带推荐（第 3 层）。已记住的不出题。
  2. **票据表**：一行一张，列 = 勾选 · 单号 · 对方 · 日期 · 合计 · 标记。点一行展开这张票的全部内容（0.2）。
  3. 底部一个主按钮「开始」（沿用开始卡现有词条，两模式同一个），按钮上带张数（「开始 · 20」）。
  - 已入账的同一张票（第 1 层）默认不勾，行上写「已入账 · IV69/00751」，勾回就是「再写一次」。
  - 一段对话同时只有**一张没确定的复核卡**：卡还没确定时用户又发来截图 / 文件，新识别的票**并进这张卡**（卡刷新、计数变），不另起一张；
    逐页截图（2.1）因此自然合成一批。
  - CC 只说一句「识别了 24 张，请在卡里核对后开始」这一类的话（模型说，不是界面文案）；不复述票面内容。
- **兜底**：没确定的票服务端不写（0.4）。卡和问题在一处，答题与核对一次办完，不是两道关。
- **落点**：工具层共用 `pearnly_core.write_precheck`：现在的写账前确认卡（`pearnly_precheck`）扩成复核卡，内容 = 预检的问题与预选（已有）+ 票面与标记（新）；
  执行方式层代录的开始卡（`express_operator`，`operator-start.tsx`）与直写共用这张卡，代录多出的只是「开始后交给电脑」；
  产品只在 `write_precheck.products` 声明「票面字段怎么读、怎么存、改了怎么校验」（Cowork：识别记录 `pages`；ERP：收单记录）。前端新组件放
  `frontend/assistant/src/components/tool-uis/`（复核卡），复用通用提问卡的题目部分（`ask-shared`）。
- **与 CC 一套**：开始卡一次问完（B2）、同题合卡（B3）、任务行「单号 · 对方」（`711f3c019`）、已入账组（`1fc6bb41f`）、开始卡不回填（`367231732`）**都是这张卡的一部分，保留**；
  新增的是票面展示、就地修改、直写也走这张卡、服务端「没确定不写」。

### 0.2 卡里展示什么、标出什么

- **每张票展开后**：对方（名称 + 税号 + 分店）、单号、开票日期、未税 / 税额 / 合计、明细行（品名、数量、单价、金额；ERP 多一列对应的物料，Cowork 进项多「货品 / 费用」）、
  原件缩略图（点开看原件，用现有原件层）。
- **直接标在格上的标记**（复核场合就该让人看到，不受「不加提示」限制；格子标色 + 图标，行上的「标记」列写最短的词）：
  - 单号：写法与这个对方以往不同（IV/69/06751 vs IV69/007xx）、识别出两种读法、像 Express 凭证号；
  - 重复：已入账（第 1 层精确）、和另一张很像（第 1 层近似）；
  - 税号：位数 / 校验位不对；金额：未税 + 税额 ≠ 合计、税额与 7% 对不上、明细合计 ≠ 未税；
  - 日期：不在当前账期、未来日期；
  - 要人定：这张票缺哪一题（和顶部问题联动，答了就消）。
  标记来源复用已有的「复核原因」：Cowork 识别入库时已经算好存着（`pearnly_cowork.history.review`：税号位数 / 校验位、金额算不平、明细合计、凭证号、单号写法、两种读法、疑似重复，
  10-02 起只作内部信号、不显示）；ERP 用 `recognition/checks.py` 的 `marks`。共用层定一份标记码，两产品各自映射，前端只认码、四语显示。
- **24 张、100 张**：表格一页 20 行，原生翻页；顶部三个筛选「全部 / 有标记 / 要人定」，默认「有标记」在前（没有就全部）；行按「要人定 → 有标记 → 其余」排；
  展开一次只开一行。行数据走服务端分页（`limit_start` / `limit_page_length`，记忆 `frappe-native-first-by-category`），卡片不一次取 100 张全部票面。
- **手机**：同一组件；表格收成两行一格（第一行「单号 · 对方」、第二行「日期 · 合计 · 标记」），点开是竖排的字段；底部「开始」固定在卡底。
  CC 桌面版里的对话是同一套前端，同一组件。
- **四语**：列名、标记词、筛选词全部 th / zh / en / ja；不显示代码原值（3.4 的全量枚举检查把复核卡的标记码也包进去）。
- **不加说明性文案**：没有「请核对以下内容」这类话；标记只是格子标色 + 一个词，点格子看到的是那一格的原值与对照值（例「以往：IV69/00752」），不是解释句。

### 0.3 就地修改

- **能改的格**：对方（从 Express 主档里选，或改名称 / 税号 / 分店）、单号、日期、未税、税额、合计、明细行（品名、数量、单价、金额、对应物料、货品 / 费用）。
  不能改：原件、识别时间、已入账那张的 Express 单号。
- **怎么改**：点格子就地变成输入框（电脑回车 / 失焦即存，手机弹原生键盘，日期用原生日期控件）；存的是这张票的票面，**不是**只存在卡片里。
- **改了怎么校验**（服务端纯函数一份，前端同一份规则即时显示）：
  - 税号 13 位 + 校验位（`pearnly_core.tax_documents.amounts.valid_tax_id`）；分店 5 位；
  - 未税 + 税额 = 合计（到 0.01，`Decimal`）；税额 = 未税 × 7%（差 1 泰铢内算平，同已有 `review._AMOUNT_TOLERANCE`）；明细金额 = 数量 × 单价，明细合计 = 未税；
  - 日期是真日期，佛历年自动换公历；
  - 校验不过：格子标红、保留人填的值；**不拦「开始」**（Express 不拦的我们不拦），唯一例外是写不进 Express 的（日期不是日期、金额不是数字、单号空）——那一张不勾、行上标出，其余照录。
  - 改完立刻按新票面重算第 1 层身份（改了单号可能就认出已入账）和标记（改对了标记消失）。
- **留痕与以后用上**：
  - Cowork：沿用 `history.storage.update_pages`（带版本号防两处同时改）→ `ocr.feedback.service.capture_saved_edit`（已有：人改票面记成识别反馈）；
    ERP：收单记录改动同样留「谁、什么时候、哪一格、原值 → 新值」，形状照 Cowork 的识别反馈，**新增**（ERP 没核到同类）。
  - 用在：对方改成某个 Express 客户 → 按税号 + 分店记住（第 3 层，下次预选）；单号 / 金额被人改 → 进识别反馈，识别线怎么用它（例如同一对方的单号写法）按识别线现有做法，本文不扩展。
  - 两个人同时改同一张：后存的那个提示该行已变、重新载入这一行（版本号冲突，现有 `conflict()`）。
- **代录特有**：改的是这张票的票面，交给电脑时用的就是改后的值；CC 桌面版在 Express 里照改后的值录。

### 0.4 确定才录入

- **确定的方式**：① 卡底点「开始」；② 卡还开着时，用户在对话里说「录吧 / 确定 / ok」这一类，CC 调确认工具（模型理解这句话）。
- **兜底（服务端，不信页面、不信模型）**：
  - 每张票带「确认时的版本号」；直写推送（`assistant.direct_push`）和代录交单（`express_operator.tasks.submit`）只收**已确认且确认后没再改过**的票，其余回「待复核」状态与下一步，不写；
  - 用对话确认时，服务端只认**这张卡出现（或最后一次改动）之后**的用户消息触发的确认，CC 自己不能在没有用户新消息的情况下确认；
  - 确认后又改了某张 → 只有那一张回到「待复核」，其余照走；
  - 卡里没勾的票这次不写，状态仍是「未写」，留在卡里，下次可以再勾。
- **直写**：确定后按卡里勾选的票推送，推送结果接在卡后面（4.1 汇总），不回头改卡。
- **代录**：确定后交给电脑，任务卡接在后面显示「等电脑 / 录入中 n/N」。
- **过期**：复核卡也按 2.3 失效（7 天没动作，或新卡已包含同一张票），失效的卡灰掉、点不动。

### 0.5 不经 CC 对话的入口

- 用户 11-09 定（选 A）：**只做 CC 对话里的入口**。LINE 收票（已有卡片确认）和文件夹定时自动录入**不做复核**，保持现状；
  Cowork 网页录入工作台本来就有自己的复核页，也不在这次改动里。第 1 层「已入账默认跳过」照样覆盖这些入口。

## 第 1 层　同一张票的统一身份

### 1.1 票面身份键（一份规则，所有入口共用）

- **情形**：同一份 Big_C_ซอยประชุม_Oct.pdf，19:30 在代录里识别成 24 条识别单；20:39 起截成 4 张 JPG 在直写里又识别成 4 条新识别单。
  两边「不是同一条记录、互相不知道」（直写笔记第 3 行）。现有两套判重各管一段：识别入库的「完全重复 / 疑似重复」只比单号或「日期 + 卖方名 + 金额」、
  只比同一个用户自己的记录（`pearnly_cowork.history.duplicates`，只作提醒）；事故分支的「已入账」判定（`operator_source.written_twin`）比单号 + 买卖方税号 + 金额 + 同连接同账套，只在 Cowork 代录用。
- **反应**：用户看不到这一层；看到的是下面 1.2–1.4 的状态。
- **兜底**：身份键 =（方向，卖方税号，卖方分店，买方税号，买方分店，**规范化单号**，开票日期，含税总额）。
  - 规范化单号：去空格、斜杠、横线、点，全角转半角，转大写（`IV/69/00751`、`IV69-00751`、`iv69 00751` 是同一个）；
  - 金额用 `Decimal` 到 0.01；日期统一公历（佛历差 543 已在识别侧纠正）；
  - 税号缺（个人、境外）时退到「对方名称规范化 + 其余字段」，并降为「近似」（只标不跳，见 1.4）。
  - 范围：同一公司（Cowork 工作区 + 客户公司 / ERP 公司）、同一 Express 目标（连接 + 账套）；**不按用户分**（岳父和会计各传一份也是同一张）。
- **落点**：纯契约放共用层 `pearnly_core.express_rules.contracts`（新 `ticket_identity.py`，无 IO、无框架依赖；税号与分店规范化复用 `express_rules.push.choices` 已有的 `digits` / `branch5`）；产品声明取字段的函数

### 1.4 同一份 PDF 拆成截图能认出；近似的只标不跳

## 第 5 层　写账兜底

### 5.1 写前查重（默认跳过）

### 5.2 格式异常：标出、不拦、不默默写错

- **情形**：第 1 张写进真账的单号是 IV/69/06751，同一卖方其余都是 IV69/007xx。
- **反应**（主会话 11-09 定，用户 11-09 加「识别后复核」后调整）：不拦；先自动重读一次，仍异常的**在复核卡对应的格子上标出**（第 0.2 条）让人看、可就地改；人没改照样写，写了的进会计看的每日清单（异常码 `format_flag`）。批次汇总、CC 回复里不另加标签。三类：
  - **单号写法**：同一卖方 + 同一单据种类以往推送过的单号「形状」（前缀字母、分隔符、位数）不同；
  - **日期**：不在当前账期、或比同批其他票差得很远（佛历差 543 已在识别侧纠正，不属于这里）；
  - **金额**：含税总额与税前 + 税额对不上，或与这个对方以往同类票相差一个数量级。
- **兜底**：先当内部信号自动交识别重读一次（同 1.4，记忆 `intake-no-post-ocr-hints`）；重读改对了就什么都不记；仍异常才在复核卡上标出，人没改就写的在推送记录上记 `format_flag`，进 5.5 清单。不拦（记忆 `express-no-block-no-block`）。
- **落点**：推送前判定放共用 `express_rules.push`：已有的 `doc_sanity`（外币、贷项、古董 / 未来日期，命中转人工）不动，新判定**只标不转人工**，另放一个纯函数模块（例 `push/format_flags.py`），由 `preflight` 调；以往单号形状从本公司推送记录读（只读、限条数）；标记写在推送记录上（新字段，与已有 `verify_state` 并列）。写后核对已有 `written_check`（写入走样、挂错对方 → `written_mismatch`），本条管的是写之前票面本身的异常，两者不重叠。
- **估时**：写码 4 h + 机器 2 h（单测按三类；用 11-08 那 4 张做回放样本）。
- **与 CC 一套**：**新增**（事故第 8 条「单号格式异常要能被发现」列为还没做）。
