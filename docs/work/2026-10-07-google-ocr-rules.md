# 谷歌识别修复：非票据与随票附属页（2026-10-07）

分支 `pearnly/google-ocr-rules`，基线 `e543a645`（Claude 引擎撤回后的 main）。与 Claude 撤回一起统一部署，部署前要过金标闸门和并发闸门（3 租户 × 10 人）。

## 起因

独立金标（测试机 `C:\PearnlyStress\语料\金标-2026-10`，Opus 逐张定的金标，谷歌现行读法跑过一遍）：

| 项 | 现状 |
|---|---|
| 真票被拒 | 1 |
| 非票据被录 | 22（转账凭条 7、还款收据 6、预扣税凭证 4、作废票 4、其他 1、送货单 1）|
| 多出的票 | 27 |
| 印了的字段读错 | 27 / 1283（2.10%）|

## 用户口径（2026-10-07）

"规则不应该写死，无法判断有争议的能让用户做选择，降低容错率，也不希望额外增加成本。"确认的三类：

1. **系统能确定的写成规则**：同一文件里已有正式票（税票 / 简易税票 / 收据 / 贷项单）时，模型记成"其他"的附属页（单号相同、没有合计、开票方相同、没有开票方）不另算一张。
2. **各家口径不同的类别，选一次、记住**：转账凭条 / PromptPay、预扣税凭证 50 ทวิ、银行还款收据。识别只标类别；没选过的推送前停下，在复核页选"录入 / 不录入"，之后同类自动套用。
3. **单张拿不准的标疑点**：盖作废章、水电"通知 + 收据"同页里的通知联、报关单页。默认不推送，复核页"仍要录入"放行。

反例：写死"转账凭条不录"会把一张银行柜台地下水费收据（6700759，谷歌标成转账凭条）丢掉且无处救回。

## 做法

- 第 1 类：`ocr/validation/attachments.py`，接在识别收尾（`runner.run_invoice`）。零费用重放：多出 27 → 11，读错 2.10% → 1.87%，被拒、漏票不增。
- 第 2 类"记在哪"：Cowork 一个租户一个工作空间、不按公司隔离，口径记在工作空间上（整个租户一条）。选"不录入"后，以后同类在识别存档时按非发票处理，走现有非发票状态（列表、文件夹录入、对账都已支持），推送账本不加新状态。已存在的记录推送时显示"不录入"原因、不推。
- 第 3 类：推送准备最前面（Express / MR.ERP 共用）拦下，复核页"仍要录入"带放行标记重提。
- 识别标记：只改图片直读提示词（第 15 条 `document_flag`），同一次读取多一个字段，不加调用。文字层 PDF 的提示词有逐字对照测试，本轮不动；预扣税凭证在原文标题规则里照旧提前结束读取，只多打类别标记。

## 限制与待办

- 第 2 类按租户一条口径：代账公司同一租户下的不同客户不能各设一条（需要时再按账套细分）。
- 文件夹录入规则页本轮不加口径预设（属文件夹录入窗口）；没选过时文件夹推送停在"要选一次"，到网页选一次即可。
- 文字层 PDF 不出还款收据 / 作废 / 通知联标记。
