# agent-desktop 调研（Vercel Labs 开源「读无障碍树操作桌面程序」工具）

- 日期：2026-11-08；主会话 local_e395dace 派；只调研，不改产品代码。
- 基线：本仓 `ae387515b`；agent-desktop 官方仓库 `vercel-labs/agent-desktop` 主干 `b43ac4f6`（v1.2.0，2026-11-05 发布）。
- 用户原话：「我昨天看到这个，感觉对我们很有用，派个窗口认真调研下这块业务」。

## 一句话结论

**不把 agent-desktop 放进 CC 桌面版，也不拿它换掉现在的代录做法。** 它唯一可借鉴的做法（给 AI 一张带编号的控件清单，让 AI 不用鼠标也能按按钮、填格）
**暂不做**：查了记录，AI 接手「点不了」只真实发生过 1 次，而且那次换成能点也解决不了（§5.1）；复议条件是代录实测出现认不出画面且卡住。
原因三条：① 它宣传的「不动鼠标、不抢前台」我们的 Express 代录 10-26 起就做到了，而且做得比它更多（后台打字、按回车走格、锁屏照录，
它在 Windows 上这三样都做不到）；② 它在 Windows 上后台只会「点按钮 / 直接改值」，Express 录单离不开的「打字后按回车让 Express 自己查对方、
算金额」必须把窗口切到前台，正好是我们要避免的；③ Windows 版 10-28 才出 1.0，官方文档自己写着 Windows 部分「没有实际跑过」，
还有「后台操作会把窗口激活到前台」等未修问题。MR.ERP 是网页，它在网页上反而比我们定的做法粗；开发测试可以当测试机上的辅助工具，但不必须。

**测试机实测（11-08，§4）印证了上面三条**：它后台「设值 / 点按钮 / 勾选」3 次都把后面的窗口激活到了最前面（我们的做法 0 次）；
后台打字、按回车都被它自己拒绝（提示要加 `--headed` 把窗口拉到前面）；读 Express 读到的东西和我们 Win32 读到的一样
（输入格没有名字，默认输出也不带位置，没法和标签对上；我们 Win32 已经按位置配好了），单据窗口工具栏 28 个按钮**全都没有名字**
（我们按命令号找），明细 / 公司列表表格（`MFCGridCtrl`）**它连表头都读不到**；菜单它只读到第一层，我们读整棵菜单树带命令号。

## 1. 我们现在怎么做（从代码和记录读的）

### 1.1 Express 代录

| 项 | 现状 | 出处 |
|---|---|---|
| 执行方式 | **后台做法**：只用 ctypes 直接给 Express 的窗口发 Windows 消息，不碰真键盘鼠标、不把 Express 拉到前面、锁屏照录；不引 pywinauto 等 | ADR-026 决定第 3 条；`companion/src/companion/express_operator/bg_desk.py` 文件头 |
| 打字 | 给焦点格发字符消息；泰文先把 Express 界面线程切到泰文输入法（否则成「?」） | `bg_desk.py` 文件头（10-28 测试机） |
| 回车走格 | 给焦点格投递按键消息，走 Express 自己的消息循环（Express 靠回车触发查对方、带出单价等） | 同上 |
| 菜单 | 读菜单树按编号 / 文字找命令号，发命令消息；不按位置数（单据窗口最大化时会开错单） | `menu.py`；评估 §15 |
| 按钮 / 工具栏 | 工具栏按命令号问亮不亮、发命令；弹窗按钮发点击消息 | `win32_desk.py` 文件头 |
| 读界面 | Win32 枚举子窗口：Express 是 MFC 程序，输入格是标准 `Edit` / `ComboBox`，标签 `Static`，明细表 `MFCGridCtrl`，工具栏 `ToolbarWindow32` | `win32_desk.py:674` `fields()`、`:818` `grid_click()` |
| 明细表格 | `MFCGridCtrl` **读不到行**；进格只能给表格控件投递鼠标按下 / 抬起（按表格内坐标，不动真鼠标） | 配方 `recipes/express-1.0.1.94.json` 公司列表说明；`win32_desk.py:818` |
| 核对 | 存档后读 DBF 逐字段核对 | 评估 §15、`book.py` |
| 认不出的画面 | 截图（`PrintWindow` 只画 Express，被挡也能截）交 AI 接手；**后台做法下 AI 不能用鼠标**，只能按键 / 打字 / 开菜单 / 截图 | `helper.py:65` `CU_BACKGROUND`；提交 cd9f8efa3、e16f50bcc |
| 有人在用 | 后台做法只有「人把这一批的 Express 切到最前面又在动键盘鼠标」才暂停；用别的程序、锁屏都不停 | `presence.py` 文件头；评估 §14 |
| 速度 | 后台做法每张 **10–11.6 秒**（其中约 6–7 秒是 Express 自己处理）；有人在用别的程序时 8.6–10.9 秒，Express 没被拉到前面 | 评估 §15 实测表（rec-laptop，服务器版 69EXP） |

所以「等电脑空闲」在 Express 后台做法里**已经不是「人在用电脑就等」**，而是「人正好在操作这一批的 Express」才停。界面上的
「等电脑空闲」是另一回事：任务派给的那台电脑还没领单（`queued`，ADR-021「谁的活谁的电脑做」，电脑关了就排队）
（`docs/work/2026-11-04-cc-code-style.md` E7）。这两件都不是 agent-desktop 能改变的。

### 1.2 MR.ERP 代录

ADR-026 已定：用 CC 自带的网页内核（QtWebEngine）开一个 CC 自己的独立窗口，在隔离脚本环境里填格、触发页面自己的事件、点按钮、读回；
窗口默认收起、锁屏照录。**不用** Edge 调试协议、Playwright、服务器浏览器（体积、轻量）。第 2 步（CC 端执行层）还没做：
`host.py:464` `ASSEMBLERS` 只有 Express。

## 2. agent-desktop 是什么（读源码，不复述宣传）

| 项 | 实际情况 | 出处 |
|---|---|---|
| 形态 | Rust 写的命令行程序 + C 库；**每条命令一个短进程，没有常驻进程**；`mcp` 子命令把命令包成 MCP 工具 | README「How it works」「MCP」；CHANGELOG（1.2.0 去掉 macOS 常驻宿主） |
| npm | 只是下载器 / 启动器；Windows x64 本体是单个 `agent-desktop.exe`，**3.8 MB**（压缩包 1.76 MB），不需要 Node 运行时 | 发布包 `agent-desktop-v1.2.0-x86_64-pc-windows-msvc.tar.gz`，sha256 `a4199f74…c3e8` 与官方 checksums 一致 |
| 依赖 | 要 VC++ 运行库（`VCRUNTIME140.dll`），干净 Windows 上直接静默退出 | issue #542 |
| 签名 | 不签名，SmartScreen / 杀毒 / 智能应用控制可能拦 | 官方 Windows 文档「Requirements」 |
| Windows 实现 | UI Automation（Rust `uiautomation` 0.25 + `windows` 0.62）；Windows 部分约 7.7 万行 | `crates/windows/Cargo.toml` |
| 后台「点」 | UIA `InvokePattern`，没有就退到 MSAA `LegacyIAccessible.DoDefaultAction` | `crates/windows/src/actions/dispatch.rs` 文件头 |
| 后台「输入」 | 只有 UIA `ValuePattern.SetValue`（直接把整格内容换掉，不产生按键） | `actions/value_write.rs` |
| 打字 / 按键 | **一律 `SendInput`**（真键盘输入队列，要目标在前台）；后台不加 `--headed` 时 `type` 直接拒绝；`press --app` 「写进前台输入队列，不能指定某个后台进程」 | `actions/physical_keyboard.rs` 文件头；官方 Windows 文档「Keys」「What works headless」 |
| 鼠标 | 双击、拖动、悬停、按坐标点全要 `--headed`（动真鼠标） | 官方 Windows 文档表格 |
| 锁屏 / 别的桌面 | **不支持**：锁屏桌面、服务会话、别的用户会话都不行；最小化的窗口不能操作 | 官方 Windows 文档「Requirements」「App naming」 |
| 权限 | 目标以管理员运行时只能读不能操作 | 同上「Permissions and elevation」 |
| 许可证 | Apache-2.0，可商用、可改、要保留声明 | `LICENSE` |
| 活跃度 | 2026-02 建库，约 1.9 万星；近一个月 79 个提交；1.0.0（含 Windows 正式版）10-28 才发，之后 9 天发了 4 版；开着的问题 74 个 | `gh repo view`、`gh release list`、`gh issue list` |
| 成熟度 | 官方 Windows 文档原话「checked against the Windows adapter… it was not run for these docs」（没在 Windows 上实跑过） | `apps/docs/content/docs/platforms/windows.mdx` 第 6 行 |

和 Windows 直接相关、还开着的问题（节选）：

- #567「Windows 后台 UIA 操作会把后台窗口激活（AutoSetFocus）」——**直接否定「不抢前台」在 Windows 上成立**（报告者用前台变化钩子记到设值、点击、勾选三种操作都激活了目标窗口）；
- #478 Windows 10 上 `list-apps` / `list-windows` 漏掉大部分顶层窗口（含普通 Win32 程序）；
- #459 记事本这种普通输入框后台 `type` 被拒，只能 `set-value`；
- #558 很深的树读不全；#578 Qt 模态框用 Invoke 打开后超时、读不了；#542 缺 VC++ 运行库静默退出。

## 3. 关键问题逐条结论

### 3.1 Express 的窗口在无障碍树里能不能读到字段和按钮？

- **能读到值，但比我们 Win32 读到的还少**（§4.2 实测，含服务器版单据窗口）：Express 是 MFC 程序，输入格、按钮、标签都是标准 Win32 控件，
  agent-desktop 认得出输入格（可设值）和按钮（可点），但输入格**没有名字**、默认输出也不带位置，配不上标签（我们 `win32_desk.fields`
  已按位置配好 25 个格）；单据窗口工具栏的按钮**全都没有名字**，分不出哪个是「新建」「保存」（我们按命令号）；
- 明细表 / 公司列表（`MFCGridCtrl`，自绘控件）**它也读不到行**；
- 菜单它只读到第一层，我们读整棵树带命令号；Windows 自带的 .NET 版 UIA 更差，只给类名。

### 3.2 能不能做到「人在用电脑时 CC 后台代录、互不干扰」，从而去掉「等电脑空闲」？

- **Express 上我们已经做到了**（§1.1：用别的程序、锁屏都不停，只有人操作这一批的 Express 才暂停）；
- agent-desktop **做不到我们现在的水平**：后台只能「点 / 直接改值」，Express 录单要靠「打字 + 回车」触发它自己的查找和计算
  （直接改值不经过回车，Express 不会去查对方、带单价，等于绕开 Express 的录入逻辑），而它的回车只能走真键盘、要切前台；锁屏不支持；
  还有 #567 后台操作激活窗口的问题；
- 界面上「等电脑空闲」是另一件事（任务派给的电脑还没领单），与操作方式无关。
- 结论：**换成它只会倒退，不能去掉任何等待。**

### 3.3 能不能放进 CC 桌面版而不违背「轻量」？

- 体积小（3.8 MB）、没有常驻进程、不需要 Node，单看占用可以接受；
- 但：要另带一个不签名的 exe（杀毒 / SmartScreen 风险；我们定过不买签名证书）、要 VC++ 运行库、每次操作起一个进程、
  Windows 版 9 天发 4 版还在大改返回格式（1.2.0 改了 2.6 版信封）；
- 能力上又不如我们自写的 ctypes（§3.2）。
- 结论：**不放进 CC**。能借鉴的只有「带编号的控件清单」这个做法（要做也是用我们现有的 Win32 读法自己实现），按记录暂不做（§5.1）。

### 3.4 MR.ERP 是网页，这类工具对它有没有更好？

- 没有。它读网页走的是 Chromium 暴露给系统的无障碍树：第一次读要 10–25 秒才稳定、只给一小部分（官方 Windows 文档「Chromium and Electron」），
  官方自己也建议网页内容改走调试协议（`launch --cdp` 交给 agent-browser）；
- 我们 ADR-026 定的是在 CC 自带网页内核里直接读写页面（DOM），比它准、快，也不需要另带程序。
- 结论：**MR.ERP 照 ADR-026 做，不用它。**

### 3.5 对开发测试（驱动测试机）有没有用？

- 有一点：测试机上要点 CC 桌面版的原生小窗（Qt 登录框、安装器、系统弹窗）、Express 的弹窗时，比自己写 PowerShell 省事；
- 但限制一样：必须在 skin3 的交互桌面里跑（SSH 会话看不到桌面，仍要一次性计划任务）；CC 网页部分我们已经用 CDP；Express 已经用代录引擎自己开；
- 结论：**可以作为测试机上的辅助工具，按需临时拷过去用，不进仓库、不进产品**；不是必须，不排专门工作。

## 4. 实测（测试机，11-08 12:53–13:00）

条件：主会话批准；测试机 lenovo-office-lan，skin3 一次性计划任务（Interactive、Limited），开跑前查到键鼠已空闲 74 分钟（没人在用）。
只跑官方 v1.2.0 发布包里的单个 `agent-desktop.exe`（包 sha256 `a4199f74…c3e8` 与官方 checksums 一致，exe sha256 `d2746670…94c3`），
没跑 npm / 安装脚本；状态目录指到临时目录（`AGENT_DESKTOP_HOME`）。Express 先用 C 盘 `C:\PearnlyExpress\70EXP`，用 CC 代录自己的会话代码后台开，
只到登录框 / 公司列表 / 工作日期 / 主窗口；14:10–14:13 再补测服务器版 `\\accserver\d$\ACCOUNT\70EXP\TEST`（主会话批准插队），
开到赊购单据窗口（菜单 1-4，只看，没新建、没保存），读完关窗、Express 正常退出；两次都没存任何东西。收尾：临时目录、计划任务读回不存在，Express / agent-desktop 进程 0，
CC 桌面版（进程 8968）全程没动。

**联网 / 遥测（主会话要求先查）**：源码与依赖锁文件里没有任何 HTTP 客户端库；唯一的网络代码是 `launch --cdp` 时探测本机 127.0.0.1 端口
（`crates/core/src/system/cdp_endpoint.rs`），我们没用这个命令；exe 里能看到的两个外部网址（`api.typesafe.ai`、`openrouter.ai`）只是内嵌的
说明文字，属于仓库里另一个 Node 脚本 `scripts/jev/`（会把屏幕描述发给外部模型），不在 exe 里执行。结论：exe 本身没有遥测或上报。

### 4.1 后台操作抢不抢前台（两个 PowerShell 小窗口：A 放后面当目标，B 放前面当「人在用的程序」，挂前台变化记录）

| 操作（都没加 `--headed`） | 结果 | A 被激活到最前面 | 耗时（含起进程） | 峰值内存 |
|---|---|---|---|---|
| agent-desktop `snapshot`（读 A 的树） | 成功，8 个可操作元素 | 否 | 168–233 ms | 19 MB |
| agent-desktop `set-value`（填输入框） | 成功，读回一致 | **是**（12:54:32.213 前台切到 A） | 233 ms | 19 MB |
| agent-desktop `click`（按按钮） | 成功（按钮收到点击，它自己报「未核实」） | **是**（12:54:34.452） | 263 ms | 19 MB |
| agent-desktop `check`（勾选） | 成功，读回一致 | **是**（12:54:36.713） | 236 ms | 20 MB |
| agent-desktop `type`（打字） | **拒绝** `POLICY_DENIED`（后台不能打字） | — | 123 ms | 18 MB |
| agent-desktop `press return`（按回车） | **拒绝**：「Retry with --headed so the named window is brought forward first」 | — | 151 ms | 15 MB |
| 我们的做法：直接给 A 的输入框发 `WM_CHAR` 打 3 个字 | 3 个字都进了输入框 | **否**（这一段前台一直是 B） | — | 不另起进程 |

（激活后是测试脚本自己把 B 放回前面的；真实场景里没人放回，人正在打的字就会打进被激活的窗口。印证官方未修问题 #567。）

### 4.2 Express 的无障碍树（C 盘 Express，账套 T9ASC）

| 画面 | agent-desktop 读到的 | 我们 Win32 读到的（代码已有） | 对比 |
|---|---|---|---|
| 登录框 | 2 个输入格（**没有名字**，第 2 个标着 secure）、OK / Cancel 按钮、4 个标签 | 同样的输入格、按钮、标签文字（`win32_desk.fields`，按标签位置配对） | 一样；它也要靠位置把标签和格子配起来 |
| 公司列表 | 4 个按钮；表格只是一个带滚动条的 group，**读不到任何一行** | 表格 `MFCGridCtrl` 读不到行，按登记表行号移过去 | 一样读不到；它没有补上这块 |
| 工作日期框 | 标签、日期格（值 20261108）、ตกลง、「...」 | 同样 | 一样 |
| 主窗口 | 状态栏文字（公司名、账套路径）、菜单栏**第一层** 8 项（1.ซื้อ … 8.อื่น ๆ） | 状态栏同样；菜单读**整棵树**带命令号（例：1.ซื้อ → 4.ซื้อเงินเชื่อ → 1.…ทำสต็อค = 50004），不用把菜单拉开 | 我们更全；它要读下一层得把菜单展开（会显示在屏幕上） |
| 单据窗口（服务器版 TEST，赊购 RR，14:12 补测） | 25 个输入格的值都读到了（单号 RR691108-001、日期、供应商 P001、价格类型下拉框……），但**每个格都没有名字**，标签是另外一串 statictext，默认输出不带位置，配不上；工具栏 28 个按钮**全都没有名字**；5 个页签读得到；明细表格只是一个空的 group，**连表头都没有** | `win32_desk.fields` 读到同样 25 个格，**每个都已配上左边标签**（แผนก、เลขที่ใบรับสินค้า、วันที่、ผู้จำหน่าย……）；工具栏按命令号问亮不亮、直接发命令；表格同样读不到行 | 我们更好用；它多出的只有「页签」这一项，代录用不上（进明细靠点表格） |
| 每次读一遍 | 0.2–0.7 秒，单据窗口 1.2 秒（含起进程，96 个元素） | 进程内直接读，毫秒级 | — |

另：Windows 自带的 .NET 版 UIA（PowerShell 直接调）读 Express 更差——所有控件都只是不带任何操作的「Pane」，只有类名；
agent-desktop 用的原生 UIA 能认出输入格和按钮。

插曲：第一次用 2567 年度的 T7ASC，工作日期（今天）不在期间，Express 在「工作日期」框反复弹「日期不在期间」提示，脚本只按确定、没进账套，
150 秒到时退出。换 2569 年度的 T9ASC 后一次走到主窗口。服务器版 TEST 第一次按 C 盘的菜单写成 1-4-1，但 TEST 的「4. ซื้อเงินเชื่อ」直接是命令、
不是子菜单，代录引擎核对菜单树后拒绝（「menu item 4 is a command, the path goes on」）、没乱开窗口；改成 1-4 后 14 秒打开单据窗口。
这也说明同一版 Express 不同账套的菜单会不一样，我们按菜单树核对的做法是必要的。12:57 测试机上还短暂出现过第二个 ExpressI（12:57:23 起，随后自行消失），来源没查清，已在占用表记下。

### 4.3 现有做法（`bg_desk`，ADR-026）与 agent-desktop 逐条对比

| 项 | 我们（`bg_desk`） | agent-desktop（Windows，不加 `--headed`） | 依据 |
|---|---|---|---|
| 后台打字 | 能：给焦点格发字符消息，泰文先切 Express 线程的输入法 | **不能**：`type` 拒绝；只能 `set-value` 整格替换，不产生按键 | §4.1；`bg_desk.py` 文件头 |
| 回车走格（Express 靠它查对方、带单价） | 能：投递按键消息，走 Express 自己的消息循环 | **不能**：`press` 拒绝，要 `--headed` 把窗口拉到前面再发真键盘 | §4.1；`physical_keyboard.rs` |
| 锁屏照录 | 能（评估 §15 实测锁屏期间每张 8.6–11.6 秒） | **不能**：官方文档写明不支持锁屏桌面 | 官方 Windows 文档 Requirements |
| 抢前台 | 不抢（§4.1 对照 0 次；评估 §15「Express 没被拉到前面」） | **抢**：设值 / 点击 / 勾选 3 次都激活目标窗口 | §4.1；issue #567 |
| 读格 | Win32 读输入格并配好左边标签（单据窗口 25 个）、按钮、状态栏、整棵菜单树（带命令号） | 读到同样的格子和值，但格子没名字、工具栏按钮没名字，菜单只到第一层 | §4.2 |
| 读明细表格 | 读不到行（按坐标进格、存档后读 DBF 核对） | 也读不到，连表头都没有 | §4.2 |
| 菜单 | 按编号 / 文字找命令号直接发，不拉开菜单 | 要逐层展开（拉开的菜单会显示在屏幕上） | §4.2 |
| 资源占用 | 进程内 ctypes，不另起进程；不代录时不导入 | 每条命令起一个进程，0.1–0.4 秒、峰值 3–20 MB；另带 3.8 MB 不签名 exe，要 VC++ 运行库 | §4.1；issue #542 |
| 认不出的画面 | 截图交 AI；后台做法下 AI 只能按键 / 打字 / 开菜单 | 给 AI 带编号的控件清单（不截图） | 能借鉴，暂不做（§5.1） |

## 6. 风险与限制

- 锁屏没实测（按官方文档写明不支持；我们的锁屏照录见评估 §15）。
- 单据窗口那次打开的是 TEST 里最近一张已作废的赊购单，表格里没有明细行；但表格在它那里连表头（画面上看得见的 No. / รหัส / คลัง …）
  都没有，只是一个空的 group，所以有明细行也读不到。
- 实测用的是 v1.2.0；它迭代很快，个别问题（如 #567）以后可能修掉，但「后台不能打字、不能按回车」是设计上的选择（打字一律走真键盘），
  不是缺陷，修 #567 也改变不了 §3.2 的结论。
- 官方问题单多为自动生成的详细报告，个别可能已在主干修复；结论以 v1.2.0 源码为准。
