# 需求影响评估：ERP「仓库」菜单移到「物料与库存」组

基线：`ba523e642`（分支 `pearnly/magical-dijkstra-4e17fb`，工作树 `.claude/worktrees/magical-dijkstra-4e17fb`）。

## 0. 需求原文与理解

- 原话（岳父，LINE，11-08，泰文）：「ย้ายเมนู คลังสินค้า มาอยู่ ใต้ เมนู สินค้าและ สต้อค อยู่ระหว่าง เมนูสต็อคและเมนูสินค้า」「คลังสินค้า เป็นเรื่องเกี่ยวกับสินค้า จึงควรนำมาไว้ในเมนู สินค้าและสต็อค」
  意思：把「仓库」菜单移到「物料与库存」菜单下，放在「库存」和「物料」之间；仓库属于物料相关，应放在这组里。
- 理解（用户已确认）：ERP 左侧「物料与库存」组变成 库存、**仓库**、物料、入库、出库、调拨、物料调整、收发存报表、盘点；
  左下角用户菜单里的「仓库」去掉（是移，不是复制）；谁能看见、谁能改不变。
- 不在范围：仓库页本身、仓库权限判据、其他菜单顺序、Cowork / DMS 菜单。

## 1. 现有同类与复用

- 菜单全由 `apps/pearnly_erp_portal/pearnly_erp_portal/hooks.py` 的 `pearnly_navigation` 声明（ADR-009），外壳 `pearnly_core/desk/navigation.py` 照画：
  `groups` 定侧栏分组与组内顺序；`user_menu` 里的路由会从侧栏移出、放到左下角。
- 结论：只改声明（`groups` 加一项、`user_menu` 删一项），共用层与前端不动。

## 2. Frappe 原生能力

- 侧栏是原生 Workspace Sidebar（分组 = Section Break + child 项），窄屏是同一份侧栏的抽屉。不涉及自定义控件。

## 3. 按类通用

- 同类：左下角另外两项（公司、团队管理）不在本需求里，不动。

## 4. 上下游数据

- 单据、库存流水、Express：不涉及（只改入口位置）。
- CC 桌面版：全仓查过 `pearnly-warehouses` / 「左下角…仓库」，CC 与对话提示里没有引用这个菜单位置；载荷不变。
- Cowork / DMS：各自声明菜单，不受影响。

## 5. 隔离与权限

- 页面准入不变：`pearnly-warehouses` 的判据最终是 `access/menu.py` 循环覆盖的
  `any_role = [ERP Menu warehouses, ERP Stock, ERP Admin]`（任务书里写的「能读 ERP Warehouse 即可进」是循环覆盖前的旧值，实际以角色判）；
  写仍由服务端 `warehouses.manage` 判。侧栏与左下角用的是同一个 `visible_pages` 判据，所以**原来左下角看得到仓库的人，移过去后侧栏照样看得到，看不到的照样看不到**。
- 待定一项（见第 12 栏）：团队管理的岗位勾选里「仓库」现在归在 `permission_groups` 的「User Settings」组。

## 6. 入口：网页、手机、LINE、拍照

- 桌面侧栏：组里多一项。窄屏：同一份侧栏抽屉，自动跟着变。
- 首页 / 快捷入口：ERP 首页没有仓库的快捷入口（已查），不涉及。
- 选择框「新建 / 高级搜索」跳转（`links`：`ERP Warehouse → pearnly-warehouses`）只看页面能不能进，不看在哪个菜单，不受影响。
- 个人侧栏排序：组内顺序按声明画，不按个人保存的顺序；已保存过顺序的人，新进侧栏的仓库照样出现（`_personal_order` 会补上新路由）；再次保存时侧栏上就带着仓库，服务端校验通过。
- LINE、拍照：不涉及。

## 7. 共用件与连带回归

- `check-impact.py --files hooks.py` 命中共用件「侧栏与菜单（shared.navigation，manual）」等：要实测各产品侧栏分组、用户菜单、主档链接、个人排序、团队页菜单权限与 main 一致（ERP 只差仓库位置）。
- 仓库页两条流程（`erp.warehouses.codes`、`erp.warehouses.rules`）照跑。
- 部署注意：侧栏条目取自站点的 Workspace Sidebar 文档，由 `after_migrate` 的 `ensure_navigation` 重建；正常部署会跑迁移。**不跑迁移只换代码时，仓库会两边都不见**（左下角已删、侧栏文档还没有它），实验栈验证时也要跑一次迁移。

## 审定与施工结果（11-08）

- 主会话审定：按建议做，岗位勾选里的「仓库」一起挪到「物料与库存」组。
- 改动：`hooks.py` 的 `pearnly_navigation` —— `groups` 物料与库存组在库存、物料之间加 `pearnly-warehouses`；`user_menu` 删仓库；`permission_groups` 的「User Settings」去掉仓库（岗位勾选跟侧栏归组）。共用层、前端、文案未改。
- 断言（改前红、改后绿）：`tests/test_native_desk_contract.py` 组内顺序、`user_menu` 只剩公司与团队管理、岗位勾选分组；排序保存夹具补上仓库；只开销售的构造场景下管理员侧栏多出只含仓库的「物料与库存」组（正式开通 ERP 功能全开，见 `features.json`，实际不会出现）。站点测试 `access/test_entry_permissions.py` 加岗位分组断言（需 POS 实验站，本次未在该站跑，见下条真站点核对）。
- 实验栈 `pearnly-whmenu-lab`（本分支源码，全部站点迁移后重启再测）：
  - 管理员（电脑 / 手机 390 宽）：侧栏「物料与库存」= 库存、仓库、物料、入库、出库、调拨、物料调整、收发存报表、盘点；左下角 = 公司、个人信息、团队管理；点仓库进页、侧栏高亮仓库。
