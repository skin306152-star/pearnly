# 需求影响评估（施工短版）：CC 接云端 Express

> 2026-11-15 夜。完整方案见 [11-11 评估](2026-11-11-express-cloud-assessment.md)；11-15 实测 T1–T6 全过，见 [实测记录](2026-11-14-express-cloud-probe-run.md)。
> 本文只写实测之后**变了什么**和这一轮**不要外部条件就能做的部分**。状态：待主会话审定，审定前不动产品代码。

## 0. 需求原文与理解

云端 Express（TSplus 远程桌面，云端不能上网）也要能用 CC。范围按用户 11-14 定：

- Cowork 和 ERP 都要直写；
- 采购、销售各类票要能代录；
- 收款只在 ERP、只直写。

用户 11-15 加了三条：

- 账号授权放在 CC「设置 → 连接」，不弹系统框，也不放进对话；
- 每次连接的安全警告框不能让人手点；
- 选目标账本的地方复用现有 Express 选择，不另造。

## 1. 现有同类与复用

| 要做的 | 复用 |
| --- | --- |
| 云端账号、密码的存取 | `companion/express_operator/credentials.py`（Windows 凭据管理器，DPAPI，本用户），新增目标名前缀 `Pearnly CC/cloud/<主机>` |
| 设置页「云端 Express」一行 | `frontend/assistant/src/components/settings.tsx` 里 MR.ERP 登录那一行的组件与样式（输入框、状态、行尾「···」） |
| 网页通知桌面版的动作 | `tomo_bridge` 的动作白名单，加 `cloud_connect` / `cloud_disconnect` / `cloud_rescan`；密码只在本机网页 → 本机进程之间走，不发服务器 |
| 被挤标记 | MR.ERP 被踢的做法（`mrerp_operator/session.py` 的 `KICKED`）：不自动重连，人点才连 |
| 云端账套上报、选目标、写账、收款 | 全部走现有 Express 路径（11-11 评估第 14 节：6 个入口的选择逻辑都不改） |
| 子进程按需拉起 | 1.9 起「窗口进程」的做法：托盘按需拉起，没连云端的电脑不导入、不起进程 |

## 2. Frappe 原生能力

服务端只多一个显示字段（「经哪台电脑 / 云端」来源标记），用原生 DocType 字段 + patch，不新建页面。

## 3. 按类通用

- 「来源 / 接法」做成账套位置的通用属性（本机 / 局域网 / 云端），不为云端单开一类。
- 被挤、登录失败的状态和 MR.ERP 用同一套状态词与显示。

## 4. 上下游数据（实测后变化）

- **连接方式改了**：桥上不再用 mstsc 打开 .rdp 文件，改为在 `--cloud-link` 子进程里内嵌 Windows 自带的远程桌面控件（mstscax）。账号、密码由 CC 直接交给控件，不经过系统密码框，也不打开 .rdp 文件（不弹安全警告）。控件窗口放在隐藏桌面或屏幕外。
  - ~~兜底：mstsc + 隐藏桌面 + 自动勾驱动器、点连接~~。11-16 撤销：不自动点 Windows 安全警告框（见 11-11 评估第 15 节「11-16 更正」）；兜底改为给 .rdp 签名，或用户本人点。
  - 控件「不弹框」是推断，见第 12 节第 1 条。
- **连接参数**：主机、端口分开写；用户名、域拆开（实测：只写用户名、不写域会连错，原因码 2055）。
- **云端 CC 第一次怎么跑起来**：云端不认「登录即运行」，Win+R 也打不进去，只能「点开始菜单 → 打命令」。所以第一次授权时，由桥对控件发鼠标键盘，把启动脚本放进云端启动文件夹（实测可写）；以后每次登录自动运行。
- **同一账号只有一个会话**：后连的挤掉先连的，原因码 3。CC 被挤 → 记标记、不重连。员工和 CC 用同一个账号时，两边共用同一块云端桌面：代录开 Express 时要先看有没有人在用（`presence`），有人就排队。
- **云端包**：整包 586 MB，拷一次 5–15 分钟。做一份不带网页内核的云端精简包（估 60–90 MB），升级时拷一次。

## 5. 隔离与权限

- 不变：令牌、设备密钥只存桥上；隧道只放行本站的机器接口白名单。
- 新增：云端账号密码只存桥本机凭据管理器，不进服务器、日志、截图。

## 6. 入口

- CC 桌面版「设置 → 连接」加「云端 Express」一行。
- 网页、LINE、手机：选择逻辑不改；有来源标记后，账套名旁显示「云端」。

- 步 A 已做（分支 `pearnly/express-cloud-source-mark` = `900c7a29c`）：心跳可选字段 `link {kind: cloud, via, host}`，两产品存到电脑行（隐藏只读字段 `link_kind` / `link_via` / `link_host`；`kind: none` 清空；缺省或坏值不改、不拒收心跳）；Cowork 电脑列表 `folder_intake.api.computers` 返回 `link`。**ERP 目前没有列电脑的接口**（ERP 网页与 CC 设置里的电脑列表只调 Cowork 接口），ERP 要显示「云端」得在做前端时补一个只读接口；ERP 账套项本来就带 `devices`，前端可按它带标记。合入前按惯例在生产镜像跑一遍完整候选离线检查（改了 pearnly_core）。

- 11-16 进度：已推送的分支有 A 来源标记、C 文件隧道、D 云端模式、云端精简包；F 只提交了 `.rdp` 生成与本机凭据存取（`pearnly/express-cloud-cc-session` = 5b531530f，未推）。F 里的断线判定、会话状态机、隐藏桌面会话、首次启动按键序列被安全审查拦下，暂停，等用户确认「云端连接改为可见窗口 / 是否告知服务商」后重新设计。

## 7. 共用件与连带回归

登记共用件：

- `cc-assistant-settings`（设置页）
- `cc-desktop-bridge`（动作白名单）
- `cc-places-heartbeat`（上报加来源字段）
- 服务端 `pearnly_core/cc_desktop/wire/report_rules.py` 账套属性白名单
- Cowork `connections/service.py:targets` 放行键

施工时跑 `check-impact.py` 出清单，逐入口实测。

## 8. 存储与成本

零新增固定费用。桥上多一个控件进程：实测 mstsc 约 240 MB 内存、空闲约 1–2% 单核，控件预计同级，只在连了云端的电脑上才有。

## 9. 删除、作废、追溯

「断开」时：

- 删本机云端凭据、设备令牌；
- 撤隧道盘；
- 下次连上时由启动脚本删云端程序目录与启动项；连不上就留着，没有令牌也联不了网。

写进 Express 的单照旧不做原生作废。

## 10. 文案

新增四语（th / zh / en / ja）：「云端 Express」「连接」「已连接 / 未连接 / 登录失败 / 账号在别处使用」，尽量沿用已有词条。不改已有文案，不加说明文字。

## 11. 测试与验收

- 施工期只用本机替身：假隧道（同进程两个目录）、假控件（录下发给控件的参数）、假断开事件（原因码 2055 / 3）。不碰云端。
- 云端真写：只写 Z1，留到用户在场的验收里做（第 12 节）。
