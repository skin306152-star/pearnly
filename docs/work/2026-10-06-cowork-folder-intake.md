# Cowork 文件夹自动录入（2026-10-06 起）

分支 `pearnly/cowork-folder-intake`，工作树 `../pearnly-wt-folder-intake`，基线 `origin/main` 6b0b1795。
全程由本窗口完成：云端、小助手、识别服务（Cloud Run）发布、测试机验证、合并部署（10-06 起不再有其他窗口分工）。

## 一、对象与权限

- **小助手**：装在客户做账电脑上，可有多个配置；每个配置 = 某个 Cowork 工作空间的一条 Express 连接（配对码）。
- **规则**挂在连接上，一条连接可以有多条规则（多个文件夹）。工作空间里有录入权限的成员都能在网页建、改、停、立即运行。
- **规则负责人** = 建规则的人；自动推送以他的身份执行，每次推送前复核他仍有权限、连接仍启用、站点推送总闸开着，否则不推。
- **本机允许读取的根目录**只能在小助手本机设一次；网页只能在这些根目录下选子文件夹（小助手只上报文件夹名，限层数）。
  这是安全边界：否则能登录网页的人可以让办公室电脑把任意文件传上云。

## 二、规则内容 = 「新建录入」弹窗的同一组前置条件（用户 10-06：照现有前置条件直接做，不另设计、不加严）

1. 目标：Express 连接（一台电脑上的某个小助手配置）。
2. 公司 → 年度账套：与弹窗同一份账套目录（`targets/catalog_groups.py`），选的就是具体年度账套，照用户的选择推，系统不自动挑。
   换财年时在网页把规则的年度改成新账套；日期不在所选账套期间的票照现有规则退回（`account_match.PERIOD_MISMATCH`）。
3. 进项 / 销项。
4. 过账类型（服务 / 存货）；选存货且账套有两个以上存货科目组时，与弹窗一样当场选一次存回账套（`targets/stock_groups.py`）。
5. 文件夹（本机根目录下，含下级子文件夹，排除 `_Pearnly结果`）、每月几号几点（曼谷时间）、启用 / 停用。

## 三、一次运行

1. **触发**：到点；网页「立即运行」；电脑关机错过的，开机后补跑一次（错过多次也只补一次）。云端不跑定时任务。
2. **收集**：PDF / JPG / PNG / HEIC；跳过隐藏、临时文件（`~$*`、`*.tmp`）和 `_Pearnly结果\`；文件 2 分钟内大小和修改时间不变才算写完。
3. **不重复上传**（只管同一个文件别传两次、别重复扣费，与推送防重无关）：本机台账（路径、大小、修改时间、sha256）+ 云端防重键（规则 + sha256），本机台账丢了也不会重复扣费。
   同一内容换名字再放进来算新上传，照常识别扣费（与「上传识别都扣费」一致）。
4. **上传**：最多 3 个并发；余额不足即停，剩下的留到下次（或充值后立即运行）。上传时带上规则的前置条件，与网页上传落成同样的识别任务。
5. **识别**：Vertex Flex 档。被限流就退避重试，不换档；到**曼谷时间次日早上 7:00** 还没识别完的改走标准档。
6. **推送**：每张票识别完，以规则负责人的身份做与网页「提交」完全相同的两步——`push.application.service.submit`（准备）
   + `companion.submission.confirm` 那一步（确认发送），之后小助手照现有队列写 Express。**不加任何新闸门**。
7. **写 Excel**：见第五节。
8. **运行记录**（网页规则下）：扫到 / 上传 / 不是发票 / 已推 / 退回（原因）/ 失败 各几份。

## 四、推送照现有规则（已通读 `push/application/service.py`、`push/express/choices.py`）

- 每张票各自准备、各自推，**一张退回不影响同批其他票**，也不影响以后的运行。
- 现有规则只拦确定错的：本方税号与账套税号确定不同、单据日期确定不在账套期间（读不出就不拦）；同票已推成功的不再推；
  小助手内容指纹闸（同内容跳过、同号不同内容退回待人定）。
- 「要人选一次」（`choice_needed`）只在这几种情况出现，按账套记住、同类以后自动套用：
  - 对方档：Express 里同税号有两个以上档，或只有一个但分店号对不上。**全新供应商 / 客户（Express 里没有这个税号）不问，照票面自动新建**；
  - 存货：存货行的品名在 Express 存货里找不到同名，也没选过（只在过账类型为存货时）；
  - 费用科目：服务类进项，分类映射没定下科目、这家供应商也没选过；
  - 付款方式：票面看不出现购 / 赊购、这家也没选过；
  - 小票 / 简易税票税额抵不抵进项：这家没选过；
  - 部门：账套有部门、整份账套还没选过（只问一次）。
- 被退回的票在网页列表上照现有方式显示原因和「选择」按钮，人选完点一下就推；选过的值记住，下次运行同类票自动过。
- 识别判定不是票据的没有票，不推，只计入运行记录。

## 五、Excel

- 位置：`<规则文件夹>\_Pearnly结果\YYYY-MM\发票号_卖方税号后4位.xlsx`（月份按运行时间）；一个 PDF 多张发票出多个；
  没有发票号的 `未识别_原文件名.xlsx`；文件名非法字符替换。
- 内容：原文件名与页码；发票号、日期、卖方 / 买方名称与税号、未税、税额、合计、明细行；账套、Express 凭证号、供应商 / 客户代码；
  未推送的写原因。
- 由云端用复核表同一模板（`roundtrip/export_writer.py`）生成，小助手下载落盘；小助手不装 openpyxl。
- 写入时机：该张推送有了结果（成功 / 退回）后。退回的在网页处理并推送成功后，小助手下一次心跳把这张 Excel 刷新为已推送。
- Excel 不回传；内容不对的直接去 ERP 改。

## 九、影响评估（10-06，只读代码，10 个改动点 × 评估 + 挑刺，另一路查漏）

结论：10 个改动点都能做成「新增 + 保护」，不需要改任何现有业务规则；推送防重确认不改（相关 42 项离线测试照旧通过）。
但原设计有几处照做会影响现有客户，必须按下面的做法实现：

| 风险 | 照原设计会怎样 | 定下的做法 |
|---|---|---|
| 识别名额 | 生产每商户同时 3 份、全站 pending 共用（含 ERP/DMS）；一次交几百份会让网页 / LINE 排队超时 | 文件先进本功能自己的暂存表，不直接建识别单；每条规则同时在途 ≤1 份，且 Redis 里商户 / 全站在途都低于上限一半才交；开跑加随机延迟。pearnly_core 不改 |
| 连接行锁 | 每个机器请求鉴权时锁 Cowork ERP Connection 行，与心跳 / 领任务 / 回执 / 网页提交争锁 | 每个配置的机器请求串行；文件字节签名直传原件桶；重活放后台任务；自动推送按连接串行 |
| 推送队列先进先出 | 几百张自动推送排在人工推送前面 | 每条连接待领取的文件夹推送 ≤5 张，回执后再补 |
| 自动推送与人工 | 人保存过的票被自动推出；自动留下未确认的 prepared 卡住别人；直接 prepare 会留下 manual 记录（网页关掉选择框时不会留） | 只推识别后没被人动过的票；先调现有 choices_view，要人选就只用现有 push_state.record_failure 写原因（网页列表照常出「选择」按钮），不建推送记录；确认失败用现有 cancel_prepared 撤回 |
| 来源判断 | request_key 前缀能被网页伪造，网页上传会被自动推送 | 只认本功能自己写的条目表 |
| 机器接口 | 鉴权只认 3 个方法、只收 JSON；照搬 queue_api._run 会把余额不足报成 503 | 白名单追加新方法（原 3 个逐字不变），两条契约测试只追加；JSON + 签名直传；自己的错误映射；直传用不带 exp_ 密钥的独立客户端 |
| 菜单 / 功能目录 | 加侧栏页或改 features.json 会改所有租户的菜单与开户权益 | 不加侧栏页、不改 features.json；入口是录入工作台里的按钮 + 子路由，出错只影响这个按钮 |
| 规则弹窗复用 | p.intake_targets 只看第一条 Express 连接，目录读取有副作用，localStorage 会改掉新建录入的默认账套 | 规则弹窗自己读同一份服务端数据，不写新建录入的本地键 |
| Excel | 改共用复核表模板会破坏回导 | roundtrip 零改动；复核表照生成后另加独立表；不落 File，按需生成；原因以 History.last_push_reason 为准 |
| 小助手 | 放进写入线会被看门狗当卡死；改 companion.json 降级会丢配对；重新配对同一 profile_id 会把根目录带到别的工作空间 | 独立守护线程、独立状态目录（schema 仍 4）、没设根目录就完全不启动；根目录与台账按连接身份作键 |
| 首次启用 | 文件夹里的旧文件会整批识别、扣费、推送 | 待用户定（见下） |
| 上线 | 改现有 DocType 要迁移所有站点；直接发 cowork-ocr 新修订版会把整站识别切到新代码 | 只新增 DocType、不加 patch；一个站点开关 pearnly_cowork_folder_intake 默认关，所有环节都先读它 |

必须碰到的现有文件（只追加登记，合并前用 git diff 白名单核对其余文件零改动）：hooks.py、companion/http_auth.py、
tests/test_companion_contract.py、tests/test_cowork_companion_queue_http_contracts.py、public/desk/intake.js、
i18n/messages.tsv 与翻译包、docs/development/architecture-policy.json 与 architecture.md（登记新域；写明「规则启用即负责人的常设确认」
是对「人工确认」不变量的明确例外）、小助手 gui_tray.py / i18n.py / version.py / tests/conftest.py。

技术口径（本窗口自定）：规则与「立即运行」走新机器接口由小助手的独立线程拉取，心跳 / 领任务 / 回执代码不改；识别完成钩子只入队；
兜底由小助手拉结果时触发，不开云端定时任务；不改按类别的 OCR 钩子；云端不重复上传的键 = 规则 + 相对路径 + sha256，不含签发人或负责人；
全链路身份冻结为规则负责人。

已知、不改现有代码的副作用：负责人用 LINE 时「上次用的账套」会变成规则的账套；录入列表会多出整批文件夹票；
旧版小助手（无自动安装）不会执行规则，网页按上报版本提示升级；夜里 Express 开着时现有「账套被占用」弹窗会让写入等待。

Flex 要动识别派发链约 12 处（加默认关闭的参数）、另起 Cloud Run 服务 cowork-ocr-flex；单张识别单有硬时限（排队 30 分钟 + 已付费宽限 3 小时），
「整张等到 07:00」只能靠暂存表实现，单张最多等约 2–3 小时。

## 十、10-07 用户定稿

- 入口：「新建录入」弹窗底部加「自动录入规则」按钮，点进去是单独一页（录入工作台子路由），每条规则各自有 立即运行 / 编辑 / 运行记录 / 停用。
  必改现有文件因此多一个 `public/desk/intake-choices.js`（只加一个按钮，出错不影响弹窗）。
- 其余按推荐：第一期**不做 Flex**（识别代码零改动，跑稳后第二期再加）；启用时文件夹里已有的文件**不处理**，只收启用之后新放进来的；
  **扣费成功后才自动推送**，余额不足停下，充值后继续。
- 原则（用户反复强调）：系统能 100% 定的不问；能按类别定的，在规则里让用户设一次，之后这一类 100% 照走；只有确实无法按类别定的才停下问。

### 文件夹放法（规则页上直接展示）

一个文件夹 = 一条规则 = 一家公司 + 一个年度账套 + 进项或销项 + 服务或存货。下级子文件夹随意分（会一起扫）；一份 PDF 里几张发票都行；
文件名随意；只放 PDF / 图片；`_Pearnly结果\` 由系统生成、不放单据；换财年在规则里改年度。

### 规则第三段「这一类以后都这样处理」

按现有 `push/express/choices.py` 的六类决定逐类归位（只显示这份账套用得到的项）：

| 决定 | 归类 | 规则里怎么处理 |
|---|---|---|
| 全新供应商 / 客户（Express 无此税号） | 系统 100% 定 | 现有规则照票面新建，不问 |
| 付款方式（票面看不出时） | 按类别设一次 | 规则默认值：现购 / 赊购 |
| 收据、简易税票税额抵不抵进项 | 按类别设一次 | 规则默认值：抵 / 不抵 |
| 服务类进项没对上科目的费用 | 按类别设一次 | 规则默认费用科目（从账套科目里选） |
| 部门（账套有部门时） | 按类别设一次 | 规则里选一次 |
| 存货品名在 Express 找不到（存货规则） | 按类别设一次 | 规则默认：照票面新建存货 / 停下选 |
| 同税号有多个档、或分店号对不上 | 无法按类别定 | 照现有规则停下等人选一次，之后记住（少见） |

实现：自动推送前调现有 `choices_view` 看缺哪项，缺的且规则有默认值的，用现有 `push.choices.record` 记成「负责人已选」
（与会计在复核页选一次完全相同），再走现有提交。注意：记下的是这份账套的共用记忆，之后同一家的手动推送也按它走——这正是现有「选一次记住」的口径。
