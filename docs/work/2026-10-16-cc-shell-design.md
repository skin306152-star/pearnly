# CC 外壳设计（照 Claude Code，开发窗口亲自实测，2026-10-15 夜）

用户 10-15 晚：「前端重构的设计和方案以及是否摸清 claude 这边的组件，我还是有些不放心，我希望你亲自摸下和策划下所有设计」。

用户 10-15 夜确认本设计（回「可以」），第 5 节三处改动一并同意。本文**取代** [研究文档](2026-10-15-claude-code-ui-study.md) 第 2、3、4 节的数值，用户已定的四条（第 7 节）不变。

## 0. 怎么摸的

- 内置浏览器登录 `claude.ai/code`（网页版，与桌面版 Code 同一套前端；桌面版差异按样式表里的 `data-variant="desktop"` 规则记）。视口 1440×900 与手机 375×812，浅色、深色各一遍。
- 用脚本读**设计系统本身**：Claude 的组件带 `data-cds="组件名"`，变量分三层：`--cds-*`（设计系统，约 500 个）、`--df-*`（桌面框架：侧栏、行、托盘）、组件私有变量。读的是样式表定义和计算后的实际值，再逐个组件读实际尺寸、颜色、悬停 / 选中 / 焦点状态。
- 交互逐项实测：悬停、组标题折叠、行「···」菜单、「分组和排序」菜单与子菜单、方向键、Shift 多选与批量菜单、工具步骤摘要的展开、右侧会话栏、项目页、项目列表、手机抽屉。
- 只读规格、不抄源代码。实测时打开过的会话栏已关回原状；聊天模式切回 Code 模式。

### 2.4 阴影与动效

- 卡片：浅 `0 0 0 1px 黑6%, 0 4px 24px 黑4%`；深 `inset 0 0 0 1px 白6%, 0 4px 24px 黑8%`。
- 悬浮：`0 0 0 .5px #0000000d, 0 2px 8px #0000000a, 0 12px 32px #00000008`（深色 `#ffffff0f / #0000004d / #00000040`）。
- 弹出（菜单）：`0 0 0 .5px #0000000f, 0 4px 12px #0000000f, 0 16px 40px #00000014`（深色 `#ffffff14 / #0006 / #00000080`），另加 1px 内环（线色）。
- 输入框：1px 环（线色）+ `0 4px 20px 黑3.5%`。
- 缓动：`cubic-bezier(.32,.72,0,1)`（主）、`(.2,0,0,1)`（快）、`(.165,.84,.44,1)`（淡出）；时长 60 / 120 / 200 / 300 / 450ms。悬停揭示用 120ms。

## 3. 组件规格（实测）

**3.1 侧栏外框**：宽 288，可拖宽、可收起成左上角小圆钮（收起后钮 32）。标题区 44：收起钮 24 + 品牌。网页版贴边；桌面窗口浮成卡片（离边 8px）。

**3.2 搜索框**：高 32、圆角 8；浅色 白50% 底，深色 白5% 底；0.5px 内环（线色）+ `0 1px 2px 黑5%`；占位字淡色 14px；右侧 12px 淡色快捷键提示。

**3.3 顶部导航行**：高 32、圆角 8、字 14 次要色、图标 20 放在 28 的前导槽里；当前页：选中底 + 主色字；行尾 24 的操作按钮悬停才出现（例：「项目」行尾「新建项目」）。

**3.4 组标题**：带高 32，左内边距 10。整行（除右侧操作区）是一个开关按钮：高 24、圆角 8，`aria-expanded`。名字 13/16 淡色，鼠标在组标题上变次要色，展开状态的开关字为主色口径。名字后 12px 箭头（收起 ›、展开 ⌄），鼠标进入侧栏才淡入。右侧操作 24×24：平时只露「分组和排序」，悬停组标题再出「新建」。
CC 侧栏改动（用户 2026-10-15 夜，配图与录屏来自 DeepSeek 桌面端；原话「侧栏还是这样做吧，参考图一，图标换成我们自己公司的图标，然后才是公司名字，然后展开收起，下面是对话……打开现在的打开公司和在这家新建对话，不要了，换成图三的内容……+还是保留，点+就在这个公司内新建对话，图4点图标就不要了」，随后补充「只改我提到的地方 其它不要动」）：
- 公司组头：最左公司图标（lucide `Building2Icon`，原「打开公司」菜单项那个，16、淡色），图标与名字隔开 6（开关的 4 + 行间距 2）；公司名同会话行标题的字号字色（14/20 次要色、常规字重，不用组标题 13/16 淡色）；整行仍是折叠开关，名字后箭头、待处理数、收起时的点、长按、菜单键、带高照旧；这家的对话行缩进到公司名文字起点（电脑、桌面窗口、手机抽屉同样）。已置顶 / 最近 / 月份组标题样式不变、下面的行不缩进。
- 右侧操作：「分组和排序」漏斗按钮从所有组标题上去掉；每个组标题右侧悬停才出「···」（手机、触屏常显），打开的就是原「分组和排序」菜单（3.6 的分组依据 / 排序方式 / 显示 / 恢复默认设置，子菜单、✓、当前值、禁用规则不变）。公司组「···」里原来的「打开公司」「在这家新建对话」去掉；手机长按组头、键盘菜单键打开的也是这份菜单。「＋」照旧（公司组：在这家开新对话、月份上个月；最近：开在最近）。
- 公司页入口改为：对话顶栏「公司名 ›」/ 手机胶囊菜单打开会话栏 → 公司卡名称；侧栏导航「公司」→ 公司列表页卡片。

**3.5 会话行**：高 32、行间 2、圆角 8；标题 14 次要色，超长渐隐；行尾 24 槽放装饰：运行中 6px 脉冲点（淡色、明暗呼吸 1.2s）、环境 / 设备图标 16 淡色、未读点。悬停：行底 = 悬停色，装饰淡出、换成「···」24（圆角 6）。选中：底 = 选中色、字主色。键盘焦点：蓝色焦点描边（1px，没有光晕，见 2.1）、露出「···」；「···」不在 Tab 顺序里，被聚焦时（菜单关了焦点还回来）自己露出并带描边。「显示 → 元数据」打开时为两行行（标题 + 说明行）。
选了文件还没发的空对话不列（用户 2026-10-16：侧栏里「选了文件但还没发」的空对话会多出一条「新对话」——输入框加附件要先建会话，会话一建就成了侧栏普通一行）：侧栏拼行时（`thread-list.tsx` 的 Cowork 按公司 / 月份 / 不分组与 ERP、DMS 按日子分组两处，`sidebar-groups.ts` 的 `unsentDrafts`）不列标题为空、又不是当前打开的那条对话（标题空 = 还没发过消息，首条消息一发就有临时标题）；当前打开的那条（或同一段对话重拉列表后的另一行）照常显示，发出后有了标题照常留下，切走不发就不再列。只在侧栏拼行时滤，不在服务端列表里滤（侧栏多设备同步会把缺的那条当成在别处删了）；公司页对话列表第 5 轮已同样不列。
单行放不下统一末尾渐隐（用户 2026-10-16：「一行放不下时，侧栏末尾是渐隐，右侧栏是省略号，统一渐隐」）：CC 前端所有单行截断的文字（侧栏、会话栏卡片与卡头摘要、公司页、列表页与页标题、菜单、标题栏、对话框标题、设置、附件名、工具步骤、工作状态行、结果文件表格的格子）末尾一律渐隐，不用省略号；**只有真的放不下才渐隐**，放得下的（含按内容收缩宽度的）末尾不淡。渐隐宽度 24（`--cc-marquee-end`，默认同侧栏的 `--cc-row-fade`）。观察器只在尺寸变了时回调，会漏量的几种时候补量（第 5 轮：页面在后台时刷新，电脑上一个 `data-overflow` 也没有）：页面回到前台（visibilitychange / pageshow）、字体载完（`document.fonts` 的 ready 与 loadingdone）时下一帧全部重量一遍；窗口改宽窄、侧栏宽度变了由同一个观察器多看根节点与侧栏两处、回调里全部重量（不另听 resize，免得每帧量两遍）；仍只有整页一个观察器。实现：`components/ui/marquee.tsx` 的 `Marquee` 挂 `lib/overflow-fade.ts`——整页共用一个 ResizeObserver 观察截断的框与里面那层文字（`.cc-marquee-text`，一直是 inline-block），文字宽 > 框的内容宽超过 0.5px 才给框设 `data-overflow`，`globals.css` 的 `:is(.cc-marquee, .cc-fade-cell)[data-overflow]` 用 mask 渐隐末尾；结果文件表格（最多 500 × 40 格）不每格挂，整张表一处登记（`watchOverflow`，格子类 `.cc-fade-cell`）。侧栏标题原来的常驻渐隐（放得下也淡掉最后 24px）并入这一种。多行截断（`line-clamp`，对话出错提示两行）不在范围、保持原样；原生下拉框（结果面板选文件）量不到文字宽，保持浏览器原样。
悬停滚动（用户 2026-10-15 夜，同上，参考录屏逐帧量过；Claude Code 没有这一条）：凡是单行、放不下被截断的文字（侧栏对话标题与元数据行、组名，会话栏卡片里的行，公司页对话行与标题，菜单里的公司名，标题栏对话名，列表页、待处理、设置等行），鼠标放到这一行上、或键盘焦点落到这一行时，约 150ms 后从开头匀速（约 40px/s、线性，时长 = 超出像素 ÷ 40，至少 0.3s）向左滚到末尾刚好露出（原有右端渐隐也让过去）并停住；滚动中左端 24 渐隐、右端保留原有渐隐；离开 / 失焦立即回到开头，没有回滚动画。放得下的不滚；系统减少动态效果、触屏 / 不能悬停的设备、就地改名中、拖动中不滚。静止时的末尾渐隐不变（10-16 起统一渐隐，见上）。实现：`lib/hover-scroll.ts` + `components/ui/marquee.tsx`，参数在 `globals.css` 的 `--cc-marquee-*`，悬停时才量滚多远（放不放得下与静止时的渐隐同一个量法 `overflowOf`）。
第 5 轮（测试窗口实测与审查）：放不放得下按文字宽与「框宽 - 右端渐隐」比（比框窄不到一个渐隐宽度、最后几个字在渐隐里的也滚；10-16 统一渐隐后放得下的末尾不再淡，改为：文字比框宽才滚，滚到最后一个字越过末尾渐隐）；只有真正的键盘操作带来的焦点才滚（上一次输入是键盘且 `:focus-visible`；用鼠标关掉菜单、焦点被还给「···」时不算，鼠标不在这一行就立即回到开头）；滚动中文字变了立即回到开头、还悬停着就重新量（只在滚动中观察这一个元素）；「整行」触发：行上没有 `data-marquee-host`、也不是按钮 / 菜单项 / 会话栏行的（设置里的行、浮着的会话栏顶部）补上了。

**3.17 拖动（共用一套）**：用户 10-15 晚「全部参考视频，非常丝滑」、10-16「所有拖拽的地方要改统一规则和效果」、10-16「对话的拖动效果怎么没和其它拖动效果统一呢」，参考 Claude 桌面版右侧栏拖卡片的录屏 IMG_5192。会话栏卡片、侧栏公司组、置顶对话、对话拖到别的公司都走 `components/ui/drag.tsx`（dnd-kit：@dnd-kit/core 6.3.1、sortable 10.0.0、utilities 3.2.2，MIT，锁定版本），修一处就在那里修：
- 拿起：鼠标按住动 3px（点一下照样是点）；手机按住 250ms 且 5px 内就拿起（没到时间就动 = 滚动；会话栏卡片把手、侧栏对话行、置顶行、公司组头同一规则）；键盘空格。能拖的把手悬停出抓手光标（会话栏卡片的 6 点把手、侧栏对话行、置顶行、公司组头同一条：共用模块给把手加 `data-drag-handle`，`globals.css` 的 `[data-drag-handle]`；不能拖时——搜索中、没存到服务端——没有；把手里的「···」仍是手指、输入框是文字光标）；会话栏卡片另有悬停出现的 6 点把手；拖动中整页 grabbing。侧栏的行与组头长按另有菜单（第 6 轮改，测试机实测原来的窗口太窄：按住 250ms 后要再动才拿起、按到 500ms 就归菜单，按住 0.4s 后每步只移 8px 或按住 0.7s 的人一直进菜单、再也拖不起来）：按住 250ms 就拿起（浮起、进入拖动）；之后手指离按下处动出 10px（`TOUCH_DRAG_SLOP`，同长按菜单作废的距离 `LONG_PRESS_SLOP`：「在拖」与「菜单不出」同一个判断；第 6 轮审查改，原来 3px 时拿起前漂的几像素加上按住时的自然抖动就算在拖，长按菜单出不来）就是在拖，长按菜单不出；只有一直不动按到菜单时间（500ms，`hooks/use-long-press.ts` 的 `LONG_PRESS_MS`，沿用）才出菜单，拿起的那一项留着，菜单出来后手指再动就收起菜单、接着拖；按住不动到菜单出来再松手：浮层原地落下，菜单留着。拿起后没动、没到菜单时间（250–500ms）就松手是点按：浮层落回（取消拖动），照样打开对话 / 折叠组（第 6 轮审查：动作慢的人点按常超过 250ms，原来这一下被吞掉）；系统的 click 不用（拿起后的 touchmove 都拦了，各平台据此吞不吞 click 不一），在按下的元素上补一个。浮层在抽屉、手机会话栏（50）之上、菜单（60）之下（`OVERLAY_Z` 55；原来是拖动库默认 999，按住不动出来的长按菜单被拿起的整组盖住）。拖没拖起来由共用模块记到 `lib/layers.ts`（`markDragMoved` / `isDragMoving`），长按菜单看它。快速滑动（250ms 内动出 5px）仍是滚动列表。
- 浮起：拿起的那一项换成浮层（克隆原来的样子，挂在 body 上；克隆外面套一层层祖先的空壳——只抄元素本身、`display: contents` 不占版面——靠祖先生效的变量与规则照旧：公司组里对话行的缩进、手机抽屉的行与组头样式，拿起时文字不横跳、不变色；克隆根外边距清零，公司组整块不下移、不被裁）：弹层底、弹出阴影、透明度 0.9、放大 1.02，从原样浮起并实时跟手。原位一律留空档（排序与对话拖到别的公司同一个样子；多选里一起拖的其余各行留淡影 0.4）。排序时其余各项拖动中就带过渡滑开让位（动效变量）。
- 在组之间移动（侧栏对话拖到别的公司 / 最近，dnd-kit 多列排序的做法，只是空档的位置由排序方式定）：指针到了别的组，空档就跟过去，出现在它移过去以后按当前「排序方式」及升降序排的位置（那组「显示更多」之外的放在已显示的最后，`sidebar-groups.ts` 的 `liftRow`），那组的行带过渡滑开、原来那组的空档同时合上——两组之间整列的行、组头、「显示更多」位置变了都从原位置带同样的过渡滑过去（共用模块的 `flowLayout`：版面一变先记位置、再从差值滑回 0，Web Animations 播 translate，不碰行内样式；换组重挂的同一行按 `data-drag-id` 接着滑；滚动不算移动；这段时间关掉滚动区的滚动锚定 `overflow-anchor`，不然变动在可见区上方时浏览器改 scrollTop，没动的行先跳一下再滑回、下面的行直接跳；让位从画出来的那一帧起算，同排序项的 CSS 过渡，主线程忙时不吃掉前段）。空档的位置由排序方式定、不跟指针，落在滚动区可见范围外（拖到展开很长的组、组顶在上面）时滚动区平滑滚动、让空档进来（`revealGap`，只滚差的那一段）。在原组里移动：组里的先后由排序方式定、不能手调，空档留在原位、别的行不动。去的组收着（放不下空档）：组头用悬停色高亮，原位空档留着。指针在组与组之间、列外：空档留在上一次的地方，不来回跳。
- 放下：松手那一下只做一件事——浮层从放手处起播落位（`landOverlay`：Web Animations 只动 transform，交给合成线程；动效变量 --cc-dur / --cc-ease；从松手这一刻起算），落点在松手时就量好（空档此刻的位置，排序时加上它让位的位移）；结束拖动（拖动库与调用方的重画：整列重排、换组、量位置、改根节点的拖动标记、发请求）等落位播完才做（`ReleaseFirst`；鼠标、键盘传感器包一层 `landFirst`，手机传感器自带，放下都先交给 `beforeEnd`）。等着的这一小段（约 0.2s）拖动库的自动滚动不滚（落点不跑）；又按下了（要开始下一次）或页面在后台动画不走时当场结束。浮层的放大、阴影同时收回，落点那一项在动画播完前不显示；没落点滑回原位；取消（Esc）照旧由拖动库在结束那次提交里滑回原位（不回拨起点）。在组之间移动：浮层滑进去的那一组里的空档；去的是收着的组就落到组头并收起（`data-dropping="into"`，略缩、淡掉）；落点在滚动区可见范围外（拖着时又滚走了）就落到可见范围的边上并同样收起，不飞出列表，拖动库落位前那次 `scrollIntoView` 不让它滚（列表不跳）；落位播完才交给调用方（`onDrop`，侧栏这时才发移动请求，`Landing` / `settleMove`；落位已播完的在结束拖动那一次当场交，与结束拖动同一次提交），请求做完前整列仍跟着动——请求失败、退回原组时那一行同样带过渡滑回去，出错行出现时下面各行也滑下去。系统或设置要求减少动态效果时不播。第 6 轮测试机（手机 CDP 逐帧）：松手后约 80ms 一帧不出，帧一出来浮层 10ms 内跳了 75px。根因：原来落位在结束拖动那次 React 提交里起播、起点又回拨到松手前那一帧（`startNow`），侧栏松手那一下要做完结束拖动的整列重画（无界面 Chrome 6 倍节流、侧栏 50 多行：改根节点拖动标记后量位置引起的整页样式与布局 25ms、结束拖动的整列重画 45ms、提交 24ms，共约 100ms），主线程卡多久，帧一出来落位就已走了多少（22% → 92%）；会话栏卡片同一处（6 倍节流 72ms：整页样式与布局 24ms、提交 31ms）。现在松手那一下约 6ms（量位置、起播），重活挪到落位播完之后；之后那一次长帧（6 倍节流约 90ms）发生在浮层已停在落点时，看不出。
- 浮层停在只能高亮组头的落点上（去的组收着、放不下空档）：浮层让开——里面的字与条数隐去，只剩很淡的一层底（`--cc-drag-peek` 0.15，`data-peek`，沿用浮层的 opacity 过渡），被它盖住的组头文字与高亮清楚可读，离开就恢复（第 7 轮：手机上浮层正好盖住收着的组头，看不到高亮；第 8 轮：0.5 半透明时浮层的字与组头的字叠在一起）。
- 范围：只在本列竖着拖，浮层上下边不出这一列（排序：这一列第一项顶边到最后一项底边，按版面位置量，不含让位的位移；在组之间移动：能放的各组加原来那组）；在组之间移动时落到哪一组只看指针高度（横向按浮层，指针偏出列外照样认）。浮层是 fixed、不在滚动区里，拖到边上自动滚动只到列表首尾，不会滚进空白。
- 键盘与读屏：空格拿起、↑↓ 移动（在组之间移动：一组一组跳，含原来那组）、空格（或回车）放下、Esc 取消，三种语言播报（在组之间移动：去别的组念「将移到」，去过别的组再拖回原组念「将移到「原组」」——第 6 轮改，原来念「已拿起」——放下按实际结果念：真的移过去了念「已移到」，回原组没动念取消（第 7 轮：落位已播完时放下的处理先把这一项交出去、空档清回原组，播报读到的成了「原组」，移过去了却念取消；改为按放下那一刻定下的去处念）；排序的落回原位念取消、挪了念放到第几位；拿起时那一次「经过」原组不念）（会话栏卡片用卡片的词，侧栏用侧栏的词）；Alt+↑/↓ 在会话栏卡头、侧栏公司组头、置顶行上直接挪一格，挪完同样念「移到第 N 位，共 M 项」（同键盘拖动的词，到头了没挪不念；共用拖动区自己的播报区，第 5 轮）。拿起时只念「已拿起」：拖动库拿起后紧跟着报一次「经过」的是拿起的那一项自己，这一次不念位置（第 5 轮：公司组头空格拿起念成「移到第 3 位」）；挪开过再回原位照常念位置。拖动中的 Esc 只取消拖动：不关浮着的会话栏、不清侧栏多选（`lib/layers.ts` 在 window 捕获阶段先记下这次 Esc），方向键也不移侧栏焦点。键盘拖动中焦点一直在被拖那一项的把手上：拖动中按在把手上的方向键（含 Home / End / 翻页、Alt+方向键）只归拖动，标成已处理，组件库对话行自带的 ↑↓ 导航不接手；在组之间移动的那一行换组重挂后焦点跟到新节点（`useFollowFocus`），方向键连续跨组；放下 / 取消后焦点留在移动后的那一行（随后请求做完又重挂也接回，只在焦点丢了时；落进收着的组给组头开关；鼠标点了别处不再接回；`keepFocusOn`）（第 8 轮：跨一次组后焦点掉到邻行，之后方向键只移焦点、拖动卡住）；已经放手、只等落位播完的那约 0.2 秒不算（`releaseDrag`），这时的 Esc 当场结束拖动并照常关一层（第 6 轮审查）。Esc 一次只关一层、最上面的先关：弹窗 / 菜单 > 拖动 > 改名、编辑框 > 浮着的会话栏 > 侧栏多选；关掉一层的都标记已处理，下面一层见到就不动（第 5 轮：取消拖动后再按 Esc，会话栏和多选被一起清掉）。关掉浮着的会话栏、设置弹窗以后焦点回到打开它的控件（会话栏开关、「公司名 ›」、齿轮、用户菜单按钮——菜单里的「设置」打开的回菜单按钮、Ctrl+, 打开的回原来的焦点）；那个控件不在了（或没记到：焦点在 BODY 时按 Ctrl+,、Safari 鼠标点按钮不拿焦点）回会话栏开关，设置先回齿轮、齿轮不在才回用户菜单按钮（按这个先后，不按页面上的先后；第 6 轮审查）；焦点原来不在这一层里（已经点去了别处）不抢；键盘关的出焦点描边，鼠标关的不出（`lib/focus-return.ts`，第 6 轮第 4 项：Esc 关掉后焦点落到 BODY）。
- 第 4 轮测试机两处的根因（按代码路径、headless Chrome 实测与录屏帧推断，没在真机上逐帧剖析主线程）：① 放手后停 0.35–0.5s：原来拿起的就是列表里那张卡本身，放下靠自写的 translate 过渡把它从放手处挪回，这个过渡要等 React 提交新顺序、拖动库收尾重测之后的下一次样式计算才开始，手机上这段主线程工作约 0.4s，卡就停在放手处压着下一张；② 滚过最后一张：限位修饰器只限住了指针位移，拖动库随后又给那张卡加上滚动差，卡被推到列表外、撑大了会话栏的可滚范围，自动滚动于是一路滚进空白。现在浮层与列表分开、动画在放下当帧开始、浮层不进滚动区，两处一起结构性去掉。
