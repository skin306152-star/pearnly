### 1.5 结论（第一步）

**A. 单别对不上（最大的两处，第二步先核）**
1. 物料调整 IA 写成盘点调整 TK；用户要的是 4-3-1（疑 JU「ปรับปรุงเพิ่ม/ลดสินค้า」）。TK 与 JU 的落库差很多：POSOPR `:` vs 8、单头无货值无科目 vs 有对方科目、盘盈取批次成本 vs 取填的单价、凭证摘要不同。
2. 入库 IR 写成 JU（正）；4-3-2 是哪簿待核（疑 PI，对方科目是在制品 11-04-03 一类）。

**B. Express 有、Pearnly 没入口或没传**
1. **单据簿选择**：OU 类每家账套有多本（自用、样品、报损、生产领料…，各带默认科目），财务原生是按用途选簿；Pearnly 固定写 OU 一本，「用途」（内部领用 / 报损）没传过去。JU 类同理。
2. **单号**：原生用 ISRUN 流水；CC 自编号且白涨 ISRUN（原生下一张会跳号）。
3. 部门 DEPCOD：取 CC 桌面版设置，不是单据上选的；单头 / 明细的 JOBCOD、COSCOD、REFDAT、PEOPLE（出入库）Pearnly 都没有——原生界面上是否有这些栏待第二步看。
4. 科目：只能在第一次提交弹窗选一次、按公司记住；原生每张单都能改。
5. 行号补位：OU / JU 的 NXTSEQ、GLJNLIT.SEQIT 写的是否与原生补位一致待比（STCRD.SEQNUM 已右对齐）。

**C. Pearnly 有、Express 没处放（有意不同，建议保留）**
仓位、调入仓位、供应商、用途（若 B1 改成选簿就用上了）、附件、物料调整的按台号码（TK / JU 是轧差数）。

**D. 手机**：与网页同一页同一接口，字段一致；第二步照样各录一遍取证。

### 2.5 业务问题：4-3-2「收货入库」= PI，与 JU 调增有什么不同

- **PI「รับส/คสำเร็จรูปจากการผลิต」= 生产完工收货**：把自己生产好的成品收进仓。凭证 **借 存货 / 贷 11-04-03 งานระหว่างทำ（在制品）**，即把在制品
  转成成品；单价填的是生产成本。没有生产（没有领料到在制品）的公司用它，会把在制品记成负数。
- **JU「ปรับปรุงเพิ่ม/ลดสินค้า」调增 = 数量调整**：盘盈、找到货、原因不明的增加。凭证 **借 存货 / 贷 51-01 ต้นทุนสินค้าเพื่อขาย（冲减销货成本）**，
  增加的价值算作成本减少（利润增加）。
- 两者落库一样（POSOPR 1 成为一批、按填的单价进均价），只差对方科目与簿 / 编号。
- **岳父「操作员收到货入库」**：货是从供应商来的，原生正确做法是 **进货单**（赊购 RR / 现购 HP，带供应商、带税），不是 4-3-x；
  ERP 里采购确认后自动生成的入库单就是这条路（不另写）。走 4-3-x 的只该是**非采购**的入库：自产完工 → PI；退库、盘盈、找到货 → JU 调增。
  所以「入库」统一改成 PI 并不对：没有生产的公司会挂出负的在制品。建议由用户 / 岳父定：入库按「来源」分（自产 → PI，其他 → JU），
  或入库固定 JU、只在选了「生产完工」时写 PI。

## 五、已知差异与 Express 重算实测（方案 A，11-18 下午，70EXP\test，已还原）

同一基线、同样内容：原生在界面录 OU（两行）→ RL → JU（三行）→ PI；CC（分支源码，方案 A、原生流水号）写同样四张。之后两边都在 Express
界面原生存同样的同日单，逐栏比。物料 A = 批次链已为负（实录 500603），物料 B = 批次干净（501780）。单号两边已相同（OU0000002 …）。

| 情形 | 原生（录单时 → 之后存同日 JU 后） | CC 方案 A（写入时 → 之后原生存同日出库 → 之后原生存同日 JU） |
|---|---|---|
| ① 批次链已断 / 为负（物料 A 出 1） | 0 → 111.96 → 109.96 | 200.22 → 200.22（存出库不重算）→ **0**（存 JU 时 Express 重算成 0） |
| ② 同日先出后进（物料 B 出 2，后有 JU、PI 进价 40） | 48 → 46.15 → 45 | 48 → 48 → 48 |
| 之后原生出库物料 A 1 个的成本 | 111.96 → 109.96 | 89.89 → **0** |
| 第一张出库凭证 | 96 → 204.27 → 201.96 → 199.96 | 296.22 → 296.22 → **96**（物料 A 那行被算成 0） |
| 物料 A 主档总金额 | 9,639.86 | 9,859.78（差 219.92），批次链停在 −1 |

结论：
- 原生存**出库**单不回头重算前面的单；存**进货类**单（JU / PI / 进货）时 Express 会重算同日已有的出库（含 CC 写的）。
- 但它重算时用的是明细上的批次栏（MLOTNUM / MREMBAL / MREMVAL / LOT*）。CC 写的批次栏与原生口径不一致：调拨明细没有批次指针；
  增加行、批次链为负时的结存口径不同。结果 Express 把 CC 的出库和之后原生出库同一件物料的成本**重算成 0**，凭证跟着改，
  **不收敛到原生，反而更偏**。
- 4-7-4 计算成本不做这件事（见 4.2）。
- 影响面：任何账套里有 CC 写的出库 / 调整，之后财务在 Express 原生存进货类单，同日（及之后）的出库成本可能被 Express 算成 0。
  CC 写的采购 / 销售也不维护批次链（既有做法），同类风险未实测。

## 八、现行口径对照、最终写法与已知差异（11-18 下午，70EXP\test 每轮还原）

### 8.1 现网写法缺陷（main 现行库存写法）

### 8.3 本分支最终写法（V3，提交 07e562fed）与收敛实测
- 增加行（JU / PI）：照原生（POSOPR 1、成批、写前结存、为负记 0、批次指针写原样）。
- 减少行（OU、JU 减少）：照 CC 写销售 IV 的现行口径（写后结存、不带指针、批次链有结存按批次价，否则按均价）。
- 调拨：两行带当前批次指针。
- 收敛实测（CC 写四张 → 原生存同日 JU，与全程原生逐栏比）：没有任何行被算成 0，凭证都在。剩余差异见 8.4。
- 试过的其他口径（减少行写前 + 指针、写前不带指针、调拨补指针前后）对最终结果没有改善，或更差（带指针会被算成 0）。

### 8.4 已知差异（不改别的单是底线）
- 只在「批次已断」时出现：原生出库那一刻按 0 出，财务存进货时 Express 把它改挂到新批（OU0000002：0 → 111.96 → 109.96）；CC 出库按均价出，

- 同日先出后进：原生在存 PI 时重算同日出库（48 → 45），CC 写 PI 不触发重算；之后原生存同日进货，物料 B 出库单价 CC 44.2 vs 原生 44.5455，
  链上结存差 3。
- 这两种差异要收敛，只能让 CC 去改动同日已存在的出库单（含财务原生录的单），未经用户同意不做。

- 物料 A 总金额差 712.8（一个单位）：CC 路径多一张调拨，原生调拨没录上，待原生调拨对位录成后再比、查到原因并对齐。
- 采购 / 销售（CC 现行写法）：赊购（A ×5 @700）不被改；赊销（B ×1，CC 按均价 33.29）在原生存同日进货后被 Express 重算为 33.32、凭证同步；没有被清零。

### 9.1 先进先出一轮续（原生调拨对位录成后）
- 批次干净物料差 712.8 的原因：分仓计价账套（ISINFO.LOC_COST = Y）原生调拨**带金额**——两行按出库成本计价、单头记货值，调入那一行成为调入仓的新一批
  （批号 = 日期 + 3 + 单号行号，LOT* 记入，NETVAL = 金额）；CC 原先两行都不带金额、调入不成批，Express 重算后少一个单位。
  已改 `dbf_transfer`：分仓计价账套照原生写（不分仓计价的 70EXP 实录本来不带金额，照旧）。重跑后该物料总金额、单价、凭证与原生一致；
  只剩明细与主档的批次链结存栏（MREMBAL / MREMVAL）记法不同（Express 内部链记账，不影响成本与凭证）。
- 批次已断物料（主档批次链 0、总结存 2,573）：原生存第一张出库时就把这件物料的整条先进先出批次链重算（主档批次结存 0 → 约 2,422），取最早一批
  剩余单价 33.33；CC 不做整链重算，按均价出，之后 Express 重算为 29.74。要对齐需在 CC 里复刻先进先出整链计算——待与主会话定。

### 9.2 先进先出出库取价（主会话定：不复刻整链，用有实录依据的简单规则）
- 规则：先进先出账套的出库 / 调整减少，按这件存货**最早仍有剩余的批**取价（进来的批按日期排，减去已出总数 = 进来合计 − 主档总结存），
  出得比这一批多就顺着往后几批摊。只读本存货库存卡，不改别的行。
- 实录依据（原生写入时）：613023026101 规则 33.313 / 原生 33.312；VSRC00019 712.8 / 712.8；613023026105 163.787 / 163.784；
  613093044105 140.653 / 140.654。
- 测试机实测：写入时 CC 33.31、原生 33.33（原来按均价 33.29）。**之后原生存同日进货，Express 把 CC 的这两行重算为 29.73**（原生 33.33）——
  原生存第一张出库时会重建这件存货主档上的整条批次链结存（0 → 约 2,422），Express 之后按它重算；CC 不做整链。差额每件 3.60，列为已知差异。
- 对照：CC 现行写法的赊销（同一件）在原生存同日进货后被 Express 收敛到 33.32（差 0.01）；库存出库这一行不收敛（29.73 vs 33.33）。

## 十一、分仓计价账套的批次链在 STLOC（11-19，69EXP 先进先出 + 分仓计价测试账套，每轮按基线还原）

- **根因**（推翻 9.2 的「原生整链重算」说法）：分仓计价账套（ISINFO.LOC_COST = Y）的先进先出批次链按「存货 × 仓」记在 STLOC：
  `MLOTNUM`（当前那一批）、`MREMBAL` / `MREMVAL`（链上结存与货值），`LOCVAL` 也随单增减。主档 STMAS 上那条只是最后动过的那个仓的抄本，
  可能是陈旧的。例：613023026101 的 01 仓链 2418 / 80549.5（指 RR2400191），主档 0（指 35 仓那一批）。
  原生在 01 仓出 1：取 01 仓链的价 33.31，明细记 01 仓链写前 2418 与指针，写后 01 仓链与主档都是 2417 / 80516.2。
  9.2 看到的「0 → 约 2,422」就是把 01 仓的链抄到主档。
- CC 原写法只读写主档那条链：增加行指错批（指到 35 仓）、明细结存记成 −1 / −2；财务之后在 Express 存同日进货，Express 照这些值重算，
  出库 33.33 → 29.73。
- **修法**（ce118666b、3e8d910fd，新模块 `companion/stock_chain.py`）：只改 CC 自己写的新行与主档类派生栏，不动任何已有单据行。
  - 分仓计价账套逐个 (存货, 仓) 判：这个仓记着链（有批号，或还没有结存）就按仓走：
    - 出库 / 调整减少：按这个仓的链取最早仍有剩余的批（从最新的批往回数到链结存为止）；
    - 明细：增减都记这个仓的链写前结存与指针；
    - 写后：这个仓的链与 `LOCVAL` 更新；主档的批次栏抄这条链（总结存照旧增减）；
    - 调拨：调出仓与调入仓各自处理，调入那一批成为调入仓链上最新的一批，主档抄调入仓的链。
  - 这个仓有结存却没批号的：照旧用主档的链。
- 实测（新写入器写 OU / RL / JU / PI 四张）：613023026101 的 01 仓链、主档链、`LOCVAL` 都是 2421 / 80682.9，与原生（NK4r）一致；
  旧写入器是主档 3 / 133.38、明细 −1 / −2。VSRC00019 不同：原生调增 +3 那一行没进 01 仓链（链 7），CC 进了（链 10），原因未明。
- **收敛实测**（新写入器写四张 → 财务原生存同日调整单 nJU2，对照原生 NKJr）：
  - 613023026101 的 CC 出库两行被 Express 重算为 33.33 / 单价 33.331，与原生一致；旧写法是 29.73。
  - 五张单的凭证分录逐条与原生一致：OU 1458.93、JU 2066.67（旧写法 1455.33 / 2070.27）。
  - 仓库货值、总结存、总货值一致。
  - **已知差异**：两件物料的批次链结存栏比原生少 2（2420 对 2422；5 对 7）。这是 Express 重算时的内部链栏，不影响这些单的成本与凭证，原因未查。
- **采购 / 销售同类现网缺陷**（只查未改，另开分支评估）：CC 写进货、销货的库存行同样只读写主档那条链，不碰 STLOC 的链与 `LOCVAL`。
  11-18 实测（CC 赊购 VSRC00019 ×5 @700、赊销 613023026101 ×1 → 原生同日调整单）：
  - 进货那行不成批（LOTBAL 0、无指针），之后主档链被 Express 改回、这 5 个不在先进先出链里；
  - 01 仓 `LOCVAL` 少记 3,500；
  - 销货写入时按均价 33.29，重算后 33.32；01 仓链与 `LOCVAL` 都没减。
- 只读统计（服务器 15 本先进先出 + 分仓计价账套，按原始字节读）：
