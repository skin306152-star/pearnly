### 1.5 结论（第一步）

**A. 单别对不上（最大的两处，第二步先核）**
1. 物料调整 IA 写成盘点调整 TK；用户要的是 4-3-1（疑 JU「ปรับปรุงเพิ่ม/ลดสินค้า」）。TK 与 JU 的落库差很多：POSOPR `:` vs 8、单头无货值无科目 vs 有对方科目、盘盈取批次成本 vs 取填的单价、凭证摘要不同。
2. 入库 IR 写成 JU（正）；4-3-2 是哪簿待核（疑 PI，对方科目是在制品 11-04-03 一类）。

**B. Express 有、Pearnly 没入口或没传**
1. **单据簿选择**：OU 类每家账套有多本（自用、样品、报损、生产领料…，各带默认科目），财务原生是按用途选簿；Pearnly 固定写 OU 一本，「用途」（内部领用 / 报损）没传过去。JU 类同理。
2. **单号**：原生用 ISRUN 流水；CC 自编号且白涨 ISRUN（原生下一张会跳号）。
3. 部门 DEPCOD：取 CC 桌面版设置，不是单据上选的；单头 / 明细的 JOBCOD、COSCOD、REFDAT、PEOPLE（出入库）Pearnly 都没有——原生界面上是否有这些栏待第二步看。
4. 科目：只能在第一次提交弹窗选一次、按公司记住；原生每张单都能改。
5. 行号补位：OU / JU 的 NXTSEQ、GLJNLIT.SEQIT 写的是否与原生补位一致待比（STCRD.SEQNUM 已右对齐）。

**C. Pearnly 有、Express 没处放（有意不同，建议保留）**
仓位、调入仓位、供应商、用途（若 B1 改成选簿就用上了）、附件、物料调整的按台号码（TK / JU 是轧差数）。

**D. 手机**：与网页同一页同一接口，字段一致；第二步照样各录一遍取证。

### 2.5 业务问题：4-3-2「收货入库」= PI，与 JU 调增有什么不同

- **PI「รับส/คสำเร็จรูปจากการผลิต」= 生产完工收货**：把自己生产好的成品收进仓。凭证 **借 存货 / 贷 11-04-03 งานระหว่างทำ（在制品）**，即把在制品
  转成成品；单价填的是生产成本。没有生产（没有领料到在制品）的公司用它，会把在制品记成负数。
- **JU「ปรับปรุงเพิ่ม/ลดสินค้า」调增 = 数量调整**：盘盈、找到货、原因不明的增加。凭证 **借 存货 / 贷 51-01 ต้นทุนสินค้าเพื่อขาย（冲减销货成本）**，
  增加的价值算作成本减少（利润增加）。
- 两者落库一样（POSOPR 1 成为一批、按填的单价进均价），只差对方科目与簿 / 编号。
- **岳父「操作员收到货入库」**：货是从供应商来的，原生正确做法是 **进货单**（赊购 RR / 现购 HP，带供应商、带税），不是 4-3-x；
  ERP 里采购确认后自动生成的入库单就是这条路（不另写）。走 4-3-x 的只该是**非采购**的入库：自产完工 → PI；退库、盘盈、找到货 → JU 调增。
  所以「入库」统一改成 PI 并不对：没有生产的公司会挂出负的在制品。建议由用户 / 岳父定：入库按「来源」分（自产 → PI，其他 → JU），
  或入库固定 JU、只在选了「生产完工」时写 PI。

## 五、已知差异与 Express 重算实测（方案 A，11-18 下午，70EXP\test，已还原）

同一基线、同样内容：原生在界面录 OU（两行）→ RL → JU（三行）→ PI；CC（分支源码，方案 A、原生流水号）写同样四张。之后两边都在 Express
界面原生存同样的同日单，逐栏比。物料 A = 批次链已为负（实录 500603），物料 B = 批次干净（501780）。单号两边已相同（OU0000002 …）。

| 情形 | 原生（录单时 → 之后存同日 JU 后） | CC 方案 A（写入时 → 之后原生存同日出库 → 之后原生存同日 JU） |
|---|---|---|
| ① 批次链已断 / 为负（物料 A 出 1） | 0 → 111.96 → 109.96 | 200.22 → 200.22（存出库不重算）→ **0**（存 JU 时 Express 重算成 0） |
| ② 同日先出后进（物料 B 出 2，后有 JU、PI 进价 40） | 48 → 46.15 → 45 | 48 → 48 → 48 |
| 之后原生出库物料 A 1 个的成本 | 111.96 → 109.96 | 89.89 → **0** |
| 第一张出库凭证 | 96 → 204.27 → 201.96 → 199.96 | 296.22 → 296.22 → **96**（物料 A 那行被算成 0） |
| 物料 A 主档总金额 | 9,639.86 | 9,859.78（差 219.92），批次链停在 −1 |

结论：
- 原生存**出库**单不回头重算前面的单；存**进货类**单（JU / PI / 进货）时 Express 会重算同日已有的出库（含 CC 写的）。
- 但它重算时用的是明细上的批次栏（MLOTNUM / MREMBAL / MREMVAL / LOT*）。CC 写的批次栏与原生口径不一致：调拨明细没有批次指针；
  增加行、批次链为负时的结存口径不同。结果 Express 把 CC 的出库和之后原生出库同一件物料的成本**重算成 0**，凭证跟着改，
  **不收敛到原生，反而更偏**。
- 4-7-4 计算成本不做这件事（见 4.2）。
- 影响面：任何账套里有 CC 写的出库 / 调整，之后财务在 Express 原生存进货类单，同日（及之后）的出库成本可能被 Express 算成 0。
  CC 写的采购 / 销售也不维护批次链（既有做法），同类风险未实测。

### 7.2 库存单批次栏收敛（变体实测，写入器变体只在测试机副本，`~/pearnly-devtools/sp1118-dbf_stock-variant.py`）
参照：原生四张（OU / RL / JU / PI）→ 原生同日 JU（物料 A +1 @100、物料 B +1 @30）。CC 路径：CC 写同样四张 → 同一张原生 JU，整本逐栏比。

| 变体 | 写入时（重算前）与原生差异 | 原生 JU 后物料 A 出库成本（原生 109.96） | 物料 B |
|---|---|---|---|
| A（分支现状：批次空按均价） | 成本 200.22 vs 0 | 0（被 Express 算成 0） | 差 |
| V1（批次空按 0、带指针、写前结存） | 主档「-」标记带进明细指针 | 0 | 差 |
| V1c（明细指针还原原样） | 只差增加行写前结存 −1 vs 0 | 0 | 差 |
| V1d（增加行写前结存为负记 0） | **写入时与原生逐栏一致**（只差原生存单时自动重算动过的行） | 0 | 差（链上结存差 3） |

查出的 Express 规则（逐栏反推）：
- R1 主档批次栏变负时首字符改「-」，但明细上的批次指针写原样（「-/F」原样是「B/F」，日期打头的是「2」）。
- R2 增加行（JU / PI）的写前结存数量为负时记 0。
- R3 **原生存进货类单时，Express 会把同日已存在、指向已用完批次、按 0 出的出库行改挂到新批次，并按新链重算成本和凭证**（原生 OU0000002：0 → 111.96）。

- R4 原生调拨两行带批次指针与链结存，Express 重算把它们算进链；CC 调拨行不带，链上结存差调拨数量（3）。
要收敛，CC 写进货类单时须照 R3 改挂同日（及之后）的出库行（含财务原生录的单）并改凭证，调拨照 R4 带批次栏；其余 R1 / R2 已在变体验证。

## 八、现行口径对照、最终写法与已知差异（11-18 下午，70EXP\test 每轮还原）

### 8.1 现网写法缺陷（main 现行库存写法）
- 复现：基线上用 main 的 CC 写入器写 OU（两行）→ RL → JU（三行，含增加行）→ 入库（main 写成 JU 正数）；然后在 Express 界面原生存一张同日 JU
  （物料 A +1 @100、物料 B +1 @30）。
- 结果：Express 重算把 CC 写的入库 JU（+5 × 150，750）和入库（+6 × 40，240）的明细金额都改成 **0**，并把这两张单的凭证分录**打了删除标记**；
  原因是 main 的调整增加行写 STCRD.POSOPR 8、不成批（原生是 1、成批），Express 不把它当进货批。
- 影响：生产上写进过 Express 的库存单只有测试租户的 1 张入库（主会话 11-18 只读核），客户账套未受影响。本分支已改为原生写法（增加行 1、成批）。
- 守住：`companion/tests/test_dbf_stock.py` 增加行 POSOPR 1 与 LOT* 的断言；真实环境回放步骤即本节复现步骤（CC 写入库 → 原生存同日进货 → 我们的入库金额与凭证都在）。

### 8.3 本分支最终写法（V3，提交 07e562fed）与收敛实测
- 增加行（JU / PI）：照原生（POSOPR 1、成批、写前结存、为负记 0、批次指针写原样）。
- 减少行（OU、JU 减少）：照 CC 写销售 IV 的现行口径（写后结存、不带指针、批次链有结存按批次价，否则按均价）。
- 调拨：两行带当前批次指针。
- 收敛实测（CC 写四张 → 原生存同日 JU，与全程原生逐栏比）：没有任何行被算成 0，凭证都在。剩余差异见 8.4。
- 试过的其他口径（减少行写前 + 指针、写前不带指针、调拨补指针前后）对最终结果没有改善，或更差（带指针会被算成 0）。

### 8.4 已知差异（不改别的单是底线）
- 只在「批次已断」时出现：原生出库那一刻按 0 出，财务存进货时 Express 把它改挂到新批（OU0000002：0 → 111.96 → 109.96）；CC 出库按均价出，
  之后 Express 按新链重算为 100。实录差额 9.96（物料 A 总金额 9,759.78 vs 原生 9,749.82），**不为 0、凭证都在**。
- 同日先出后进：原生在存 PI 时重算同日出库（48 → 45），CC 写 PI 不触发重算；之后原生存同日进货，物料 B 出库单价 CC 44.2 vs 原生 44.5455，
  链上结存差 3。
- 这两种差异要收敛，只能让 CC 去改动同日已存在的出库单（含财务原生录的单），未经用户同意不做。
