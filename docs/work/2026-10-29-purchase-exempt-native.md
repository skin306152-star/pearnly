# 直写进货单整单免税照 Express 原生记法（2026-10-29）

主会话 10-29 定：生产写账缺陷，排第一；照原生改，改在共用的 express_rules，直写与代录一起受益；独立分支，验收复核后随下一批上线。
基线：origin/main 8a8c9b0f。分支 `pearnly/purchase-exempt-vat`。

## 影响评估

- **现象**：
  - CC 直写进货单 `has_vat = vat > 0`（`dbf_writer.write_purchase`）。整单免税的进货单记成 FLGVAT 0、不写进项税记录。
  - ERP 采购单只在混合税率（有行 > 0%）时标免税行；勾了税务发票但全是 0% 的单，一行都不标。
  - 销货、退货早已按原生改过（`has_vat = vat > 0 or bool(entry.vat_fields)`），进货漏了。
- **原生记法**（测试机语料 158 本只读统计；「按商品记增值税」开关打开 21 本、关闭 137 本，两种模式结果一样）：
  - 免税单：价格类型 FLGVAT 1（现购）/ 2（赊购），税率 7%；免税明细 VATCOD '0'、NETVAL = TRNVAL；单头 AMTRAT0 = 免税额；ISVAT 一行 AMT01 = 应税部分（整单免税为 0）、VAT01 = 税额、AMTRAT0 = 免税额。
  - 例：BakeLab RR680121-011（关闭模式）、ASIA MIN RR670229-009（打开模式）。
  - FLGVAT 0 只用于供应商不开税票的单（37,478 张，明细不标免税）。
- **同类与落点**：
  - ERP 收银日汇总 / 退货与混合税率采购已用同一套键：明细 `vat_exempt`、表头 `vat_fields`（AMT01 / AMTRAT0）。
  - 整单免税就是「免税额 = 整张税前」的同一情形。
  - 把「免税额 → ISVAT 金额栏」与「载荷版本」收进共用 `express_rules`，ERP 推送调它；CC 直写进货判断改成与销货一致。
- **上下游**：
  - ERP：勾了税务发票（`has_vat`，默认勾）而行税率 0% 的行标免税；没勾的整张照旧是无税（FLGVAT 0）。
  - Cowork 识别：票面没有逐行免税标记，税额 0 的照旧写 FLGVAT 0。免税商品还是供应商不收税，靠识别分不出来，另报主会话定口径，本次不动。
  - 代录：草稿按免税行选价格类型（`a9f8a660`，在 `pearnly/express-operator`）。
- **CC 桌面版**：要发新版。载荷盖新版本号 12（整单免税的进货单），旧版 CC 按版本诚实拒收，派单只交给报过支持 12 的电脑。
- **生产已写的单**（10-29 一次 SSH 只读 SELECT）：
  - 正式客户 0 张：ERP gize / mrerp / polymer 还没直写过采购单；erpcowork 没有进货推送。
  - 演示 / 测试租户：ccdemo 税额 0 的 4 张（3 张带供应商税号）、testcowork 21 张（19 张带税号）。都是 Cowork 识别来的，分不出是否免税；testerp 写过 2 张，都不是税额 0。
  - 已写的单不改。
- **验收**：
  - 62 本清空测试账套离线回归（整单免税 RR / HP、混合、无税三种，核单头 / 明细 / ISVAT 与未写表逐字节不变）；
  - 语料两种模式真实免税单按答案逐字段比对；
  - CC 契约测试；ERP 推送单测。
