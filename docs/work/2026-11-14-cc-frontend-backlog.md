### 8.4 专查三件

**甲 CC 自己新开对话、或把内容放到别的对话**
- 服务端从不因定时任务、LINE 来单、提醒、回执自己新建会话：会话只在 `K/assistant/sessions.py:451`（用户点新对话）与 `:507-520`（建代录任务同时建它那段，= 触发对话）建；`express_operator/tasks.py:314-332` 旧代录任务补建属旧数据兼容。CC 桌面版也不自己开对话（只有快捷输入条 D16，用户发起）。
- **CC 自己开新对话的在网页前端**：提醒点开的落点（P-10，`F/lib/nav.ts:343-385`）、侧栏待处理占位行点了开新对话（W09）。按新口径要改。
- **内容落到别的对话 / 对话之外**：P-3（ERP 要人选 → Desk 弹窗 / 新窗口）、P-6（对账 → Desk）、P-7（定时任务结果挂建任务的对话、挂不上只有通知）、P-9（别的对话提醒带进当前对话）、D01（批次结果只在执行电脑托盘）。
- 用户点「交给 CC」开新对话预填（W21）是用户发起、不自动发，不算 CC 自开；要不要改成预填进当前对话，可一并定。
- **没有「触发它的对话」的纯后台任务（要用户定落点）**：① 按计划运行的定时任务（运行前提醒、完成简报），尤其网页上建、从没在 CC 里碰过的任务；② 每天 08:30 待处理日报；③ LINE、ERP / Cowork 网页发起、由 CC 桌面版写账的单的结果（D01 现在只在执行电脑上弹）；④ 直写结论晚到时原对话已被删 / 归档。建议：内容留在原入口（定时任务页、「待处理」、LINE 回复、单据状态），对话里不新开；若要进对话，固定挂「公司 · 本月」那段对话；叫人照 ② ③。LINE 来的单（S13–S15）只回 LINE，属 LINE 入口自己的，不动。

**乙 「是否在当前对话页」现在怎么判**
- 最准的现成判定：`F/lib/managed-agents/activity.ts:49-51` `viewing()` = 是当前活动对话 且 对话页开着 且 `document.visibilityState === "visible"`，但**只用于侧栏圆点**，不用于通知。
- 回复完成通知只看整窗 `document.hasFocus()`；提醒在桌面版不判；推送不判（服务端没有任何「谁在看哪段」的状态，唯一相关是 `sessions.notices_seen` 记已看，`K/assistant/sessions.py:1087`）。
- 手机：同浏览器，装成应用切后台时 visibilityState = hidden，可用。
- CC 桌面版：托盘拿得到窗口 visible / active、锁屏、屏幕关、被完全挡住 3 秒（`visibility_watch.py`），但不知道是哪段对话；QtWebEngine 里窗口被挡住时 `hasFocus` / `visibilityState` 的取值没核实。
- 多标签 / 多设备：各判各的，没有协调；已发出的通知不撤回。
- 结论：新口径要一个统一判据——页面（浏览器、手机、桌面版窗口）上报「在看哪段 + 可见」，服务端发推送、托盘弹通知前都按它判。

**丙 开关与账户静音**
- Desk 的提示音遵守账户静音（`frappe.utils.play_sound`、`product.js:264-267`，K03 对账提示音走它）。
- CC 网页 / 手机 / 桌面版**没有自己的提示音**，也都**不读账户静音**；网页推送只有每台设备自己的开关（`F/lib/push.ts`），服务端不看偏好；桌面版没有通知开关，只能在 Windows 设置里关。
- 新口径的「不在就响」是新增能力，必须同时接账户静音，否则违反 AGENTS.md。

#### 乙：「是否在当前对话页」现在怎么判定

- 侧栏圆点与「看过」：`F/lib/managed-agents/activity.ts:49-51` viewing() = 是当前活动对话 且 对话页开着（不是定时任务页）且 `document.visibilityState === "visible"`。这是最接近新口径的判定，但**只用于圆点，不用于通知**。
- 回复完成通知 W01：只看 `document.hasFocus()`，且只盯当前活动对话；同一页切到别的对话后原对话跑完不通知；等人（W02）完全不通知。
- 提醒通知 W03：CC 桌面版窗口里不判（一律弹）；浏览器只看 `hasFocus()` 与推送开没开，不看是不是这段对话。
- 推送 W04：后台脚本不判，服务端也不判（无「在线 / 正在看」状态）。
- 手机：同浏览器；装成应用后切到后台 visibilityState 变 hidden。手机上切到别的 App 时 hasFocus 为假，判定可用。
- CC 桌面版窗口被挡住 / 最小化：QtWebEngine 里 `hasFocus()`、`visibilityState` 的取值**没核实**（窗口被别的窗口挡住但仍是前台时可能仍算 visible）。
- 多标签 / 多设备：每个标签各判各的，没有跨标签协调；同一人两台设备都会收到推送；「看过」靠服务端 `notices_seen` + 列表 unread 同步圆点，但不撤回已发出的通知。新口径要「在对话里就不响」，需要页面把「正看着哪段」回报给后台脚本 / 服务端，现在没有。

#### 丙：提示音与通知的开关、账户静音

- 提示音：CC 网页 / 手机**没有任何自己的提示音**（无 Audio / play / AudioContext）；系统通知未设 `silent`，响不响由操作系统与浏览器的通知设置决定。
- 通知开关：只有设置里的「通知」推送开关（W30，`F/lib/push.ts`）。注意它只管 Web Push 订阅；W01 回复完成通知和推送关着时的 W03 只看浏览器通知权限，**关了开关仍可能弹**。CC 桌面版窗口里没有这一行，系统通知由桌面端自己管。
- 账户静音：前端与 `K/assistant/` 都没读 Frappe 用户设置的静音（grep mute_sounds 0 命中），**不遵守**。新口径加提示音时应读账户静音（Desk 已有的规矩）。
- 对话提醒卡里的「打开通知」按钮（W07）是第二个入口，与 W30 同一个 `usePush`。

#### 乙　「人在不在当前对话」现在怎么判（桌面版）

- **回复完成（D04）**：对话页 `document.hasFocus()`。CC 窗口在前面且激活 = 在；藏到托盘、最小化、被别的程序抢了焦点 = 不在。**被挡住但已失焦**算不在（会弹）；**CC 与 Express 并排、焦点在 Express** 也算不在（会弹）。只看当前显示的对话：`isRunning` 只跟当前对话，别的对话跑完不叫人（没核实真机）。
- **提醒（D03）**：桌面端完全不判（`desktop.ts:126` 桌面端一律弹）；**D02 文件夹同步那路、D01 批次通知也不判**，CC 窗口开着、人正盯着那段对话照弹照响。
- **托盘其实拿得到窗口状态**：窗口进程随 `status` 报 `visible / active / url / paused`（`window_main.py:206-215`、`window_link.WindowHost`；`visibility_watch.py` 还会判锁屏、屏幕关、被完全挡住 3 秒），但只用于「停画」与「自动更新先不装」（`gui_tray.py:_window_open`），通知判定没用它。
- **托盘不知道窗口里是哪段对话**：桌面端地址不跟对话变（`frontend/assistant/src/lib/nav.ts:208-214` 桌面端不改地址），所以 `url` 认不出当前对话；要按新口径判，需要页面经桥报「当前对话编号」（例如 `window.tomo` 加一个读当前对话的方法，或状态里带上）。
- **多设备**：D01 / D02 弹在**执行任务的那台电脑**（可能是办公室共用机，不是发起人在用的设备）；手机 / 浏览器另有推送（`push.send_notice`），各端不知道别的端是否已在看那段对话。新口径下应以「发起人在不在那段对话」为准，执行电脑本身不该替别人叫人（待主会话定）。

#### 丙　提示音、通知开关、账户静音

- **提示音**：桌面版与网页 CC 都没有自带提示音代码（无 winsound / MessageBeep / `new Audio`）。响声全来自 Windows 应用通知（`toast.py` 没设 `audio`，按库默认 = 系统默认通知音）或托盘气泡的系统音，没核实真机；Windows「通知」设置 / 专注助手关掉 CC 才不响。
- **通知开关**：桌面版设置里**没有**通知开关；CC 窗口的网页通知权限对自家站点自动授予（`gui_tomo.py:56`、`gui_tomo.py:111`），用户在页面里无法拒绝；只能在 Windows 系统设置里关 CC 的通知。网页 CC 的浏览器推送开关（`lib/push.ts`）只管浏览器 / 手机，不管桌面版。
- **账户静音**：AGENTS.md 要求「提示音遵守账户静音」（Frappe Desk 的用户设置）。CC 桌面版与 `frontend/assistant` 都**不读**账户静音（grep `mute` 无命中），通知与系统音照常——按新口径做「不在对话页时提示音 + 通知」时要接上账户静音，否则违反仓库规则。

#### 乙　「是否在看这个对话」现在怎么判定

- **服务端：没有任何在线 / 可见性 / 当前对话状态。** 唯一相关的是 `notices.seen`：对话页打开某段对话时调 `sessions.notices_seen`（`sessions.py:1087`）记已看（只管侧栏圆点）。`push.send` 发给此人所有订阅设备，不看他在哪（`push.py:202-237`）；只核对登录会话还在。
- **后台脚本**：`assistant/service_worker.js:30-44` 收到推送每条都弹（注释：不弹 iPhone 会撤订阅、Chrome 会补通用通知）——所以「在就不通知」不能靠收到后不弹，只能**服务端不发**。
- **前端（另一路详查）**：`frontend/assistant/src/lib/desktop.ts:115-118` 回复完成通知只看整窗 `document.hasFocus()`（不分哪段对话）；`:121-129` 提醒：CC 桌面版窗口一律弹，浏览器开了推送就交给推送、没开且无焦点才弹。最小化 / 被挡、多设备同时开都没有判断。
- 改法要点：页面上报「此刻在看的对话 + 可见」心跳（可复用实时连接），服务端 `notices.post` 发推送前查：此人有设备正在看该对话且可见 → 只出卡、不推送；否则推送。CC 桌面版托盘（S04）同一判据。
