分支 `pearnly/stock-purchase-sale-chain`，基线 origin/main 21f452b9a（= 线上 release-20261120-1422）。
前情与原生实录见 [库存四入口对齐](2026-11-18-stock-express-parity.md) 第八、九、十一、十二节；原生规则 [1-戊①](2026-10-25-express-native-rules.md)。

## 需求影响评估（交主会话审定后施工）

### 0. 需求与理解

- 来源：主会话 11-22 任务书（K 系列第一项，现网缺陷、所有账套）。
- 三件事：
  1. 销货出超：结存 > 0 但不够时，`stock_sale.write_stock_lines` 按「总结存均价 × 全部数量」结转；原生只摊现有货值、多出的按 0（1-戊①：3 个 180 卖 5 → 成本 180，链 −2 / 0）。
  2. 进货 / 销货库存行只读写主档 STMAS 那条链，不碰 STLOC 分仓链与 `LOCVAL`（先进先出 + 分仓计价账套：进货不成批、仓库货值少记、之后取价偏）。复用库存四单的新写入器，不许两套。
  3. 补实录：平均成本账套、不分仓先进先出账套的「存单即重算当天」原生行为（库存 C 只实录了先进先出 + 分仓计价）。
- 不在范围：代录（Express 自己算，不经我们的写入器，只做回归确认）；存量账修补（真实客户无受影响账，见 §4）；
  批次链结存差 2 的已知差异（第十一节）；CC 引导卡、ERP 界面。

### 1. 现有同类与复用（关键：现在是三套取价）

| 写入处 | 取价 | 明细批次栏 | STLOC 链 / LOCVAL |
|---|---|---|---|
| 库存四单 `dbf_stock`（OU / JU / PI / TK） | 平均成本：主档链 MREMVAL / MREMBAL，超出部分按均价（D4 方案 A）；先进先出不分仓：`_fifo_prices`；先进先出 + 分仓：`stock_chain.fifo_lots`，出超按 0，存单即重算当天（库存 C） | 照原生（增加行成批、写前结存、指针） | 分仓计价账套写（`stock_chain.write`） |
| 调拨 `dbf_transfer` | 同上（调出侧） | 照原生 | 写 |
| **销货 `stock_sale.write_stock_lines`**（IV / HS / 现销，Cowork 与 ERP 共用） | **主档总结存均价 TOTVAL / TOTBAL × 全数量**（不分成本法） | 写后结存、无指针 | **不写** |
| **进货 `stock_purchase.write_stock_in_lines`**（RR / HP） | 净额 | POSOPR 0、写后结存、**不成批**、无指针 | **不写** |
| 退货回库 `dbf_refund`（SR）、作废 `dbf_void` | 原单成本 / 回滚 | 不成批 | 不写 |

- 结论：把 `dbf_stock` 里逐行「取价 + 批次栏 + 链增减」那一段（约 590–750 行，平均 / 先进先出 / 分仓三支、出超、当天开日）抽成共用模块
  （放 `stock_chain` 旁的 `stock_costing.py`，纯计算 + 读库存卡），库存四单、调拨、销货、进货都调它；`dbf_stock` / `dbf_transfer` 改成调用方，行为不变（单测与 101 本回归守住）。
- 销货的 ②③ 支（结存 ≤ 0 按标准成本 / 人填成本 / 0）是销货特有的口径（61EXP 实证），保留在 `stock_sale`，只把「有结存」那支换成共用取价。

### 平均成本（COSMTD = A）

| | 销货写入时：成本 / 明细批次栏 | 原生存同日进货后：销货成本 / 凭证 | 主档（总结存 / 链） |
|---|---|---|---|
| 原生 IV0000051（T1 → T2） | **1,200**（多出 2 按 0）；记**写前** 25 / 1,200 + 当前批指针 TK0000001；主档链 −2 / 0、批号标「-」、LASUPD 改单据日 | **1,260**（30 个里出 27，1,400 / 30）/ 1,260 | 3 / 140，链 3 / 140 指 RR |
| CC 现行口径·出超按 0（Cexcess） | 1,200；记写后 −2 / 0、无指针；LASUPD 不改 | **200** / 200 | 3 / **1,200**，链 **−22** / 0 |
| CC 现行口径·出超按均价（Cavg） | 1,296；记写后 −2 / −96、无指针 | **200** / 200 | 3 / 1,200，链 −22 |
| CC 原生口径（出超按 0 + 写前 + 指针，Cnat） | 1,200；25 / 1,200 + TK0000001 | **1,260 / 1,260** | 3 / 140，链 3 / 140 —— **与原生逐栏一致**（只差 LASUPD） |

- Express 存同日单时从当天排最前那一行记的「写前」链与指针起整段重算（库存 C 的规则在平均成本账套同样成立）。CC 减少行记写后、不带指针时，
  Express 把它当写前读，链被当成空 → CC 的销货被重算成 200，主档货值与链都错。出超按 0 还是按均价，重算后结果一样，关键是明细批次栏。
- **这是现网缺陷**（不只出超）：平均成本、不分仓账套里，CC 写的销货（以及库存单的领用 / 调减，同一口径）只要是当天第一行，
  财务之后原生存同日进货，成本就被重算错。
