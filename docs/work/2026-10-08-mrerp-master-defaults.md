# MR.ERP 导入值不再写死 TEST2019（2026-10-08）

分支 `pearnly/mrerp-defaults`，基线 `ea0ab555`（= origin/main）。用户 2026-10-08 批准方案与文案（「可以」）；口径「MR.ERP 有源码，以源码为准」。

## 现象与根因（MR.ERP 源码只读 `/Users/skin/mrerp-source/src` 核实）

旧线上（`ec2e5c957e6b`）MR.ERP 导入表里约 40 处、19 类值照抄 Korn 的样本与 TEST2019 账套：表头分店 `00000` / 部门 `BOI1` /
工作 `00002` / 员工 `กร ทดสอบ` / 销售区 `สุพรรณบุรี` / 运输 `ขนส่งโดยบริษัท`，明细仓库 `0000`，现金销售收款科目 `1111-01` /
`1112-01`，自建客户 `1-11` / `1130-03` / `กร` / `สุพรรณ` / `TRUCK1`，自建供应商 `2-21` / `2110-01`，自建商品 `03-FIG` / `ผน` /
8 个科目 / `CODE_NOAP`，费用物料 `04-SER` / `5230-01`。MR.ERP 导入（`imp*/component/importpc.php`）对这些值全部必填并与
这家公司自己的主档逐条比对，对不上整张单据被拒、不会自动建档 —— 除 TEST2019 外任何公司都推不进去（安全失败，不是假成功）。
模板库 `stderp2020` 里 `2110-01` 是银行透支、`5230-01` 是交通差旅、`2-21` 是其他应付：就算存在，含义也不对。

另两处顺带修正：
- 现金销售把全额记在「รับอื่นๆ 1」槽：MR.ERP 过账（`arse/component/arsepc.php` insacglhd）对这一槽借记**菜单关联的借方 3**
  （配了就不用行上的科目），不一定是现金；现金栏 `จำนวนเงินสดรับ`（第 16 列）才借记现金（菜单关联借方 1 或参考科目 2）。
- 主档自建把「มีอยู่ในระบบแล้ว」一律当已建好：商品**名称**重复也带这句（`impstkmas` importpc），码并没建出来。

## 有意变化（相对旧线上 `ec2e5c957e6b`）

1. 所有账套专属值按这家公司的主档与人选，旧线上写死（换公司必被拒）。
2. 现金销售现金收款进现金栏（旧线上记「รับอื่นๆ 1」）。转账 / 刷卡仍记「รับอื่นๆ 1」+ 所选银行科目：若这个菜单在 MR.ERP 关联了借方 3，
   MR.ERP 会记到那个科目（源码行为，只能在 MR.ERP 的菜单关联里改）。
3. 销项明细对不上商品码留空（旧线上写 TEST2019 的商品 `123`）。
4. 主档名称重复不再当成已建好。

## 已知限制 / 未验证

- 只按源码实现，**没在真站点上试过**接口返回、大小与耗时（用户口径：以源码为准；端到端以上线后第一张真票为准，同 09-28）。
  销项推送会读赊销接口（带全部客户与商品，大公司估 15–20 MB/次）。
- 参考科目没配全的公司：货品自建 / 现金收款会停在 `ERR_MRERP_MASTER_UNREADABLE`，要先在 MR.ERP 的参考科目里配好。
- 名或姓本身带空格的员工不出现在选项里（MR.ERP 导入永远对不上）。

## MR.ERP 自身的安全观察（不归本仓，转告用户）

`login/mainmenu.php` 按网址参数 `comidyear` 直接切公司，没核对账号权限；`bshlistboxdata` 不查菜单权限。
