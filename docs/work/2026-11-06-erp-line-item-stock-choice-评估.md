## 结论先说

1. **最大的阻塞在 CC 桌面版，不在 ERP**。CC 写 Express 采购（RR / HP）和销售（IV / HS）时，**一张单里库存行和非库存行混着就拒写**
   （`companion/src/companion/purchase_lines.py:103-104`、`companion/src/companion/dbf_sales.py:538-542`，原因写的是「两条写入路径的 STCRD SEQNUM 都从 1 起会撞」）。
   用户要的「同一张票有的入库、有的只记账」正是这种单，所以接了 Express 的公司**必须先改 CC、发新版**（载荷升 19，旧版诚实拒收），否则这种单在 ERP 能入账、写不进 Express。
   这也说明现在就有一类单写不进去：LINE 选「库存商品」的采购，识别补的「不可抵扣的增值税」行固定是服务（`integrations/intake.py:262-264`），整张就是混行（只按代码推断，未实测）。
2. **ERP 这边大半已有底子**：采购行本来就有 `item_type`（货物 / 服务，`purchase_line.json`），识别也逐行给 `item_type`（`purchasing/recognition.py:21`），
   Express 推送也逐行判库存（`express/push.py:182-188`）。缺的是：销售行没有这个字段；LINE 用整批二选一把识别的逐行结果盖掉；网页把它藏在收起的「附加信息」里；
   没有「票面品名 → 物料」的记忆；各入口按不同口径新建物料。
3. **CC 对话现在不能建 ERP 采购 / 销售单**（ERP 只给 CC 列单、推送、看单、改票面合计的工具，`express/cc_tools.py:573-664`），定时任务、Excel 导入也不建这两种单，
   收银台是另一套 `ERP Sale`。所以真正要改的入口是：**LINE、网页采购、网页销售**，加上 Express 推送判据与 CC 桌面版写入。
4. **施工排在库存整改合入之后**：它的分支已提交代码，改了采购 / 销售页的行仓、`positions.py`、`push.py`、两个 `entry.py`、术语表等 15 处与本需求重叠的文件（第 6 节）。

5. **Cowork 同样覆盖（第 15 节）**：Cowork 不记库存，每行要定的是「对 Express 已有存货 / 新建存货 / 记费用」。复核页本来就有逐行过账类型，混行载荷映射器本来就会出、卡在同一处 CC 拒写；
   改法是把现有的「存货对照」一问扩成每行一问（加「记费用」），LINE 去掉上传前「入账方式」改成识别后追问。记忆不建共用表：规则与键共用，存储各产品各自（一个站点只装一个产品）。MR.ERP 只有整张货 / 费，不出按行选择。

## 0. 需求原文与理解

- **原话**（用户 11-06，经主会话转来；主会话复述后用户回答「是的」）：
  「line 那边，采购为什么会问库存或者服务？……是否考虑增加 line 和网页端，line 采购录入后继续追问，商品 1，2，3，是否入库，追问仓库或者仓位，网页端做成录入后按钮……
  我希望采购和销售，具备这批次的录入是否要新建物料，是否要入库，等等关键字段或者提问，让用户有选择性，可以选择这批次的采购和销售只是记账还是要动物料的主档信息，
  列入新建，出入库，库存，成本，等等关键字段的信息，让用户有选择性，又或者我们在 line 使用时，这批识别的物料，其中有些不新建，有些又入库，有些又不入库，这是一个大的物料数据串联改动」。
- **我的理解**：采购单、销售单的**每一行**各自定：
  ① 对应哪个物料：已有的 / 新建 / 不建（只记账）；② 动不动库存：采购入库、销售出库，或不动；
  ③ 放哪：仓库一张单一个（单头，库存整改刚定的口径），仓位每行可以不同；④ 成本：采购入库按票面单价，带出、可改。
  系统先预选，定不了的才问，问一次记住。LINE 识别后只对定不了的几行追问；网页每行能改，加一个整批设置的弹窗；接 Express 的公司按行写成存货行或费用 / 服务行。
- **为什么现在 LINE 会问「服务还是库存商品」**：ERP 要知道这张单进不进库存。现在是上传前整批问一次（`integrations/line_flow.py:360`），
  选「库存商品」就每行都当物料、认不到的自动新建、全部入库；选「服务」就全部只记账。识别其实已经逐行分了货物 / 服务，被这一问盖掉了。
- **不在本需求范围**：
  - 给 CC 对话新加「建采购 / 销售单」的工具（现在没有，见 12 节 #9）；
  - 运费等摊进物料成本（到岸成本，见 12 节 #7）；
  - 采购「未到货、以后再收」的收货步骤（ERP 采购单 = 已付且到货的进货单，「不入库」在这里只表示只记账，不是待收货）；
  - 改识别提示词（销售识别不加 `item_type`，见 12 节 #12）；
  - 已写进 Express 的采购 / 销售单作废回写 Express（现在就没有，另立任务，见旁见）；
  - 收银台、盘点、出入库、物料调整单。

### 4.2 预选规则与「问一次记住」的键

**记忆表**（新 DocType，暂名「明细物料记忆」`ERP Line Item Memory`，只经一个模块读写，同 `category_memory` 的写法）：

- 键：`公司 × 方向（采购 / 销售）× 对方（供应商 / 客户，散客为空）× 品名键`，记录名 = 四者的 sha256；品名键沿用 `category_memory.item_key`（去大小写、空白、标点，泰文声调保留）。
  〔15.3 调整〕键直接用共用写账规则的 `item_subject`（`方向|对方税号或名称|规范品名`，`K/express_rules/push/choices.py:71-77`），与 ERP Express Choice 的 `item` 同一个键，ERP 与 Cowork 共用这条键函数和预选顺序。
- 值：物料（可空 = 只记账且不挂物料）、`item_type`、仓位、最后一张单（追查用）。
- 为什么带公司：同一个本地供应商可以给两家公司供货，一家管库存、一家只记账；分类记忆不分公司，是因为分类与 Cowork 共用口径，这里不能照搬（12 节 #3）。
- 学习：每次提交成功（网页、LINE 编辑页、修改）按行上**最终**的值覆盖记下；作废不撤销记忆（轻便口径，下次人改了就覆盖）。

**每一行的预选顺序**（纯函数，放在产品自己的域包，例如 `products/line_rules.py`，不依赖 Frappe；读写在 `products/line_memory.py`）：

| # | 条件 | 结果 | 状态 |
|---|---|---|---|
| 1 | 行上人已经选了物料或改过入库勾选 | 照人选的 | 已定 |
| 2 | 识别补的「不可抵扣的增值税」行（采购） | 只记账 | 已定 |
| 3 | 记忆命中（四键全中），记住的物料仍启用、属于这家公司可用的档 | 记住的物料 + 入库与否 + 仓位 | 已定 |
| 4 | 对方是「一般供应商 / 散客」或 #3 没中：这家公司这个方向下，这个品名键的全部记忆**结论一致** | 用它 | 已定 |
| 5 | 按条码 / 编码 / 品名认出已有物料（现有认法），且不是 Express 非库存品 | 这件物料 + 入库（销售出库） | 已定 |
| 6 | 认出的是 Express 非库存品（有 Express 码且 `express_stock = 0`，如运费、服务费类主档） | 这件物料 + 只记账 | 已定 |
| 7 | 采购识别给 `item_type = service`（运费、服务费、手续费），或单据类型是「费用」 | 只记账 | 已定 |
| 8 | 其余（认不出、识别说是货物） | 预选「新建并入库」（与现在网页、LINE 库存的结果一样） | **未定** → LINE 追问；网页照预选显示，不另提示 |

- 「未定」只在 LINE 触发追问；网页每行都看得见、改得了，不加提示语（录入口不加识别后提示的口径）。
- 预选不会替人删改：只填空着的行；人改过的不动。
- 销售没有 #2、#7（销售识别不读类型），认不出的销售行同样是 #8。
- 一张单的仓库：单头已有预填规则（本人上次 → 卖货仓 → 唯一仓 → 空，`inventory/warehouses.py:159-191`），不另记；只有「有入库行且单头仓定不下来」才问（LINE）或必填（网页，现状）。
- 仓位：记忆 → 物料建议仓位（在单头仓清单里才用）→ 单头仓位 → 空。空是允许的（`positions.check`：空仓位照旧可以）。

### 4.3 ERP 单据流

- **提交**（`purchasing/entry.py::_post`、`sales/entry.py::_post`）：先对行跑预选补空（服务端，保证 API、旧页面、LINE 都一致）→ 货物行认物料，认不到新建（采购现有；销售按 12 节 #2）→
  只对货物行入库 / 出库（采购现有；销售改成「货物行且有物料」）→ 学习记忆 → 排 Express（现有）。
- **新建物料的来由**：建在提交事务里，单据保存后回填 `origin_doctype / origin_name`，物料页能看到是哪张采购 / 销售单建的。
- **历史数据**：销售行 patch 回填 `item_type`：有物料且这张单过过出库 → goods，其余 → service（与当时实际结果一致，不改任何库存）。采购行不用动。
- **修改（采购）**：原单的行选择原样带进新单可改；原单作废冲回入库、新单按新选择入库（现有 `_cancel` + `_post`）。

### 6.1 LINE 对话设计

**上传前**：公司 → 对方 → 已付 / 未付 →（已付）付款方式 → 上传。删掉「服务 / 库存商品」和仓库两步（`line_flow.py:161-164,360,384-385`）。

**识别后**（每张票一张预览卡，照现在只有「编辑」）：

1. 全部行已定、且（没有入库行，或单头仓定得下来）→ **不问**，只发卡片。卡片每行多一个标签：「入库」/「出库」/「只记账」/「新建 · 入库」。
2. 有未定的行 → 在同一次发送里，卡片后面跟一条带快捷回复的文字（不另起一次发送）：

   ```
   <供应商> · <单号>
   新物料：
   2. <品名>
   3. <品名>
   5. <品名>
   [全部新建并入库] [全部只记账] [逐项选择] [取消]
   ```
   销售是「全部新建并出库」。
3. 「逐项选择」→ 一项一问：`2. <品名>` `[新建并入库] [只记账] [选已有物料] [取消]`；
   「选已有物料」→ 请打物料名称或编码 → 照现有打字找（名称模糊、编码准确命中，≤12 条列序号按钮，太多请多打几个字，没找到再问）。
4. 有入库行、单头仓定不下来 → 问仓库（现有按钮 / 打字找，`line_flow.py:225-259`）；同一批后面几张沿用这次选的仓，不再问。
5. 选定的仓建了仓位清单、且入库行里有没有可用仓位的 → 问一次仓位：清单 ≤11 个列按钮 + 「不填」，多了打字找；这张票没仓位的入库行都放这里。每行不同的到网页改。
6. 问完回复更新后的卡片（每行标签已变），不另发说明文字。

**放不下怎么办**：未定行多于一屏时，第 2 步文字里列全部序号与品名（文字没有 12 个的限制，卡片本来有 28KB 上限和「还有 N 项」），按钮仍是固定 4 个；逐项选择一次一行，不受 12 个按钮限制。

**多张票同一批**：识别是逐张排队、各自出卡（`intake.py:165-213`）。追问**一次只问一张**：先识别完的先问；这张问完（或点取消）再问下一张。每条提问开头写「供应商 · 单号」，分得清问的是哪张。
正在问 A 时 B 的卡片先照常发出、不带提问，A 问完再接 B 的提问。

**30 分钟会话**：上传前的选择照旧存在 LINE 会话里 30 分钟（`line_flow.py:27`）。识别后每行的选择存在这张票的 `ERP LINE Intake` 上（`line_choices`），**不随会话过期**；
会话只记「现在问到哪张票哪一步」（用于把打字认成找物料）。过期或中途去点菜单开始新一批：没答完的那张保持预选，卡片「编辑」照样能在网页改完提交；旧按钮点了回「这个选项已经不是当前的」（现有文案）。

**取消**：不改这张票、不清上传前的选择（与上传前的「取消」不同），这张票按预选（未定的行 = 新建并入库）显示；不阻断。

**消息额度**：卡片在识别完成后已经用回复令牌发、超出 5 条或令牌失效时推送（`intake.py:206-210`）；提问与卡片同一次发送，按钮作答都是回复，不另占推送。
同一次发送多带一条文字算不算另一条额度，施工前按 LINE 官方计数规则核一次。

### 15.0 概念对照：Cowork 每一行要定什么

Cowork 不记库存，它的「物料」就是客户 Express（或 MR.ERP）账套里的存货 / 商品主档。所以每一行要定的是：

| ERP（第 0–14 节） | Cowork |

| 对应已有 ERP 物料 / 新建物料 / 不建只记账 | 对应 Express 已有存货（库存品或非库存品主档）/ 新建存货 / 不建存货、写成费用 / 服务行 |
| 入库 / 出库 / 不动 | 库存行（`stock_item` / `stock_sale`）在 Express 带进出库；费用 / 服务行（`non_stock_item` / `direct_account`）不碰库存 |
| 仓库（单头）、仓位（行） | 仓库 = Express 仓（`loccod`）；**Cowork 现在推单不带仓**，CC 写进账套主仓（`ISINFO.MAINLOC`，`companion/src/companion/account_rules.py:58-64`）；Express 只有「仓」一级（STLOC），**没有仓位**，Cowork 也没有（只有盘点模块有 `location` 文本，`C/stocktake/contracts.py:12`） |
| 成本 = 票面行金额 ÷ 数量 | 同（CC 入库按行净额，`companion/src/companion/stock_purchase.py` 文件头） |

**一个问题**：把现有的「存货对照」`item`（`K/express_rules/push/choices.py:216-235`，只问库存行）扩成**每一行都可问**，选项是：
Express 目录里的物料（库存品与非库存品都列，服务端搜索）、「新建存货」（现有 `__new__`）、「记费用」（新值）。选了库存品 / 新建存货 = 库存行；选了非库存品 / 记费用 = 费用 / 服务行。
这样「这行动不动库存」和「对哪个存货」是同一个回答，行上的过账类型由它推出；`posting_kind_needed`（部分行没声明）并进这一问，不再单独存在。
