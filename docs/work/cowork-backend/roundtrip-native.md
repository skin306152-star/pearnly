# Excel复核往返的原生后端合同（第六批）

来源固定为线上 `ec2e5c957e6b4be7dee93ffdd2dae9fa83f69188`；开工/交付Cloud Run身份和OCR相关配置复核均与第五批一致。完整源路径和差异见 [独立审计](roundtrip-parity-audit.md)、[解析器](roundtrip-parser.md)、[导出器](roundtrip-export.md)。这只交付本地后端，未连接产品前端、真实计费服务或ERP。

## 归属与入口

`pearnly_cowork.roundtrip` 负责复核工作簿，spec/money/contracts为纯契约，parser是有资源限制的字节适配，export_mapping为纯准备，export_writer写工作簿。intake将每张解析单据映射到不可变Source逻辑区段；access只检查不可信PRN引用；results保持单据边界；service/api提供授权导出。它们不导入外部ERP写者。

`POST pearnly_cowork.roundtrip.api.export(names)` 逐条读取同Site、同公司/客户的1至100条History。固定返回ขาย/ซื้อ/รอจำแนก/สรุป，空表保留；泰文表名和表头是读写协议，不随账户语言改变。这个明确命名的复核接口与旧按Express推送适配器自动选模板的入口不同；尚未提供旧simple、VAT、打印、MR.ERP上传等其它格式，也没有新增菜单或占位页。

导出当前历史字段，不更新历史。原生识别历史首个page.fields已含合并结果：检查Source已封存且History在绑定记录中后，只取首票字段，后页继续作为原始证据，不再次拼明细、不按相同商品内容去重、不用后页填回用户清空的主票字段。未绑定的手工/迁入多页无法证明该结构时明确拒绝。手工单页仍按既有字段处理。

真实推送动作和最新推送状态没有接数据库查询，原生出口不注入push_facts，ERP号/码/成功状态与新建主档清单留空。纯writer能接受将来由服务端核实的事实，但客户不能通过RPC上传facts，普通发票字段也不能伪造它们。

## 上传、保存和计费

1. 复用私有原件上传与幂等 `ocr.api.submit`。普通表格仍走第五批L2；真实首行七列指纹命中后先走专用解析。通用table_engine保留防误送模型的拒绝检查。
2. 冻结日期、业务计费档位和确定性引擎，不构造模型客户端，不要求无用的供应商凭据。仍需明确的当前Site OCR计费配置及余额准入。
3. Source仍为logical_section，但单位是 `roundtrip_document`，一张解析票一个编号，含待判；保存sheet/行号/原行键、原始表格证据、字节SHA及转换后Pipeline页的摘要。受理和恢复均使用同一anchor_date，投影变化不能改写清单。
4. PRN键只是不可信声明。受理、worker解析及保存冻结结果前都查当前Site History权限，且必须与原件同公司/客户。旧UUID未映射或不可读时明确拒绝，不改当新票、不代替会计删原记录。无键的票沿旧合同作为新输入。
5. 新History、原件完整绑定、Batch保存结果同一事务；原History及其ERP记录不动。源字符收费按原Excel所有非空缓存值 `len(str(value))`，不按表数、解析票数或token。零模型费用不意味着业务免费。保存成功后使用稳定 `cowork.invoice:<batch>` 结算；丢回执只重试计费，不重读文件、不跑模型、不建第二批历史。
6. 整本工作簿可能含隐藏旧键、摘要和未消费内容，因此coverage_complete保持false：上传者仍受当前范围授权，其他读者不能仅凭新票全绑定读取整本；不授予文档PDF物理预览。清单不复制到Version或公开metadata。

## 明确修复与保护

正常源样本字段、列序、公式、方向、税基/VAT算法和字符单位按固定源码对照；以下不能写成“与旧行为完全一样”：

- 旧通用二次分组会合并不同原记录/不同方向的同号票，新链保留reader已确定的逐票边界，不把第二张标成副本。
- 待判即使没有票号仍保存人工标记，不被完整性闸误丢；不以整批direction将待判变已判。旧pending读器未带回对手方和金额的事实保留，相关原格仍在私有原件证据中，不宣称待判是完整可执行财务单据。
- 指纹命中但空、损坏、表名带空格异常、50连续空行后还有业务行，明确报错，不静默漏行或改走付费模型。
- 对能证明的schema别名适配 `items.subtotal → amount`，冲突拒绝；不能猜测含税total为税基。普通业务金额Decimal守恒，源浮点半分和无法表示的Excel数字精度差异详列于导出文档。
- 原生多页历史首页合并明细只导一次；缺少可信绑定的多页明确拦截。
- 文本固定为字符串，不把用户以等号开头的文本变成公式；只有协议内四类算术公式由writer生成。选择无权/缺失历史时整批失败，不像旧入口悄悄跳过；公司/客户不同必须分开导出。
