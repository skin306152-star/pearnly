# 需求影响评估：ERP 网页端新建收款（第二版：一页一个权限）

> 2026-11-14 收款闭环窗口写。第一版（「收款」「我的收款」两个入口）主会话同意后，用户 11-14 改口：
> 「不应该这个公司的都在侧栏收款里吗，不区分谁和谁，只要勾选收款功能的人，都能用这个，也能看全部，不用区分得这么细」。
> 第二版按此收成一套，主会话 11-14 审定三条：①只有勾了「收款」或管理员看得到侧栏「收款」，只有销售岗位的不再看得到；
> ②编辑、放行、撤回、补凭证不分谁录的（网页 / LINE / CC 同一个服务层判据），CC 列表列本公司全部可按「谁录的」筛，LINE 结果照旧只推录的人；
> ③去掉「我的收款」，旧地址与已发出的 LINE 卡【编辑】仍能打开那一笔。下面是第二版的结论，第一版的细节见提交历史。

## 第二版要点
- 入口：只留侧栏「销售 → 收款」。列表（本公司全部，谁录的那一列保留作信息）+ 页头「新建」+ 点开：草稿原生弹窗改 / 副按钮撤回；
  待写入 / 失败的看明细、主按钮撤回；已写入的只看 + 导出 / 看凭证。「我的收款」从侧栏、个人菜单、外壳白名单去掉，词条 `erp.nav.myCollections` 删除；
  `/desk/pearnly-my-collections/<记录>` 留一个不进菜单的页原样转到 `/desk/pearnly-collections/<记录>`；新的 LINE 卡【编辑】直接指新地址。
- 权限：`collection.view` 与 `collection.write` 同一判据（收款岗位、管理员；跟着「收款」功能开通），侧栏「收款」看「收款」功能；
  11-11 发给销售岗位的 ERP Collection 读权限在迁移时收回。服务层 `_own` 改成「本公司 + 有收款权限」，`can_read` 同；
  原生读权限 `collection.access` 不再按人过滤。两个人同时改同一笔草稿按版本号拒后到的。
- LINE：录收款流程不变；【确认】仍要卡片会话属于点的人；点自己 LINE 里没有的卡（别人的、伪造的）不再作废那一笔；结果照旧只推录的人。
- CC：`erp_collection_list` 列本对话公司全部，可带 `collector` 筛；`erp_collection_status` 同一权限。
- 「新建」弹窗的公司：默认取页面当前公司；本人能用、接了账本的只有一家时不显示；多家给下拉、只列本人能用的；服务端再判。
- 上线说明要写：只有销售岗位、没勾收款的人从此看不到「收款」页。上线前读一次各正式租户「有销售岗位但没勾收款」的人数（查法见任务记录 §7）。

## 0. 需求原文与理解

- 原话（用户 11-13 晚，主会话交接第十节）：「收款 pearnly erp 网页端也可以新建收款，弹窗编辑相关字段，提交后就写入 exp，这个和明天的优先排一起」。
- 理解：能录收款的人（收款岗位、管理员——见本分支第 1 件「管理员默认有收款」）在 ERP 网页里点「新建」，在原生弹窗里填一笔收款，点提交后和 LINE / CC 一样排单，由 CC 桌面版写成 Express 的 RE；结果在列表里看。
- 不在范围：网页改已放行的收款、删除记录、作废已写进 Express 的 RE（仍由财务在 Express 原生作废）；付款单、退货；网页端识别转账凭证金额。

## 1. 现有同类与复用

- 规则与写账：`collection/service.py`（`book_options` / `choose_book` / `customers` / `open_invoices` / `methods` / `store_voucher` / `create_draft` / `release` / `withdraw`），LINE（`integrations/line_collection.py`）、CC（`collection/cc_tools.py`）都只调它；排单 `collection/push.py`。
- 网页：「销售 → 收款」`public/desk/collections.js`（只看、导出、凭证），「我的收款」`public/desk/my-collections.js`（本人记录、草稿原生弹窗改 `update_draft`）。
- 结论：**扩展现有**。服务层一行规则不改，只加网页入口与一个放行来源；弹窗沿用「我的收款」编辑弹窗的字段写法（同一个文件里抽成共用函数，新建与编辑一套）。

## 2. Frappe 原生能力

- `frappe.ui.Dialog`：Select（公司、账套、销售员、部门）、Autocomplete（客户，服务端 `customers` 搜索、按输入取，不一次取全）、Table（未收清发票：单号 / 日期 / 未收 / 本次收）、Currency（现金、各转账方式、折扣）、Attach（转账凭证，走 `store_voucher` 同一个上传口）。
- 页头主按钮 `page.set_primary_action`（「新建」）。不新增样式、不自定义控件。

## 3. 按类通用

- 同类：收款三个入口（LINE、CC、网页）。网页补上后三处同一服务、同一套规则码与文案（`collection/texts.py`）。
- 入口放两处：「销售 → 收款」（看收款的人：销售岗位、管理员）与「我的收款」（录收款的人）。按钮只给 `collection.write` 的人显示；只有销售岗位、没有收款的人看不到「新建」，服务端也拒绝。

## 4. 上下游数据

- ERP：建 `ERP Collection`（`source = "web"`，新增来源值），放行即预留发票余额（`RESERVING`），写成后回 RE 号、刷新应收快照——全部沿用。
- Express：同一载荷（`receipt`，版本 20），**CC 桌面版不改**；同 YOUREF 去重照旧。
- 「提交后就写入」：弹窗提交 = 建草稿 + 放行一步完成（同一事务）；放行的「同意」记为这次提交（`consent_ref = web:<会话>:<请求号>`，同一请求号重复提交只建一笔）。弹窗本身就是复核（满足「识别后必须复核再录」：内容全展示、可改、点提交才录）。
- Cowork / DMS：不涉及（收款只在 ERP）。

## 5. 隔离与权限

- 服务端：`create_draft` / `release` 本来就 `guard.require("collection.write")` + 本人可用公司（`_company`）+ 本人记录（`_own`）；网页只是又一个调用方。
- 跨公司：公司下拉只列 `companies_for()`（本人可用、接了 Express 的）；直接调接口带别家公司被拒。
- 管理员看全部、收款岗位只看自己的（`collection.access` 不变）。

## 6. 入口：网页、手机、LINE、拍照

- 网页桌面 / 窄屏：原生 Dialog 在手机宽度下单列显示，Table 字段原生横向滚动；验收要截 375 宽。
- LINE：不变（富菜单第 4 格）。CC：不变（收款工具）。
- 拍照：转账凭证用 Attach（手机浏览器原生选文件 / 拍照），不接共用相机件。

## 7. 共用件与连带回归

- 改到的登记共用件：`desk/list.js` 不改；`my-collections.js` / `collections.js` 是收款自有。服务层不改规则，只在 `contracts.SOURCES` 加 `web`、加一个网页提交函数。
- 新增流程 `scripts/flows/erp_web_collection.py`（实验栈：新建现金 / 转账带凭证 / 超收被拒 / 无权限看不到按钮且接口 403 / 撤回），产品地图登记两个入口（「新建」、「撤回」）。

## 8. 存储与成本

- 凭证图片同 LINE（统一原件层），无新增外部调用、无固定月费。

## 9. 删除、作废、追溯

- 网页「我的收款」给没被电脑领走的（草稿、待写入、失败）加「撤回」（`service.withdraw`，同 LINE【撤回】）；记录不删、凭证保留。已写进 Express 的不撤，照旧由财务在 Express 作废。
- 追溯：来源 `web`、`consent_ref`、`confirmed_at`、录入人都留在记录上，收款列表的来源筛选多一个「网页」。

## 10. 文案与官方 UI

- 新增：来源「网页」（`erp.collection.source.web`，四语）、Table 列「本次收」（若现有词条没有就新增）、「撤回」按钮（用 LINE 现有词条）。新增文案按官方风格，过 `check-copy.py`，交付附 `--report`。
- 改已有：`collections.js` 文件头说明（开发注释，不是界面文案）。没有改已有界面文案。

## 14. 11-14 晚接手：改金额后提交报「请至少选择一张发票」、列表截断、旧地址

接手收款窗口（交接 `收款-旧地址与新建弹窗-交接-11-14晚.md`，提交 c32e48ec9 起），本机实验栈 `pearnly-col14-lab`（线上镜像 054aa603）。

**缺陷根因（实测）**：「客户」用的是官方 Autocomplete，它在**失焦**时会再报一次 change。选好客户后，点表格里的勾选框或「本次收」格子，
客户框就失焦 → `pick_customer` 又跑一遍 → 清表、重拉发票 → 刚勾的行、刚填的金额全回到 0，正在编辑的格子被重画、输入框消失。
提交时发票行金额都是 0，被过滤成空列表，服务端照规则回「请至少选择一张发票」（超收规则根本轮不到）。
抓到的调用栈：`grid.refresh ← reset_customer ← pick_customer ← ProductAutocomplete.change`。
**修法**：记住已列出的「公司 + 客户」，客户没换就不重拉、不清表（`collection-new.js`）。行对象、表格取数本身没问题（`grid.data === df.data`，行对象同一个）。

**流程 `erp.web.collection` 改成真人操作**（不再直接改行对象）：两张都勾（带出 1000 / 500）→ 点格子输入金额 → 提交。
- 超收：第一张输入 1200 → 服务端回「超过未收金额，请重新输入」，不是「请至少选择一张发票」，弹窗不关、什么都不留；
- 正常：第二张输入 300、现金 1300 → 库里明细逐张是 1000.00 / 300.00（与界面一致），合计 1300；
- **去掉修复跑 = 红**：勾选与金额被冲成 0、两次都报「请至少选择一张发票」（同真机现象）；**放回 = 绿**（电脑、手机）。
- 流程自身一处：被拒后上面压着提示框，原来只关掉提示框、收款弹窗还开着；改成一层层关。另外选客户只认本输入框自己的下拉
  （共用 `pick` 会先点中上一个已关弹窗留在页面里的同名下拉项）。

**列表截断**：另一个提交（共用列表 `desk/list.js` 手机宽度不写列宽 + 收款日期列放宽），属共用件连带回归，逐入口实测完再推。
另：`collections.js` 的注释提到 `desk/actions.js`，命中 `desk-head-actions` 的特征串，登记为 not_entries（不调用白名单，旧地址入口见 erp.page.collections 与流程 erp.line.collection）。

收款三条流程（本机实验栈，修复后）：`erp.web.collection` 电脑 / 手机通过、`erp.line.collection` 手机通过、`erp.collections.refused` 电脑通过。
