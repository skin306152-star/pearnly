# ERP「同步 Express」改后台落库、落库只写变化的行（2026-10-23）

- 状态：开发与测试机实测完成，本地全闸门、生产镜像 `29404c6a` 候选离线检查通过；待用户同意后合入 main、部署。
- 分支 `pearnly/erp-express-sync-background`，工作树 `.claude/worktrees/erp-sync-bg`，基线 `cecc475e`（= origin/main，生产镜像
  `29404c6a`，见 [发布记录](2026-10-23-release-3205521e.md)）。

## 现象（生产，已上线 3205521e）

线上 testerp 公司 CO-00078（税号 0105531007042 / 00000）点「同步 Express」：CC 13:28:30 → 13:28:45 读完 C 盘 T9GIS（请求
`5bc5182d…` done，结果约 1 MB），落进 ERP 时 `express.api.sync_company` 在网页请求里跑，超过 gunicorn 120 秒被杀（erp-web
`13:30:32 A request timed out`，前端 499），整笔回滚：这家公司的客户、供应商、商品、仓库都还是 0，`express_book` 为空；请求停在
done、没被取走，后台也没有任务接着做。

## 原因

1. 手动同步在网页请求里最多等 30 秒电脑读完，读完就地落库。
2. 落库逐条 `get_doc` 读出比对再决定写不写，几千条要几分钟；T9GIS 有 17,981 个客户。
3. 后台同步任务的超时只有 `JOB_WAIT + 300` 秒；失败只在单行出错时记 Error Log，整次失败没有地方看。
4. 准备写账时顺带读好的账套（`masters.ensure`）也在调用它的地方落库，可能是网页请求（单据弹窗里选完 / 重试）。

## 修法

| 位置 | 改动 |
|---|---|
| `express.api.sync_company` → `masters.start` | 请求里只看能不能读、发起读取，排后台任务，立刻回「读取中」；不等电脑、不落库 |
| `masters.sync`（后台任务） | 等电脑读完（`JOB_WAIT`）后落库，超时 `JOB_WAIT + LAND_LIMIT`（3,600 秒）；任何出错回滚、记 Error Log、结果记在公司上；手动发起的做完推给本人（`pearnly_erp_express_sync`） |
| `masters.ensure` / `land` | 准备写账时读好的账套：存账套资料（准备接着用），落进 ERP 主档改排后台任务 `land`，不在请求里落 |
| 落库 `apply` | 现有档的比对字段一次取出（商品连同单位表），在内存里比，没变的行不读出、不保存；有变化 / 新建的照旧经文档保存（校验与锁不变）；每 500 条提交一次 |
| ERP Company | 新增只读字段 `express_sync_state`（读取中 / 落库中 / 已同步 / 电脑离线 / CC 桌面版要更新 / 失败）、`express_sync_note`（失败原因码或出错信息） |
| 公司页 | 接了 Express 的公司多一个只读「Express」段：账套、最近同步时间、状态、失败原因；点「同步 Express」立刻提示「读取中」，后台做完收到推送就提示结果并重画 |

每小时的自动同步（`sync_all`）、写单后的同步（`push.job_changed`）同一个后台任务，同样记结果、不静默。

## 验证

### 本地

`tests/test_erp_express_direct.py`（25 项）新增：
- 第二次同步没有变化的档不读出（`get_doc` 一调就失败）、改一条只写一条；
- 手动同步只发起读取、排后台任务（带发起人），即使电脑已经读好也不在请求里落库，公司状态记「读取中」；
- 后台任务出错：回滚、记 Error Log、公司状态「失败」并带出错信息、推给发起人；
- 准备写账时读好的现用账套排后台任务 `land`，不在请求里落库。

### 测试机大账套实测（实验栈只起栈、不切域名：底座 = 生产镜像 `29404c6a`，源码 = 本分支）

C 盘账套用 CC 自己的读法只读读出（`express_masters.collect`，T9TSDV12 3.7 秒、T9GIS 13.0 秒），在实验栈 ERP 新建一家同税号的
LAB 公司，落库两次计时：

| 账套 | 客户 / 供应商 / 商品 / 仓库 | 首次落库（全部新建） | 再同步（没有变化） | 旧落库再同步（对照） |
|---|---|---|---|---|
| T9TSDV12 | 9,829 / 1,570 / 5,972 / 3 | 44.5 秒 | 0.3 秒 | 4.8 秒 |
| T9GIS | 17,981 / 1,436 / 2,361 / 15 | 55.6 秒 | 0.5 秒 | — |

两次都没有单行出错（Error Log 0）。两份账套 STLOC 都没有结存行（库存调整 0）。

判断：实验栈首次落库约 1 分钟，生产机更慢（那次生产请求从电脑读完到被 120 秒超时杀掉，落库跑了约 100 秒还没完），所以根本
问题是在网页请求里落库；挪到后台任务（上限 3,600 秒）后大账套首次落库也够用。再同步只写变化的行，比旧做法快约 15 倍。

没在测试机上走的：点按钮 → CC 读 → 后台任务 → 推送页面这一整条（实验栈没有接 CC 的 ERP 成员）；这几步由本地测试覆盖，上线后
在生产 testerp CO-00078（T9GIS）点一次「同步 Express」核对。
