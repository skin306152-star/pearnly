# 仓库库位清单（第 5 项）

设计（主会话 10-26 审定）：`docs/work/2026-10-26-vehicle-units-设计.md` 第 8 节（岳父：库位做成通用的，仓库下建库位清单）。
基线 main `d8d42e6f`，分支 `pearnly/locations`。

## 做了什么

- 清单是仓库的子表 `ERP Warehouse.locations`（`ERP Warehouse Location`：库位、在用），读写跟着仓库走；没建清单的仓库位照旧手输，行为不变。
  （设计写的是单独一张 `ERP Location`；改成子表少一套权限与查询，维护就在仓库弹窗里，用原生 Table。）
- 统一校验 `positions.check`：建了清单，库位只能是清单里在用的，空库位（不分库位）照旧可以。挂在三处：单据行 `positions.prepare`
  （商品上的建议库位不在清单就留空，单据上明写的不在清单就拒）、库存流水 `stock.apply_movement`（货**进**到的库位要在清单里；
  从旧库位出货、作废冲回照常）、盘点记录（记在账面那个位置照常，换到别处要在清单里）。
- 接口 `inventory/locations.py`：库位格选项（按仓库、按输入搜，最多 50 个）；维护读清单（带各库位现在的库存，和有库存还没进清单的库位）；
  保存清单（名称去空白不能重；有库存的不能停用；用过的、有库存的不能删）。
- 页面：仓库编辑弹窗加「库位清单」（原生 Table：库位 / 在用 / 当前库存）和「带入有库存的库位」；库位格换成原生 Autocomplete，
  选项按所选仓库从服务端取：出入库明细、采购 / 销售明细、盘点录入、期初录入。没建清单的仓没有选项、照旧手输。
- Express 只有仓库没有库位，不涉及 CC。

## 用途 / 入口 / 配置

| 入口 | 去向 | 需要 |
| --- | --- | --- |
| 仓库 → 打开 → 库位清单 / 带入有库存的库位 | 建、停用、删库位 | `warehouses.manage` |
| 出入库 / 采购 / 销售明细、盘点录入、期初录入 → 库位 | 从清单选（没清单照旧手输） | 各单据原有权限 |

## 新增文案（无改已有文案）

DocType 标签「库位清单」；服务端提示 4 条（库位不在此仓库的库位清单中、有库存的库位不能停用、已使用的库位不能删除、库位重复）；
页面词条 `stock.location.list`、`stock.location.fromStock`（带入有库存的库位）。
