# 施工计划：数字会计员与客户记忆（与多电脑 T5 并行，2026-10-15 定）

用户 2026-10-15 原话：「数字会计员：CC 接下一家客户整个月的闭环（收单、录账、对账、报税草稿、异常清单），会计员只做审核签字」；
「客户记忆：每家客户的记账规矩、供应商习惯、改过的地方都积累下来，越用越准，换了会计员也不丢」；排期「按这个排期来，写进施工计划，
今天收尾完明天开第 1 批」；当晚改为不按日期、按顺序与依赖连续推进（见下「顺序与依赖」）。

建在已有能力上，不另起产品：公司主档（[ADR-020](../adr/0020-cc-company-master.md)）、知识库、记住的选择、Express 历史科目、定时任务、
待处理与早上汇总、银行 / 收入对账、ภ.พ.30 与预扣税草稿、Express 回读。多电脑方案见 [多电脑方案](2026-10-13-cc-multi-desktop-plan.md)
（D1–D9 已拍板），跨年度换账套见 [交接](2026-10-15-handoff-cc.md) T1。

## 可靠性原则（每期都要守）

1. **模型只读和提议，写不写由确定性规则决定**：税号校验位、含税拆税算术、期间 / 分店 / 本方税号硬闸（`targets/account_match.py`），
   重复单号进异常清单（照「推送不查重不拦」不拦）。任一关判不出就进异常，不猜。
2. **按家分自动化档位，用实测数据升档**；出问题自动降档。
3. **每一笔可核对、可追溯**：推后用 Express 回读核对；谁写的、按哪条规则写的都留记录。
4. **签字锁月**：签过的月份 CC 不再改，要改须重开并写原因。

## 数字会计员：月结台账

每家公司每月一张，状态从现有数据现算、不另存一份：收单（定时任务 + 按前 3 个月学到的固定来源列本月缺单）→ 录账（按档位推送）→
对账（银行、收入接到已推分录）→ 报税草稿（与 Express 回读交叉核对）→ 异常清单 → 会计员审核签字（月报 docx）→ 锁月。

自动化档位：**L0** CC 只提议、人推（新客户第一个月，只学习）；**L1** 规则已定的自动推（同供应商同科目 ≥3 次或人定的规则），其余排队；
**L2** 整月由 CC 做成草稿，会计员看异常清单并签字。

## 客户记忆：统一的「客户规则」

把知识库、记住的选择、Express 历史统一成带来源的规则：内容、范围（公司 / 分店 / 年度）、来源（人定 / CC 学来 / Express 历史）、证据（哪几张单）、
谁何时定。优先级：会计员在对话里明说 > 人定的公司规则 > Express 历史已定 > 名称匹配。从纠正中学（复核时改的、Express 里改了 CC 推的分录经回读发现），
月底 CC 一次问「要不要记住」，点了才生效；与近期做法冲突就标出请人确认；存在公司主档上全所共用；CC 用到哪条就说出来，主档页可查改删。

## 验证

- 每期：本地全闸门、分支 CI、改 `pearnly_core` 时候选离线检查（`~/pearnly-devtools/cand-run.sh`）。
- 第 3 期：测试机 `C:\PearnlyStress\语料\06-录入推送`（6205 份、62 家，带 Express 答案）按家模拟整月，用已有识别结果回放（不付费重识别），
  量自动推送部分的准确率（目标 ≥99.5%）、能自动的占比、异常数；达标后测试租户一家整月试点，再上真实客户。
- 测试写入只写测试机 C 盘 `C:\PearnlyExpress`，局域网 Accserver / S 盘不写。
- 多人场景（各用自己的电脑）需要第二个 testcowork 测试用户，由用户在「团队管理」添加并自己在录制笔记本上登录（账号 `acct` 下装 CC 桌面版）。
