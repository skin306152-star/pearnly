# 需求影响评估：单据打印（领料单、收货单 1:1，其余单据同一风格）

> 按「需求影响评估」模板填写，交主会话审定后施工。基线 `origin/main` `dfc9ea31`。`P/` = `apps/pearnly_erp_portal/pearnly_erp_portal/`，`D/` = `P/pearnly_erp_portal/doctype/`。
> 事实来自 10-25 全仓只读排查。两份 Print Format 预览样张等出入库 B 段实验栈冒烟时一起截（主会话 10-25 定）。

## 0. 需求原文与理解

- 岳父原话：สามารถพิมพ์ใบเบิกจ่ายสินค้า ลองดัดแปลงดูครับ（要能打印领料出库单，照样板改改）；样板：领料单 `images/17.webp`（ใบเบิกสินค้า / GOODS ISSUE SLIP）、
  收货单 `images/18.webp`（ใบรับสินค้า / GOODS RECEIPT NOTE）；抬头补充：รายการตรงนี้ เอามาจากข้อมูลบริษัท หน้าข้างล่าง（抬头取自公司资料页）。
- 用户原话：「涉及到打印的地方，用官方原生打印功能……排查会涉及到打印的地方，都加上」；**最新口径（以此为准）**：「按照老丈人的模版1:1做，不要有任何不一样的地方，logo默认pearnly 但公司可自定义」。
- 理解：
  1. 出库单打印成领料单、入库单打印成收货单，版面与样板 1:1（栏位、顺序、标题、泰英双语、绿色、10 行表格、四个签字栏、勾选框，不增不减不改措辞）；
  2. ERP 有的数据填进去，没有的留空线手写；勾选框能对上的按数据打勾；
  3. Logo 默认 PEARNLY，公司上传了自己的就用公司的；
  4. 其余该打印的单据照这两份的风格做；一律 Frappe 原生 Print Format + Letter Head + 原生打印 / PDF。
- 不在范围：为填满样板去补业务字段（缺栏位清单另定）；改单据业务流程；Express 那边的打印。

## 1. 现有同类与复用

| 现有打印 | 位置 | 处理 |
| --- | --- | --- |
| 采购单生成「代收据」「预扣税证明」PDF | `P/purchasing/output.py:93-123` 用 `frappe.render_template` + `P/purchasing/voucher.html` + `get_pdf`，存成私有 File | 保留（已生成的凭证文件、预扣税证明有法定格式），第二批再评估是否改成 Print Format |

## 2. Frappe 原生能力

- Frappe 16.33.0：标准 Print Format（Jinja，`standard: Yes`，放在 App 模块目录 `print_format/<名>/<名>.json` 随代码维护、迁移时同步，不用 fixtures）、Letter Head（按记录，可设图片 / HTML，HTML 抬头在渲染时带 `doc`）、原生打印预览、PDF、Print Settings（纸张、页眉页脚每页重复）。
- 用法建议：
  - **Print Format**：每类单据一个标准 Print Format，Jinja 只读真实字段；表格 10 行一页、页码、续页用原生分页。
  - **Letter Head**：一条站点级「Pearnly 单据抬头」（HTML），按 `doc` 所属公司取 Logo / 名称 / 地址 / 电话 / 邮箱；样板的抬头和标题框、单号框在同一行，若 Letter Head 只放公司块会把标题框挤到下一行，**为了 1:1**，Letter Head 放整条抬头行（左公司块、右标题框 + 单号 / 日期 / 页码），标题按单据类型取。每页重复抬头用 Print Settings 的「重复页眉页脚」。这一点样张时实测（PDF 生成器 wkhtmltopdf 还是 Chrome、页码变量能不能用）。
- **必须先补的权限**：ERP 岗位角色（「ERP Menu …」）没有 `print` 权限位（`P/access/setup.py:9-10,27` 只给 read / select 等；`apps/pearnly_core/pearnly_core/provisioning.py:314-327` 把没给的位写 0）；`has_permission` 钩子已放行 print。不补的话，除了 System Manager 谁都打不开 `/printview`——**现在 POS「打印收据」对收银员很可能就打不开**（仓库里没有验证过），实验栈要先复现。修法：岗位角色在对应单据上加 print 位（按读权限给，服务端照样按公司 / 仓库 / 收银台过滤）。

**税票风险（建议写死，不做成选项）**

- 接了 Express 的公司：正式税票由 Express 出、以 Express 单号为准。ERP 打印的销售单**不能叫税票**，标题用 ใบส่งของ / DELIVERY NOTE（或 สำเนาเอกสาร），不印「ใบกำกับภาษี」字样，避免同一笔交易两套号、两张税票。
- 没接 Express 的公司要税票：按 ม.86/4 完整税票必备项（「ใบกำกับภาษี」字样；卖方名称、地址、税号、总部 / 分店号；买方名称、地址、税号、总部 / 分店号（局长公告 196 号）；税票号与册号；商品名称、种类、数量、价值；税额与价值分开；开票日）。ERP 现有字段基本齐（销售单有买方名称 / 地址，卖方有税号 / 分店），缺「买方分店号」的要补数据——这一单另立需求，不放第一批。
- 收银小票：简易税票（ม.86/6）需要收银机向税务局备案（ภ.พ.06 批准）。建议小票一律印 ใบเสร็จรับเงิน，不印「ใบกำกับภาษีอย่างย่อ」，除非客户确认收银机已备案——列第 12 节。
- 退货：退款要开贷项单（ใบลดหนี้，ม.86/10）。接 Express 的由 Express 出 SR；ERP 小票退货打 ใบรับคืนสินค้า，不叫贷项单。

**公司资料、Express 与分店**

- 抬头字段来源：`ERP Company` 的 `company_name`、`address`（一整段）、`phone`、`contact_email`、`tax_id`、`branch`。**没有 Logo 字段** → 新增 Attach Image `logo`；没上传就印 App 自带的 PEARNLY Logo（与样板一致）。页脚不放 Pearnly 小字（Logo 默认已是 PEARNLY，页脚再放显得重复，更干净）。
- 接了 Express 的公司：名称 / 税号 / 分店建档时从 Express 写入，地址 / 电话只在空时补（`P/express/masters.py:375-388`），**现在 ERP 里都能改**。主会话口径是「从 Express 读回、只读」——要做到，需把这几栏并进 Express 锁定（`P/express/locks.py`）并在同步时以 Express 为准覆盖，属于对现有行为的改动，列第 12 节确认。邮箱 Express ISINFO 没有，仍在 ERP 维护。
- 没接 Express 的公司：在 ERP 公司资料里维护（现状）。
- 分店：ERP 的公司本来就是按「税号 + 分店」一家一条（`P/express/companies.py:69`），同一法人的不同分店是不同的 ERP 公司、各有地址。所以**按单据所属公司（即分店）打印**，自然就是分店地址，不需要新做「分店地址」。没有分店 DocType，仓库也没有地址。

**CC / Express / Cowork**：打印只读 ERP 数据，不写 Express，CC 载荷不变；Cowork / DMS 不涉及。车辆四项若上线，按台商品的车架号 / 发动机号在行下印一行（模板预留，不改 1:1 版面的栏位）。

## 5. 隔离与权限

- 打印 / PDF 走原生 `has_permission`（print 位）+ `permission_query_conditions`，已按当前公司、本人、仓库、收银台过滤（`P/hooks.py:270-271, 505-522`）；补 print 位后，能读这张单的人才能打这张单。
- Letter Head 按 `doc` 的公司取数据，不读当前用户的默认公司，不会把 A 公司的抬头印到 B 公司的单上。
- 公司 Logo 文件私有（`is_private`），打印渲染在服务端读，PDF 里嵌入，不出公开地址。

## 6. 入口：网页、手机、LINE、拍照

- 网页 / 手机：入库 / 出库弹窗与详情页加「打印」（官方 `frappe.ui.get_print_settings` / 打开 `/printview`，同 POS 做法），手机浏览器同样打开打印预览、可存 PDF。
- LINE、拍照、CC 对话：不涉及（不在 LINE 里发 PDF，无需求）。

## 7. 共用件与连带回归

- 新登记共用件「单据打印」（Letter Head + 公共 Jinja 宏 + print 权限位），入口：`erp.stock-out.print`、`erp.stock-in.print`、（#3）`erp.purchase.print`、`erp.page.pos-receipts` 的打印收据；第二批每加一种单据补一条。
- 改 `P/access/setup.py` 的角色权限位属于全岗位共用，要回归各岗位菜单与列表权限。
- 冒烟：新增「打印预览能出、PDF 能出」探针——对每个入口取一张单，请求 `/printview?doctype=…&name=…&format=…` 断言 200 且含单号；请求 `frappe.utils.print_format.download_pdf` 断言 PDF 头与页数；用非 System Manager 的岗位账号跑（专门复现 print 位问题）。

## 8. 存储与成本

- 打印不落盘（原生预览 / PDF 即时生成）；公司 Logo 每家一张。无外部调用、无月费。PDF 生成占 web 进程 CPU，单张秒级，不影响并发目标。

## 9. 删除、作废、追溯

- 作废单据仍可打印，抬头旁加原生「已作废」水印（Print Format 里按 status 显示 CANCELLED / ยกเลิก）——这是 1:1 版面外唯一的增加，列第 12 节确认。
- 不保存打印件，不需删除。

## 10. 文案与官方 UI

- 版面文字全部照样板原文（泰英双语），属于模板内容，不进界面词条；单据标题、栏位名不改措辞。
- 界面只加「打印」按钮（Frappe 自带 `Print` 词条）。
- 日期：样板印的是 `25/10/2026`（公历、日 / 月 / 年）。1:1 就照公历；Express 和泰国单据常用佛历（25/10/2569）——列第 12 节。金额：`1,234.00`。
- 语言：泰英双语就是样板本身；中文不出现在这两份模板上。

## 11. 测试与验收

- 单元：Jinja 渲染（字段缺失留空不报错、勾选映射、超过 10 行分页、作废水印）、Letter Head 按公司取数、无 Logo 回落 PEARNLY。
- 冒烟：第 7 节探针（含非管理员岗位）。
- 实验栈：两份样张截图（预览 + PDF 各一张）与样板并排给主会话 → 转用户和岳父确认。
- 1:1 核对：栏位逐项对照表（随样张交）。
