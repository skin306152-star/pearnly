## 改了什么

| # | 问题 | 改法 |
|---|---|---|
| 21 | 连续盘点把上一件的实际位置带给下一件，盖掉账面位置，结束盘点时真的调库存 | 只有账上**没有位置**的新品才沿用上一件的位置；有账面位置就用账面位置；修改已录记录不沿用。ERP 与 Cowork 两份 `stocktake-entry.js` 同改。 |
| 1 | 库存页搜索写「按名称或条码搜」，只比商品名 | `inventory/contracts.product_matches`：名称、编码、条码、二维码内容任一包含关键字即命中（与商品列表同口径）；另按售卖单位上的条码精确命中。 |
| 26 | LINE 快捷按钮截到 20 字，名称相近的公司 / 供应商分不清 | 选公司 / 供应商 / 客户 / 仓库时提问里列出带编号的全名；按钮去掉「บริษัท / จำกัด / (มหาชน) / Co., Ltd.」等通用词。 |
| 8 | 没配 LINE 渠道的租户，每次打开个人资料页弹错误框 | 绑定状态接口带 `channel`（`pearnly_core.line.is_configured()`，共用层未改）；没配就在 LINE 块里显示已有的那句「这个账号还没配置 LINE 通道」，不去发码。ERP 与 Cowork 同改。 |
| 11 | 公司税号不查校验位，采购识别却查 | `masters/contracts.tax_id_problem` 用共用层 `tax_documents` 的同一校验位算法（识别也用它）：13 位数字一律验校验位，本公司必须 13 位；供应商 / 客户非 13 位（外国主体）照旧放行。公司、供应商、客户手工保存时检查，只在税号有变动时查（旧值不挡其他字段修改）。报错与识别同一句「税号校验位不对」。识别自动建供应商那条路不拦（识别侧已有复核提示）。 |
| 15 | 「单号前缀」改了不生效 | 用户定隐藏：DocType 字段 `hidden`，接口不再读写；库里的列与旧值保留。本地验收脚本改用备注字段，并补「校验位不对的税号被拒」。 |
| 20 | POS 付款键盘按「分」输入 | 按标准不改：`official-pos_payment.js` 与锁定版本 ERPNext 16.34.1 官方原件逐行一致（官方即按分输入，v16 无现金快捷面额）。 |
