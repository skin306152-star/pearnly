## 2. 重连时旧密钥 401 被当成「服务端旧版」

- 现象（10-18 录制机，`docs/work/2026-10-18-release-4090d01f.md`）：重连前用旧密钥认电脑被拒 401，日志「服务端还不认电脑（旧版），
  半小时后再问」。新密钥照常认上、不影响写账，是分类错。
- 按类核对：服务端机器接口 401 只来自 `http_auth._deny` / `credentials.authenticate`（密钥被吊销、电脑被移除、不是这个站点发的），
  403 是 `_deny_permission`（总闸 / 停用），404 是没有这条方法。桌面端把 401 / 403 / 404 一起当「旧服务端或总闸」的有三处：
  `device_link`（认电脑 / 断开）、`folder_client`、`request_client`。心跳那条线本来就分开（401 → 托盘「连接已失效，请在设置中重新连接」）。
- 改法：
  - `device_link`：`REJECTED = (401,)` 抛新的 `KeyRejected`，`REFUSED = (403, 404)` 才抛 `OldServer`。认电脑遇到 `KeyRejected`：记
    「这把密钥服务端不认（已吊销、电脑已移除或不是这个站点发的），等重新连接」，五分钟后再试，**不标 `device_state`、不停用成员**
    （不影响取任务、写账；3xx 被改写成 401 这类偶发也不会误停）；重新连接换了密钥，按新密钥马上认。`settle_old_key`、`leave` 分开记日志，
    行为不变（照旧只删本机成员）。
  - `folder_client` / `request_client` 的 `Refused` 带状态码（`rejected` = 401）。MR.ERP 只读成员没有心跳：文件夹同步回 401 报 `auth`，
    托盘显示成离线 +「连接已失效，请在设置中重新连接」（与心跳 401 同一句现有文案，没有新文案）；按需请求只是日志分开，退避不变。
  - 服务端 `device_api.py` 的说明同步改。
- 测试：`companion/tests/test_device_link.py`（401 抛 `KeyRejected` 不是 `OldServer`、成员照常可用、日志不写旧版、五分钟再试、
  新密钥马上认；403 / 404 照旧半小时）、`test_folder_member.py`（401 → auth，403 / 404 → offline）、`test_tray.py`（auth → 重新连接提示）；
  契约测试改成 `REJECTED == {401}`、`REFUSED == {403, 404}`，且服务端 401 / 403 的来源还在。

### 本机量测（Mac，Apple M5 Pro，本地 SSD，合成文件；脚本在本会话临时目录，不进仓库）

1000 份合成 `GLJNL.DBF`（各约 240 KB），每项跑 5 次取中位：

| 场景 | 墙钟 | CPU |
|---|---|---|
| 只读表头 1000 份（open + 读 8 字节） | 13.5 ms | 13.5 ms |
| 头一次：stat + 读表头 + 记进本机索引 | 20.0 ms | 20.0 ms |
| 之后（文件没变）：只 stat、用本机索引 | 6.3 ms | 6.3 ms |
| 对照：1000 次 stat | 1.3 ms | 1.3 ms |

本机索引多出约 180 KB / 1000 份（键是临时目录的长路径；Windows 路径短些）。本地盘上可以忽略；真机以读网络盘的往返为主：按 10-18 记录的
模型（局域网每次 stat 加 2 毫秒、每次打开加 6 毫秒）估办公室测试机 1353 份：装 1.9.1 后头一次整套扫描多约 1353 ×（2 + 6）≈ 11 秒墙钟
（CPU 仍限在 15% 个核内，读盘等待不占 CPU），之后每次整套重扫多约 1353 × 2 ≈ 2.7 秒墙钟、只给有新录入的那几份各多一次打开。
**真机数字以测试机实测为准**（下面第 3 节）。

## 给测试窗口的验收步骤

前提：服务端用本分支实时源码挂到测试环境（`PEARNLY_TESTENV_SRC=<本工作树> bash scripts/testenv.sh live cowork`，测完 `lab-stop`）；
测试机装本分支 Companion checks 打出的测试包（GitHub Actions 这次运行的附件 `companion-installer-test`，留 1 天；装完关于里是 1.9.1），
装完照旧以普通权限重启 CC 桌面版。

### 1. 托盘提醒按公司打开

1. 在 testcowork 的网页（不在 CC 对话里）给一家**已建主档**的公司建一条定时任务（读测试机上的文件夹，文件夹属于这家公司），把提醒时刻设成
   几分钟后（用指定时刻，不等真实日期）。
2. 等提醒到点（服务端每 5 分钟）、CC 桌面版文件夹同步（约 1–2 分钟）：托盘弹提醒。
3. **点托盘通知（要人在电脑前，或测试窗口能远程点桌面时代点）**：CC 窗口打开并直接是这家公司的主档页（不是定时任务页）。
   再来一次时先把 CC 窗口开在对话页：点通知后页面内切到主档页、不重新加载。
4. 对照：在 CC 对话里建的任务（提醒挂在那段对话上）点开仍是那段对话；一次来两条以上合成一条，点开是定时任务页。
5. `companion.log` 里没有「对话提醒交给托盘失败」。

### 2. 401 不再当旧服务端

1. 测试机 CC 桌面版连着 testcowork。在网页「设置 → 电脑」里把这台电脑移除（管理员可做；吊销它的密钥）。
2. 看 `%APPDATA%\Pearnly\logs\companion.log`：应有「这把密钥服务端不认（已吊销、电脑已移除或不是这个站点发的），等重新连接」，
   **不应有**「服务端还不认电脑（旧版），半小时后再问」。托盘状态：「连接已失效，请在设置中重新连接」。
3. 只读文件夹的 MR.ERP 成员（有的话）同样显示这一句（原来只显示离线）。
4. **在 CC 窗口点「连接」重新连接（要人在电脑前或远程操作）**：新密钥马上认上（日志「认电脑」不等半小时），推一张单照常写入。
5. 对照：没被移除的成员整个过程照常取任务、写账。
