# Express 账套选择照真实用法 + 目录改为缓存 / 手动重新读取（2026-09-27）

分支 `codex/express-catalog-select`，基线 `origin/main` 96024a4c。用户 2026-09-27 同意方案后开工。

## 起因（测试租户真实数据，只读核对）

- 办公室那台小助手授权了 15 个 Express 数据文件夹（57EXP～70EXP、ExpressI 等），共上报 965 份账套。
- 每个 EXP 文件夹 = 打开那一年 Express 看到的登录列表，**不等于会计年度**：59EXP 列表里有 LJLAND 2546～2559，
  68EXP 列表里同时有 68LJLAND 和 69LJLAND。
- 旧网页「公司 → 年度」：公司取 ISINFO 法定名（读不到就用登录列表名），年度取文件夹名 →
  读不到公司名的老账套一行一家「公司」；同一公司同一文件夹的几份账套（审计版 / 数据版、分厂）年度下拉里是一排相同的「68EXP」。
- 打开弹窗就让小助手快扫（只读登记表、**不读公司名**），小助手每 30 分钟又带公司名全扫；两者互相覆盖，
  实测 20:07 那版公司名 0 个、20:09 又回到 473 个。推送前网页还要再刷新一次拿回执。

## 改成什么

| 位置 | 改动 |
|---|---|
| 选择 | Express：**年度 = 数据文件夹**（新的在上，无年份的排后）→ **账套 = 该文件夹登录列表原样**（名字、顺序），第二行小字公司法定名；够不到 / 写不进的不列；同一文件夹重名的补目录名区分。MR.ERP 仍是「公司 → 年度」。 |
| 分组来源 | 服务端纯函数 `pearnly_cowork/targets/catalog_groups.py`，`connections.service.targets` 返回 `groups`；网页弹窗与 LINE 同用这一份。 |
| 缓存 | 打开弹窗用服务端存着的目录，不再现扫；服务端还没有目录时才自动读一次。弹窗加「重新读取」。上次在该连接选的账套本机记住、下次预选。 |
| 推送检查 | 不带刷新回执时改为**按当前目录核对**：账套在当前这份目录里、可用、可写、程序目录（若指定）对得上即可；**不再钉死连接绑定的那个文件夹**（年度文件夹之间可选）。带回执的旧调用照旧严格核对。写入前小助手仍对照 Express 登记表与授权文件夹当场再核（`worker._task_settings`，未改）。 |
| 小助手 1.2.2 | 扫描一律带公司名，ISINFO 按修改时间缓存（公司名 / 税号 / 默认科目一次读）；平时每分钟后台比一次各文件夹登记表 + 当前账套科目表，变了才重扫，另每天兜底全扫（取消每 30 分钟全扫）；「重新读取」整套重扫，配对时「全部授权」的还会重新找盘上的年度文件夹并记进授权名单；刷新超时 120 秒 → 300 秒。 |
| 下拉组件（共用层） | 产品下拉皮肤按纯文本补回官方的选项第二行说明（`pearnly_core/public/desk/select.js`）。账套下拉上限 99 → 1000（63EXP 有 182 份）。 |

有意的行为变化已登记：`scripts/cowork-targets-source-parity.py` 不再比对「不带回执」的情况（旧版一律 proof_missing）。
