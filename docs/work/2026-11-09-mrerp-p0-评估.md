## 0. 需求原文与理解

- 原话：用户 11-09「MR.ERP 在 CC 里要和 Express 一样，Cowork 和 ERP 的直写、代录四种组合都要做到 Express 现在的程度」。主会话 11-09 定：P0 七项先开工；①共用通道部分与 A 对文件（已对：①②③由 D 做，A 审接口）；⑦等 A 第 3 批；④改已有文案先给清单；风险 7 口径（直写复用会话、被踢走等人、不抢登录）。
- 理解：开关打开后，四种组合遇到 MR.ERP 公司时，要和 Express 公司**走同一套卡片、同一套原因码、同一套设置入口、同一把写者锁 / 同票判定**，而且 ERP 代录能真的把单派到电脑上的 MR.ERP 执行层。
- 不在范围：P1 各项（认领已有档、按日期挑年度、按客户记住、按行仓库、AI 接手、疑似重复、自动推档位、现购走代录、逐行免税拆单、库存进出单）；复核卡本体（A 做）；真站点探路（等岳父）。

## 1. 现有同类与复用

- 全部复用现有：Cowork 的 MR.ERP 代录接法（`service.py:895-913`、`companion/mrerp_jobs.py`、`operator_source.py:21-31`）是 ① 的样板；ERP 直写的 `mrerp_needed` 卡片项是 ③ 的样板；Cowork 的 `ERR_MRERP_*` 词条是 ④ 的样板；A 的 `pearnly_core.ledger_tickets`（`entered` / `one_writer`）是同票判定与写者锁的唯一入口。
- 新建只有一处：共用通道里的 MR.ERP 账号租约（从 Cowork 下沉，不是新写一份）。

## 2. Frappe 原生能力

- ⑤ 公司页 MR.ERP 段用官方 Desk（FieldGroup / Dialog / ControlLink 的 `get_query` 服务端搜索），账套列表走 `limit_start / limit_page_length`；不加 Vue。其余项不涉及界面框架。

## 3. 按类通用

- 一类：「CC 写账目标 = 账本种类」。Express 与 MR.ERP 在卡片、原因码、设置入口、同票判定、写者锁、等电脑规则上同一套；四组合（两产品 × 两模式）一起覆盖，不只修一格。
- 不覆盖：LINE 收单、文件夹定时（定时只走直写，已有 MR.ERP 前置检查；复核卡范围也不含）。

## 4. 上下游数据

- ERP：MR.ERP 公司的单据入账后照现有规则排「账本」（`MRERP_LEDGER`）；代录单冻结载荷在共用任务上，回执写回单据 `ledger_state`（与 Express 同字段）。MR.ERP 不回对方档码 / 存货码（与 Express 不同，ADR-027 §6 ③ 的「待补码」不适用），ERP 主档同步不读 MR.ERP，不会重复建档。
- Express 映射：不涉及（MR.ERP 公司不接 Express）。
- CC 桌面版：载荷不变（MR.ERP 代录载荷 18 已有，`worker.py:248-255、392-395` 按载荷 target 分路，不分通道）；不发新版本。原因码改发专用码属执行层改动，**要发 CC 新版**（④ 那一批随下次 CC 发布）。
- Cowork：① 动 Cowork `mrerp_jobs.py`（租约改引用共用层），金样锁住；③ 动 Cowork 预检。DMS 不涉及。

## 5. 隔离与权限

- 共用任务按租户站点隔离不变；`target=mrerp` 的任务只派给 `route_device` 那台、且心跳报过 `mrerp` 与该连接号的电脑（同 Cowork 现规则 `route_contracts.decide`）。
- 账号租约键 = 网址 + 用户名（`mrerp.session.lock_key`），跨产品同一把：Cowork 与 ERP 用同一 MR.ERP 账号时互斥（现在两边各一把，会互踢）。
- ⑤ 接口全部服务端判 ERP 管理员 + 开关；密码不经任何接口（只在 CC 桌面版授权）。

## 6. 入口

- CC 对话（电脑网页 / 手机网页同一前端）、CC 桌面版代录。⑤ 是 ERP 网页公司页 + CC 设置连接页。手机端 ⑤ 的设置行只读（同 Express）。不涉及 LINE、拍照、相机。
