## 修复

| 页 | 现象 | 原因 | 修法 |
|---|---|---|---|
| 银行 / 收入 | 打开已完成任务、什么都不改，页面期末 / 差额就和导出不一致；点保存把错数写进存档 | 结果页从排好序的结果行倒推原始输入：同一天的流水被重排，期末取错行；税表同号多行时总账算几遍；同凭证另一边的行丢失；科目只剩第一个 | 建任务、确认复核、每次保存时把两边原始输入按文件顺序存进 `inputs_json`，页面从它出发；收入页面改总账金额按差额补一行；旧任务仍按结果行还原，但同号只还原一次、科目全留、没改过的不动期末 |
| 银行 | 总账只改单号 / 日期，整列余额被改错 | 「金额改没改」连日期单号一起比 | 按行位置只比借贷金额 |
| 银行 | 待复核任务清空一行余额后保存 / 确认弹系统错误 | 对空余额取整 | 判这一行没对上，后面按推算值接着核 |
| 银行 | 总账「(500.00)」冲销被记成同方向，差额 1,000 | 旧线上取绝对值 | 负数记到另一边（与 09-28 收入对账同一口径） |
| 银行 | 总账没有余额列时期初期末整个反号 | 旧线上期初「贷 − 借」，逐行余额却是「借 − 贷」 | 统一「借 − 贷」（银行科目借增贷减） |
| 收入 | 同一凭证有折扣借方时报假差额，调节表走不平 | 旧线上正数税表只取贷方 | 比凭证净贷方（贷 − 借） |
| 收入 | 税表同一单号几行，每行都和整张凭证比，报 −400 / −600 | 旧线上逐行比 | 前几行认自己的税表金额、最后一行认余下的，差额只记一次 |
| 收入 / 销项税 | 合计写在第二、三格时被当成一张发票，税表合计翻倍 | 旧线上只看第一格 | 另认「没日期、没带数字的单号、某文字格以合计字样开头」的行（名称里带 รวม 的客户不受影响） |
| 销项税 | .xls 发票号 / 分支带「.0」、数字税号掉开头 0，一致的行判「疑似匹配」 | 格子浮点直接转字 | 整数浮点还原成整数文字；数字格子 12 位税号补回 0 |
| 销项税 | 报告只有合计列时 VAT 算两遍（1,070 → 1,140） | 没有未税列时拿合计再加 VAT | 合计本身含税，不再加；导出同一口径 |
| 销项税 | 发票表没有合计列时按 0 比 | 直接取合计列 | 用「未税 + VAT」补（与 CSV 发票表同一口径） |
| 录入 | 多页票某页日期写成「28-Sep-26」，复核页任何保存都失败 | 保存时所有页严格校验，复核页只能改主页面 | 没改过日期的页沿用入库时的宽松规则；改了还是严格 |
| 录入 | 复核页改的是一页，推送读的是另一页，报「请选进项还是销项」 | 推送取第一个非副本页（哪怕是空页），复核页取填得最满的页 | 推送与复核页同一判定（`contracts.history.primary_page`），全都读不出时仍按旧规则 |
| 三个对账列表 | 面包屑只剩「…」「销...」 | 09-29 给指示器配样式时给面包屑加了「最多占标题区 40%」，标题区按内容定宽 | 去掉百分比上限，空间不够时指示器先截断 |

有意变化已在对照测试逐字登记（`tests/test_cowork_gl_text_source_parity.py`、`tests/test_cowork_reconciliation_income_vat_parity.py` 的 `INTENTIONAL`，每处替换断言只命中一次，其余逐字对照）。

## 没修、需要用户定或属旧版口径

- **推送金额口径**：票面有折扣或预扣税时复核页不提示，推送按旧线上「税前 + 税额 = 合计」退回「金额算不平」。修哪一边会改变写进 Express 的数（推送要带折扣 / 预扣，或复核页也按推送口径标红），待用户定。
- 上传完成提示「成功 N 张 · 失败 M 份」单位不同：旧线上同样如此，未改。
- 收入对账容差内的小差额（≤ 0.01）在调节表上显示为 0，调节表可能差 0.01：未改。
