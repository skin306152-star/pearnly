# CC 引导式录入：Express 必填覆盖表（第 1 期验收依据）

- 属于 [CC 引导式录入评估](2026-11-12-cc-guided-entry.md)；分支 `pearnly/cc-guided-entry-51673b`，基线 `origin/main` 32695c276。只读调研，没改产品代码、没连测试机和生产。
- 用户 11-12：「一定要注意一个问题，收集信息的问题和相关复核卡的字段，是否覆盖或者满足exp的相关必填要求。我举个列：用户选择了这批商品是库存，
  但是发现这个是新商品，需要新建，但是缺成本，这种模型无法判断的，是否覆盖给到用户填入，又或者复核卡的字段列入商品是否可以修改，
  这可能只是我想到的一些地方，还有很多我没有想到的地方需要满足覆盖」。
- 原则：写一张单、建一条主档时 Express 必须有值的每个字段，只能是三种之一——**后台自动定**（有依据）、**引导卡问**、**复核卡可改**。
  「缺了就静默写个默认值」「缺了直接失败让用户看不懂」都算缺口。

### 2.4 负库存选项（用户 11-12：「exp那边好像是新建商品时有个选项的，是否允许负库存」——属实，两处都有）

| 层级 | 字段 | 取值 | 证据 |
|---|---|---|---|
| 物料 | `STMAS.NEGALLOW`，字符 1 位；Express 界面叫「ส/ค ติดลบได้? [Y, N, A]」 | `Y` 允许；`N` 不允许；空 = 跟账套；`A` 没测过 | `C/table_specs.py:141`；`C/stock_guard.py:8-10`（10-25 在服务器测试账套 `70EXP\test` 实录） |
| 账套 | `ISINFO.NEGALLOW` | `N` 不允许，其余允许 | `C/stock_guard.py:58-60` |
| 账套 | `ISINFO.CHKNEGLEV` | 1 / 2（空按 2）按单个仓核；0 只核全仓合计 | `C/stock_guard.py:63-70` |
| 账套 | `ISINFO.NEGAUTH` | **含义没查到**（表里有这一栏，代码没读） | 本机账套副本表头 |

- **Express 自己的行为**（已有实录，`C/stock_guard.py:8-20` 引的共享笔记「服务器test账套-录单结果」）：物料级盖过账套级。`Y`：只弹 605 提醒、照存，分仓可以变负。
  `N` 或账套不许：按仓核时录那一行就拦（Message 4224）；只核全仓时保存时拦（Message 4091）。是**拒绝，不是警告**。
- **我们直写读不读**：读。写销货、调拨、库存单、作废入库前都照同一套规则核，不够就整单不写、回 `STOCK_INSUFFICIENT`（`C/dbf_sales.py:276-279`、`C/dbf_transfer.py:163`、
  `C/dbf_stock.py:380-382`、`C/dbf_void.py:151`）。服务端也读得到：账套设置与每件物料的选项、结存都随主档读回（`C/express_masters.py:59,146`），所以引导卡能在写之前就把事实列出来。
- **新建物料时 Express 的默认值**：本机一套原生库存品 37 件，33 件是空（跟账套）、4 件是 `Y`，没有 `N`；非库存 127 件全空。看起来默认是空，**只有 1 套、不算定论**，
  62 套的分布并进测试机补证第 ② 项，界面默认值在第 ① 项新建物料时截图确认。
- **现有代码建新物料写什么**：不是照抄模板，是写死 `Y`（`C/product_master.py:566,580-585,712`），理由是「新品当次就要卖成负」。这等于替账套改了规矩（缺陷 G-B6）。
- **按「Express 不拦的不拦、Express 拦的不绕过」定的做法**：
  - 已有物料：照它自己的选项办（现状已是）。允许 → 照写不问；不允许且不够 → 不写，卡上列事实，不出「要不要卖成负」的题（Express 不给这个选择）。
  - 新建物料：选项默认留空（跟账套），收在「新物料」的「已定」里，展开可改成允许 / 不允许（D-4 的原则）。销售随单新建的物料结存是 0：账套（或用户选的）不许负库存 →
    这张单写不进，卡上如实说「这件是新物料、没有库存，这本账套不许负库存」，先录进货再录这张；允许 → 照写。
  - 与「填单位成本 / 不结转成本」那一题的关系：**先过负库存这一关，过了才问成本**。只有允许负库存、而这一行没有成本基础时才出成本题；不允许负库存的单不出成本题
    （写不进），等进货录了以后有了成本基础，也不用问。

## 8. CC 桌面版载荷接口约定（载荷 21「引导录入」）

服务端施工窗口（第 1 期）与「CC 桌面版载荷与写入缺陷」窗口共同的依据。现有机制不变：载荷带 `payload_version`，CC 桌面版不在支持集里的版本诚实拒收
`ERR_PAYLOAD_VERSION`（`C/payload_contract.py:56,84-89`）；服务端按载荷里出现的键盖最低版本（`P/common.py:245-268` `finalize_payload`），派单只交给报过支持该版本的电脑。

### 8.1 总则

- 新版本号 **21**，常量两边同名同值：服务端 `P/common.py` 的 `GUIDED_PAYLOAD_VERSION = 21`，CC 桌面版 `C/payload_contract.py` 的 `GUIDED_PAYLOAD_VERSION = 21` 并进 `SUPPORTED_PAYLOAD_VERSIONS`。
- **只有带了下表任一新键的载荷才盖 21**；不带新键的载荷与现在逐字节相同（LINE、网页、定时任务、自动推都不受影响）。
- 表头新键 `guided: true` =「这张单是人在 CC 对话里过了引导卡之后写的」。它打开电脑端的**不静默**模式：下面标「引导模式拒收」的情形，电脑端不再用默认值写，
  而是整单不写、回原因码并带回候选，服务端把它变成引导卡上的一题（做法同已有的 `SERVICE_VAT_BASIS_CHOICE`，载荷 13，`C/dbf_writer.py:390-396`、`E/prepare.py:81-90`）。
  不带 `guided` 的载荷，这些情形的行为与现在完全一样。
- 金额、成本、系数一律十进制字符串（同现有 `qty`、`unit_price`）；日期用现有佛历格式（同 `docdate_be`）；编码是 Express 里的原码。
- 新键的值不合法（码不在对应的表里、日期早于单据日、负数）一律整单拒收，不回落默认。

| **销售员不问、不显示**（D-1，依据是本机一套销售员全空） | 赊销单 **90% 带销售员**，现销单 93.5% 带；客户档 59% 带销售员 | 那一套不代表多数。原生销售单绝大多数有销售员，而我们直写**完全不写**（`C/dbf_sales.py:503-531`）。**新缺口 G-A15**：销售单的销售员照 Express 取客户档上的销售员自动带上；客户档没有时不问（留空）。不显示可以维持，但不能不写 |
| **部门不问**（D-1） | 赊购 76%、现购 84% 不记部门；赊销 47.5% 不记；**现销 94% 记了部门** | 维持不问，但写法要对：部门取单据簿默认（现有做法，`P/choices.py:229-236`）。现销几乎都有部门，说明它来自单据簿默认而不是人填——与现有做法一致，不算缺口 |
| **新对方税号为空照建是缺口**（G-A8 的一部分） | 供应商档 31.5% 没税号，客户档 **72% 没税号** | 不算缺口：原生就这样。卡上仍显示、可补，但空着不拦 |
| **代录销售单不填「อ้างอิง」是缺陷**（G-B2） | 原生赊销单 90%、现销单 96.5% 这一格本来就是空的 | 不是缺陷：Express 原生也不填。真正的问题换了一个：销售单的票面号在 Express 里就是单号本身，直写把票面号写成单号，**代录是让 Express 自动编号，票面号没有进账**。改列为 G-B2′，做法待定（代录时手填单号要先在测试机试） |
| **账期不写按 0 天只是「静默默认」**（G-R2） | 供应商档 91% 账期是 0，客户档 70% 是 0；但赊购单 **56% 的到期日晚于单据日**（8–30 天 37%、31–60 天 13%），赊销单 73% 晚于单据日 | 比原来想的重要：过半的赊单到期日不是当天，而档上多数没账期——说明会计是**逐张填到期日**的。G-R2 维持，优先级上调：复核卡上赊的单必须露出到期日 |
| 标准成本不写 | 库存品 92.6% 标准成本是 0 | 维持「不写」。也说明零库存时「取标准成本」多半取到 0，G-A11 的成本题确实用得上 |

### 9.3 负库存选项（补 2.4 节）

| 项 | 原生取值 |
|---|---|
| 账套不许负库存 `ISINFO.NEGALLOW = N` | S 盘副本 **39.4%**（407 / 1033）；T 账套 28.7%；服务器副本 4% |
| 按仓核还是按全仓 `CHKNEGLEV` | 0（全仓）61.5%、2（按仓）36.8%、1 占 1.7% |
| 物料级 `STMAS.NEGALLOW`（库存品） | 空 64.7%、**N 29.7%**、Y 5.7%；**三组里都没有出现过 `A`** |
| `ISINFO.NEGAUTH` | 空 77.5%、`5` 占 21.4%、`9` 占 1.1%（像是一个级别数字；含义仍没查到，要看界面） |

- 约四成账套不许负库存、三成库存品逐件标了不许：**G-B6 不是边角情况**，现在「新建物料写死允许、销售随单新建不核」会在相当多的账套里写出 Express 不让写的负数。
- 新建物料的默认值：空占多数，支持「留空跟账套」；但 `N` 有三成，可能是某些账套新建时默认就是 `N`，或会计逐件改的——界面默认值仍要实看。
- `A` 在 174 万件物料里一次都没出现：载荷键 `negallow` 只收 空 / `Y` / `N` 没问题。

### 9.4 其它观察（不改结论，记一笔）

- 库存品换算系数：7.6% 的库存品有不为 1 的包装系数；「单位同码、系数却不为 1」占 0.4%（G-B1 说的那种形状原生也有少量，新建时仍应写 1）。
- 客户信用额度：12% 的客户设了额度；代码里没有任何信用额度检查（原来就列在「没查到」里），Express 自己拦不拦要看界面。
- 价格类型 `FLGVAT`：现销单原生 90.6% 是 `2`，我们按单别写 `1`（`C/dbf_fields.py:20-34`）；赊购 9%、赊销 12% 是 `1`。金额不受影响，是显示口径；已有专门记录（`docs/work/2026-10-29-express-rules-vat.md`），不在本表范围，提一句备查。
- 成本法：先进先出 86%、平均法 14%；用不用部门全部是「用」。
