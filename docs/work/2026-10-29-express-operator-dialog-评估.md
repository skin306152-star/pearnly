# 需求影响评估：实操对话框（甲）

> 2026-10-29 实操窗口起草，交主会话审定后施工。

## 0. 需求原文与理解

- 原话（主会话 10-29 转达用户定的甲）：保留对话框，照 Claude 做成底部一行输入框，不是主角。
  - 开工不用说话：选公司、选月份即建任务，右侧放资料，点开始（照旧）。
  - 中途拿不准的（科目、供应商对应哪个 Express 档等）在对话里弹选项按钮让人点，也可以打字答；答完接着做。
    按「不确定的地方让人选一次、之后复用」的口径记住。
  - 对话里可以临时交代（跳过第 N 张、重做、本月运费记到某科目），也可以问结果（第 N 张为什么没录、今天录了多少）。
  - 不加说明性文案和欢迎语。
- 我的理解：
  - 实操任务页底部那个输入框（现在复用对话页的 Composer）发出的话，交给 CC 对话引擎处理，引擎带一组「实操工具」。
  - 任务里要人选的项（开始前确认、录到中途停下等人选的）以选项卡片出在这个任务的对话里，点了就记住、接着录。
  - 右侧栏照旧，是主看板，对话是辅助。
- 不在本需求范围：
  - AI 自己替人决定不确定项（只问、只记人的选择）；
  - 语音；
  - 跨任务、跨公司的对话；
  - 改直写对话页的行为；
  - 新的报表。

## 1. 现有同类与复用

- 对话引擎：`apps/pearnly_core/pearnly_core/assistant/`（`engine.py`、`toolrun.py`、`engines/anthropic_managed_agents.py`）。
  产品用 `hooks.pearnly_assistant_tools` 声明工具，现在只有 Cowork 声明。
- 选项卡片：对话侧已有（`frontend/assistant/src/components/pending.tsx`、`company-cards.tsx` 的按钮卡），
  答完走产品「选一次」的同一套核对：Cowork 是 `companies.rules`，ERP 是 `express.choices.remember`。
- 实操已有的能力：
  - 预检问题：`model.Question`、`ConfirmSection`；
  - 共用层 API `status / resolve / precheck / start / task_*`；
  - 桥上控制 `skip / retry / stop / resume`；
  - 预检里人定的项先记住再交单（ERP `operator._remember`、Cowork `operator_source` 同口径）。
- 结论：扩展现有。
  - 共用层新加一组实操工具（`pearnly_core/express_operator/tools.py`），由共用层声明给两个产品。
  - 前端在任务页嵌对话线程（复用 Thread 与卡片）。
  - 不新建引擎、不另做卡片。

## 2. Frappe 原生能力

- 不涉及：CC 前端是独立 SPA（`frontend/assistant`），不是 Desk 页面；服务端只加白名单方法与工具，不加 DocType 字段。
- 每个任务的对话线程挂在现有对话会话表上，不新建 DocType。

## 3. 按类通用

- Cowork、ERP 两个产品走同一套共用层工具；凡实操支持的单据种类都覆盖。
- 对话里能做的动作只限实操已有的能力：跳过、重做、标结果、答选项、问状态。不新增写账能力。

## 4. 上下游数据

- 记住的选择：写进产品现有的「选一次」记录（同直写），直写之后也按它走。这是口径一致，不是副作用。
- 「本月运费记到某科目」：
  - 按公司规则记（同直写）；
  - 只对这个任务生效的临时规则另存在任务上，不进公司规则（见第 12 节问题 2）。
- Express：录法不变，载荷不变，CC 桌面版不用发新版（跳过、重做走现有桥上控制）。
- Cowork / ERP 单据：不改字段；状态照现有推送链路回写。

## 5. 隔离与权限

- 任务只给创建人看（现有）；对话线程绑任务号 + 本人。
- 工具在服务端按本人会话执行，每次先过 `products.allowed(user, company)` 与记录范围（ERP `guard.scope_filters`）。
- 跨公司：工具只认这个任务的公司，问别家公司的单一律拒。

## 6. 入口

- CC 桌面版实操页：主入口。
- 网页、手机上打开同一任务：
  - 能看、能问、能答选项；
  - 跳过、重做要录单的电脑在线，不在线如实说。
- LINE、拍照：不涉及（实操不在 LINE 里）。

## 7. 共用件与连带回归

- 改到的共用件：对话引擎（工具注册）、实操共用层、CC 前端 Thread / Composer。
- 回归：
  - 按 `scripts/check-impact.py` 出清单逐入口实测；
  - 对话侧人工回归同昨天：新建、附件、切会话、侧栏排序；
  - Cowork 对话工具照常。

## 8. 存储与成本

- 只有打字发问才调模型；点选项按钮、预检、开始不调模型。
- 每句约一次对话调用，同现有对话的单价；没有新增固定月费。
- 线程消息存现有会话表，量与对话侧相当。

## 9. 删除、作废、追溯

- 删任务时连同它的对话线程一起删。
- 记住的选择留在公司规则里，在现有地方改或删。
- 对话里叫「重做」的单：走现有放弃 / 作废两道保护。已入账的单不在对话里作废，要人在 Express 里处理（照现有口径）。

## 10. 文案与官方 UI

- 不加欢迎语、说明文案。
- 按钮文字来自数据（科目名、供应商名）或复用现有词条（已入账、没有入账、跳过、重试）。
- 回答由模型按界面语言生成。
- 若有新增固定词条，过 `scripts/check-copy.py` 并附清单。

## 11. 测试与验收

- 离线：
  - 工具的权限：别家公司、别人的任务一律拒；
  - 跳过、重做、标结果、答选项各走现有路径；
  - 问状态回真数；
  - 前端：选项卡片出现在任务线程，点了记住并接着录。
- 实验栈 + 测试机实机（69EXP\test）：
  - 一张单中途停在「选供应商」，在对话里点选项后接着录成；
  - 打字「跳过第 2 张」「第 1 张为什么没录」「今天录了多少」各一次；
  - 截图给主会话。
- 用户要亲自看：对话框不抢主角、选项卡片的样子。

## 12. 要问用户的点

| # | 问题 | 我的建议 | 不定的影响 |
|---|---|---|---|
| 1 | 中途有一张要人选时，其余的单是否接着录 | 接着录别的，这张排到最后，人答完再录 | 不定就整批停下等人，慢 |
| 2 | 「本月运费记到某科目」是只对这个任务，还是按公司一直记住 | 按公司记住（同直写「选一次」）；用户说「只这次」时只记在任务上 | 两种存法不同 |
| 3 | 打字提问每句要调一次模型（约同对话侧单价） | 照做，按钮操作不调模型 | 无 |

2. 前端：任务页线程、选项卡片、发送接引擎：约 2 小时。
3. 闸门、实验栈与测试机实机、截图：约 1.5 小时。要服务器版 Express 在线，20:40 前收尾。

- 合计约 5–6 小时。今天 20:40 前做不完实机：建议今天做完 1、2 和离线测试，实机放到下一次服务器在线时。

## 审定（2026-10-29，主会话转达用户批复「可以」）

第 12 节三点全部按建议：

1. 某张单要人选时，其余接着录，这张挪到最后，人答了再录。
2. 「本月运费记到某科目」这类交代按公司记住；用户明说「只这一次」才只用在这个任务上。
3. 打字提问每句调一次模型，按对话侧价格计费；按钮不调模型。

施工顺序：单据类型覆盖（真实语料）与对话框都做；要服务器版 Express 的部分先在 20:40 前做，离线部分不受关机影响。

## 施工记录（10-30，离线部分）

- 服务端（共用层）：
  - 任务表加「对话」「待执行的控制」两栏，对话会话表加「所属实操任务」一栏（原生迁移随源码）。
  - `tasks.thread`：一个任务一段对话，第一次打字时建；对话侧栏的列表不列这种对话；删任务连对话一起删。
  - `sessions.send`：这种对话每条都在批末系统消息里带上任务号、月份、状态和公司名。公司名是租户输入的，转义后包在标签里，并写明它只是数据、不是指令。
  - 工具 `express_operator_status`（以站点为准收尾后回每张单的编号、状态、Express 单号、原因）和 `express_operator_control`（跳过 / 重做，按编号或单据编号）。两个产品在 hooks 里列上，步骤名译文进 pearnly_core 术语表。
  - `tasks.push_control` / `take_controls`：跳过、重做先记在任务上，执行的那台电脑的 CC 页面取走后，照桥上已有的控制去做。
  - `tasks.answer`：录到中途停下等人选的单，人点了选项，产品先记下（同开始前确认），再按原批次号把这一张交回同一个任务（CC 的批次按批次号接着收，跑完了也会重开）。只认这个任务里「未完成」的单，要过产品的公司权限。
- 前端：
  - 任务页底部输入框：打的字交给这个任务的对话，资料照旧进资料区。开始以后打字不再另建任务。
  - 回复画在单据行下面，复用对话页的消息组件 `ThreadMessages`。
  - 「未完成」的单先在站点预检一次，要选的按类出下拉，选齐点「确认」交回任务，不调模型。
  - 执行的那台电脑轮询进度时，每 6 秒取一次跳过 / 重做。
- 离线测试：实操任务 11 项（对话只建一次、说明转义、别人的任务拒、控制只认本任务的单、作答只交未完成的单并带原批次号、删任务连对话、工具编号）；对话模块 166 + 26 项；实操前端规则 14 项。
- 没做 / 待做：
  - 实验栈 + 测试机实机（要服务器版 Express 在线）；
  - 第 12 节第 1 点「其余接着录、这张排最后」不用改 CC 宿主：宿主只在整批的原因（登录、公司、授权名额、服务器、预算）上停整批，
    单张录不了的标「等人」后接着录下一张；要人选的单在服务端交单时就停在「未完成」不交给电脑，人点了选项才按原批次号交回，
    排在这一批最后（batch.run_one / host.handle，10-30 核对）；
  - 「本月运费记到某科目」按公司记住：Cowork 对话里本来就有公司规则工具，ERP 没有，另议。

## 实机（10-30 下午，实验栈 testcowork 挂本分支 44bbe6f9 + 录制机 aksar 的 CC 测试包 44bbe6f9）

- 前端修了一处：任务页运行时原来把会话控制器的消息当 ThreadMessage 直接交给组件库，整页崩到「重新加载」（unstable_state）。改成同对话页：ThreadMessageLike + `convertMessage: (m) => m`。
- 问进度（打开 10-28 已完成的任务）：打「这个任务录了几张？每张的 Express 单号是多少？」。
  - 任务页里出现这句话、步骤行「查看了实操任务」、CC 回答「录了 1 张……HP0000038，已录入」，与任务一致；
  - 实验库读回：任务记了对话号，对话行 operator_task = 任务号、不在对话侧栏。
- 跳过（新任务，10 月，3 张：OP6g / OP6f / OP3c）：点「开始」后 3 秒打「跳过第 3 张，不要录它。」。
  - CC 调工具，回「已将第 3 张设为跳过……排队等电脑执行」；任务的待执行控制被执行电脑取走（清空）；
  - CC 批次里第 3 张标成跳过、没录（回执 OPERATOR_SKIPPED），第 1 张录成 HP0000089。
- 中途出现的两件事（都不是对话甲本身）：
  1. 第一轮的第 2 张停在 push.native_target_mismatch：录制机 CC 从 10-27 起暂停，16:03 恢复时上报的账套目录多了 TEST2（582 → 583），排在后面领的那张冻结的目标对不上，按现有保护转人工。
  2. 第二轮第 2 张 `line1: refused: Express has no focused field`：我在录制机拉起的观察脚本窗口抢了前台，Express（之前被前台探针留在最前面）的界面线程没了焦点格，后台方式打字找不到格子就停。空单头 HP0000090 已按两道保护作废。
     这是后台方式的真缺口：Express 原本在最前面时，人点别的程序也会这样。要在打字前把焦点放回上一格（或从表单重新定位当前格）再打，记为待修。
