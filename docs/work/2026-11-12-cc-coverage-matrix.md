## 0. 怎么读这张表

**四种状态（每个「格子 × 业务」只能是其中之一）**

| 记号 | 含义 | 判据 |
|---|---|---|
| **验过** | 能做，且真写进账本验证过 | 有单号 + 读回或账本界面截图，**入口是 CC**（对话或 CC 里这项业务自己的入口），**且证据不早于这条写入路最近一次大改** |
| **没验** | 能做，但没真写验证过 | 代码路径在、工具在。细分两种，都算「没验」：**没验·过期** = 以前经 CC 入口真写过，但之后这条路大改过、没重验；**没验·旁证** = 同一条写入路经别的入口（ERP 网页提交、LINE、脚本、引擎层）真写过，CC 入口没有 |
| **做不了** | 现在做不了 | 没有工具 / 开关关着 / 被明确拒绝 / 在未合入的分支上。写明缺什么 |
| **不做** | 定了不做 | 写明用户或主会话哪天的口径 |

「大改」的基准日（见第 5 节机器检查的 `revalidate_after`）：**所有 CC 写入路 = 2026-11-11**（写入计划、一句话下令、只写选中账套同一晚上线，`d83919935` 11-11 13:15 提交、`6275e4999` 当晚部署）；代录另有 11-04 改版与 11-08 事故修复。**11-11 之后，没有任何一张单经 CC 入口成功真写进任何账本**（压测写入格被 R2-5 挡住，`docs/work/2026-11-11-prod-stress-round2.md:3`）。所以按这个判据，现在「验过」是 0 项；以前验过的全部列在「没验·过期」，并写明最后一次的单号。
