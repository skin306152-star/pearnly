## 0. 需求原文与理解

- 提出人：岳父（经用户中泰互译对话 + Express 截图），11-10 晚用户补充 4 条。用户已对岳父说 2–3 天。
- 理解：大米经销商 5–6 个收款员每天在店门口收 20–30 家。收款员在 **LINE（这家租户自己的官方号）或 CC 对话**里：选公司（账套）→ 找客户 → 勾未付发票 → 选收款方式（现金 / Express 已建的收款类型）→ 填金额 → 转账拍凭证 → 不够时组合 / 折扣 / 部分 → 确认 → 服务器交给 CC 桌面版写成 Express RE 收款单，回 RE 号；电脑不在线先「已记录、待写入」，上线自动补写。ERP 网页「销售 → 收款」只看、导出、点开凭证。
- 不在范围（防扩展）：网页录入 / 修改 / 作废 / 重写收款（11-10 已定）；支票；预扣税、利息（填 0）；一笔钱付几家客户（建议不做，见 §12）；Cowork；MR.ERP 账本的收款；Express 原生作废 RE（写错由财务在 Express 原生作废）；ERP 自己开的销售单上已有的「收款」按钮（只改 ERP 单据收款状态，不写 Express，本批不动）。

## 2. Frappe 原生能力

- 新 DocType + 子表（Table 字段）存收款记录；附件走原件层登记（同 ERP 识别原件），不用 File 公开链接。
- 列表、筛选、导出：Frappe 服务端分页（`limit_start` / `limit_page_length`）+ FilterArea + `p.export_file`，同 ERP 其他列表页；不一次取全。
- 权限：Frappe 角色 + ERP `access` 能力码（服务端判），产品自己声明菜单（`hooks.pearnly_navigation`）与功能目录（`features.json`）。
- 不需要自定义 UI 组件；LINE 端是 LINE 原生消息（快捷回复、Flex），编辑走 ERP 现有 `line_login.entry_url` 打开 Frappe 原生 Dialog（不是 Vue）。

## 3. 按类通用

- 类别：「收付款写进账本」。本批只做应收端 RE。同类还有：应付端付款 PS（ARRCPCQ 的镜像 APRCPCQ / APRCPIT 已在账套里）、现销 HS 收转账（ARRCPCQ 一行，`stock-b-remaining-design.md:77` 待实录）——**本批不覆盖**，但 `dbf_receipt` 的「收款方式行」写法按类写成可给 PS / HS 复用的函数（类型前缀 + 单号、科目取 ZR/ZP 的 ACCNUM01），不为单一场景写死。
- 入口类：LINE、CC 对话（电脑 / 手机）同一服务端流程；ERP 网页只读。
- 公司类：按类通用、不按这家客户写死——收款类型、折扣类型、销售员、部门全部实时读这本账套；客户编号、发票号前缀不做任何假设。

### 4.3 CC 桌面版

- 新写入模块 `dbf_receipt.py` + `worker` 分流 `direction="receipt"`；载荷版本升到 20，旧版回「版本过高」诚实拒收，ERP 记录显示「CC 桌面版需更新」。
- 主档读回加 ZR / RE / OESLM；新按需种类 `express_ar_open`（一本账套全部未收清发票：单号、日期、客户、销售员、部门、净额、余额，几千行、几十 KB）。
- **写前重读（管钱底线）**：拿到 `PEARNLY.LCK` 后逐张读 ARTRN 当前 `REMAMT`，任一张本次收 > 当前余额（含已被别人收清）→ **整单不写**，回 `already_collected` + 每张当前余额；不自动缩小金额。
- 幂等：抬头 `YOUREF`（C30，界面「อ้างอิง」）填我们的收款记录号；写前查同客户同 YOUREF 已存在就回原 RE 号不重写（同 `dbf_sales` 的 `ref_no+客户`）。

## 5. 隔离与权限（全部服务端拦）

- 新能力码：`collection.write`（LINE / CC 录收款）、`collection.view`（网页收款页看、导出、看凭证）。新岗位「收款员」只给 `collection.write`（不给销售开单）；`collection.view` 给 ERP Admin 与销售岗位。LINE 第 4 格按 `collection.write` 显示，无权是锁图。
- 公司：只列 `allowed_companies`；客户、发票、收款类型都按所选公司的账套取，提交时服务端逐项复核属于这本账套。
- 收款员看所有客户（需求第四节 1：不按收款员过滤）；收款记录收款员只看自己的，`collection.view` 看本公司全部。
- 凭证照片私有，取图走权限判定（本人或 `collection.view`）。
- 账套：只写所选公司经 `target.pick` 定下的那本（11-10「只写对话选中的账套」）；记录里冻结账套键，写入时 CC 再核公司税号（`account_company_matches`）。

## 8. 存储与成本

- 凭证照片：转账约占 70%，每天约 100–120 张 × 压缩后 200–400 KB ≈ 每天 30–40 MB、每月约 1 GB，进原件层（ADR-024，保留同其他原件）。**要核一下甲骨文原件卷余量**（免费 200G 额度已用满，新建卷会收费）。
- 收款记录：每天约 150 条，几 KB，可忽略。未收清快照几千行。
- 外部调用：不识别（不花识别费）；LINE 路径不用模型。CC 对话路径每笔约几次工具调用，模型费约 0.01–0.03 美元/笔（只在用 CC 录时）。
- LINE 推送额度（在这家客户自己的官方号上）：结果尽量用回复（等写入最多约 20 秒，期间显示三个点）；只有电脑不在线、过后补写成功时才用推送。若大量补写，免费额度（泰国免费版每月 300 条）可能不够——需告知客户可能要升级官方号套餐（客户付，不是我们的固定月费）。
- 我们新增固定月费：无。

## 9. 删除、作废、追溯

- 网页不删不改（已定）。收款员录错：**还没写进 Express 的**，可在 LINE / CC 撤回（记录标「已撤回」，不删，凭证保留）；**已写进的**由财务在 Express 原生作废（11-10 已定），再由收款员重录。
- 追溯：记录存收款员、来源（LINE / CC）、确认时间、每次状态变化、CC 回执（RE 号、写入电脑、读回核对）、撤回人。
- Express 里被作废的 RE：本批不回读作废状态（总表 11-09「写错的单不管」）；网页上仍显示当时写入的 RE 号。

## 12. 要主会话定（附建议）

| # | 问题 | 建议 | 不定的影响 |
|---|---|---|---|
| 1 | LINE【确认】与 CC「一句话下令」怎么统一 | **服务端同一个放行规则**：先出确认卡（= 复述：公司·账套·客户·几张发票各收多少·方式·折扣·合计），之后用户**下一次明确同意**才放行，且只写卡片展示后没再改过的版本。LINE 没有模型对话，【确认】按钮（或打「ยืนยัน / 确认 / ok」）就是那句同意；CC 里说「录吧」或点输入框上方「录吧」快捷回复。都走 A 线 `pearnly_write_plan / start` 那套（计划 + 用户消息序号）。「停」：单笔收款，没被电脑领走前可撤回 | 不统一则 LINE、CC 两套放行规则，违反总表 11-10 |
| 2 | 代录模式下要不要也能录收款 / RE 代录配方做不做 | 收款工具在 CC 两种模式都可用，**执行一律直写**（不叫用户换模式）；RE 代录配方本批不做 | 若要求代录也做：多 4–6 小时 + 样本录制，且会抢办公室 Express 界面 |
| 3 | 一笔钱付几家客户 | 本批不做（一张 RE 只对一个客户，Express 原生也是） | 若要做需拆成多张 RE 并共用一张凭证，+3–4 小时 |
| 4 | 客户的退货单 / 减项（ARRCPIT RECTYP 5）要不要能在收款时抵扣 | 本批不做，只列发票 | 有退货单的客户收款员要按抵扣后的钱收，Express 里财务另做 |
| 5 | 撤回：没写进 Express 之前允许收款员在 LINE / CC 撤回 | 允许（乱用兜底「可撤回」） | 不允许则录错只能等写进去再找财务作废 |
| 6 | 新岗位「收款员」 | 新建（只能录收款，看不到销售开单） | 用现有销售岗位则收款员能开销售单 |
| 7 | NLTTEST 写入授权 | 请主会话当面向用户确认：先「原生录 5 张做金标」，再「我们写 5 张」，只写 NLTTEST，白天做，记录保留不作废（或用户指定作废） | 没金标只能按推断写，四个待核点有记错科目的风险 |
| 8 | 这家客户的 Express 版本 | 要核是不是 1.0.1.94（与 NLTTEST 同） | 版本不同要先读它的表结构，可能多 1–2 小时 |

新租户（这家大米客户单开租户 + 自己的官方号，走现有 LINE 开户流水线）需要客户提供：
1. 公司全称、税号、分店号（开租户、对上 Express 账套）；
2. LINE 官方号：在 LINE Developers 建好 Messaging API 频道，给 **Channel ID + Channel secret**（流水线自动取令牌、建 LIFF）；webhook 的「Use webhook」要人手动打开（LINE 无接口）；官方号套餐（推送额度，见 §8）；
3. 装 Express 的那台电脑（能访问账套文件夹）装 CC 桌面版，用租户管理员账号登录一次；电脑白天常开（关了就排队）；
4. 收款员名单（姓名、手机号或 LINE），由管理员在 ERP「团队」里发号并勾「收款员」；收款员加官方号好友并绑定；
5. 在 Express 里确认收款类型已建好并配了科目（现金、各银行转账、ส่วนลดเงินสด）。
