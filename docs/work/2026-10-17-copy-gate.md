### 与设计稿的出入（有意）

| 设计 | 实际 | 原因 |
| --- | --- | --- |
| `extract-ts.cjs` 用 frontend/assistant 的 typescript 解析 i18n.ts / TSX | Python 自写 JS 词法 + 对象解析（i18n.ts）、正则（TSX） | 任务要求纯标准库；本工作树没装 node_modules，提交钩子与 gate.sh 也不必依赖 npm ci |
| checkout `filter: blob:none` | 只加 `fetch-depth: 0` | 部分克隆下 `git cat-file --batch` 逐个懒取基线文件，一次要取约 200 个；完整历史只有约 63 MB |
| 术语词在终端界面拦、后台标黄 | 分强 / 弱两档：强（接口、缓存、载荷、适配器、API、payload…）产品界面拦；弱（字段、令牌、队列、调用、参数、token、webhook、queue）只在 CC 网页 / CC 桌面版 / 登录页 / LINE 卡片拦 | 499d4417 定稿里「字段」等 9 处出现在租户 Desk 的错误提示里，Frappe 官方中文也用「字段」 |
| 提示 1 句、拦截线 30 字 | 2 句、40 字 | 定稿的「按物料编码匹配，未匹配时按条码匹配；重复导入的行将被覆盖。」等 6 条提示是 2 句 |
| 翻译包新增手工行直接拦 | 标黄；新代码引用的词必须在术语表或基线翻译包里，否则 R-HARD 拦 | 生成器只合并不删，术语表改写过的 msgid 会在翻译包留残留行（da-phase3 / multi-desktop 实际出现），分不清手工还是残留 |
| 豁免失效永远报错 | `--repo` 看一个不带登记表的分支时不校验失效 | 豁免表是本工作树的，和还没变基的分支文案对不上；带着表的分支（含变基后）照常校验 |
| 读屏说明 card / drag.instructions 预先登记 | 未登记 | 只在 cc-shell-rebuild 分支里，main 上登记会立刻失效；它们现在只触发标黄，不需要豁免 |
| R-TALK 词表 | 另加「你」（第二人称口语）、「^要」「只…了」 | 设计稿列为必拦的「要人选」「单据较多，只统计了一部分」「等你处理」原词表抓不到 |
| 首页问候「早上好 / 下午好 / 晚上好」 | 预先登记 R-HELLO 豁免 | 泰文 สวัสดีตอนเช้า 命中寒暄词；照 Claude 网页版首页问候，已上线 |
