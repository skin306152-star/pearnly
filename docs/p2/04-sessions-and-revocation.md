# P2.04 会话登记与撤权

日期：2026-09-17。环境：样板站点 `cowork-a.localhost`、`erp-a.localhost`。

## 设计

- **不另造令牌**。登录会话就是 Frappe 原生 session；`pearnly_core` 只做"登记"，
  把每个会话记一行，用于展示、审计与撤权。
- 身份服务侧用 ID token 里的 `sid` 关联，撤权时按 `sid` 精确终止，不误伤别人的会话。
- 撤权分四种：退出本产品、退出全部、改密后撤销其它会话、账号停用。

| 文件 | 作用 |
|---|---|
| `pearnly_core/sessions.py` | 登记、列出、退出本产品、退出全部 |
| `doctype/pearnly_session/` | 会话登记表（用户、部署、会话 id、身份会话 id、UA、IP、状态） |
| `hooks.py` 的 `on_session_creation` | 登录后自动登记 |
| `password.py` | 改密成功后调用"保留当前、撤销其余" |

## 已实测的六条

| 场景 | 结果 |
|---|---|
| 同一站点两个"设备"各自登录 | 登记表 **2 行**，两个会话同时有效 |
| 设备 A 登录是否踢掉设备 B | **不踢**，B 仍有效 |
| **跨产品**：同一账号在 Cowork 与 ERP 两个站点登录 | **两个会话同时有效，互不影响** |
| 两个站点各自的登记表 | Cowork 记 3 条、ERP 记 1 条，**各记各的** |
| 在 Cowork 调用"退出全部" | Cowork 的会话全部失效（`revoked: 3`）；**ERP 的会话不受影响** |
| 改密 | 返回 `revoked_other_sessions: 1`；**当前会话保留，别的会话失效** |
| 账号停用 | 身份服务直接拒绝登录；停用期间登录流程中断 |

其中"跨产品互不踢"这条此前一直挂在未验清单上，现在有证据了。

## 过程中修掉的一个实现错误

最初手写删除 Frappe 会话记录（`frappe.db.delete("Sessions", ...)`），运行时报
`DoesNotExistError: DocType Sessions not found`。改用框架自带的
`frappe.sessions.clear_sessions(user=…, keep_current=…)`——它会同时清数据库与缓存，
比手写可靠。**教训：能用框架的会话 API 就不要自己拼表名。**

## 明确未做

1. **真正的"全局退出"（跨所有产品）没有做。** 现在的"退出全部"是**单个站点范围内**的。
   跨站点的全局退出需要汇总各站点的登记表，属于控制面能力（P4）。本轮验证的是
   "一个产品的操作不影响另一个产品"，这正好也是用户要的。
2. **管理员交接**（owner 转移）未做。
3. **会话列表界面**未做：接口 `my_sessions` 已可用，产品界面还没接。
4. 会话登记表**没有过期清理**，长期运行会累积。
5. 会话的 `last_seen_at` 只在登录时写一次，中间没有刷新。
