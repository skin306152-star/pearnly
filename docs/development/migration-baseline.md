# 迁移必须跟随旧项目当前线上版本

依据：用户 2026-09-19 明确要求，迁移任何功能时必须同步旧项目线上状态，避免迁入旧代码。本规定适用于所有功能迁移，DMS 也不例外。

## 哪个版本才是来源

来源是**当时正在承接生产流量的代码及影响该功能的配置**。必须区分四个事实：本地工作树 HEAD、远端分支 HEAD、已构建镜像、实际运行并接收流量的版本。

- 旧本地目录可能落后且带未提交改动，不能直接按目录复制。
- GitHub 最新提交可能尚未发布，也可能只新增文档，不能直接称为当前生产。
- 最新 Ready revision、候选标签或成功构建可能尚未接流量，要读实际流量/路由。
- Web、Worker、队列消费者和前端资源可能分属不同版本，要按功能经过的组件分别核对。
- 如果有源码挂载、热补丁或动态配置，镜像标签不足以证明实际代码；继续核对覆盖文件、配置或校验和。

## 开工前必须完成

1. **只读回查生产**：目标环境、组件、revision、不可变镜像 digest、流量或消费者归属、核验时间。
2. **映射源码**：用构建记录、镜像源码标签或应用版本等可核对证据定位完整 commit SHA；记录证据位置。只有 revision 名称含短 SHA 而无映射依据时，不算完整证明。
3. **读取固定快照**：使用该 SHA 的只读源码。对象已在本地可用 `git show <sha>:<path>`；否则在独立只读副本中获取，不 reset、pull 或覆盖来源工作树的他人内容。
4. **核对实际行为**：读该功能的入口、共享调用方、队列/重试、权限、相关开关、接口合同、前端产物和语言包。配置只记必要非敏感值或安全引用，不复制生产密钥和用户数据。
5. **登记迁移合同**：线上行为、固定源码、新落点、保留项、有意差异及其当前需求依据。已经退役的旧流程不能因为本地还有文件就复活。

缺少生产访问、源码映射或版本身份不明确时，标记“线上基准未确认”，暂停移植部分；可以继续只读调查和独立工程准备。不得用旧记录或推测代替，也不为取证发送消息、建单或修改生产。

## 迁移中与交付前再次核验

长任务续接、来源项目发布后，以及本批合并/交付前，重新读取线上身份。记录第一次和最后一次核验时间及 SHA，不永久固定为某个历史版本。

- 线上未变：保留回读证据，按已选范围验收。
- 线上变了：比较旧生产基线与新生产基线，检查本功能和共享依赖；有影响则同步迁移最新增量、更新合同并复验后再交付。
- 变更仅是文档，或已证明完全不影响本批及其依赖：记录具体差异路径和不影响的理由，可以复用相关检查，不重跑业务全套。
- 正在分流发布、不同组件版本不一致、线上有未入库补丁：分别记录实际版本及适用范围，先查清本功能使用哪套代码；存在关键歧义时不能宣称已与线上对齐。

“同步”指核对并迁入最新已上线的相关行为，不授权自动更新旧生产，也不要求搬入远端尚未上线的新功能。框架适配可以不同；用户明确要求的功能差异单列，不能用“适配”掩盖漏迁最新修复。

## 工作包必须留下的证据

| 字段 | 要求 |
| --- | --- |
| 功能与组件 | 哪个入口、服务、Worker 或前端参与 |
| 首次 / 最后核验时间 | 实际时间与时区；不是文档创建时间 |
| 线上身份 | 环境、revision、digest、实际流量/消费者版本 |
| 源码映射 | 完整 SHA、依据、只读快照位置 |
| 相关运行配置 | 开关、协议或 schema 差异；不记秘密值 |
| 增量比较 | 首尾线上版本差异、影响判断、已补齐内容 |
| 新仓落点与验证 | 成功、拒绝、失败恢复及已知有意差异 |

工作包和 PR 都应能指向这份证据。证据不足时不能勾选迁移完成或“与旧线上一致”；它不影响如实交付已完成的独立文档和调查结果。
