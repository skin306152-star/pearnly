# 卡片有效期（全产品通用规范）

> 草稿 11-13（A 线，主会话派；用户 11-13：「卡片有效期……dms 做过相关规则，查下照做」）。基准是 DMS 已上线的做法，
> 收款 LINE 卡、CC 对话卡（允许卡 / 提问卡 / 引导卡 / 写入计划「写入」/ 代录任务卡）都照这里做；新卡片开工前先对这份。

这里说的「卡片」：任何点一下就会让服务端**写东西**（写账、交单、确认收款、记住选择、删除）或**推进流程**的按钮组，
不管它出现在 LINE、网页还是 CC 对话里。只读的展示卡不在范围内（但它上面的「编辑 / 打开」按钮在，见第 3 条）。

## 规则

1. **一张卡一个一次性确认号，服务端原子消费。** 同一张卡第二次点，号对不上，绝不写第二次。
   DMS：`pearnly_core/line_session.py` `consume_nonce`；`pearnly_dms/booking/conversation/booking_flow.py`。
   CC：允许卡 / 提问卡以执行记录的 `awaiting_approval` 为号，`toolrun.decide` 只认本对话、本人、还在等的那一次；写入计划以计划号 +
   状态 `awaiting` 为号，`write_plan.start` 只认最新一份。
2. **出新卡就换号，旧卡当场作废**：编辑、重问、失败还回预览都换。
   DMS：`line_session.replace_review_payload`。CC：建新计划旧的标 `replaced`；同一题在别处答过或已记住 → 卡片自动收起。
3. **只读按钮只校验不消费，但必须校验**（开编辑页、看详情）。DMS：`line_session.verify_nonce`。
4. **时间上限写在服务端状态上，过期读出来是空 / 失效；判定在读的时候做，不加定时任务**（记忆 no-cloud-idle-spend）。
   - DMS：会话默认 30 分钟；待选 / 预览 / 逐问 120 分钟；已登记外部写入的会话不随时间消失（`line_session.py:9-13,28-30,59`）；
     回执差异卡单独 23 小时、一张卡只认领一次（`booking/conversation/review_fix.py`）。
   - CC 代录任务：还有没处理的单、且 **7 天没有任何动作**；或**同一公司后来开的代录任务已包含它没处理的票** → 已失效
     （设计 docs/work/2026-11-09-cc-misuse-graceful-design.md 2.3；`express_operator.tasks.expired`）。票不丢，新任务能拉进来。
   - CC 直写对话里会写账的确认（写入计划「写入」、要「允许」的写入工具卡）：**待主会话定**（建议同 DMS 预览 120 分钟）。
   - 只提问不写账的提问卡：不按时间作废——答案交回时服务端逐张重判（已入账的跳过），只在出了新的同题卡或所属任务失效时收起 / 置灰。
5. **点了回什么**（服务端是底线，页面禁用按钮只是表现）：
   - 当前卡第一次点 → 执行；
   - 同卡处理中 / 已处理又点 → 不回话（不重复执行、不报错）；
   - 被新卡替换、过期、已用完 → 回「已失效」状态（不是报错文案），页面把卡置灰写「已失效」，LINE 回「此项已过期，请重新开始」
     （DMS `dms.card.TXT_EXPIRED`）；
   - 已处理的卡点「编辑」→「此卡片已失效，请使用最新的卡片」（DMS `messages.tsv:192` 口径）。
6. **「已失效」与「已取消」分开**：过期 / 被替换写「已失效 / หมดอายุ / Expired / 期限切れ」；用户自己点取消（或停止）写「已取消」。
   CC：执行记录状态 `expired`（只在投影里）→ 卡片「已失效」；`cancelled` →「已取消」。
7. **旧步骤的按钮不跳步**：吃下、原步重问当前这一步。
8. **取消只取消被点的那张、且还没被认领的卡**：旧卡不能抹掉新工作；已提交写入的不说「已取消」。
9. **写过之后只有三种结局**：成功回执；明确被拒 → 原卡带原因还回并换新号；其余结果未知 → 转人工、只读核对、绝不重放。
10. **重试按钮只给「明确发生在写入之前」的失败**。

## 各产品现状（11-13）

| 规则 | DMS | 收款 LINE 卡 | CC 对话卡 |
|---|---|---|---|
| 1 一次性号 | 有 | 缺（确认不要求会话在、草稿无过期） | 允许卡 / 计划有（执行记录、计划状态） |
| 2 出新卡旧卡作废 | 有 | 缺（重开收款旧草稿不作废） | 计划有；提问卡同题收起 |
| 4 时间上限 | 30 / 120 分钟、23 小时 | 缺 | 代录任务 7 天 + 新任务含同票：`pearnly/cc-card-expiry` 已做；直写确认待定 |
| 5 过期回状态 | 有 | 缺（统一 "no longer current"） | 代录卡片 / 计划回 expired：已做 |
| 6 已失效 ≠ 已取消 | 有 | 缺 | 已做（新词条 `steps.expired`） |

## 新卡片开工检查

- 这张卡点了写什么？写之前服务端核哪一个号、哪一个状态？
- 出新卡时旧卡怎么作废？过期时限是多少、写在哪个状态上、在哪一处读时判定？
- 过期 / 被替换 / 处理中又点 / 已处理又点，各回什么（状态，不是报错）？页面怎么显示（已失效 / 已取消）？
- 先写旧代码红的测试：重复点不写两次、旧卡点了不写、过期点了不写。
