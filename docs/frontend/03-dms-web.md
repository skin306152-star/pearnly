# DMS 网页端：先看老产品，再动手

日期：2026-09-18。

## 一句话教训

**动手之前先把老产品读完**。这一轮先做了一版"自己设计"的 DMS 网页端，
被用户当场指出"现在的产品没有这个东西"，返工重做。原因不是理解错了需求，
而是**没有先去看老产品里这些东西长在哪**。

## 老产品 DMS 到底有什么（`static/dms/dms.html` 的 nav，就四项）

| 老产品的项 | 干什么 |
|---|---|
| 身份证录入 `intake` | 四步向导：上传证件 → 客户匹配 → 资料确认 → 推送 DMS |
| 推送记录 `records` | 推送历史。列：时间 /(老板视角多一列"操作员")/ 客户 / 方式 / 状态 |
| 操作员 `roster` | **仅老板可见**。每行一位销售/管理员：各自 DMS 账密，逐行「发绑定码」 |
| 套餐与余额 `billing` | 余额、单价、套餐、订阅/取消续订、充值（生成充值单+上传凭证）、扣费/充值记录、导出明细 |

两个"不在导航里"的东西，是这次返工的关键：

| 东西 | 老产品里它**实际在哪** |
|---|---|
| 连接第三方 DMS（MR.ERP DMS） | **身份证录入页里的一张卡**（`#dx-erp-cards`）+「配置」打开的向导。**不是页面** |
| LINE 绑定码 | **操作员页每一行的按钮**「发绑定码」，点开弹窗（加好友 → 发码 → 可重新生成 / 剩余有效期）。**不是页面** |

「推送记录」的数据源是**推送日志**（`/api/erp/logs?adapter=mrerp_dms`；
老板视角走 `/api/dms/records` 全租户 + 操作员归属列），不是身份证录入那张表。

## 本产品砍掉哪一项

用户 2026-09-17：

> "DMS 身份证录入网页端不要了，业务几乎都在 LINE 完成，网页只负责绑定第三方 dms
> 和其它不变，**只取消网页前端的录入入口**。"

所以侧栏是对齐老产品、减去「身份证录入」：

```text
首页（订阅与计费）   ← 原"套餐与余额"并过来，与 ERP/Cowork 同一个页面
推送记录            ← 后端（推送日志）还没有，页面如实占位
操作员              ← 已做：含每行「发绑定码」
```

## 「取消录入入口」落成了什么

三处一起改，缺一处等于没取消：

1. **新前端侧栏**里没有录入了（`frontend/src/lib/nav.ts` 的 dms 段）。
2. **Desk 工作台**入口标题从「身份证录入」改成「推送记录」
   （`pearnly_control/features.py` 的 `WORKSPACE_LABEL`）—— 名字本身在说
   "这里不是录入的地方"。
3. **后端权限**：那张表对业务角色**只读**（`READ_ONLY_ON_WEB`）。Frappe 的"新增"
   按钮就是按 `create` 权限出现的，所以这是原生做法；直接调接口也会被拒
   （实测 HTTP 403）。⚠️ **不影响 LINE**：webhook 是 `allow_guest` 的独立通道，
   不走这个业务角色。

## 操作员这一页（已做，照老产品搬）

- 列：操作员 / 角色 / 查询权限 / LINE 状态 / 状态 / 操作。
- 行内：**发绑定码** / 编辑 / 停用·启用 / 删除。
- 新增：显示名 / DMS 用户名 / DMS 密码 / 角色（销售·管理员）/ 允许在 LINE 使用查询功能。
- 编辑：DMS 用户名与密码**各改各的**，留空 = 不修改。
- 停用确认：「停用后其 DMS 推送停止并解除 LINE 绑定」；启用确认：「启用后需重新发绑定码连接 LINE」。
- 删除确认：「将解绑其 LINE、移除 DMS 连接；**推送记录将保留**」。
- **仅租户管理员**能用（老产品里这一页 nav 仅 owner 可见、员工直调后端 403）；
  后端 `pearnly_dms/roster.py` 的 `_require_admin` 才是边界。

数据模型也照老产品：**每个操作员 = 一个本地账号 + 他自己的 DMS 账密 + 一行档案**。
操作员账号**只走 LINE**：不建统一身份绑定（`Pearnly Identity` 没这行就登不进来）、
不给本地密码 —— 老产品原话是"操作员 user 永不该有 dms 门 token（只走 LINE）"。

### 两处已知差异（明写，不隐瞒）

1. **"先连接 DMS 才能新增操作员"这条前置检查暂时没有**。老产品新增操作员要先拿老板
   那条 MR.ERP 连接当模板，**新平台还没有 DMS 连接（endpoint）的后端**，无处可依。
   等 DMS 连接做出来必须补上。
2. **"销售提成归属"只能自动匹配**。老产品是下拉选 DMS 顾问（`/api/dms/roster/advisors`
   读外部 DMS 名册并钉死），新平台没有 DMS 连接，取不到名册，所以下拉暂时禁用并说明原因。

## 「连接第三方 DMS」现在没有家 —— 需要定

老产品里那个入口活在**身份证录入页**里，而这一页按用户要求砍掉了。
老产品没有第二个入口（`DXCONNECT.mount` 在成品代码里从没被调用过）。
所以"连接 DMS 的卡/向导放哪"在**老产品里没有答案**，这次**不自己编**，列为待定。
